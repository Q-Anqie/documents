## 选择题

在匹配 IP 地址的正则 \d{1,3}\.\d{1,3} 中，\. 不能写成 .，原因是？

 . 在正则里表示字符串结束
 . 只能匹配数字，无法匹配点号
 . 是元字符，匹配任意字符；\. 才匹配真正的点号
 两者等价，只是写法习惯不同

💡 这是最常见的正则陷阱：192a168b1c1 也会被 \d{1,3}.\d{1,3} 匹配上。凡是字面量中的元字符（. * + ? ( ) [ ] { } ^ $ | \），都要用反斜杠转义

量词 {2,4} 的含义是？

 匹配第 2 到第 4 个字符
 前面那个字符重复出现 2 到 4 次
 匹配值为 2 到 4 的数字
 从第 2 个位置开始匹配 4 个字符

💡 量词作用于紧邻的那一个字符或分组。\d{2,4} 表示 2～4 位数字；* 是 0 次或多次，+ 是 1 次或多次，? 是 0 次或 1 次

对文本 &lt;div&gt;A&lt;/div&gt;&lt;div&gt;B&lt;/div&gt;，&lt;div&gt;.*&lt;/div&gt; 和 &lt;div&gt;.*?&lt;/div&gt; 的匹配结果分别是？

 两者都只匹配到第一个 div
 两者都匹配整段文本
 前者只匹配第一个，后者匹配整段
 前者把整段都吞进去，后者只匹配第一个 div

💡 * 默认是贪婪的，会一路吃到最后一个 &lt;/div&gt;；加上 ? 变成非贪婪，匹配到最近的结束标签就停。提取响应中的字段时，漏写这个 ? 是最典型的"匹配过多"故障

断言 \d+(?=元) 匹配 "100元 200个" 的结果是？

 只匹配 100，且不把"元"算进结果
 匹配 100元
 匹配 200
 匹配 100 和 200 两个结果

💡 (?=...) 是正向前瞻，只要求"后面必须是什么"，本身不参与匹配也不消耗字符——所以结果里只有数字，没有"元"。这正是它比普通分组好用的地方

要从 "$100" 中提取出 100，正确的写法是？

 \d+(?=\$)
 (?&lt;=\$)\d+
 (?&lt;!\$)\d+
 [$\d]+

💡 (?&lt;=...) 是正向回顾（后顾），要求"前面必须是什么"；(?=...) 是前瞻，要求"后面必须是什么"；带 ! 的则是取反。方向搞反是断言类问题最常见的错误

在 JMeter 的 Regular Expression Extractor 中，模板填 $1$ 表示？

 取整个匹配到的字符串
 取最后一个匹配结果
 取正则中第 1 个捕获组的内容
 取第 1 个数字字符

💡 JMeter 用 $n$ 引用第 n 个捕获组，所以要提取 token 必须把目标值用括号圈起来，例如 "token":"(eyJ[^"]+)"。没加括号时 $1$ 拿不到想要的值

非捕获组 (?:...) 的作用是？

 让分组不参与匹配
 只做分组，不占用捕获组编号，也不进提取结果
 让整个正则忽略大小写
 表示该分组可以被重复使用

💡 当括号只是用来限定量词范围、并不需要提取内容时，用 (?:) 更合适。它能避免捕获组编号错位——编号一乱，$1$ 或 group(1) 就会取到错误的字段

Python 中 re.match 与 re.search 的区别是？

 match 返回所有匹配，search 只返回第一个
 match 区分大小写，search 不区分
 两者完全等价，只是历史遗留的别名
 match 只从字符串开头匹配，search 会扫描整个字符串

💡 判断"整串是否符合某格式"用 fullmatch，从任意位置找内容用 search，match 则只在开头尝试。很多"断言不生效"的脚本，就是把 search 误写成了 match

写 Python 正则时推荐使用 r"\d+" 而不是 "\d+"，原因是？

 避免反斜杠被 Python 字符串本身转义，导致传给正则引擎的内容变样
 加 r 前缀可以提升匹配速度
 不加 r 会导致中文无法匹配
 不加 r 时 re 模块会直接报错

💡 没有 r 前缀时，Python 会先按字符串规则解释反斜杠，"\d" 这类序列可能被吃成别的字符，正则拿到的就不是你写的模式。凡是写正则，一律加 r 前缀是最省心的习惯

要把手机号 13812348000 脱敏成 138****8000，思路是？

 用 re.findall 把手机号全部替换为空字符串
 用 re.split 按数字切分后重新拼接
 用 re.sub 配合捕获组与反向引用，只替换中间四位
 用 re.match 判断格式后再做字符串截取和拼接

💡 标准做法是 re.sub(r"(\d{3})\d{4}(\d{4})", r"\1****\2", s)：用捕获组圈住要保留的前三位和后四位，替换时用 \1、\2 反向引用回来。日志脱敏、身份证脱敏都是同一套路

日志里每行都可能出现 ERROR，想提取所有以 ERROR 开头的行，需要开启哪个标志？

 re.IGNORECASE
 re.MULTILINE
 re.DOTALL
 不需要任何标志，默认就能匹配每一行

💡 默认情况下 ^ 只匹配整个字符串的开头，re.MULTILINE 让它匹配每一行的行首。而 re.DOTALL 是让 . 能匹配换行，re.IGNORECASE 是忽略大小写，三者用途不同

正则"匹配不到"时，下列哪种排查思路最不可取？

 检查目标文本里是否有隐藏的换行或空格
 检查元字符是否漏了转义，分组是否漏了括号
 用在线正则工具逐步缩小表达式范围定位问题
 直接不断加 .* 把表达式改得更"宽松"

💡 到处补 .* 会让表达式失去约束力，可能匹配到完全不相关的内容，把问题从"匹配不到"变成"匹配错"。正确做法是先用 .* 缩小范围验证，再逐步收紧并转义特殊字符
