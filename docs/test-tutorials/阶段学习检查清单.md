# 阶段学习检查清单

这份清单用来判断你是否真的学会了，而不是"看过教程"。每学完一个阶段，都建议用清单自查一次。勾不上的地方不要急着跳到下一章，先回到对应教程补练。

!!! tip "勾选状态会自动保存"
    每个阶段的复选框都会记住你的勾选，**下次打开这一页还在**（存在本机浏览器的 localStorage 里，换浏览器或清站点数据会丢，详见 [学习进度说明](学习中心/学习进度说明.md)）。

    这一页的勾选**不等同于**「学习中心」里的教程完成度——学习中心记的是「这篇教程我读完了」，这里记的是「这条能力我真的会了」。两件事分开记，才能看出「读完了但不会用」的差距。

---

## 怎么用这一页

!!! warning "先明确一件事：这里的勾，没有客观验证"

    这份清单是**自评**。自评最容易犯的错是"我大概知道"就勾上，等面试官追问两句才发现讲不完整。

    所以判断一条该不该勾，用下面这个标准：

    | 勾之前的自问 | 不该勾的样子 | 该勾的样子 |
    |--------------|--------------|------------|
    | 让我不看资料讲一遍，能讲几分钟？ | 只能说出一句定义 | 能举一个自己遇到的例子，能说出反例 |
    | 让我现场做一遍，能不能做出来？ | 记得"好像是用 `grep`" | 能直接敲出命令并解释每个参数 |
    | 出了问题我能不能自己定位？ | 只能等别人帮我看 | 能说出先查什么、再查什么 |

    **一条的判据越模糊，越容易自我欺骗。** 下面每一组清单后面都跟了一句「用什么验证」，对着它做一遍再勾。

**推荐的用法节奏**：

1. **阶段开始时**先通读一遍，知道这一阶段要练到什么程度，别急着勾。
2. **学习过程中**遇到能对上号的内容，回来勾一条——勾的瞬间顺便回忆「我是怎么验证的」。
3. **阶段结束时**整体过一遍，把勾不上的列成补课清单，回对应教程补。
4. **面试前一周**再过一遍，重点看「能说清楚」那几组——面试考的就是这个。

**进度怎么看**：每个阶段顶部的进度条只统计这一阶段的勾选情况。**低于 80% 不建议进入下一阶段**，因为后一阶段会大量复用前一阶段的能力（比如第 3 阶段的接口测试要用第 2 阶段的 HTTP 和 Postman）。

## 最终达标标准

如果你能独立完成下面这件事，说明已经具备初级测试工程师的项目能力：

```text
拿到一个登录/下单/支付/查询类需求
  -> 拆测试点
  -> 写测试用例
  -> 准备测试数据
  -> 执行功能和接口测试
  -> 查数据库和日志
  -> 提交缺陷
  -> 回归验证
  -> 输出测试报告
```

不要只追求"学到第几章"。真正重要的是：你能不能把一个需求从头测到尾。

!!! tip "怎么判断自己是不是真的走完了一遍"
    上面这条链路上，有 4 个环节是「不看资料就容易卡住」的，它们才是真正的检验点：

    | 环节 | 卡住的样子 | 走通的样子 |
    |------|------------|------------|
    | 拆测试点 | 只能想到正常路径 | 能按「正常 / 异常 / 边界 / 状态 / 权限」五个角度各列几条 |
    | 准备测试数据 | 等别人给数据 | 知道自己造数据、且测完能清理 |
    | 查数据库和日志 | 只会看页面 | 能定位到具体哪张表、哪条日志、哪个时间点 |
    | 输出测试报告 | 只贴用例通过率 | 能给出「能不能上线」的判断和依据 |
