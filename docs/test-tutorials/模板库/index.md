# 模板库

模板库用于解决新手常见问题：知道要写测试文档，但不知道格式、字段和内容深度。这里的模板可以直接复制到表格、文档或项目管理工具中使用。

## 使用方式

1. 先看模板字段，理解每一列为什么存在。
2. 再看示例，模仿示例写自己的内容。
3. 最后用检查清单确认是否遗漏关键信息。

## 每份模板都给了一段「直接复制」

五份模板的开头都有一段 `text` 代码块形式的**纯文本骨架**。点右上角的复制按钮，粘进禅道、Jira、飞书、语雀、Excel 都不会散架。

**为什么不用表格当模板**：表格在本页看起来整齐，但复制到那些工具里会因为竖线和换行散成一团，实际没法用。所以本页的办法是分工：

- 表格用来说明「每个字段为什么存在」，帮助你理解。
- 代码块用来实际填写，保证复制可用。

## 除了格式，这些模板还回答了「怎么判断」

格式是最简单的部分，难的是判断。所以每份模板都补了一节判断依据：

| 模板 | 补了什么判断依据 |
|------|------------------|
| 缺陷报告 | 严重程度和优先级不是一回事，四种真实组合；开发说「这不是 bug」时的五种应对 |
| 测试用例 | 用例写到多细才够，用「换个人能不能执行」判断；用例评审的四个必查角度 |
| 接口测试用例 | 断言要写三层（响应/内容/数据），各层分别漏掉什么；接口幂等按 HTTP 语义怎么测 |
| 测试计划 | 排期怎么估才不离谱，四个环节的时间占比；风险要写成「条件 → 影响 → 动作」 |
| 上线检查清单 | 先解决「清单没人执行」，负责人/时点/证据三列；上线后 30 分钟按时间顺序验证 |

## 新手建议

- 不要为了填满模板而写废话，每个字段都要服务于沟通。
- 不确定的内容可以写“待确认”，但不要空着不管。
- 模板不是死格式，实际项目里要跟团队工具适配。
- 最重要的不是表格好看，而是别人能看懂、能复现、能决策。
