# 集合框架深入（Storing Data Using the Collections Framework）

> 来源：Oracle 官方 [Dev.java 教程](https://dev.java/learn/) →《The Collections Framework》子文章
> 本模块在「模块四-集合框架」基础上**补全子文章细节**：List 实现选择、迭代、工厂方法、Map 深入、键值操作、排序 Map、ArrayList vs LinkedList。后端面试最高频板块。

## 一、为什么集合框架如此重要？

**集合框架（Collections Framework）是 JDK 中使用最广泛的 API。** 无论你开发什么应用，几乎都要在内存中存储和处理数据。数据结构的的历史几乎和计算本身一样悠久——集合框架正是对"如何在内存中存储、组织、访问数据"这些早在 Java 发明前就成熟概念的**高效实现**。

**发展史（面试可聊）**：
- 1998 年 Java SE 2 首次引入
- **Java SE 5**：加入泛型（最重大更新）
- **Java 8**：加入 Lambda 表达式 + 接口默认方法（最重大更新之一）
- 几乎每个 JDK 版本都有改动

> **本质**：集合框架是一组**接口**，建模不同容器里存储数据的方式；每种接口至少有一个**实现类**。理解接口与实现分离是核心。

---

## 二、集合层次结构（Collection Hierarchy）

```
Iterable
 └── Collection
      ├── List        (有序、可重复、可索引)
      │    ├── ArrayList        (内部数组)
      │    └── LinkedList       (双向链表)
      ├── Set         (不重复)
      │    ├── HashSet          (哈希)
      │    ├── LinkedHashSet    (哈希+插入序)
      │    ├── SortedSet → TreeSet (排序)
      │    └── NavigableSet
      └── Queue / Deque
           ├── LinkedList
           ├── ArrayDeque
           └── PriorityQueue
```

> 独立于 Collection 的 **Map**：`HashMap`、`LinkedHashMap`、`TreeMap`（SortedMap/NavigableMap）、`Hashtable`、`ConcurrentHashMap`。

---

## 三、Collection 接口（The Collection Interface）

`Collection` 是最基础的集合接口，定义了所有集合共有的操作：

```java
// 基础操作
int size();                    // 元素个数
boolean isEmpty();             // 是否为空
boolean contains(Object o);    // 是否包含
boolean add(E e);              // 添加（成功返回 true）
boolean remove(Object o);      // 移除
void clear();                  // 清空

// 批量操作
boolean addAll(Collection<? extends E> c);
boolean removeAll(Collection<?> c);
boolean retainAll(Collection<?> c);   // 只保留交集
boolean containsAll(Collection<?> c);

// 数组转换
Object[] toArray();
<T> T[] toArray(T[] a);
```

> **注意**：`Collection` 接口在集合框架里**没有具体实现类**，它依赖其子接口的实现。但 `Collections` 工具类提供了一大批静态方法。

## 四、List 接口与实现选择（Extending Collection with List）

**`List` 接口在普通集合上新增两个功能**：
1. 迭代顺序**始终固定**，且遵循元素被加入的顺序（插入序）。
2. 元素**有索引**，可按位置访问。

```java
List<String> list = new ArrayList<>();
list.add("a");      // 末尾添加
list.add(0, "z");   // 指定索引插入
String s = list.get(0);      // 按索引取
list.set(0, "x");            // 替换
list.remove(0);              // 移除
list.indexOf("a");           // 查找索引
```

### ArrayList vs LinkedList —— 怎么选？

`List` 接口有两个实现：**`ArrayList`**（内部数组）和 **`LinkedList`**（双向链表）。**哪一个更好？**

> **官方结论：不确定时，首选 `ArrayList`。** 60 年代计算机发明时关于链表的优势（插入删除快于数组）在现代硬件下已不成立——**CPU 缓存与指针追逐（pointer chasing）** 大大削弱了链表的性能优势。**遍历 `ArrayList` 远比 `LinkedList` 快**，主要因为指针追逐和 CPU 缓存未命中。

- **`ArrayList`**：随机访问 O(1)，内存连续、缓存友好，遍历快。**默认推荐**。
- **`LinkedList`**：头尾插入/删除 O(1)，但随机访问 O(n)、指针追逐导致缓存不友好。**仅在频繁头尾操作且需 Deque 行为时考虑**。

> **面试高频**：ArrayList vs LinkedList 的底层结构、增删改查时间复杂度、为何现代环境下 ArrayList 优先（CPU 缓存/指针追逐/连续内存）。

## 五、迭代集合（Iterating over the Elements of a Collection）

三种迭代方式：

```java
// 1. for-each（语法糖，底层是 iterator）
for (String s : list) System.out.println(s);

// 2. 显式 Iterator（可安全删除）
Iterator<String> it = list.iterator();
while (it.hasNext()) {
    String s = it.next();
    if (s.equals("x")) it.remove();   // 用 it.remove() 而非 list.remove()，避免并发修改异常
}

// 3. 集合自带 forEach（Java 8+，接受 Lambda）
list.forEach(s -> System.out.println(s));
```

> **关键坑（面试必考）**：在 for-each 循环里用 `list.remove()` 会抛 **`ConcurrentModificationException`**（fail-fast 机制）。必须用 `Iterator.remove()`，或用 `removeIf`（Java 8+）：
>
> ```java
> list.removeIf(s -> s.equals("x"));   // 最简洁安全的删除方式
> ```

## 六、Set / SortedSet / NavigableSet

**`Set` 不重复元素**。常用实现：

| 实现 | 底层 | 特性 |
|------|------|------|
| `HashSet` | HashMap | 无序，O(1) 增删查 |
| `LinkedHashSet` | 哈希+链表 | 保留**插入序** |
| `TreeSet` | 红黑树 | **按自然序/比较器排序**，O(log n) |

```java
Set<String> set = new HashSet<>();
set.add("a");
set.contains("a");  // true
set.remove("a");
```

**`SortedSet` / `NavigableSet`**（TreeSet 实现）提供排序能力：

```java
SortedSet<Integer> sorted = new TreeSet<>();
sorted.add(3); sorted.add(1); sorted.add(2);
sorted.first();   // 1（最小）
sorted.last();    // 3（最大）
sorted.subSet(1, 3);   // [1, 2) 子集
sorted.headSet(3);     // < 3
sorted.tailSet(1);     // >= 1
```

## 七、Map 接口（Maps）

**`Map` 不是 `Collection` 的子接口**，它是独立的键值对映射结构。键唯一（Map 键的集合是 Set）。

```java
Map<String, Integer> map = new HashMap<>();
map.put("a", 1);
map.put("b", 2);

Integer v = map.get("a");        // 1
map.getOrDefault("c", 0);        // 0（不存在返回默认值）
map.containsKey("a");            // true
map.remove("a");

// 遍历
for (Map.Entry<String, Integer> e : map.entrySet()) {
    System.out.println(e.getKey() + ": " + e.getValue());
}
map.forEach((k, v) -> System.out.println(k + ": " + v));
```

### Map 实现对比

| 实现 | 特性 | 用途 |
|------|------|------|
| `HashMap` | 无序，O(1)，非线程安全 | **默认首选** |
| `LinkedHashMap` | 保留插入序（或访问序） | 需要顺序时 |
| `TreeMap` | 按键排序（自然序/比较器） | 需要有序遍历时 |
| `Hashtable` | 线程安全但性能差 | **已过时，用 ConcurrentHashMap** |
| `ConcurrentHashMap` | 线程安全，高并发 | **并发场景首选** |

> **面试高频**：HashMap 底层（数组+链表+红黑树，Java 8 起链表长度>8 转红黑树）、扩容机制（默认 0.75 负载因子）、线程安全（Hashtable vs ConcurrentHashMap vs Collections.synchronizedMap）。

## 八、Map 与 Lambda（Maps and Lambdas）

Java 8 起 Map 新增一批便捷方法，配合 Lambda 非常强大：

```java
Map<String, Integer> map = new HashMap<>();

// computeIfAbsent：键不存在则计算放入（类似"惰性初始化"）
map.computeIfAbsent("key", k -> 42);

// merge：处理重复键（聚合）
map.merge("count", 1, Integer::sum);   // 若已有值则求和，否则设为 1

// getOrDefault：不存在返回默认值
int v = map.getOrDefault("key", 0);

// replaceAll：批量更新
map.replaceAll((k, v) -> v * 2);
```

> **面试加分**：`computeIfAbsent` 用于缓存、`merge` 用于分组计数（`groupingBy` 类似）、`getOrDefault` 避免 NPE。

## 九、处理键和值（Working with Keys and Values）

```java
Map<String, Integer> map = new HashMap<>();
map.put("a", 1);

map.keySet();       // 键的 Set 视图（改动会反映到 map）
map.values();       // 值的 Collection 视图
map.entrySet();     // 键值对 Set

// 遍历视图
for (String key : map.keySet()) { ... }
for (Integer val : map.values()) { ... }
for (Map.Entry<String, Integer> e : map.entrySet()) { ... }
```

> **注意**：视图是"活的"，对视图的修改（如 `remove`）会反映到原 Map；但**直接对视图 add 不一定会成功**。遍历时修改 Map 会抛 `ConcurrentModificationException`。

## 十、排序 Map（Sorted Maps）

**`TreeMap`** 按键排序，配合自定义比较器：

```java
// 自然序（键需实现 Comparable）
TreeMap<String, Integer> tree = new TreeMap<>();
tree.put("banana", 2); tree.put("apple", 1); tree.put("cherry", 3);
tree.firstKey();   // "apple"
tree.lastKey();    // "cherry"
tree.headMap("banana");   // {apple=1}
tree.tailMap("banana");   // {banana=2, cherry=3}
tree.subMap("apple", "cherry");  // [apple, cherry)

// 自定义比较器（倒序）
TreeMap<String, Integer> rev = new TreeMap<>(Comparator.reverseOrder());
```

## 十一、选择键类型（Choosing Keys）

**Map 的键选择有讲究**，直接影响正确性和性能：

- 键应**不可变**且正确实现 `equals`/`hashCode`（如 `String`、`Integer`、枚举）。
- 自定义对象做键时，**必须重写 `equals` 和 `hashCode`**，否则查找失败。
- 不要用可变对象做键（hash 值变了会导致找不到）。
- 多键场景可封装成不可变键对象，或用 `LinkedHashMap`/组合。

```java
// 自定义类做键必须重写 equals/hashCode
class Key {
    final int id;
    Key(int id) { this.id = id; }
    @Override public boolean equals(Object o) { ... }
    @Override public int hashCode() { ... }
}
```

> **面试高频**：Map 键为何要不可变 + 正确 equals/hashCode、`HashMap` 查找原理（hash → 桶 → 链表/红黑树）。

## 十二、栈与队列（Stacks and Queues）

**Deque（双端队列）** 是栈/队列的首选，**`Deque` 接口取代了古老的 `Stack` 类**（`Stack` 已过时，继承自 Vector，性能差）。

```java
// 作为栈（LIFO）—— 用 ArrayDeque，不用 Stack
Deque<Integer> stack = new ArrayDeque<>();
stack.push(1); stack.push(2); stack.push(3);
int top = stack.pop();        // 3（后进先出）
stack.peek();                 // 查看栈顶不移除

// 作为队列（FIFO）—— 用 ArrayDeque 或 LinkedList
Queue<String> queue = new ArrayDeque<>();
queue.offer("a"); queue.offer("b");   // 入队
String front = queue.poll();           // "a" 出队
queue.peek();                          // 查看队首

// 优先级队列（按优先级出队，非 FIFO）
PriorityQueue<Integer> pq = new PriorityQueue<>();
pq.offer(3); pq.offer(1); pq.offer(2);
pq.poll();   // 1（最小优先）
```

> **面试高频**：为何不用 `Stack`（继承 Vector、全方法同步、性能差）、`Deque` 作为栈/队列首选、`ArrayDeque` vs `LinkedList`、`PriorityQueue` 堆实现（默认小顶堆）。

## 十三、工厂方法（Factory Methods）

**Java 9 起集合提供不可变工厂方法**，用于快速创建不可变集合（不可增删改）：

```java
List<String> list = List.of("a", "b", "c");       // 不可变 List
Set<String> set = Set.of("a", "b");                // 不可变 Set
Map<String, Integer> map = Map.of("a", 1, "b", 2); // 不可变 Map（最多10对）
Map<String, Integer> bigMap = Map.ofEntries(
    Map.entry("a", 1), Map.entry("b", 2));         // 多于10对

// 使用
list.get(0);       // "a"
// list.add("d");  // 抛 UnsupportedOperationException（不可变）

// 可变集合可用 Arrays.asList 或 new ArrayList<>(List.of(...))
List<String> mutable = new ArrayList<>(List.of("a", "b"));
```

> **面试高频**：`List.of()` 返回的集合**不可变**且**禁止 null**（`NullPointerException`）、与 `Arrays.asList` 的区别（前者固定大小+不可变，后者可变但定长）、为何用不可变集合更安全。

## 核心速查表

| 主题 | 关键点 | 要点 |
|------|--------|------|
| 层次 | Iterable→Collection→List/Set/Queue；Map 独立 | 接口与实现分离 |
| List 选择 | `ArrayList` 默认优先 | CPU 缓存/指针追逐使链表优势消失 |
| 迭代 | for-each / Iterator / forEach | 循环中删除用 `removeIf` 或 `it.remove()` |
| Set | HashSet/LinkedHashSet/TreeSet | 不重复，TreeSet 排序 |
| Map | HashMap 默认，TreeMap 排序，ConcurrentHashMap 并发 | 键需不可变+equals/hashCode |
| Map 新 API | computeIfAbsent/merge/getOrDefault/replaceAll | Java 8 便捷方法 |
| 栈队列 | `Deque`（ArrayDeque）取代 `Stack` | 栈 LIFO、队列 FIFO、PriorityQueue |
| 工厂方法 | `List.of/Set.of/Map.of` | 不可变、禁 null、防意外修改 |
| ArrayList vs LinkedList | 数组 vs 双向链表 | 随机访问 O(1) vs O(n)，默认 ArrayList |

> **后端实操**：日常用 `ArrayList` + `HashMap`；并发用 `ConcurrentHashMap`；去重用 `HashSet`；排序用 `TreeMap`/`TreeSet`；栈队列用 `ArrayDeque`；不可变数据用 `List.of`。避免 `Stack`、`Hashtable`、`Vector` 等遗留类。
