# 注解（Annotations）

> 来源：Oracle 官方 [Dev.java 教程](https://dev.java/learn/) →《Annotations》
> 忠实翻译，保留全部代码示例。本文为后端面试高频板块（Spring、MyBatis 等框架基石）。

**注解为程序提供元数据（metadata）。** 它们本身不影响代码逻辑，而是为编译器、开发工具、运行时提供信息。注解有许多用途，主要包括：

1. **给编译器的信息** —— 编译器可用注解检测错误或抑制警告。
2. **编译期与部署期处理** —— 软件工具可处理注解信息以生成代码、XML 文件等。
3. **运行时处理** —— 某些注解可在运行时被读取（这正是反射、Spring 框架的基础）。

---

## 一、注解的格式（The Format of an Annotation）

**最简单的形式**：注解看起来像下面这样，`@` 符号告诉编译器后面是注解。下面例子的注解名是 `Override`：

```java
@Override
void mySuperMethod() { ... }
```

**带元素（element）的注解**——元素可命名也可匿名，且有值：

```java
@Author(name = "John Doe", date = "3/27/2003")
```

```java
@SuppressWarnings("unchecked")
```

**若只有一个名为 `value` 的元素**，则可以省略名字：

```java
@SuppressWarnings("unchecked")     // 等价于 @SuppressWarnings(value = "unchecked")
```

**若注解没有元素**，则括号也可省略（如上面 `@Override` 的例子）。

**同一声明可应用多个注解**：

```java
@Author(name = "Jane Doe")
@Ebook
public class MyClass { ... }
```

**若注解类型相同**，则称为**重复注解（repeating annotation）**（Java SE 8 起支持）。

注解类型可以是 Java SE API 中 `java.lang` 或 `java.lang.annotation` 包定义的（如 `Override`、`SuppressWarnings`），也可以自定义（如上面的 `Author`、`Ebook`）。

---

## 二、注解可以用于哪里？（Where Annotations Can Be Used）

**注解可应用于声明**：类、字段、方法及其他程序元素的声明。用于声明时，按惯例每个注解占一行。

**Java SE 8 起，注解还可应用于类型的使用（type use）**，这种形式叫**类型注解（type annotation）**。例如：

```java
// 类实例创建表达式
@Readonly List<String> list = new @Readonly ArrayList<>();

// 类型转换
String s = (@NonNull String) obj;

// implements 子句
class MyClass implements @Readonly Serializable { ... }

// 抛出异常声明
void myMethod() throws @Critical NullPointerException { ... }
```

## 三、声明注解类型（Declaring an Annotation Type）

很多注解取代了代码中的注释。假设一个软件团队习惯在每个类主体开头写注释提供重要信息：

```java
public class Generation3List extends Generation2List {
    // Author: John Doe
    // Date: 3/27/2003
    // Class description: ...
}
```

要用注解添加同样的元数据，必须先定义注解类型。语法：

```java
@interface ClassPreamble {
    String author();
    String date();
    String currentRevision() default "1";
    String lastModified() default "N/A";
    String lastModifiedBy() default "N/A";
    // ...
    String[] reviewers();
}
```

注解类型定义看起来像接口定义，只是关键字 `interface` 前加了 `@`。**注解类型本身是接口的一种形式。** 注解体里的元素声明看起来很像方法，且可定义默认值（`default`）。

定义后即可使用（填值）：

```java
@ClassPreamble(
    author = "John Doe",
    date = "3/27/2003",
    currentRevision = "6",
    lastModified = "4/12/2004",
    lastModifiedBy = "Jane Doe",
    reviewers = {"Alice", "Bob"}
)
public class Generation3List extends Generation2List { ... }
```

> **注意**：要让 `@ClassPreamble` 的信息出现在 Javadoc 生成的文档里，必须在 `@ClassPreamble` 定义上标注 `@Documented` 注解。

## 四、预定义注解类型（Predefined Annotation Types）

Java SE API 预定义了一组注解类型。有些被 Java 编译器使用，有些作用于其他注解。

### 4.1 Java 语言使用的注解类型（java.lang 中）

`java.lang` 定义的预定义注解是 **`@Deprecated`、`@Override`、`@SuppressWarnings`**。

**`@Deprecated`** —— 表示被标记的元素已过时、不应再使用。程序一旦使用带 `@Deprecated` 的方法、类或字段，编译器就生成警告。过时元素还应用 Javadoc `@deprecated` 标签文档化：

```java
/**
 * @deprecated
 * 解释为何过时、用什么替代
 */
@Deprecated
public void oldMethod() { ... }
```

> Java SE 9 起，`@Deprecated` 增加了 `forRemoval` 属性，表示该元素是否将在未来版本中被移除，默认值为 `false`。

**`@Override`** —— 告诉编译器该元素意在覆盖父类声明的元素。虽然覆盖方法时**不是必须**用它，但它能帮助防止错误：若被 `@Override` 标记的方法未能正确覆盖父类方法，编译器会报错。

```java
@Override
public String toString() { return "MyClass"; }
```

**`@SuppressWarnings`** —— 告诉编译器抑制本来会生成的特定警告。每个编译器警告属于一个类别，Java 语言规范列出四类：

| 警告字符串 | 含义 |
|-----------|------|
| `unchecked` | 未检查警告（与泛型之前的遗留代码交互时产生） |
| `deprecation` | 过时警告 |
| `removal` | 移除警告 |
| `preview` | 预览特性警告 |

```java
@SuppressWarnings("unchecked")
List<String> list = (List<String>) legacyList;   // 抑制 unchecked 警告
```

```java
@SuppressWarnings({"unchecked", "deprecation"})   // 抑制多类警告
```

**`@SafeVarargs`** —— 应用于方法或构造器时，断言代码没有对 varargs 参数执行潜在的不安全操作。使用时，与 varargs 相关的 unchecked 警告被抑制。

**`@FunctionalInterface`**（Java SE 8 引入）—— 表示该类型声明意在作为**函数式接口**（符合 Java 语言规范定义）。若编译器发现它不是有效的函数式接口，会报错。

### 4.2 作用于其他注解的元注解（java.lang.annotation 中）

作用于其他注解的注解叫**元注解（meta-annotation）**。

**`@Retention`** —— 指定被标记的注解如何存储：

| RetentionPolicy | 含义 |
|-----------------|------|
| `SOURCE` | 注解仅在源代码级保留，被编译器忽略 |
| `CLASS` | 编译器在编译期保留，但 JVM 忽略 |
| `RUNTIME` | JVM 保留，可在运行时读取（反射） |

**`@Documented`** —— 表示使用该注解的元素应被 Javadoc 工具文档化（默认注解不包含在 Javadoc 中）。

**`@Target`** —— 限制该注解可应用到的 Java 元素类型。值是 `ElementType` 之一：

| ElementType | 可应用位置 |
|-------------|-----------|
| `ANNOTATION_TYPE` | 注解类型 |
| `CONSTRUCTOR` | 构造器 |
| `FIELD` | 字段或属性 |
| `LOCAL_VARIABLE` | 局部变量 |
| `METHOD` | 方法 |
| `MODULE` | 模块声明 |
| `PACKAGE` | 包声明 |
| `PARAMETER` | 方法参数 |
| `RECORD_COMPONENT` | record 的组件 |
| `TYPE` | 类、抽象类、接口、注解接口、枚举、record 声明 |
| `TYPE_PARAMETER` | 类型参数 |
| `TYPE_USE` | 类型使用处（如字段声明） |

**`@Inherited`** —— 表示该注解类型可从父类继承（默认不继承）。查询注解时，若类无此注解，则查询其父类。仅适用于类声明。

**`@Repeatable`**（Java SE 8 引入）—— 表示被标记的注解可对同一声明或类型使用多次。

## 五、类型注解与可插拔类型系统（Type Annotations and Pluggable Type Systems）

Java SE 8 之前，注解只能应用于声明。**Java SE 8 起，注解可应用于任意类型使用**——即你能用类型的任何地方都能用注解：类实例创建表达式（`new`）、强转（cast）、`implements` 子句、`throws` 子句。这种形式叫**类型注解**。

类型注解旨在支持对 Java 程序进行更强类型检查。Java SE 8 不提供类型检查框架，但允许编写（或下载）一个作为可插拔模块、与 Java 编译器配合使用的类型检查框架。

**示例**：你想确保程序中某个变量永不被赋为 `null`，避免 `NullPointerException`。可写一个自定义插件来检查，然后修改代码给该变量加注解：

```java
@NonNull String str = "hello";   // 声明该变量永不为 null
```

编译时带上 `NonNull` 模块，若编译器检测到潜在问题就打印警告。修正代码消除所有警告后，运行时该错误就不会发生。**可同时使用多个类型检查模块，每个检查一种错误**，在 Java 类型系统之上叠加自定义检查。

> 实际中不必自己写类型检查模块，第三方已做好——如华盛顿大学的 **Checker Framework**，包含 `NonNull` 模块、正则模块、互斥锁模块。

## 六、重复注解（Repeating Annotations）

有些场景你想对同一声明或类型使用应用**同一个注解多次**。Java SE 8 起的重复注解支持做到这点。

**场景示例**：你写代码使用一个定时器服务，能在指定时间或计划运行方法（类似 UNIX cron）。现在你想在每月最后一天和每周五晚上 11 点都运行 `doPeriodicCleanup()` 方法。为此创建一个 `@Schedule` 注解并应用两次：

```java
@Schedule(dayOfMonth = "last")
@Schedule(dayOfWeek = "Fri", hour = 23)
public void doPeriodicCleanup() { ... }
```

由于兼容性原因，重复注解存储在**容器注解（container annotation）**中，由 Java 编译器自动生成。要让编译器做到这点，代码里需要两个声明：

**第 1 步：声明可重复注解类型** —— 该注解类型必须用 `@Repeatable` 元注解标记。`@Repeatable` 括号里的值是编译器生成的容器注解类型：

```java
@Repeatable(Schedules.class)
public @interface Schedule {
    String dayOfMonth() default "first";
    String dayOfWeek() default "Mon";
    int hour() default 12;
}
```

**第 2 步：声明容器注解类型** —— 容器注解必须有一个数组类型的 `value` 元素，数组的组件类型必须是可重复注解类型：

```java
public @interface Schedules {
    Schedule[] value();
}
```

> 未先声明为可重复就对同一声明应用相同注解，会产生编译错误。

**读取（Retrieving Annotations）**：反射 API 提供多个方法读取注解。返回单个注解的方法（如 `AnnotatedElement.getAnnotation(Class)`）行为不变——只在该类型注解存在时返回单个；若存在多个，需先取容器注解。Java SE 8 新增的方法（如 `AnnotatedElement.getAnnotationsByType(Class)`）会扫描容器注解一次返回多个。

---

## 七、设计注意事项（Design Considerations）

设计注解类型时，要考虑该类注解的**基数（cardinality）**：现在一个注解可用零次、一次，若标记为 `@Repeatable` 则可用多次。也可用 `@Target` 元注解限制注解可用位置。**设计注解类型要谨慎**，确保使用它的程序员觉得它尽可能灵活且强大。

## 核心速查表

| 概念 | 要点 |
|------|------|
| 注解本质 | 元数据，本身不影响逻辑，为编译器/工具/运行时提供信息 |
| 格式 | `@` + 注解名（+ 可选元素/值），`@Override`、`@Author(...)` |
| 预定义注解 | `@Deprecated`、`@Override`、`@SuppressWarnings`、`@SafeVarargs`、`@FunctionalInterface` |
| 元注解 | `@Retention`、`@Target`、`@Documented`、`@Inherited`、`@Repeatable` |
| Retention | `SOURCE` / `CLASS` / `RUNTIME`（运行时可读，反射基石） |
| 类型注解 | Java 8 起可标注任意类型使用，配合可插拔类型检查器 |
| 重复注解 | `@Repeatable` + 容器注解（数组 value 元素），Java 8 起 |
| 读取 | 反射 `getAnnotation` / `getAnnotationsByType` |

> **面试高频**：`@Retention(RUNTIME)` 为何是 Spring/MyBatis 运行时读取注解的前提、`@Target` 限制注解用武之地、`@Repeatable` 容器注解机制、`@FunctionalInterface` 与 lambda 关系、`@Inherited` 继承行为。
