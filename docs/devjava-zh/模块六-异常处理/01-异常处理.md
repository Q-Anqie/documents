# 异常处理（Exceptions）

> 来源：Oracle 官方 [Dev.java 教程](https://dev.java/learn/) →《Exceptions》
> 忠实翻译，保留全部代码示例与官方配图。

**异常（exception）是程序执行过程中发生、打断正常指令流的事件。** 当方法内发生错误时，该方法会**创建一个异常对象**，并把它交给运行时系统（JVM）处理。这个创建异常对象并交给运行时系统的过程称为**抛出异常（throwing an exception）**。

---

## 一、什么是异常？异常处理的作用

### 为什么需要异常处理

当方法内部出错（如数组越界、文件找不到），它会创建异常对象并**抛出**。运行时系统收到异常后，会在**调用栈（call stack）**中寻找能处理它的「异常处理器」。若找到合适的处理器，异常就被处理，程序可继续；若找不到，程序终止并打印栈轨迹。

[调用栈与异常传播](../assets/images/exceptions/call-stack.png)

### 异常的优势

传统语言（如 C）用错误码返回方式处理错误，程序员可能忘记检查错误码。Java 的异常机制：

1. **把错误处理代码与常规代码分离**。
2. **沿调用栈向上传播错误**，与函数的调用层级解耦。
3. **对错误类型分组，并区分错误类型**。

### 已检查异常 vs 未检查异常

- **已检查异常（checked exception）**：编译器强制要求 `catch` 或声明抛出的异常（如 `IOException`、`SQLException`）。这类异常是调用方必须妥善处理的。
- **未检查异常（unchecked exception）**：编译器**不强制**处理，通常是编程错误（如 `NullPointerException`、`ArithmeticException`、`IndexOutOfBoundsException`）。它们继承自 `RuntimeException`。

### 未检查异常的争议

未检查异常（`RuntimeException`）让「是否处理」的决定权交给开发者，而不是编译器。支持者认为它让代码更简洁，让那些几乎无法恢复的错误（如空指针）不被冗长的 try-catch 拖累；反对者认为它使错误被无声忽略。**实践中**：可恢复的预期错误用已检查异常，编程错误用未检查异常。

## 二、异常层次结构

[异常类层次](../assets/images/exceptions/throwable-hierarchy.png)

所有异常和错误都是 `Throwable` 类的子类：

```
Throwable
├── Error                 （严重错误，程序无法恢复，通常不捕获）
│   └── OutOfMemoryError, StackOverflowError, ...
└── Exception             （程序可处理的异常）
    ├── RuntimeException  （未检查异常，编程错误）
    │   └── NullPointerException, ArithmeticException, ...
    └── IOException, SQLException, ...  （已检查异常，需处理）
```

- **`Error`**：严重错误（如 `OutOfMemoryError`），程序一般无法合理恢复，**不建议捕获**。
- **`Exception`**：程序可预期、可恢复的情况。
  - **`RuntimeException`**（及其子类）：未检查异常，编译不强制处理。
  - **其他 `Exception` 子类**：已检查异常，编译器强制捕获或声明。

## 三、捕获与处理异常（Catching and Handling）

用 `try` 块包围可能抛异常的代码，用 `catch` 块捕获，用 `finally` 块清理。

### 基本结构

```java
try {
    // 可能抛出异常的代码
    int result = 10 / divisor;
} catch (ArithmeticException e) {
    // 处理算术异常
    System.out.println("除数不能为零: " + e.getMessage());
} finally {
    // 无论是否异常都会执行的清理代码（如关闭资源）
    System.out.println("finally 块总会被执行");
}
```

### 多 catch 块

```java
try {
    readFile();
} catch (FileNotFoundException e) {
    System.err.println("文件找不到: " + e.getMessage());
} catch (IOException e) {
    System.err.println("读文件出错: " + e.getMessage());
}
```

**注意**：多 `catch` 时，**子类异常必须放在父类异常之前**（否则父类会先捕获，子类永远执行不到）。

### try-with-resources（资源自动关闭）

**Java 7+ 推荐**，`try` 块中声明的资源（实现了 `AutoCloseable`）**自动关闭**，无需手动 `finally` 关闭：

```java
try (BufferedReader br = new BufferedReader(new FileReader("file.txt"))) {
    String line;
    while ((line = br.readLine()) != null) {
        System.out.println(line);
    }
} catch (IOException e) {
    e.printStackTrace();
}
// br 自动关闭，即使抛出异常
```

这避免了传统 `finally` 中关闭资源时产生资源泄漏的风险，代码更简洁。

## 四、抛出异常（Throwing）

用 `throw` 关键字手动抛出一个异常对象。

### 自定义异常类

```java
public class MyException extends Exception {
    public MyException(String message) {
        super(message);
    }
}
```

### 抛出异常

```java
public void checkAge(int age) throws MyException {
    if (age < 0) {
        throw new MyException("年龄不能为负数: " + age);
    }
}
```

### 声明抛出异常（throws 子句）

如果方法不捕获某已检查异常，必须在方法签名中用 `throws` 声明，让调用方处理：

```java
public void readFile(String path) throws IOException {
    // 读文件，可能抛 IOException
}
```

### 链式异常（Chained Exceptions）

用 `initCause` 或构造器把底层异常包装到更高层异常，保留根因：

```java
try {
    // ...
} catch (SQLException e) {
    throw new MyException("数据库错误: " + e.getMessage(), e);  // 保留根因
}
```

## 五、异常处理器与传播

[异常处理机制示意](../assets/images/exceptions/exception-handler.png)

**异常传播规则**：

1. 方法抛出异常后，运行时系统搜索调用栈，找第一个能处理该异常类型的 `catch` 块。
2. 若当前方法的 `try` 块没有匹配的 `catch`，异常沿调用栈**向上传播**到调用者。
3. 若整个调用栈都没有处理器，程序终止并打印**栈轨迹（stack trace）**，定位异常的完整调用链。

## 六、最佳实践

| 实践 | 说明 |
|------|------|
| 用 try-with-resources | 自动关闭资源，防泄漏 |
| catch 具体异常 | 避免 catch `Exception`/`Throwable` 吞掉所有错误 |
| 记录异常 | 至少 `e.printStackTrace()` 或记日志，不要空 catch |
| 保留根因 | 用链式异常（chained exception）传递底层原因 |
| 区分异常类型 | 可恢复用已检查异常，编程错误用未检查异常 |
| finally 只做清理 | 不要在 finally 里 return 或抛出会掩盖原始异常的异常 |
| 不过度捕获 | 只在需要处理的地方捕获 |
| 用自定义异常 | 用有意义的异常类型传递业务语义 |

## 核心速查表

| 概念 | 说明 | 示例 |
|------|------|------|
| 异常 | 程序执行中打断正常流程的事件 | `throw new MyException()` |
| 抛出 | 创建异常对象交给运行时系统 | `throw` |
| 捕获 | try-catch 处理异常 | `catch (IOException e)` |
| 清理 | finally 或 try-with-resources | `finally { br.close(); }` |
| 声明 | throws 子句声明可抛出的已检查异常 | `throws IOException` |
| 已检查异常 | 编译器强制处理 | `IOException` |
| 未检查异常 | 运行时异常，不强制 | `NullPointerException` |
| Error | 严重错误，一般不捕获 | `OutOfMemoryError` |
| 自定义异常 | 继承 Exception/RuntimeException | `class MyException extends Exception` |
| 链式异常 | 保留根因 | `initCause` / 构造器传 cause |

> **面试高频**：已检查 vs 未检查异常的区别、try-with-resources 原理（`AutoCloseable`）、`Error` vs `Exception`、异常传播沿调用栈、自定义异常、链式异常保留根因、`finally` vs try-with-resources。
