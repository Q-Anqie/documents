# 接口（Interface）深入：定义、实现与作为类型

> 来源：Oracle 官方 [Dev.java 教程](https://dev.java/learn/) →《Interfaces》模块
> 忠实翻译，保留全部代码示例与官方配图。

软件工程中有很多情形，需要让不同的小组就一份「契约（contract）」达成一致，明确他们的软件如何交互。每个小组都应该能在**不了解对方代码如何编写**的情况下写自己的代码。一般来说，**接口就是这样的契约**。

一个经典的例子：想象一个未来社会，计算机控制的机器人汽车在没有人类驾驶员的情况下穿梭于城市街道。汽车制造商编写软件（当然是 Java）来操控汽车——启动、停止、加速、左转等等。另一个工业小组——电子导航仪器制造商——制造接收 GPS 位置数据和交通状况无线传输、并据此驾驶汽车的计算机系统。汽车制造商必须发布一份**行业标准接口**，详细说明哪些方法可以被调用让汽车移动（任何厂商的任何汽车）。导航制造商据此编写软件，调用接口中描述的方法来指挥汽车。**两个小组都不需要知道对方软件的实现方式。** 事实上，每个小组都视自己的软件为高度专有，并保留随时修改的权利，只要它继续遵守已发布的接口。

在 Java 语言中，**接口是一种引用类型（reference type），类似于类**，但只能包含**常量、方法签名、默认方法、静态方法**（private 或 public，不能 protected；Java 9 起还可含 private 方法）和**嵌套类型**。方法体只存在于默认方法和静态方法中。

## 一、定义接口 Relatable

要声明一个实现某接口的类，在类声明中加入 `implements` 子句。你的类可以**实现多个接口**，所以 `implements` 关键字后面跟一个以逗号分隔的接口列表。`implements` 子句必须跟在 `extends` 子句之后（如果有的话）。

考虑一个定义如何比较对象大小的接口：

```java
public interface Relatable {

    // 该接口返回的对象：若当前对象比其他对象大返回正数
    // 相等返回 0，更小返回负数
    public int isLargerThan(Relatable other);
}
```

如果你能比较相似对象的大小——无论它们是什么——实例化它们的类就应该实现 `Relatable`。

任何类都可以实现 `Relatable`，只要存在某种方法比较从该类实例化的对象的相对「大小」。对字符串，可以是字符数；对书，可以是页数；对学生，可以是体重；依此类推。对平面几何对象，面积是个好选择（见下面的 `RectanglePlus` 类），而体积适合三维几何对象。所有这些类都能实现 `isLargerThan()` 方法。

**如果你知道一个类实现了 `Relatable`，你就知道可以比较从该类实例化的对象的大小。**

## 二、实现 Relatable 接口

下面是「创建对象」一节介绍的 `Rectangle` 类，改写成实现 `Relatable`：

```java
public class RectanglePlus implements Relatable {
    public int width = 0;
    public int height = 0;
    public Point origin;

    // 四个构造器，初始化矩形
    public RectanglePlus() {
        origin = new Point(0, 0);
    }
    public RectanglePlus(Point p) {
        origin = p;
    }
    public RectanglePlus(int w, int h) {
        origin = new Point(0, 0);
        width = w;
        height = h;
    }
    public RectanglePlus(Point p, int w, int h) {
        origin = p;
        width = w;
        height = h;
    }

    // 移动矩形的方法
    public void move(int x, int y) {
        origin.x = x;
        origin.y = y;
    }

    // 计算面积
    public int getArea() {
        return width * height;
    }

    // 实现 Relatable 接口的方法
    public int isLargerThan(Relatable other) {
        RectanglePlus otherRect = (RectanglePlus) other;
        if (this.getArea() < otherRect.getArea())
            return -1;
        else if (this.getArea() > otherRect.getArea())
            return 1;
        else
            return 0;
    }
}
```

因为 `RectanglePlus` 实现了 `Relatable`，任意两个 `RectanglePlus` 对象的大小都能比较。

> **注**：`isLargerThan()` 方法（在 `Relatable` 接口中定义）接收一个 `Relatable` 类型的对象。这行代码把 `other` 强制转换为 `RectanglePlus` 实例：`RectanglePlus otherRect = (RectanglePlus) other;`。**类型转换告诉编译器该对象到底是什么。** 直接在 `other` 上调用 `getArea()`（即 `other.getArea()`）会编译失败，因为编译器不知道 `other` 实际上是 `RectanglePlus` 的实例。

## 三、接口的演进（Evolving Interfaces）

考虑你已经开发出的名为 `DoIt` 的接口：

```java
public interface DoIt {
    void doSomething(int i, double x);
    int doSomethingElse(String s);
}
```

假设稍后你想给 `DoIt` 添加第三个方法，使它变成：

```java
public interface DoIt {
    void doSomething(int i, double x);
    int doSomethingElse(String s);
    boolean didItWork(int i, double x, String s);   // 新增
}
```

如果你做这个改动，所有实现旧 `DoIt` 接口的类都会**出问题**，因为它们不再实现旧接口了。依赖这个接口的程序员会强烈抗议。

**尽量预判接口的所有用途，从一开始就完整地指定它。** 如果你想给接口加方法，有几个选项：

- 创建一个扩展 `DoIt` 的 `DoItPlus` 接口：

```java
public interface DoItPlus extends DoIt {
    boolean didItWork(int i, double x, String s);
}
```

现在你的代码用户可以继续用旧接口，或升级到新接口。

- 或者，把新方法定义为**默认方法（default method）**：

```java
public interface DoIt {
    void doSomething(int i, double x);
    int doSomethingElse(String s);

    default boolean didItWork(int i, double x, String s) {
        // 方法体
        return false;
    }
}
```

注意：**你必须为默认方法提供实现**。你也可以给现有接口定义新的静态方法。

> 拥有实现了添加了默认/静态方法接口的类的用户，**不必修改或重新编译**它们就能容纳这些额外方法——只要这些新默认方法与那些类实现的其他接口的现有方法不冲突。

## 四、默认方法（Default Methods）

「接口」一节描述了一个涉及计算机控制汽车制造商的例子，他们发布行业标准接口描述哪些方法可被调用来操作汽车。如果这些汽车制造商添加新功能，比如飞行，会怎样？他们需要指定新方法，让其他公司（如电子导航仪器制造商）能让他们的软件适应飞行汽车。这些汽车制造商该在哪里声明这些新的飞行相关方法？如果加到原接口，实现过这些接口的程序员就得重写实现。如果作为静态方法添加，程序员会把它们视为实用工具方法，而非必要、核心的方法。

**默认方法让你能给库的接口添加新功能，同时保证与为旧版本接口编写的代码的二进制兼容性。** 确保你添加的默认方法不与那些类实现的其他接口的现有方法冲突。

考虑以下接口 `TimeClient`：

```java
import java.time.*; 

public interface TimeClient {
    void setTime(int hour, int minute, int second);
    void setDate(int day, int month, int year);
    void setDateAndTime(int day, int month, int year,
                        int hour, int minute, int second);
    LocalDateTime getLocalDateTime();
}
```

下面这个类 `SimpleTimeClient` 实现 `TimeClient`：

```java
import java.time.*;
import java.lang.*;
import java.util.*;

public class SimpleTimeClient implements TimeClient {

    private LocalDateTime dateAndTime;

    public SimpleTimeClient() {
        dateAndTime = LocalDateTime.now();
    }

    public void setTime(int hour, int minute, int second) {
        LocalDate currentDate = LocalDate.now();
        LocalTime timeToSet = LocalTime.of(hour, minute, second);
        dateAndTime = LocalDateTime.of(currentDate, timeToSet);
    }

    public void setDate(int day, int month, int year) {
        LocalDate dateToSet = LocalDate.of(day, month, year);
        LocalTime currentTime = LocalTime.now();
        dateAndTime = LocalDateTime.of(dateToSet, currentTime);
    }

    public void setDateAndTime(int day, int month, int year,
                               int hour, int minute, int second) {
        LocalDate dateToSet = LocalDate.of(day, month, year);
        LocalTime timeToSet = LocalTime.of(hour, minute, second);
        dateAndTime = LocalDateTime.of(dateToSet, timeToSet);
    }

    public LocalDateTime getLocalDateTime() {
        return dateAndTime;
    }

    public String toString() {
        return dateAndTime.toString();
    }

    public static void main(String... args) {
        TimeClient myTimeClient = new SimpleTimeClient();
        System.out.println(myTimeClient.toString());
    }
}
```

假设你想给 `TimeClient` 接口添加新功能，比如通过 `ZonedDateTime` 对象指定时区（`ZonedDateTime` 类似 `LocalDateTime`，只是还存储时区信息）：

```java
public interface TimeClient {
    void setTime(int hour, int minute, int second);
    void setDate(int day, int month, int year);
    void setDateAndTime(int day, int month, int year,
                        int hour, int minute, int second);
    LocalDateTime getLocalDateTime();

    // 新方法：时区
    ZonedDateTime getZonedDateTime(String zoneString);
}
```

修改 `TimeClient` 接口后，你还得修改 `SimpleTimeClient` 类并实现 `getZonedDateTime()` 方法。然而，与其让 `getZonedDateTime()` 保持抽象（如前一个例子），**不如定义它的默认实现**。（记住，抽象方法是声明时没有实现的方法。）

用 `default` 关键字在接口方法定义的开头，指定它是默认方法。**接口中所有方法声明（包括默认方法）都隐式是 public**，所以你可以省略 `public` 修饰符。

```java
public interface TimeClient {
    // ...原有方法...

    default ZonedDateTime getZonedDateTime(String zoneString) {
        return ZonedDateTime.of(getLocalDateTime(), ZoneId.get(zoneString));
    }
}
```

有了这个接口，你**不必修改 `SimpleTimeClient` 类**，而这个类（以及任何实现 `TimeClient` 接口的类）已经有了定义好的 `getZonedDateTime()` 方法。下面的 `TestSimpleTimeClient` 示例从 `SimpleTimeClient` 实例调用 `getZonedDateTime()`：

```java
public class TestSimpleTimeClient {
    public static void main(String... args) {
        TimeClient myTimeClient = new SimpleTimeClient();
        System.out.println("Current time: " + myTimeClient.toString());
        System.out.println("Time in California: " +
            myTimeClient.getZonedDateTime("Blah blah").toString());
    }
}
```

## 五、扩展含默认方法的接口

当你扩展一个含默认方法的接口时，可以：

- **完全不提默认方法**，让扩展接口继承该默认方法。
- **重新声明默认方法**，使其变为抽象方法。
- **重新定义默认方法**，使其覆盖它。

例如，按如下方式扩展 `TimeClient`：

```java
public interface AnotherTimeClient extends TimeClient { }
```

任何实现 `AnotherTimeClient` 的类都会有默认方法 `TimeClient.getZonedDateTime()` 指定的实现。

假设你这样扩展 `TimeClient`：

```java
public interface AbstractZoneTimeClient extends TimeClient {
    public ZonedDateTime getZonedDateTime(String zoneString);
}
```

任何实现 `AbstractZoneTimeClient` 的类都**必须实现** `getZonedDateTime()` 方法；该方法与其他非默认（非静态）方法一样，是抽象方法。

再假设你这样扩展 `TimeClient`：

```java
public interface HandleInvalidTimeZoneClient extends TimeClient {
    default public ZonedDateTime getZonedDateTime(String zoneString) {
        try {
            return ZonedDateTime.of(getLocalDateTime(), ZoneId.get(zoneString));
        } catch (DateTimeException e) {
            System.err.println("Invalid zone ID: " + zoneString +
                "; using the default time zone instead.");
            return ZonedDateTime.of(getLocalDateTime(), ZoneId.systemDefault());
        }
    }
}
```

任何实现 `HandleInvalidTimeZoneClient` 的类都会使用此接口指定的 `getZonedDateTime()` 实现，而非 `TimeClient` 接口指定的。

## 六、静态方法（Static Methods）

除了默认方法，你还可以在接口中定义静态方法。（**静态方法是与定义它的类关联、而非与任何对象关联的方法**；类的每个实例共享其静态方法。）这让库中组织辅助方法更容易；你可以把特定接口的静态方法留在同一个接口里，而非放在单独类中。下面的例子定义了一个检索时区对应 `ZoneId` 对象的静态方法；如果没有与给定标识符对应的 `ZoneId` 对象，就用系统默认时区。（因此可以简化 `getZonedDateTime()` 方法）：

```java
public interface TimeClient {
    // ...原有方法...

    static ZoneId getZoneId(String zoneString) {
        try {
            return ZoneId.of(zoneString);
        } catch (DateTimeException e) {
            System.err.println("Invalid time zone: " + zoneString +
                "; using default time zone instead.");
            return ZoneId.systemDefault();
        }
    }

    default ZonedDateTime getZonedDateTime(String zoneString) {
        return ZonedDateTime.of(getLocalDateTime(), getZoneId(zoneString));
    }
}
```

同类的静态方法一样，你用 `static` 关键字在方法签名开头，指定接口方法定义是静态方法。**接口中所有方法声明（包括静态方法）都隐式是 public**，所以可省略 `public`。

> **Java SE 9 起**，你可以在接口中定义 **private 方法**，用于从接口的默认方法中抽象出一段公共代码，同时定义它的实现。这些方法属于实现，定义时既不能是 default 也不能是 abstract。例如，你可以把 `getZoneId` 设为 private，因为它承载的代码对接口实现而言是内部的。

## 七、把默认方法整合进现有库

默认方法让你能给现有接口添加新功能，同时保证与为旧版本接口编写的代码的**二进制兼容性**。特别是，**默认方法让你能给现有接口添加接受 lambda 表达式作为参数的方法**。本节演示 `Comparator` 接口如何被增强为带默认和静态方法。

考虑 `Card` 和 `Deck` 类。`Card` 接口包含两个枚举类型（`Suit` 和 `Rank`）和两个抽象方法（`getSuit()` 和 `getRank()`）：

```java
public interface Card extends Comparable<Card> {

    enum Suit { DIAMONDS, CLUBS, HEARTS, SPADES }
    enum Rank { ACE, DEUCE, THREE, FOUR, FIVE, SIX, SEVEN, EIGHT,
                NINE, TEN, JACK, QUEEN, KING }

    Suit getSuit();
    Rank getRank();
}
```

`Deck` 接口包含操纵牌堆中卡片的各种方法：

```java
public interface Deck {
    List<Card> getCards();
    Deck deckFactory();
    int size();
    void addCard(Card card);
    void addCards(List<Card> cards);
    void addDeck(Deck deck);
    void shuffle();
    void sort();
    void sort(Comparator<Card> c);
    String deckToString();
    // ...等
}
```

类 `PlayingCard` 实现接口 `Card`，类 `StandardDeck` 实现接口 `Deck`。`StandardDeck` 实现抽象方法 `Deck.sort()` 如下：

```java
public void sort() {
    Collections.sort(entireDeck);
}
```

方法 `Collections.sort()` 对元素类型实现了 `Comparable` 接口的 `List` 实例排序。成员 `entireDeck` 是元素类型为 `Card`（它扩展了 `Comparable`）的 `List` 实例。类 `PlayingCard` 实现 `Comparable.compareTo()` 方法如下：

```java
public int compareTo(Card o) {
    return (this.getRank().compareTo(o.getRank()));
}
```

方法 `compareTo()` 让 `StandardDeck.sort()` 先按花色、再按点数给牌排序。

如果你想先按点数、再按花色排序呢？你需要实现 `Comparator` 接口指定新排序标准，并用带 `Comparator` 参数的排序方法版本 `sort(List<T> list, Comparator<? super T> c)`。可以在 `StandardDeck` 类中定义如下方法：

```java
public void sort(Comparator<Card> c) {
    Collections.sort(entireDeck, c);
}
```

有了这个方法，你就能指定 `Collections.sort()` 如何对 `Card` 类实例排序。一种方法是实现 `Comparator` 接口指定排序方式，示例 `SortByRankThenSuit` 如下：

```java
public class SortByRankThenSuit implements Comparator<Card> {
    public int compare(Card firstCard, Card secondCard) {
        int compVal =
            firstCard.getRank().compareTo(secondCard.getRank());
        if (compVal != 0) return compVal;
        else
            return firstCard.getSuit().compareTo(secondCard.getSuit());
    }
}
```

下面调用按点数、再按花色给扑克牌堆排序：

```java
public void sortByRankThenSuit() {
    StandardDeck myDeck = new StandardDeck();
    myDeck.sort(new SortByRankThenSuit());
    myDeck.sort((firstCard, secondCard) ->
        firstCard.getRank().compareTo(secondCard.getRank()));
}
```

但这太冗长；如果只指定排序标准、避免创建多个排序实现会更好。假设你就是编写 `Comparator` 接口的开发者，你会给 `Comparator` 接口添加哪些默认或静态方法，让其他开发者更容易指定排序标准？

首先，假设你想不考虑花色、按点数给牌排序。可以如下调用 `StandardDeck.sort()`：

```java
myDeck.sort((firstCard, secondCard) ->
    firstCard.getRank().compareTo(secondCard.getRank()));
```

因为 `Comparator` 接口是**函数式接口**，你可用 lambda 表达式作为 `sort()` 方法的参数。此例中 lambda 比较两个整数值。

如果你的开发者能**只调用 `Card.getRank()`** 就创建 `Comparator` 实例，会更简单。特别是，如果开发者能创建一个比较**任何能通过方法（如 `getValue()` 或 `hashCode()`）返回数值**的对象的 `Comparator` 实例，会有帮助。`Comparator` 接口用静态方法 `comparing` 增强了这一能力：

```java
myDeck.sort(Comparator.comparing((card) -> card.getRank()));
```

此例中你可以用方法引用替代：

```java
myDeck.sort(Comparator.comparing(Card::getRank));
```

这次调用更好地展示了如何指定不同排序标准、避免创建多个排序实现。

`Comparator` 接口还增强了 `comparing` 的其他版本，如 `comparingDouble()` 和 `comparingLong()`，让你能创建比较其他数据类型的 `Comparator` 实例。

假设开发者想创建能按多个标准比较对象的 `Comparator` 实例。比如，如何先按点数、再按花色给牌排序？如前，可用 lambda 指定：

```java
myDeck.sort((firstCard, secondCard) -> {
    int compVal = firstCard.getRank().compareTo(secondCard.getRank());
    if (compVal != 0) return compVal;
    else return firstCard.getSuit().compareTo(secondCard.getSuit());
});
```

如果开发者能**从一系列 `Comparator` 实例构建一个 `Comparator`**，会更简单。`Comparator` 接口用默认方法 `thenComparing()` 增强了这一能力：

```java
myDeck.sort(Comparator.comparing(Card::getRank).thenComparing(Card::getSuit));
```

`Comparator` 接口还增强了 `thenComparing()` 的其他版本：

1. `thenComparing(Function)`：接收一个用于提取比较元素键的函数。注意该键必须是 `Comparable` 的实例。
2. `thenComparingInt()`、`thenComparingLong()`、`thenComparingDouble()`：与上一个重载相同，但不必为键付出装箱/拆箱代价。

你可以用第一个重载更简单地重写前一个例子。

假设开发者想创建能**逆序**排列对象集合的 `Comparator` 实例。比如，如何按点数降序（Ace 到 Two，而非 Two 到 Ace）给牌排序？如前可用另一个 lambda。但如果开发者能通过调用方法反转现有 `Comparator` 会更简单。`Comparator` 接口用默认方法 `reversed()` 增强了这一能力：

```java
myDeck.sort(Comparator.comparing(Card::getRank).reversed());
```

这个例子演示了如何用默认方法、静态方法、lambda 表达式和方法引用增强 `Comparator` 接口，创建更有表现力的库方法——程序员通过查看它们如何被调用就能快速推断其功能。**用这些构造来增强你库中的接口吧。**

## 八、接口作为类型（Using an Interface as a Type）

当你定义一个新接口时，就定义了一个新的**引用数据类型**。你可以在任何使用其他数据类型名的地方使用接口名。如果定义了一个类型为接口的引用变量，任何赋给它的对象都必须是**实现该接口的类的实例**。

举一个例子，这是一个在一对对象中找最大对象的方法，适用于任何从实现 `Relatable` 的类实例化的对象：

```java
public static Object findLargest(Object object1, Object object2) {
    Relatable obj1 = (Relatable) object1;
    Relatable obj2 = (Relatable) object2;
    if ((obj1).isLargerThan(obj2) > 0)
        return object1;
    else
        return object2;
}
```

通过把 `object1` 转换为 `Relatable` 类型，它就能调用 `isLargerThan()` 方法。

如果你坚持在大量类中实现 `Relatable`，那么从任何这些类实例化的对象都能用 `findLargest()` 方法比较——只要两个对象是同一类。同理，它们都能用以下方法比较：

```java
public static Object findSmallest(Object object1, Object object2) {
    Relatable obj1 = (Relatable) object1;
    Relatable obj2 = (Relatable) object2;
    if ((obj1).isLargerThan(obj2) < 0)
        return object1;
    else
        return object2;
}

public static boolean isEqual(Object object1, Object object2) {
    Relatable obj1 = (Relatable) object1;
    Relatable obj2 = (Relatable) object2;
    if ((obj1).isLargerThan(obj2) == 0)
        return true;
    else
        return false;
}
```

这些方法适用于任何「可比较」对象，无论其类继承是什么。当它们实现 `Relatable` 时，它们可以同时具有自己类（或超类）类型和 `Relatable` 类型。**这给它们带来多重继承的一些优势：它们既能从超类、也能从接口获得行为。**

## 核心要点速查

| 主题 | 关键点 |
|------|--------|
| 接口本质 | 引用类型，只含常量、方法签名、默认/静态方法、嵌套类型 |
| implements | 一个类可实现多个接口，`implements` 在 `extends` 之后 |
| 接口作为契约 | 编译器强制实现类包含接口全部方法，否则编译失败 |
| 类型转换 | 接口引用变量需显式强转回具体类才能调用其特有方法 |
| 默认方法 | `default` 关键字，向后兼容地扩展接口，必有方法体 |
| 静态方法 | `static` 关键字，与接口关联而非对象，可组织辅助方法 |
| private 方法 | Java 9+，默认方法间共享内部代码，非 default/abstract |
| 演进接口 | 默认方法 / 静态方法实现向后兼容；`DoItPlus extends DoIt` 升级 |
| 接口作为类型 | 接口名可作引用类型，多态 + 类型多重继承 |
