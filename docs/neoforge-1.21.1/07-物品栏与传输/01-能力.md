# 能力（Capability）

能力（Capability）允许以动态且灵活的方式暴露功能，而不必被迫直接实现大量接口。

概括地说，每个能力都以接口的形式提供一个功能。

NeoForge 为方块、实体和物品堆（ItemStack）添加了能力支持。后续各节将对此进行更详细的说明。

## 为什么使用能力？

能力被设计用来把方块、实体或物品堆**能做什么**与**如何做到**分离开来。如果你在犹豫能力是否适合某个任务，请先问自己以下几个问题：

1. 我是否只关心方块、实体或物品堆**能做什么**，而不关心它**如何做到**？
1. 这个**什么**，也就是该行为，是否只对部分方块、实体或物品堆可用，而不是全部？
1. 这个**如何**，也就是该行为的实现，是否依赖于具体的方块、实体或物品堆？

以下是一些良好使用能力的示例：

- *“我希望我的流体容器能与其他模组的流体容器兼容，但我并不了解每种流体容器的具体细节。”* - 是的，使用 `IFluidHandler` 能力。
- *“我希望统计某个实体中有多少物品，但我不知道这个实体可能如何存储它们。”* - 是的，使用 `IItemHandler` 能力。
- *“我希望为某个物品堆填充能量，但我不知道这个物品堆可能如何存储能量。”* - 是的，使用 `IEnergyStorage` 能力。
- *“我希望给玩家当前瞄准的任意方块施加某种颜色，但我不知道这个方块会如何被转换。”* - 是的。NeoForge 没有提供为方块上色的能力，但你可以自行实现一个。

以下是一个不推荐使用能力的示例：

- *“我希望检查某个实体是否在我的机器范围内。”* - 不，改用辅助方法即可。

## NeoForge 提供的能力

> 相关 Minecraft Wiki：[物品栏](https://zh.minecraft.wiki/w/物品栏)

NeoForge 为以下三个接口提供了能力：`IItemHandler`、`IFluidHandler` 和 `IEnergyStorage`。

`IItemHandler` 暴露了一个用于处理物品栏槽位的接口。类型为 `IItemHandler` 的能力有：

- `Capabilities.ItemHandler.BLOCK`：方块的自动化可访问物品栏（用于箱子、机器等）。
- `Capabilities.ItemHandler.ENTITY`：实体的物品栏内容（额外的玩家槽位、生物/生物实体的物品栏/背包）。
- `Capabilities.ItemHandler.ENTITY_AUTOMATION`：实体的自动化可访问物品栏（船、矿车等）。
- `Capabilities.ItemHandler.ITEM`：物品堆的内容（便携背包之类）。

`IFluidHandler` 暴露了一个用于处理流体栏的接口。类型为 `IFluidHandler` 的能力有：

- `Capabilities.FluidHandler.BLOCK`：方块的自动化可访问流体栏。
- `Capabilities.FluidHandler.ENTITY`：实体的流体栏。
- `Capabilities.FluidHandler.ITEM`：物品堆的流体栏。
由于桶持有流体的方式，这个能力属于特殊的 `IFluidHandlerItem` 类型。

`IEnergyStorage` 暴露了一个用于处理能量容器的接口。它基于 TeamCoFH 的 RedstoneFlux API。类型为 `IEnergyStorage` 的能力有：

- `Capabilities.EnergyStorage.BLOCK`：方块内部包含的能量。
- `Capabilities.EnergyStorage.ENTITY`：实体内部包含的能量。
- `Capabilities.EnergyStorage.ITEM`：物品堆内部包含的能量。

## 创建能力

NeoForge 支持方块、实体和物品堆的能力。

能力允许通过一定的分发逻辑来查找某些 API 的实现。NeoForge 中实现了以下几种能力：

- `BlockCapability`：用于方块和方块实体的能力；行为取决于具体的 `Block`。
- `EntityCapability`：用于实体的能力；行为取决于具体的 `EntityType`。
- `ItemCapability`：用于物品堆的能力；行为取决于具体的 `Item`。

> **提示**
>
> 为与其他模组兼容，我们建议尽可能使用 NeoForge 在 `Capabilities` 类中提供的能力。否则，你可以按本节所述创建自己的能力。

创建一个能力只需一次函数调用，得到的对象应存储在 `static final` 字段中。必须提供以下参数：

- 能力的名称。
    - 多次创建同名能力将始终返回同一个对象。
    - 名称不同的能力**完全独立**，可用于不同目的。
- 被查询的行为类型。这就是 `T` 类型参数。
- 查询中用于附加上下文的类型。这就是 `C` 类型参数。

例如，下面是一个用于区分侧的方块 `IItemHandler` 能力的声明方式：

```java
public static final BlockCapability<IItemHandler, @Nullable Direction> ITEM_HANDLER_BLOCK =
    BlockCapability.create(
        // Provide a name to uniquely identify the capability.
        ResourceLocation.fromNamespaceAndPath("mymod", "item_handler"),
        // Provide the queried type. Here, we want to look up `IItemHandler` instances.
        IItemHandler.class,
        // Provide the context type. We will allow the query to receive an extra `Direction side` parameter.
        Direction.class);
```

`@Nullable Direction` 对方块而言如此常见，以至于有一个专门的辅助方法：

```java
public static final BlockCapability<IItemHandler, @Nullable Direction> ITEM_HANDLER_BLOCK =
    BlockCapability.createSided(
        // Provide a name to uniquely identify the capability.
        ResourceLocation.fromNamespaceAndPath("mymod", "item_handler"),
        // Provide the queried type. Here, we want to look up `IItemHandler` instances.
        IItemHandler.class);
```

如果不需要上下文，应使用 `Void`。同样有一个用于无上下文能力的专门辅助方法：

```java
public static final BlockCapability<IItemHandler, Void> ITEM_HANDLER_NO_CONTEXT =
    BlockCapability.createVoid(
        // Provide a name to uniquely identify the capability.
        ResourceLocation.fromNamespaceAndPath("mymod", "item_handler_no_context"),
        // Provide the queried type. Here, we want to look up `IItemHandler` instances.
        IItemHandler.class);
```

对于实体和物品堆，`EntityCapability` 和 `ItemCapability` 中分别存在类似的方法。

## 查询能力

一旦我们在静态字段中拥有了 `BlockCapability`、`EntityCapability` 或 `ItemCapability` 对象，就可以查询能力。

对于实体和物品堆，我们可以用 `getCapability` 尝试查找某个能力的实现。如果结果为 `null`，则没有可用的实现。

例如：

```java
var object = entity.getCapability(CAP, context);
if (object != null) {
    // Use object
}
```

```java
var object = stack.getCapability(CAP, context);
if (object != null) {
    // Use object
}
```

方块能力的使用方式略有不同，因为没有方块实体的方块也可以拥有能力。此时查询是在 `level` 上进行的，并把我们要查找的 `pos`（位置）作为额外参数：

```java
var object = level.getCapability(CAP, pos, context);
if (object != null) {
    // Use object
}
```

如果已知方块实体和/或方块状态，可以把它们传入以节省查询时间：

```java
var object = level.getCapability(CAP, pos, blockState, blockEntity, context);
if (object != null) {
    // Use object
}
```

给出一个更具体的示例：下面是从 `Direction.NORTH` 一侧查询某个方块的 `IItemHandler` 能力的方式：

```java
IItemHandler handler = level.getCapability(Capabilities.ItemHandler.BLOCK, pos, Direction.NORTH);
if (handler != null) {
    // Use the handler for some item-related operation.
}
```

## 方块能力缓存

> 相关 Minecraft Wiki：[方块](https://zh.minecraft.wiki/w/方块)

当查询一个能力时，系统在底层会执行以下步骤：

1. 如果未提供方块实体和方块状态，则获取它们。
1. 获取已注册的能力提供者。（下文会详细说明）。
1. 遍历这些提供者，询问它们是否能提供该能力。
1. 其中一个提供者会返回一个能力实例，可能还会分配一个新对象。

该实现相当高效，但对于频繁执行的查询（例如每个游戏刻都执行），这些步骤会占用大量服务器时间。`BlockCapabilityCache` 系统可以为在给定位置频繁查询的能力带来显著的提速。

> **提示**
>
> 通常，`BlockCapabilityCache` 只创建一次，然后存储在频繁执行能力查询的对象的一个字段中。具体在何时何地存储缓存由你决定。

要创建缓存，请调用 `BlockCapabilityCache.create`，传入要查询的能力、level、位置以及查询上下文。

```java
// Declare the field:
private BlockCapabilityCache<IItemHandler, @Nullable Direction> capCache;

// Later, for example in `onLoad` for a block entity:
this.capCache = BlockCapabilityCache.create(
    Capabilities.ItemHandler.BLOCK, // capability to cache
    level, // level
    pos, // target position
    Direction.NORTH // context
);
```

随后用 `getCapability()` 查询缓存：

```java
IItemHandler handler = this.capCache.getCapability();
if (handler != null) {
    // Use the handler for some item-related operation.
}
```

**缓存会由垃圾回收器自动清理，无需注销。**

还可以在能力对象发生变化时接收通知！这包括能力发生改变（`oldHandler != newHandler`）、变为不可用（`null`）或再次变为可用（不再是 `null`）。

此时创建缓存需要两个额外参数：

- 一个有效性检查，用于判断缓存是否仍然有效。
    - 在最简单的方块实体字段用法中，`() -> !this.isRemoved()` 就足够了。
- 一个失效监听器，在能力发生变化时被调用。
    - 你可以在这里对能力的变化、移除或出现做出反应。

```java
// With optional invalidation listener:
this.capCache = BlockCapabilityCache.create(
    Capabilities.ItemHandler.BLOCK, // capability to cache
    level, // level
    pos, // target position
    Direction.NORTH, // context
    () -> !this.isRemoved(), // validity check (because the cache might outlive the object it belongs to)
    () -> onCapInvalidate() // invalidation listener
);
```

## 方块能力失效

> 相关 Minecraft Wiki：[方块](https://zh.minecraft.wiki/w/方块)

> **说明**
>
> 失效机制仅适用于方块能力。实体和物品堆能力无法被缓存，也不需要失效处理。

为确保缓存能正确更新其存储的能力，**模组开发者必须在能力发生变化、出现或消失时调用 `level.invalidateCapabilities(pos)`**。

```java
// whenever a capability changes, appears, or disappears:
level.invalidateCapabilities(pos);
```

NeoForge 已经处理了区块加载/卸载以及方块实体创建/移除等常见情况，但其他情况需要模组开发者显式处理。例如，模组开发者必须在以下情况下使能力失效：

- 之前返回的能力不再有效时。
- 提供能力的方块（无方块实体）被放置或状态改变时，通过重写 `onPlace`。
- 提供能力的方块（无方块实体）被移除时，通过重写 `onRemove`。

关于一个普通方块的示例，请参考 `ComposterBlock.java` 文件。

更多信息请参考 [`IBlockCapabilityProvider`][block-cap-provider] 的 javadoc。

## 注册能力

能力**提供者**（provider）是最终提供能力的东西。能力提供者是一个函数，它可以返回一个能力实例，或者在无法提供该能力时返回 `null`。提供者是特定的：

- 针对它们所提供的那一个给定能力，以及
- 针对它们所提供的那一个方块实例、方块实体类型、实体类型或物品实例。

它们需要在 `RegisterCapabilitiesEvent` 中注册。

方块提供者通过 `registerBlock` 注册。例如：

```java
@SubscribeEvent  // on the mod event bus
public static void registerCapabilities(RegisterCapabilitiesEvent event) {
    event.registerBlock(
        Capabilities.ItemHandler.BLOCK, // capability to register for
        (level, pos, state, be, side) -> <return the IItemHandler>,
        // blocks to register for
        MY_ITEM_HANDLER_BLOCK,
        MY_OTHER_ITEM_HANDLER_BLOCK
    );
}
```

一般来说，注册会针对某些方块实体类型，因此还提供了 `registerBlockEntity` 辅助方法：

```java
event.registerBlockEntity(
    Capabilities.ItemHandler.BLOCK, // capability to register for
    MY_BLOCK_ENTITY_TYPE, // block entity type to register for
    (myBlockEntity, side) -> myBlockEntity.myIItemHandlerForTheGivenSide
);
```

> **危险**
>
> 如果方块或方块实体提供者之前返回的能力不再有效，*你必须使缓存失效**，方式是调用 `level.invalidateCapabilities(pos)`。更多信息请参考上文的[失效一节][invalidation]。

实体注册类似，使用 `registerEntity`：

```java
event.registerEntity(
    Capabilities.ItemHandler.ENTITY, // capability to register for
    MY_ENTITY_TYPE, // entity type to register for
    (myEntity, context) -> myEntity.myIItemHandlerForTheGivenContext
);
```

物品注册同样类似。注意提供者接收的是物品堆：

```java
event.registerItem(
    Capabilities.ItemHandler.ITEM, // capability to register for
    (itemStack, context) -> <return the IItemHandler for the itemStack>,
    // items to register for
    MY_ITEM,
    MY_OTHER_ITEM
);
```

## 为所有对象注册能力

如果出于某种原因你需要为所有方块、实体或物品注册提供者，就需要遍历对应的注册表并为每个对象注册提供者。

例如，NeoForge 使用这套系统为所有 `BucketItem`（不包括子类）注册流体处理器能力：

```java
// For reference, you can find this code in the `CapabilityHooks` class.
for (Item item : BuiltInRegistries.ITEM) {
    if (item.getClass() == BucketItem.class) {
        event.registerItem(Capabilities.FluidHandler.ITEM, (stack, ctx) -> new FluidBucketWrapper(stack), item);
    }
}
```

提供者按其注册顺序被询问某个能力。如果你希望在你的某个对象上先于 NeoForge 已注册的提供者运行，请以更高的优先级注册你的 `RegisterCapabilitiesEvent` 处理器。

例如：

```java
modBus.addListener(RegisterCapabilitiesEvent.class, event -> {
    event.registerItem(
        Capabilities.FluidHandler.ITEM,
        (stack, ctx) -> new MyCustomFluidBucketWrapper(stack),
        // blocks to register for
        MY_CUSTOM_BUCKET);
}, EventPriority.HIGH); // use HIGH priority to register before NeoForge!
```

NeoForge 自身注册的提供者列表请参见 [`CapabilityHooks`][capability-hooks]。
