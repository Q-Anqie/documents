# 方块状态

> 相关 Minecraft Wiki：[方块](https://zh.minecraft.wiki/w/方块)

你经常会遇到这样的情况：你想要一个方块具有不同的状态。例如，小麦作物有八个生长阶段，为每个阶段单独做一个方块显然不合理。或者你有一个台阶或类似台阶的方块——一个底部的状态、一个顶部的状态，以及一个两者兼有的状态。

这正是方块状态发挥作用的地方。方块状态是一种简单的方式，用于表示方块可以拥有的不同状态，例如生长阶段或台阶的放置类型。

## 方块状态属性

> 相关 Minecraft Wiki：[方块](https://zh.minecraft.wiki/w/方块)

方块状态使用一套属性系统。一个方块可以拥有多个不同类型的属性。例如，末地传送门框架有两个属性：是否有眼睛（`eye`，2 个选项）以及它被放置的方向（`facing`，4 个选项）。因此，末地传送门框架总共有 8（2 * 4）种不同的方块状态：

```
minecraft:end_portal_frame[facing=north,eye=false]
minecraft:end_portal_frame[facing=east,eye=false]
minecraft:end_portal_frame[facing=south,eye=false]
minecraft:end_portal_frame[facing=west,eye=false]
minecraft:end_portal_frame[facing=north,eye=true]
minecraft:end_portal_frame[facing=east,eye=true]
minecraft:end_portal_frame[facing=south,eye=true]
minecraft:end_portal_frame[facing=west,eye=true]
```

`blockid[property1=value1,property2=value,...]` 这种记法是文本形式表示方块状态的标准方式，原版在某些地方（例如命令中）就使用了它。

如果你的方块没有定义任何方块状态属性，它仍然恰好拥有一个方块状态——也就是那个没有任何属性的状态，因为没有属性可以指定。它可以表示为 `minecraft:oak_planks[]`，或者直接写成 `minecraft:oak_planks`。

与方块一样，每个 `BlockState` 在内存中都只存在一份。这意味着 `==` 可以且应当被用于比较 `BlockState`。`BlockState` 同时也是一个 final 类，意味着它不能被继承。**所有功能都应放在对应的 [Block][block] 类中！**

## 何时使用方块状态

> 相关 Minecraft Wiki：[方块](https://zh.minecraft.wiki/w/方块)

### 方块状态 vs. 独立方块

一条好的经验法则是：**如果它有不同名称，就应当是一个独立的方块**。以椅子方块为例：椅子的朝向应当是一个属性，而不同种类的木材则应拆分为不同的方块。因此，每种木材类型都有一个椅子方块，而每个椅子方块有四个方块状态（每个方向一个）。

### 方块状态 vs. [方块实体][blockentity]

这里的经验法则是：**如果你有有限数量的状态，就使用方块状态；如果你有无限或近乎无限数量的状态，就使用方块实体。** 方块实体可以存储任意数量的数据，但比方块状态更慢。

方块状态和方块实体可以结合使用。例如，箱子使用方块状态属性来表示方向、是否含水、是否变为大箱子等，而存储物品栏、当前是否打开、与漏斗的交互则由方块实体处理。

对于"一个方块状态最多能有多少个状态"这个问题没有确定的答案，但我们建议：如果你需要超过 8-9 位的数据（即超过几百个状态），就应当改用方块实体。

## 实现方块状态

> 相关 Minecraft Wiki：[方块](https://zh.minecraft.wiki/w/方块)

要实现一个方块状态属性，请在你的方块类中创建或引用一个 `public static final Property<?>` 常量。虽然你可以自由地实现自己的 `Property<?>`，但原版代码提供了若干便利实现，应当能覆盖大多数使用场景：

- `IntegerProperty`
    - 实现 `Property<Integer>`。定义一个持有整数值的属性。注意不支持负数值。
    - 通过调用 `IntegerProperty#create(String propertyName, int minimum, int maximum)` 创建。
- `BooleanProperty`
    - 实现 `Property<Boolean>`。定义一个持有 `true` 或 `false` 值的属性。
    - 通过调用 `BooleanProperty#create(String propertyName)` 创建。
- `EnumProperty<E extends Enum<E>>`
    - 实现 `Property<E>`。定义一个可以取某个枚举类值的属性。
    - 通过调用 `EnumProperty#create(String propertyName, Class<E> enumClass)` 创建。
    - 也可以只使用枚举值的一个子集（例如 16 个 `DyeColor` 中的 4 个），参见 `EnumProperty#create` 的重载。
- `DirectionProperty`
    - 继承 `EnumProperty<Direction>`。定义一个可以取 `Direction` 的属性。
    - 通过调用 `DirectionProperty#create(String propertyName)` 创建。
    - 提供了若干便利谓词。例如，要获得一个表示水平方向的属性，调用 `DirectionProperty.create("<name>", Direction.Plane.HORIZONTAL)`；要获得 X 轴方向，调用 `DirectionProperty.create("<name>", Direction.Axis.X)`。

`BlockStateProperties` 类包含共享的原版属性，应尽可能使用或引用它们，而不是创建自己的属性。

有了属性常量之后，在你的方块类中重写 `Block#createBlockStateDefinition(StateDefinition$Builder)`。在该方法中调用 `StateDefinition.Builder#add(YOUR_PROPERTY);`。`StateDefinition.Builder#add` 有一个可变参数，因此如果你有多个属性，可以一次性全部添加。

每个方块还会有一个默认状态。如果没有指定其它内容，默认状态使用每个属性的默认值。你可以在构造方法中调用 `Block#registerDefaultState(BlockState)` 方法来更改默认状态。

如果你希望更改放置方块时使用哪个 `BlockState`，请重写 `Block#getStateForPlacement(BlockPlaceContext)`。例如，可以用它根据玩家放置时站立或注视的位置来设置方块的方向。

为了进一步说明，下面是 `EndPortalFrameBlock` 类中相关部分的代码：

```java
public class EndPortalFrameBlock extends Block {
    // Note: It is possible to directly use the values in BlockStateProperties instead of referencing them here again.
    // However, for the sake of simplicity and readability, it is recommended to add constants like this.
    public static final DirectionProperty FACING = BlockStateProperties.FACING;
    public static final BooleanProperty EYE = BlockStateProperties.EYE;

    public EndPortalFrameBlock(BlockBehaviour.Properties pProperties) {
        super(pProperties);
        // stateDefinition.any() returns a random BlockState from an internal set,
        // we don't care because we're setting all values ourselves anyway
        registerDefaultState(stateDefinition.any()
                .setValue(FACING, Direction.NORTH)
                .setValue(EYE, false)
        );
    }

    @Override
    protected void createBlockStateDefinition(StateDefinition.Builder<Block, BlockState> pBuilder) {
        // this is where the properties are actually added to the state
        pBuilder.add(FACING, EYE);
    }

    @Override
    @Nullable
    public BlockState getStateForPlacement(BlockPlaceContext pContext) {
        // code that determines which state will be used when
        // placing down this block, depending on the BlockPlaceContext
    }
}
```

## 使用方块状态

> 相关 Minecraft Wiki：[方块](https://zh.minecraft.wiki/w/方块)

要从 `Block` 得到 `BlockState`，调用 `Block#defaultBlockState()`。默认方块状态可以通过 `Block#registerDefaultState` 更改，如上所述。

你可以通过调用 `BlockState#getValue(Property<?>)` 并传入你想要取值的属性，来获得某个属性的值。沿用我们的末地传送门框架示例，代码大致如下：

```java
// EndPortalFrameBlock.FACING is a DirectionProperty and thus can be used to obtain a Direction from the BlockState
Direction direction = endPortalFrameBlockState.getValue(EndPortalFrameBlock.FACING);
```

如果你想得到一个具有不同取值组合的 `BlockState`，只需在已有的方块状态上调用 `BlockState#setValue(Property<T>, T)`，传入属性和它的值。以我们的末地传送门框架为例，大致如下：

```java
endPortalFrameBlockState = endPortalFrameBlockState.setValue(EndPortalFrameBlock.FACING, Direction.SOUTH);
```

> **注意**
>
> `BlockState` 是不可变的。这意味着当你调用 `#setValue(Property<T>, T)` 时，你实际上并没有修改该方块状态。相反，内部会执行一次查找，然后返回你请求的方块状态对象，它是具有这组确切属性值的唯一一个对象。这也意味着仅仅调用 `state#setValue` 而不把结果保存到变量中（例如存回 `state`）是没有任何效果的。

要从世界（level）中获取 `BlockState`，使用 `Level#getBlockState(BlockPos)`。

### `Level#setBlock`

要在世界中设置 `BlockState`，使用 `Level#setBlock(BlockPos, BlockState, int)`。

`int` 参数值得额外解释，因为它的含义并不那么直观。它表示所谓的更新标志（update flags）。

为了帮助正确设置更新标志，`Block` 中有若干以 `UPDATE_` 为前缀的 `int` 常量。如果你想组合它们，可以通过按位或运算把这些常量组合起来（例如 `Block.UPDATE_NEIGHBORS | Block.UPDATE_CLIENTS`）。

- `Block.UPDATE_NEIGHBORS` 向相邻方块发送更新。更具体地说，它会调用 `Block#neighborChanged`，后者又会调用若干方法，其中大多数在某种程度上与红石相关。
- `Block.UPDATE_CLIENTS` 将方块更新同步到客户端。
- `Block.UPDATE_INVISIBLE` 明确不在客户端更新。这也会覆盖 `Block.UPDATE_CLIENTS`，导致更新不被同步。方块在服务端始终会被更新。
- `Block.UPDATE_IMMEDIATE` 强制在客户端主线程上重新渲染。
- `Block.UPDATE_KNOWN_SHAPE` 阻止邻居更新递归。
- `Block.UPDATE_SUPPRESS_DROPS` 禁用该位置旧方块的掉落。
- `Block.UPDATE_MOVE_BY_PISTON` 仅供活塞代码使用，用于表明方块是被活塞移动的。它主要负责延迟光照引擎的更新。
- `Block.UPDATE_ALL` 是 `Block.UPDATE_NEIGHBORS | Block.UPDATE_CLIENTS` 的别名。
- `Block.UPDATE_ALL_IMMEDIATE` 是 `Block.UPDATE_NEIGHBORS | Block.UPDATE_CLIENTS | Block.UPDATE_IMMEDIATE` 的别名。
- `Block.NONE` 是 `Block.UPDATE_INVISIBLE` 的别名。

还有一个便利方法 `Level#setBlockAndUpdate(BlockPos pos, BlockState state)`，它在内部调用 `setBlock(pos, state, Block.UPDATE_ALL)`。
