# 方块

> 相关 Minecraft Wiki：[方块](https://zh.minecraft.wiki/w/方块)

方块是 Minecraft 世界的基础。它们构成了所有的地形、结构和机器。如果你有兴趣制作模组，那么多半会想要添加一些方块。本页将引导你完成方块的创建，以及你可以用它们做的一些事情。

## 一方块统御万物

> 相关 Minecraft Wiki：[方块](https://zh.minecraft.wiki/w/方块)

在开始之前，理解这一点很重要：游戏中每种方块永远只存在一个实例。一个世界由成千上万个指向那个方块在不同位置的引用组成。换句话说，同一个方块只是被显示了很多次。

因此，一个方块只应被实例化一次，而且是在[注册][registration]期间。方块注册完成后，你就可以按需使用那个已注册的引用。

与大多数其他注册表不同，方块可以使用 `DeferredRegister` 的一个专用版本，称为 `DeferredRegister.Blocks`。`DeferredRegister.Blocks` 的行为基本上与 `DeferredRegister<Block>` 相同，但有一些细微差别：

- 它们通过 `DeferredRegister.createBlocks("yourmodid")` 创建，而不是常规的 `DeferredRegister.create(...)` 方法。
- `#register` 返回 `DeferredBlock<T extends Block>`，它继承自 `DeferredHolder<Block, T>`。`T` 是我们正在注册的方块所属类的类型。
- 还有一些用于注册方块的辅助方法。详见[下文][below]。

那么现在，让我们来注册方块：

```java
//BLOCKS is a DeferredRegister.Blocks
public static final DeferredBlock<Block> MY_BLOCK = BLOCKS.register("my_block", () -> new Block(...));
```

注册方块之后，所有对新 `my_block` 的引用都应使用这个常量。例如，如果你想检查某个位置的方块是否是 `my_block`，代码大致如下：

```java
level.getBlockState(position) // returns the blockstate placed in the given level (world) at the given position
        //highlight-next-line
        .is(MyBlockRegistrationClass.MY_BLOCK);
```

这种做法还带来一个便利：`block1 == block2` 可以正常工作，可用来替代 Java 的 `equals` 方法（当然，用 `equals` 仍然可以，但由于它本来也是按引用比较，所以没有意义）。

> **危险**
> 不要在注册之外调用 `new Block()`！一旦这样做，事情就可能而且必然会出问题：
>
> - 方块必须在注册表未冻结时创建。NeoForge 会为你解冻注册表并在之后冻结它们，因此注册是你创建方块的时间窗口。
> - 如果你在注册表再次冻结时尝试创建和/或注册方块，游戏会崩溃并报告一个 `null` 方块，这可能非常令人困惑。
> - 如果你仍然设法持有一个游离的方块实例，游戏在同步和保存时将无法识别它，并会将其替换为空气。

## 创建方块

> 相关 Minecraft Wiki：[方块](https://zh.minecraft.wiki/w/方块)

如前所述，我们首先创建 `DeferredRegister.Blocks`：

```java
public static final DeferredRegister.Blocks BLOCKS = DeferredRegister.createBlocks("yourmodid");
```

### 基础方块

对于不需要特殊功能的简单方块（想想圆石、木板等），可以直接使用 `Block` 类。为此，在注册期间用 `BlockBehaviour.Properties` 参数实例化 `Block`。这个 `BlockBehaviour.Properties` 参数可以通过 `BlockBehaviour.Properties#of` 创建，并可以通过调用其方法来自定义。其中最重要的方法有：

- `destroyTime` —— 决定破坏方块所需的时间。
    - 石头的破坏时间是 1.5，泥土是 0.5，黑曜石是 50，基岩是 -1（不可破坏）。
- `explosionResistance` —— 决定方块的爆炸抗性。
    - 石头的爆炸抗性是 6.0，泥土是 0.5，黑曜石是 1,200，基岩是 3,600,000。
- `sound` —— 设置方块在被击打、破坏或放置时发出的声音。
    - 默认值是 `SoundType.STONE`。更多细节见[声音页面][sounds]。
- `lightLevel` —— 设置方块的光照发射。接受一个以 `BlockState` 为参数、返回 0 到 15 之间值的函数。
    - 例如，荧石使用 `state -> 15`，火把使用 `state -> 14`。
- `friction` —— 设置方块的摩擦系数（滑度）。
    - 默认值是 0.6。冰使用 0.98。

因此举例来说，一个简单的实现大致如下：

```java
//BLOCKS is a DeferredRegister.Blocks
public static final DeferredBlock<Block> MY_BETTER_BLOCK = BLOCKS.register(
        "my_better_block", 
        () -> new Block(BlockBehaviour.Properties.of()
                //highlight-start
                .destroyTime(2.0f)
                .explosionResistance(10.0f)
                .sound(SoundType.GRAVEL)
                .lightLevel(state -> 7)
                //highlight-end
        ));
```

更多文档请参阅 `BlockBehaviour.Properties` 的源码。更多示例，或想查看 Minecraft 使用的值，可以看看 `Blocks` 类。

> **注意**
> 重要的是要理解，世界中的方块与物品栏中的方块并不是同一回事。物品栏中看起来像方块的东西实际上是 `BlockItem`，一种特殊的[物品][item]，在使用时会放置一个方块。这也意味着创造模式标签页或最大堆叠数量之类的东西是由对应的 `BlockItem` 处理的。
>
> `BlockItem` 必须与方块分开注册。这是因为方块不一定需要物品，例如当它本就不打算被收集时（比如火）。

### 更多功能

直接使用 `Block` 只能实现非常基础的方块。如果你想添加功能，比如玩家交互或不同的碰撞箱，就需要一个继承 `Block` 的自定义类。`Block` 类有许多可以重写以实现不同功能的方法；更多信息见 `Block`、`BlockBehaviour` 和 `IBlockExtension` 类。另见下方的[使用方块][usingblocks]一节，了解方块的一些最常见用例。

如果你想制作一个有不同变体的方块（想想有底部、顶部和双层变体的台阶），你应当使用[方块状态][blockstates]。最后，如果你想要一个存储额外数据的方块（想想存储其物品栏的箱子），则应当使用[方块实体][blockentities]。这里的经验法则是：如果你有有限且数量合理较少的状态（最多几百个状态），就使用方块状态；如果你有无穷或近乎无穷的状态，就使用方块实体。

#### 方块类型

方块类型是用于序列化和反序列化方块对象的 [`MapCodec`][codec]。这个 `MapCodec` 通过 `BlockBehaviour#codec` 设置，并[注册][registration]到方块类型注册表。目前，它唯一的用途是在生成方块列表报告时。每个 `Block` 子类都应创建一次方块类型。例如，`FlowerBlock#CODEC` 代表大多数花的方块类型，而它的子类 `WitherRoseBlock` 有单独的方块类型。

如果方块子类只接受 `BlockBehaviour.Properties`，那么可以用 `BlockBehaviour#simpleCodec` 创建 `MapCodec`。

```java
// For some block subclass
public class SimpleBlock extends Block {

    public SimpleBlock(BlockBehavior.Properties properties) {
        // ...
    }

    @Override
    public MapCodec<SimpleBlock> codec() {
        return SIMPLE_CODEC.value();
    }
}

// In some registration class
public static final DeferredRegister<MapCodec<? extends Block>> REGISTRAR = DeferredRegister.create(BuiltInRegistries.BLOCK_TYPE, "yourmodid");

public static final DeferredHolder<MapCodec<? extends Block>, MapCodec<SimpleBlock>> SIMPLE_CODEC = REGISTRAR.register(
    "simple",
    () -> simpleCodec(SimpleBlock::new)
);
```

如果方块子类包含更多参数，则应当使用 [`RecordCodecBuilder#mapCodec`][codec] 创建 `MapCodec`，并为 `BlockBehaviour.Properties` 参数传入 `BlockBehaviour#propertiesCodec`。

```java
// For some block subclass
public class ComplexBlock extends Block {

    public ComplexBlock(int value, BlockBehavior.Properties properties) {
        // ...
    }

    @Override
    public MapCodec<ComplexBlock> codec() {
        return COMPLEX_CODEC.value();
    }

    public int getValue() {
        return this.value;
    }
}

// In some registration class
public static final DeferredRegister<MapCodec<? extends Block>> REGISTRAR = DeferredRegister.create(BuiltInRegistries.BLOCK_TYPE, "yourmodid");

public static final DeferredHolder<MapCodec<? extends Block>, MapCodec<ComplexBlock>> COMPLEX_CODEC = REGISTRAR.register(
    "simple",
    () -> RecordCodecBuilder.mapCodec(instance ->
        instance.group(
            Codec.INT.fieldOf("value").forGetter(ComplexBlock::getValue),
            BlockBehaviour.propertiesCodec() // represents the BlockBehavior.Properties parameter
        ).apply(instance, ComplexBlock::new)
    );
);
```

> **注意**
> 尽管方块类型目前基本上没有被使用，但随着 Mojang 继续向以 Codec 为中心的结构演进，预计它未来会变得更加重要。

### `DeferredRegister.Blocks` 辅助方法

我们已经在[上文][above]讨论了如何创建 `DeferredRegister.Blocks`，以及它会返回 `DeferredBlock`。现在，让我们看看这个专用 `DeferredRegister` 还提供了哪些其他工具。先从 `#registerBlock` 开始：

```java
public static final DeferredRegister.Blocks BLOCKS = DeferredRegister.createBlocks("yourmodid");

public static final DeferredBlock<Block> EXAMPLE_BLOCK = BLOCKS.registerBlock(
        "example_block",
        Block::new, // The factory that the properties will be passed into.
        BlockBehaviour.Properties.of() // The properties to use.
);
```

在内部，它会将 properties 参数应用到提供的方块工厂（通常是构造函数）上，从而简单地调用 `BLOCKS.register("example_block", () -> new Block(BlockBehaviour.Properties.of()))`。

如果你想使用 `Block::new`，可以完全省略工厂：

```java
public static final DeferredBlock<Block> EXAMPLE_BLOCK = BLOCKS.registerSimpleBlock(
        "example_block",
        BlockBehaviour.Properties.of() // The properties to use.
);
```

这与上一个示例完全相同，只是稍短一些。当然，如果你想使用 `Block` 的子类而不是 `Block` 本身，就必须改用前一种方法。

### 资源

如果你注册了方块并将其放置到世界中，你会发现它缺少纹理之类的东西。这是因为[纹理][textures]等由 Minecraft 的资源系统处理。在 Minecraft 中添加新方块时，你应当编写或[生成][datagen]以下文件：

- 一个[方块状态文件][bsfile]
- 一个[方块模型][model]
- 一个[翻译][i18n]
- 一张[战利品表][loottable]
- 一些方块[标签][tags]，例如用于挖掘

对于上述所有内容，也请参考相似的原版方块的文件和数据生成器。

## 使用方块

> 相关 Minecraft Wiki：[方块](https://zh.minecraft.wiki/w/方块)

方块很少被直接用于做事。事实上，Minecraft 中两个最常见的操作——获取某个位置的方块、设置某个位置的方块——使用的都是方块状态，而不是方块。通用的设计思路是：由方块定义行为，但行为实际通过方块状态来运行。因此，`BlockState` 经常作为参数传递给 `Block` 的方法。关于方块状态如何被使用，以及如何从方块获取一个方块状态，见[使用方块状态][usingblockstates]。

在若干场景中，`Block` 的多个方法会在不同时机被调用。以下小节列出了最常见的与方块相关的流程。除非另有说明，所有方法都会在两个逻辑侧（客户端与服务端）被调用，并且应在两侧返回相同的结果。

### 放置方块

方块放置逻辑由 `BlockItem#useOn` 调用（或其某个子类的实现，例如用于睡莲的 `PlaceOnWaterBlockItem`）。关于游戏如何走到这一步，见[交互流程][interactionpipeline]。在实践中，这意味着一旦 `BlockItem`（例如一个圆石物品）被右键点击，该行为就会被调用。

- 会检查若干前置条件，例如你不在旁观者模式、方块所需的所有功能开关均已启用，或目标位置不在世界边界之外。如果至少有一项检查失败，流程结束。
- 对当前位于尝试放置位置上的方块调用 `BlockBehaviour#canBeReplaced`。如果返回 `false`，流程结束。在此返回 `true` 的典型情况是高草或雪层。
- 调用 `Block#getStateForPlacement`。这里会根据上下文（包括位置、旋转、所放置的面等信息）返回不同的方块状态。例如，对于可以朝不同方向放置的方块这很有用。
- 用上一步得到的方块状态调用 `BlockBehaviour#canSurvive`。如果返回 `false`，流程结束。
- 通过 `Level#setBlock` 调用将该方块状态设置到世界中。
    - 在那次 `Level#setBlock` 调用中，会调用 `BlockBehaviour#onPlace`。
- 调用 `Block#setPlacedBy`。

### 破坏方块

破坏方块要稍微复杂一些，因为它需要时间。这个过程大致可分为三个阶段："初始化"、"挖掘"和"实际破坏"。

- 当按下鼠标左键时，进入"初始化"阶段。
- 接着需要按住鼠标左键，进入"挖掘"阶段。**该阶段的方法每刻都会被调用。**
- 如果"持续"阶段没有被中断（通过松开鼠标左键）且方块被破坏，则进入"实际破坏"阶段。

或者，对于喜欢伪代码的人：

```java
leftClick();
initiatingStage();
while (leftClickIsBeingHeld()) {
    miningStage();
    if (blockIsBroken()) {
        actuallyBreakingStage();
        break;
    }
}
```

以下小节进一步将这些阶段拆解为实际的方法调用。

#### "初始化"阶段

- 仅客户端：以鼠标左键和主手触发 `InputEvent.InteractionKeyMappingTriggered`。如果事件被取消，流程结束。
- 会检查若干前置条件，例如你不在旁观者模式、主手中 `ItemStack` 所需的所有功能开关均已启用，或相关方块不在世界边界之外。如果至少有一项检查失败，流程结束。
- 触发 `PlayerInteractEvent.LeftClickBlock`。如果事件被取消，流程结束。
    - 注意，当事件在客户端被取消时，不会向服务端发送数据包，因此服务端不会运行任何逻辑。
    - 然而，在服务端取消此事件仍会导致客户端代码运行，这可能导致不同步！
- 调用 `Block#attack`。

#### "挖掘"阶段

- 触发 `PlayerInteractEvent.LeftClickBlock`。如果事件被取消，流程转到"结束"阶段。
    - 注意，当事件在客户端被取消时，不会向服务端发送数据包，因此服务端不会运行任何逻辑。
    - 然而，在服务端取消此事件仍会导致客户端代码运行，这可能导致不同步！
- 调用 `Block#getDestroyProgress` 并将其累加到内部破坏进度计数器中。
    - `Block#getDestroyProgress` 返回 0 到 1 之间的浮点数，表示每刻应增加多少破坏进度。
- 进度覆盖层（裂纹纹理）会相应更新。
- 如果破坏进度大于 1.0（即已完成，即方块应被破坏），则退出"挖掘"阶段并进入"实际破坏"阶段。

#### "实际破坏"阶段

- 调用 `Item#canAttackBlock`。如果返回 `false`（判定该方块不应被破坏），流程转到"结束"阶段。
- 如果方块是 `GameMasterBlock` 的实例，则调用 `Player#canUseGameMasterBlocks`。这决定玩家是否有能力破坏仅创造模式可用的方块。如果为 `false`，流程转到"结束"阶段。
- 仅服务端：调用 `Player#blockActionRestricted`。这决定当前玩家是否无法破坏该方块。如果为 `true`，流程转到"结束"阶段。
- 仅服务端：触发 `BlockEvent.BreakEvent`。如果被取消或 `getExpToDrop` 返回 -1，流程转到"结束"阶段。初始的取消状态由上述三个方法决定。
    - 仅服务端：触发 `PlayerEvent.HarvestCheck`。如果 `HarvestCheck#canHarvest` 返回 `false`，或传入破坏事件的 `BlockState` 为 null，则该事件的初始经验值将为 0。
    - 仅服务端：如果 `PlayerEvent.HarvestCheck#canHarvest` 返回 `true`，则调用 `IBlockExtension#getExpDrop`。该值会传给 `BlockEvent.BreakEvent#getExpToDrop`，供流程后续使用。
- 仅服务端：调用 `IBlockExtension#canHarvestBlock`。这决定该方块能否被收获，即破坏时是否掉落。
- 调用 `IBlockExtension#onDestroyedByPlayer`。如果返回 `false`，流程转到"结束"阶段。在那次 `IBlockExtension#onDestroyedByPlayer` 调用中：
    - 调用 `Block#playerWillDestroy`。
    - 通过 `Level#setBlock` 调用将该方块状态从世界中移除，方块状态参数为 `Blocks.AIR.defaultBlockState()`。
        - 在那次 `Level#setBlock` 调用中，会调用 `Block#onRemove`。
- 调用 `Block#destroy`。
- 仅服务端：如果之前对 `IBlockExtension#canHarvestBlock` 的调用返回 `true`，则调用 `Block#playerDestroy`。
    - 仅服务端：调用 `Block#dropResources`。这决定方块被挖掘时掉落什么。
        - 仅服务端：触发 `BlockDropsEvent`。如果事件被取消，则方块破坏时不掉落任何东西。否则，`BlockDropsEvent#getDrops` 中的每个 `ItemEntity` 都会被加入当前世界。
- 仅服务端：如果之前 `IBlockExtension#getExpDrop` 的调用返回了大于 0 的值，则用该结果调用 `Block#popExperience`。

### 刻更新（Ticking）

刻更新是一种每 1/20 秒（即 50 毫秒，"一刻"）更新（tick）游戏部分内容的机制。方块提供了多种刻更新方法，它们以不同方式被调用。

#### 服务端刻更新与刻调度

`BlockBehaviour#tick` 通过计划刻（scheduled tick）调用。计划刻可以通过 `Level#scheduleTick(BlockPos, Block, int)` 创建，其中 `int` 表示延迟。原版在许多地方使用了它，例如大型垂滴叶的倾斜机制就大量依赖该系统。其他常见使用者是各种红石元件。

#### 客户端刻更新

`Block#animateTick` 仅在客户端每帧调用。仅客户端的行为在此发生，例如火把粒子的生成。

#### 天气刻更新

天气刻更新由 `Block#handlePrecipitation` 处理，独立于常规刻更新运行。它仅在服务端、仅当以某种形式下雨时、以 1/16 的概率被调用。例如下雨或下雪时填充的炼药锅就使用了它。

#### 随机刻更新

随机刻系统独立于常规刻更新运行。随机刻必须通过方块的 `BlockBehaviour.Properties` 调用 `BlockBehaviour.Properties#randomTicks()` 方法来启用。这使方块能够参与随机刻机制。

每个游戏刻，区块中会有一定数量的方块发生随机刻。该数量由 `randomTickSpeed` 游戏规则定义。默认值为 3 时，每刻会从区块中随机选择 3 个方块。如果这些方块启用了随机刻，则调用它们各自的 `BlockBehaviour#randomTick` 方法。

随机刻被 Minecraft 中广泛的机制使用，例如植物生长、冰与雪的融化，或铜的氧化。
