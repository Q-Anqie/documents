# 存档数据

存档数据（Saved Data，SD）系统可用于在维度（level）上保存额外数据。

_如果数据是特定于某些方块实体、区块或实体的，请考虑改用[数据附加](https://docs.neoforged.net/docs/1.21.1/datastorage/attachments)。_

## 声明

> 相关 Minecraft Wiki：[NBT格式](https://zh.minecraft.wiki/w/NBT格式)

每个 SD 实现都必须继承 `SavedData` 类。有两个需要注意的重要方法：

- `save`：允许实现将 NBT 数据写入维度。
- `setDirty`：一个必须在更改数据后调用的方法，用于通知游戏存在需要写入的更改。如果不调用，`#save` 将不会被调用，原始数据将保持不变。

## 附加到维度

任何 `SavedData` 都是动态加载和/或附加到维度的。因此，如果某个维度上从未创建过它，那么它就不会存在。

`SavedData` 由 `DimensionDataStorage` 创建和加载，可通过调用 `ServerChunkCache#getDataStorage` 或 `ServerLevel#getDataStorage` 访问。由此，你可以通过调用 `DimensionDataStorage#computeIfAbsent` 获取或创建 SD 的实例。它会尝试获取 SD 的当前实例（如果存在），或创建一个新实例并加载所有可用数据。

`DimensionDataStorage#computeIfAbsent` 接收两个参数。第一个是 `SavedData.Factory` 的实例，它由一个用于构造 SD 新实例的提供器和一个用于将 NBT 数据加载到 SD 中并返回它的函数组成。第二个参数是该维度实现的、存储在 `data` 文件夹中的 `.dat` 文件名。名称必须是有效的文件名，且不能包含 `/` 或 `\`。

例如，如果一个 SD 在下界中被命名为 "example"，那么将在 `./<level_folder>/DIM-1/data/example.dat` 处创建文件，其实现如下：

```java
// In some saved data implementation
public class ExampleSavedData extends SavedData {

    // Create new instance of saved data
    public static ExampleSavedData create() {
        return new ExampleSavedData();
    }

    // Load existing instance of saved data
    public static ExampleSavedData load(CompoundTag tag, HolderLookup.Provider lookupProvider) {
        ExampleSavedData data = ExampleSavedData.create();
        // Load saved data
        return data;
    }

    @Override
    public CompoundTag save(CompoundTag tag, HolderLookup.Provider registries) {
        // Write data to tag
        return tag;
    }

    public void foo() {
        // Change data in saved data
        // Call set dirty if data changes
        this.setDirty();
    }
}

// In some method within the class
netherDataStorage.computeIfAbsent(new Factory<>(ExampleSavedData::create, ExampleSavedData::load), "example");
```

如果某个 SD 不是特定于某个维度的，则该 SD 应附加到主世界，可通过 `MinecraftServer#overworld` 获取。主世界是唯一永远不会被完全卸载的维度，因此非常适合存储跨维度数据。
