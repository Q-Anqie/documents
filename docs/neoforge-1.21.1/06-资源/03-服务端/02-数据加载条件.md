# 数据加载条件

有时，当另一个模组存在时，或者当任何模组添加了另一种矿石类型时，我们希望禁用或启用某些功能。针对这些用例，NeoForge 添加了数据加载条件。它们最初被称为配方条件，因为配方是该系统最初的用例，但此后已扩展到其他系统。这也是为什么一些内置条件仅限于物品。

大多数 JSON 文件可以选择在根处声明一个 `neoforge:conditions` 块，它会在数据文件实际加载之前被求值。当且仅当所有条件都通过时加载才会继续，否则该数据文件将被忽略。（此规则的例外是[战利品表][loottable]，它们会被替换为空战利品表。）

```json5
{
    "neoforge:conditions": [
        {
            // Condition 1
        },
        {
            // Condition 2
        },
        // ...
    ],
    // The rest of the data file
}
```

例如，如果我们只想在 ID 为 `examplemod` 的模组存在时加载我们的文件，我们的文件大致如下：

```json5
{
    // highlight-start
    "neoforge:conditions": [
        {
            "type": "neoforge:mod_loaded",
            "modid": "examplemod"
        }
    ],
    // highlight-end
    "type": "minecraft:crafting_shaped",
    // ...
}
```

> **注意**
>
> 大多数原版文件已被修补为使用 `ConditionalCodec` 包装器来支持条件。然而，并非所有系统都能使用条件，尤其是那些不使用 [Codec] 的系统。要了解某个数据文件是否可以使用条件，请检查其背后的 Codec 定义。

## 内置条件

### `neoforge:true` 与 `neoforge:false`

它们不包含任何数据，并返回预期值。

```json5
{
    // Will always return true (or false for "neoforge:false")
    "type": "neoforge:true"
}
```

> **提示**
>
> 使用 `neoforge:false` 条件可以非常干净地禁用任何数据文件。只需在需要的位置放置一个包含以下内容的文件：
>
> ```json5
> {"neoforge:conditions":[{"type":"neoforge:false"}]}
> ```
>
> 以这种方式禁用文件**不会**导致日志刷屏。

### `neoforge:not`

此条件接受另一个条件并将其取反。

```json5
{
    // Inverts the result of the stored condition
    "type": "neoforge:not",
    "value": {
        // Another condition
    }
}
```

### `neoforge:and` 与 `neoforge:or`

这些条件接受被操作的条件并应用预期的逻辑。可接受的条件数量没有限制。

```json5
{
    // ANDs the stored conditions together (or ORs for "neoforge:or")
    "type": "neoforge:and",
    "values": [
        {
            // First condition
        },
        {
            // Second condition
        }
    ]
}
```

### `neoforge:mod_loaded`

如果加载了具有给定模组 ID 的模组，此条件返回 true，否则返回 false。

```json5
{
    "type": "neoforge:mod_loaded",
    // Returns true if "examplemod" is loaded
    "modid": "examplemod"
}
```

### `neoforge:item_exists`

如果具有给定注册名的物品已注册，此条件返回 true，否则返回 false。

```json5
{
    "type": "neoforge:item_exists",
    // Returns true if "examplemod:example_item" has been registered
    "item": "examplemod:example_item"
}
```

### `neoforge:tag_empty`

如果给定的物品[标签][tag]为空，此条件返回 true，否则返回 false。

```json5
{
    "type": "neoforge:tag_empty",
    // Returns true if "examplemod:example_tag" is an empty item tag
    "tag": "examplemod:example_tag"
}
```

## 创建自定义条件

自定义条件可以通过实现 `ICondition` 及其 `#test(IContext)` 方法，并为其创建[映射 Codec][codec] 来创建。`#test` 中的 `IContext` 参数可访问游戏状态的一些部分。目前，这只允许你从注册表查询标签。某些带条件的对象可能比标签加载得更早，此时上下文将是 `IContext.EMPTY`，完全不包含任何标签信息。

例如，假设我们要重新实现 `tag_empty` 条件，但针对实体类型标签而非物品标签，那么我们的条件大致如下：

```java
// This class is basically a boiled-down copy of TagEmptyCondition, adjusted for entity types instead of items.
public record EntityTagEmptyCondition(TagKey<EntityType<?>> tag) implements ICondition {
    public static final MapCodec<EntityTagEmptyCondition> CODEC = RecordCodecBuilder.mapCodec(inst -> inst.group(
            ResourceLocation.CODEC.xmap(rl -> TagKey.create(Registries.ENTITY_TYPES, rl), TagKey::location).fieldOf("tag").forGetter(EntityTagEmptyCondition::tag)
    ).apply(inst, EntityTagEmptyCondition::new));

    @Override
    public boolean test(ICondition.IContext context) {
        return context.getTag(this.tag()).isEmpty();
    }

    @Override
    public MapCodec<? extends ICondition> codec() {
        return CODEC;
    }
}
```

条件是一个 Codec 注册表。因此，我们需要[注册][register]我们的 Codec，如下所示：

```java
public static final DeferredRegister<MapCodec<? extends ICondition>> CONDITION_CODECS =
        DeferredRegister.create(NeoForgeRegistries.Keys.CONDITION_CODECS, ExampleMod.MOD_ID);

public static final Supplier<MapCodec<EntityTagEmptyCondition>> ENTITY_TAG_EMPTY =
        CONDITION_CODECS.register("entity_tag_empty", () -> EntityTagEmptyCondition.CODEC);
```

然后，我们就能在某些数据文件中使用我们的条件（假设我们在 `examplemod` 命名空间下注册了该条件）：

```json5
{
    "neoforge:conditions": [
        {
            "type": "examplemod:entity_tag_empty",
            "tag": "minecraft:zombies"
        }
    ],
    // The rest of the data file
}
```

## 数据生成

虽然任何数据包 JSON 文件都可以使用加载条件，但只有少数[数据提供器][datagen]被修改为能够生成它们。这些包括：

- [`RecipeProvider`][recipeprovider]（通过 `RecipeOutput#withConditions`），包括配方进度
- `JsonCodecProvider` 及其子类 `SpriteSourceProvider`
- [`DataMapProvider`][datamapprovider]
- [`GlobalLootModifierProvider`][glmprovider]

至于条件本身，`IConditionBuilder` 接口为每种内置条件类型提供了返回相应 `ICondition` 的静态辅助方法。
