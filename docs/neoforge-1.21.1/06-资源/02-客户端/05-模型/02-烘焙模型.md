# 烘焙模型

> 相关 Minecraft Wiki：[模型](https://zh.minecraft.wiki/w/模型)

`BakedModel` 是带有纹理的形状在代码中的表示。它们可以有多种来源，例如来自对 `UnbakedModel#bake`（默认模型加载器）或 `IUnbakedGeometry#bake`（[自定义模型加载器][modelloader]）的调用。一些[方块实体渲染器][ber]也会使用烘焙模型。模型的复杂程度没有限制。

模型存储在 `ModelManager` 中，可通过 `Minecraft.getInstance().modelManager` 访问。随后，你可以调用 `ModelManager#getModel`，通过其 [`ResourceLocation`][rl] 或 [`ModelResourceLocation`][mrl] 获取某个模型。模组基本上总是会复用先前已自动加载并烘焙的模型。

## `BakedModel` 的方法

### `getQuads`

烘焙模型最重要的方法是 `getQuads`。该方法负责返回一个 `BakedQuad` 列表，这些四边形随后可被发送到 GPU。在建模程序（以及大多数其他游戏）中，与四边形对应的是三角形，但由于 Minecraft 总体上以正方形为核心，开发者选择在 Minecraft 的渲染中使用四边形（4 个顶点）而非三角形（3 个顶点）。`getQuads` 有五个可用参数：

- 一个 `BlockState`：正在渲染的[方块状态][blockstate]。可能为 null，表示正在渲染物品。
- 一个 `Direction`：被剔除的面的方向。可能为 null，表示应返回无法被遮挡的四边形。
- 一个 `RandomSource`：可用于随机化的客户端随机源。
- 一个 `ModelData`：要使用的额外模型数据。这可能包含渲染所需的来自方块实体的额外数据。由 `BakedModel#getModelData` 提供。
- 一个 `RenderType`：用于渲染该方块的[渲染类型][rendertype]。可能为 null，表示应返回此模型所使用的所有渲染类型的四边形。否则，它是 `BakedModel#getRenderTypes` 返回的渲染类型之一（见下文）。

模型应当大量使用缓存。这是因为尽管区块只在其中的方块发生变化时才会重建，但此方法中进行的计算仍然需要尽可能快，并且由于该方法在每个区块区段中被调用的次数极多，理想情况下应当大量缓存（最多可达每个区块区段中给定模型使用的每个渲染类型七次 × 相应模型使用的渲染类型数量 × 4096 个方块）。此外，[BER][ber] 或实体渲染器实际上可能每帧多次调用此方法。

### `applyTransform` 与 `getTransforms`

`applyTransform` 允许在对模型应用视角变换时应用自定义逻辑，包括返回一个完全不同的模型。此方法由 NeoForge 添加，用于替代原版的 `getTransforms()` 方法，后者只允许你自定义变换本身，而不能自定义其应用方式。不过，`applyTransform` 的默认实现会转而调用 `getTransforms`，所以如果你只需要自定义变换，也可以直接覆写 `getTransforms` 即可。`applyTransforms` 提供三个参数：

- 一个 `ItemDisplayContext`：模型被变换到的[视角][perspective]。
- 一个 `PoseStack`：用于渲染的姿态栈。
- 一个 `boolean`：是否使用左手渲染的修改值而非默认的右手渲染；若渲染的手是左手（副手，或若在选项中启用了左手模式则为主手）则为 `true`。

> **注意**
>
> `applyTransform` 和 `getTransforms` 仅对物品模型生效。

### 其他方法

`BakedModel` 中其他你可以覆写和/或查询的方法包括：

| 签名                                                                          | 作用                                                                                                                                                                                                                                                                                                                                                                                                         |
|-------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `TriState useAmbientOcclusion()`                                              | 是否使用[环境光遮蔽][ao]。接受 `BlockState`、`RenderType` 和 `ModelData` 参数，并返回一个 `TriState`，它不仅允许强制禁用 AO，也允许强制启用 AO。有两个重载，各自返回 `boolean` 参数，并分别只接受一个 `BlockState` 或完全不接受参数；这两个重载均已弃用并待移除，请改用第一个变体。                                                                                                                        |
| `boolean isGui3d()`                                                           | 此模型在 GUI 槽位中渲染为 3D 还是平面。                                                                                                                                                                                                                                                                                                                                                                       |
| `boolean usesBlockLight()`                                                    | 为模型打光时使用 3D 光照（`true`）还是来自正面的平面光照（`false`）。                                                                                                                                                                                                                                                                                                                                         |
| `boolean isCustomRenderer()`                                                  | 若为 true，则跳过常规渲染，改为调用关联的 [`BlockEntityWithoutLevelRenderer`][bewlr] 的 `renderByItem` 方法。若为 false，则通过默认渲染器渲染。                                                                                                                                                                                                                                                                |
| `ItemOverrides getOverrides()`                                                | 返回与此模型关联的 [`ItemOverrides`][itemoverrides]。这仅对物品模型有意义。                                                                                                                                                                                                                                                                                                                                   |
| `ModelData getModelData(BlockAndTintGetter, BlockPos, BlockState, ModelData)` | 返回该模型要使用的模型数据。此方法会被传入一个已有的 `ModelData`，若方块有关联的方块实体，则为 `BlockEntity#getModelData()` 的结果，否则为 `ModelData.EMPTY`。此方法可用于需要模型数据但没有方块实体的方块，例如需要连接纹理的方块。                                                                                                                                                                          |
| `TextureAtlasSprite getParticleIcon(ModelData)`                               | 返回该模型要使用的粒子精灵。可以使用模型数据，以便针对不同的模型数据值使用不同的粒子精灵。NeoForge 新增，替代了原版无参数的 `getParticleIcon()` 重载。                                                                                                                                                                                                                                                        |
| `ChunkRenderTypeSet getRenderTypes(BlockState, RandomSource, ModelData)`      | 返回一个 `ChunkRenderTypeSet`，其中包含用于渲染该方块模型的渲染类型。`ChunkRenderTypeSet` 是一个由集合支持的有序 `Iterable<RenderType>`。默认回退到[从模型 JSON 获取渲染类型][rendertype]。仅用于方块模型，物品模型使用下面的重载。                                                                                                                                                                          |
| `List<RenderType> getRenderTypes(ItemStack, boolean)`                         | 返回一个 `List<RenderType>`，其中包含用于渲染该物品模型的渲染类型。默认回退到常规的模型绑定渲染类型查找，其始终产生只含一个元素的列表。仅用于物品模型，方块模型使用上面的重载。                                                                                                                                                                                                                              |

## 视角

Minecraft 的渲染引擎为物品渲染总共识别 8 种视角类型（若算上代码中的回退则为 9 种）。这些类型用于模型 JSON 的 `display` 块中，并在代码中通过 `ItemDisplayContext` 枚举表示。

| 枚举值                    | JSON 键                   | 用途                                                          |
|---------------------------|---------------------------|---------------------------------------------------------------|
| `THIRD_PERSON_RIGHT_HAND` | `"thirdperson_righthand"` | 第三人称的右手（F5 视角，或其他玩家身上）                     |
| `THIRD_PERSON_LEFT_HAND`  | `"thirdperson_lefthand"`  | 第三人称的左手（F5 视角，或其他玩家身上）                     |
| `FIRST_PERSON_RIGHT_HAND` | `"firstperson_righthand"` | 第一人称的右手                                                |
| `FIRST_PERSON_LEFT_HAND`  | `"firstperson_lefthand"`  | 第一人称的左手                                                |
| `HEAD`                    | `"head"`                  | 位于玩家的头盔盔甲槽时（通常只能通过命令实现）                |
| `GUI`                     | `"gui"`                   | 物品栏、玩家快捷栏                                            |
| `GROUND`                  | `"ground"`                | 掉落的物品；注意掉落物品的旋转由掉落物渲染器处理，而非模型    |
| `FIXED`                   | `"fixed"`                 | 物品展示框                                                    |
| `NONE`                    | `"none"`                  | 代码中的回退用途，不应在 JSON 中使用                          |

## `ItemOverrides`

`ItemOverrides` 是一个类，为烘焙模型提供了一种处理 [`ItemStack`][itemstack] 状态并通过 `#resolve` 方法返回新烘焙模型的方式。`#resolve` 有五个参数：

- 一个 `BakedModel`：原始模型。
- 一个 `ItemStack`：正在渲染的物品堆叠。
- 一个 `ClientLevel`：模型正在其中渲染的维度。这应只用于查询维度，不得以任何方式修改它。可能为 null。
- 一个 `LivingEntity`：模型渲染所在的实体。可能为 null，例如从[方块实体渲染器][ber]渲染时。
- 一个 `int`：用于随机化的种子。

`ItemOverrides` 还以 `BakedOverride` 的形式持有模型的覆盖选项。一个 `BakedOverride` 对象是模型 [`overrides`][overrides] 块在代码中的表示。烘焙模型可以使用它来根据其内容返回不同的模型。`ItemOverrides` 实例的所有 `BakedOverride` 列表可通过 `ItemOverrides#getOverrides()` 获取。

## `BakedModelWrapper`

`BakedModelWrapper` 可用于修改一个已存在的 `BakedModel`。`BakedModelWrapper` 是 `BakedModel` 的子类，它在构造函数中接受另一个 `BakedModel`（"原始"模型），并默认将所有方法重定向到该原始模型。随后你的实现可以只覆写选定的方法，如下所示：

```java
// The generic parameter may optionally be a more specific subclass of BakedModel.
// If it is, the constructor parameter must match that type.
public class MyBakedModelWrapper extends BakedModelWrapper<BakedModel> {
    // Pass the original model to super.
    public MyBakedModelWrapper(BakedModel originalModel) {
        super(originalModel);
    }
    
    // Override whatever methods you want here. You may also access originalModel if needed.
}
```

编写好模型包装类之后，你必须将这些包装器应用到它应当影响的模型上。请在针对 `ModelEvent.ModifyBakingResult` 的[客户端][sides][事件处理器][event]中完成：

```java
@SubscribeEvent // on the mod event bus only on the physical client
public static void modifyBakingResult(ModelEvent.ModifyBakingResult event) {
    // For block models
    event.getModels().computeIfPresent(
        // The model resource location of the model to modify. Get it from
        // BlockModelShaper#stateToModelLocation with the blockstate to be affected as a parameter.
        BlockModelShaper.stateToModelLocation(MyBlocksClass.EXAMPLE_BLOCK.defaultBlockState()),
        // A BiFunction with the location and the original models as parameters, returning the new model.
        (location, model) -> new MyBakedModelWrapper(model);
    );
    // For item models
    event.getModels().computeIfPresent(
        // The model resource location of the model to modify.
        new ModelResourceLocation(
            ResourceLocation.fromNamespaceAndPath("examplemod", "example_item"),
            "inventory"
        ),
        // A BiFunction with the location and the original models as parameters, returning the new model.
        (location, model) -> new MyBakedModelWrapper(model);
    );
}
```

> **警告**
>
> 在可能的情况下，通常鼓励使用[自定义模型加载器][modelloader]，而不是在 `ModelEvent.ModifyBakingResult` 中包装烘焙模型。自定义模型加载器在需要时也可以使用 `BakedModelWrapper`。
