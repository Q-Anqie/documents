# 注册载荷（Payload）

载荷（Payload）是在客户端与服务器之间发送任意数据的一种方式。它们通过 `RegisterPayloadHandlersEvent` 事件中的 `PayloadRegistrar` 进行注册。

```java
@SubscribeEvent // on the mod event bus
public static void register(final RegisterPayloadHandlersEvent event) {
    // Sets the current network version
    final PayloadRegistrar registrar = event.registrar("1");
}
```

假设我们想要发送以下数据：

```java
public record MyData(String name, int age) {}
```

那么我们可以实现 `CustomPacketPayload` 接口，创建一个可用于发送和接收该数据的载荷。

```java
public record MyData(String name, int age) implements CustomPacketPayload {
    
    public static final CustomPacketPayload.Type<MyData> TYPE = new CustomPacketPayload.Type<>(ResourceLocation.fromNamespaceAndPath("mymod", "my_data"));

    // Each pair of elements defines the stream codec of the element to encode/decode and the getter for the element to encode
    // 'name' will be encoded and decoded as a string
    // 'age' will be encoded and decoded as an integer
    // The final parameter takes in the previous parameters in the order they are provided to construct the payload object
    public static final StreamCodec<ByteBuf, MyData> STREAM_CODEC = StreamCodec.composite(
        ByteBufCodecs.STRING_UTF8,
        MyData::name,
        ByteBufCodecs.VAR_INT,
        MyData::age,
        MyData::new
    );
    
    @Override
    public CustomPacketPayload.Type<? extends CustomPacketPayload> type() {
        return TYPE;
    }
}
```

从上面的示例可以看出，`CustomPacketPayload` 接口要求我们实现 `type` 方法。`type` 方法负责返回该载荷的唯一标识符。此外我们还需要一个读取器，之后配合 `StreamCodec` 来读写载荷数据。

最后，我们可以把这个载荷注册到注册器上：

```java
@SubscribeEvent // on the mod event bus
public static void register(final RegisterPayloadHandlersEvent event) {
    final PayloadRegistrar registrar = event.registrar("1");
    registrar.playBidirectional(
        MyData.TYPE,
        MyData.STREAM_CODEC,
        new DirectionalPayloadHandler<>(
            ClientPayloadHandler::handleDataOnMain,
            ServerPayloadHandler::handleDataOnMain
        )
    );
}
```

剖析上面的代码，我们可以注意到以下几点：
- 注册器拥有 `play*` 系列方法，可用于注册在游戏 play 阶段发送的载荷。
    - 这段代码中看不到的是 `configuration*` 与 `common*` 方法；它们同样可用于为配置（configuration）阶段注册载荷。`common` 方法可同时为配置阶段和 play 阶段注册载荷。
- 注册器使用了 `*Bidirectional` 方法，可用于注册同时发往逻辑服务端和逻辑客户端的载荷。
    - 这段代码中看不到的是 `*ToClient` 与 `*ToServer` 方法；它们可分别用于注册仅发往逻辑客户端或仅发往逻辑服务端的载荷。
- 载荷的类型被用作该载荷的唯一标识符。
- [stream codec][streamcodec] 用于将载荷读写到跨网络发送的缓冲区中。
- 载荷处理器是载荷到达某一逻辑侧时的回调。
    - 若使用 `*Bidirectional` 方法，则可以使用 `DirectionalPayloadHandler` 为每个逻辑侧分别提供两个独立的载荷处理器。

现在我们已经注册了载荷，接下来需要实现处理器。在本例中我们将专门查看客户端侧处理器，不过服务端侧处理器与之非常相似。

```java
public class ClientPayloadHandler {
    
    public static void handleDataOnMain(final MyData data, final IPayloadContext context) {
        // Do something with the data, on the main thread
        blah(data.age());
    }
}
```

这里有几点需要注意：

- 此处的处理方法接收载荷以及一个上下文对象。
- 默认情况下，载荷的处理方法在主线程上被调用。


如果你需要执行一些资源密集型的计算，那么这项工作应该在网络线程上完成，而不是阻塞主线程。做法是在注册载荷之前，通过 `PayloadRegistrar#executesOn` 将 `PayloadRegistrar` 的 `HandlerThread` 设置为 `HandlerThread#NETWORK`。

```java
@SubscribeEvent // on the mod event bus
public static void register(final RegisterPayloadHandlersEvent event) {
    final PayloadRegistrar registrar = event.registrar("1")
        .executesOn(HandlerThread.NETWORK); // All subsequent payloads will register on the network thread
    registrar.playBidirectional(
        MyData.TYPE,
        MyData.STREAM_CODEC,
        new DirectionalPayloadHandler<>(
            ClientPayloadHandler::handleDataOnNetwork,
            ServerPayloadHandler::handleDataOnNetwork
        )
    );
}
```

> **注意**
>
> 在调用 `executesOn` 之后注册的所有载荷，都会保持相同的线程执行位置，直到再次调用 `executesOn`。
>
> ```java
> PayloadRegistrar registrar = event.registrar("1");
> 
> registrar.playBidirectional(...); // On the main thread
> registrar.playBidirectional(...); // On the main thread
> 
> // Configuration methods modify the state of the registrar
> // by creating a new instance, so the change needs to be
> /// updated by storing the result
> registrar = registrar.executesOn(HandlerThread.NETWORK);
> 
> registrar.playBidirectional(...); // On the network thread
> registrar.playBidirectional(...); // On the network thread
> 
> registrar = registrar.executesOn(HandlerThread.MAIN);
> 
> registrar.playBidirectional(...); // On the main thread
> registrar.playBidirectional(...); // On the main thread
> ```

这里有几点需要注意：

- 如果你想在主游戏线程上运行代码，可以使用 `enqueueWork` 向主线程提交任务。
    - 该方法会返回一个 `CompletableFuture`，它将在主线程上完成。
    - 注意：返回的是 `CompletableFuture`，这意味着你可以把多个任务串联起来，并在同一处处理异常。
    - 如果你没有在 `CompletableFuture` 中处理异常，那么该异常会被吞掉，**并且你不会收到任何通知**。

```java
public class ClientPayloadHandler {
    
    public static void handleDataOnNetwork(final MyData data, final IPayloadContext context) {
        // Do something with the data, on the network thread
        blah(data.name());
        
        // Do something with the data, on the main thread
        context.enqueueWork(() -> {
            blah(data.age());
        })
        .exceptionally(e -> {
            // Handle exception
            context.disconnect(Component.translatable("my_mod.networking.failed", e.getMessage()));
            return null;
        });
    }
}
```

有了自己的载荷之后，你就可以用它们通过[配置任务][configuration]来配置客户端与服务器。

## 发送载荷

`CustomPacketPayload` 通过原版的封包系统在网络中发送：发往服务器时用 `ServerboundCustomPayloadPacket` 包装载荷，发往客户端时用 `ClientboundCustomPayloadPacket` 包装载荷。发往客户端的载荷最多只能包含 1 MiB 数据，而发往服务器的载荷只能包含少于 32 KiB 的数据。

所有载荷都通过 `Connection#send` 以某种抽象层级发送；然而，如果你想根据给定条件向多个玩家发送封包，直接调用这些方法通常并不方便。因此 `PacketDistributor` 提供了若干便捷实现来发送载荷。向服务器发送封包只有一个方法（`sendToServer`）；但根据应当接收载荷的玩家不同，向客户端发送封包有多个方法。

```java
// ON THE CLIENT

// Send payload to server
PacketDistributor.sendToServer(new MyData(...));

// ON THE SERVER

// Send to one player (ServerPlayer serverPlayer)
PacketDistributor.sendToPlayer(serverPlayer, new MyData(...));

/// Send to all players tracking this chunk (ServerLevel serverLevel, ChunkPos chunkPos)
PacketDistributor.sendToPlayersTrackingChunk(serverLevel, chunkPos, new MyData(...));

/// Send to all connected players
PacketDistributor.sendToAllPlayers(new MyData(...));
```

更多实现请参见 `PacketDistributor` 类。
