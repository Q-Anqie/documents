# 模组文件

模组文件负责确定哪些模组被打包进你的 JAR、在“模组”菜单中显示哪些信息，以及你的模组应如何被游戏加载。

## `gradle.properties`

`gradle.properties` 文件保存你模组的各种通用属性，例如模组 id 或模组版本。在构建期间，Gradle 会读取这些文件中的值，并将其内联到各个位置，例如 [neoforge.mods.toml][neoforgemodstoml] 文件。这样一来，你只需在一处修改值，它就会自动应用到所有地方。

大多数值也在 [MDK 的 `gradle.properties` 文件][mdkgradleproperties]中作为注释加以说明。

### 模组 ID

模组 ID 是区分你的模组与其它模组的主要方式。它被用于大量位置，包括作为你模组[注册表][registration]的命名空间，以及作为你的[资源包与数据包][resource]命名空间。两个模组若拥有相同的 id，将导致游戏无法加载。

因此，你的模组 ID 应当是独特且易记的。通常它就是模组的显示名称（但为小写），或其中的某种变体。模组 ID 只能包含小写字母、数字和下划线，长度必须在 2 到 64 个字符之间（含两端）。

> **说明**
>
> 在 `gradle.properties` 文件中修改此属性会自动将变更应用到所有地方，但主模组类中的 [`@Mod` 注解][javafml]除外。在那里，你需要手动修改以匹配 `gradle.properties` 文件中的值。

### 组 ID

虽然 `build.gradle` 中的 `group` 属性仅在你计划将模组发布到 maven 时才需要，但始终正确设置它被认为是良好的做法。这一工作已通过 `gradle.properties` 的 `mod_group_id` 属性为你完成。

组 id 应设置为你最顶层的包。更多信息参见[包组织][packaging]。

```properties
# In your gradle.properties file
mod_group_id=com.example
```

你的 Java 源代码（`src/main/java`）中的包现在也应符合该结构，并带有一个表示模组 id 的内层包：

```text
com
- example (top-level package specified in group property)
    - mymod (the mod id)
        - MyMod.java (renamed ExampleMod.java)
```

## `neoforge.mods.toml`

`neoforge.mods.toml` 文件位于 `src/main/resources/META-INF/neoforge.mods.toml`，是一个 [TOML][toml] 格式的文件，用于定义你模组的元数据。它还包含关于你的模组应如何被加载进游戏的额外信息，以及在“模组”菜单中显示的展示信息。[MDK 提供的 `neoforge.mods.toml` 文件][mdkneoforgemodstoml]包含解释每个条目的注释，此处将更详细地说明。

`neoforge.mods.toml` 可分为三部分：与模组文件关联的非模组专属属性；模组属性，每个模组一个区段；以及依赖配置，每个模组或每组模组的依赖各一个区段。`neoforge.mods.toml` 文件相关的某些属性是强制性的；强制性属性要求必须指定值，否则会抛出异常。

> **注意**
>
> 在默认 MDK 中，Gradle 会将此文件中的各种属性替换为 `gradle.properties` 文件中指定的值。例如，行 `license="${mod_license}"` 表示 `license` 字段被替换为 `gradle.properties` 中的 `mod_license` 属性。像这样被替换的值应在 `gradle.properties` 中修改，而不是在此处修改。

#### 特性（Features）

特性系统允许模组要求在加载系统时必须具备某些设置、软件或硬件。当某个特性无法满足时，模组加载将失败，并向用户告知该要求。这些配置使用[表][table] `[features.<modid>]` 创建，其中 `modid` 是消费该特性的模组标识符。目前，NeoForge 提供以下特性：

| 特性          | 描述                                                                                                                                                                                                | 示例                             |
|------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------|
| `javaVersion`   | Java 版本的可接受版本范围，以 [Maven 版本范围][mvr] 表示。它应当是 Minecraft 所使用的受支持版本。                                                       | `javaVersion="[17,)"`  |
| `openGLVersion` | OpenGL 版本的可接受版本范围，以 [Maven 版本范围][mvr] 表示。Minecraft 要求 OpenGL 3.2 或更新版本。如果你希望要求更新的 OpenGL 版本，可以在此设置。  | `openGLVersion="[4.6,)"` |

#### 模组属性（Mod Properties）

模组属性系统是一个从任意键到值的映射，这些值关联到特定模组。当模组文件定义了相同键但提供不同元数据时，这会很有用。由此，可以通过 `IModInfo#getModProperties` 从映射中获取对象值，从而得到某个键的具体属性值。这些配置使用[表][table] `[modproperties.<modid>]` 创建，其中 `modid` 是消费所定义属性的模组标识符。

```java
// Assume we have two mods `mod1` and `mod2` with the following property configuration in separate files
// [modproperties.mod1]
// key="value1"
// [modproperties.mod2]
// key="value2"

@Mod("mod1")
public class ModOne {

    private final String key;

    public ModOne(ModContainer container) {
        // Will store 'value1' in key
        this.key = (String) container.getModInfo().getModProperties().get("key");
    }
}

@Mod("mod2")
public class ModTwo {

    private final String key;

    public ModTwo(ModContainer container) {
        // Will store 'value2' in key
        this.key = (String) container.getModInfo().getModProperties().get("key");
    }
}
```

### 依赖配置

模组可以声明其依赖，NeoForge 会在加载模组之前检查这些依赖。这些配置使用[表数组][array] `[[dependencies.<modid>]]` 创建，其中 `modid` 是消费该依赖的模组标识符。

| 属性       | 类型    | 默认值        | 描述                                                                                                                                                                                                                                                                                                                                                                                                                                                                | 示例                                      |
|----------------|---------|----------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|----------------------------------------------|
| `modId`        | string  | **mandatory**  | 作为依赖添加的模组标识符。                                                                                                                                                                                                                                                                                                                                                                                                                           | `modId="jei"`                                |
| `type`         | string  | `"required"`   | 指定该依赖的性质：`"required"` 是默认值，若该依赖缺失则阻止模组加载；`"optional"` 在依赖缺失时不会阻止模组加载，但仍会校验该依赖是否兼容；`"incompatible"` 在存在该依赖时阻止模组加载；`"discouraged"` 在存在该依赖时仍允许模组加载，但会向用户显示警告。 | `type="incompatible"`                        |
| `reason`       | string  | _nothing_      | 可选的面向用户的消息，用于说明为何需要该依赖，或为何它与本模组不兼容。                                                                                                                                                                                                                                                                                                                                                                    | `reason="integration"`                       |
| `versionRange` | string  | `"*"`          | 语言加载器可接受的版本范围，以 [Maven 版本范围][mvr] 表示。`"*"` 匹配任意版本。                                                                                                                                                                                                                                                                                                                                                 | `versionRange="[1, 2)"`                      |
| `ordering`     | string  | `"NONE"`       | 定义该模组必须在此依赖之前（`"BEFORE"`）还是之后（`"AFTER"`）加载。若顺序无关紧要，则返回 `"NONE"`                                                                                                                                                                                                                                                                                                                                    | `ordering="AFTER"`                           |
| `side`         | string  | `"BOTH"`       | 该依赖必须存在的[物理侧][sides]：`"CLIENT"`、`"SERVER"` 或 `"BOTH"`。                                                                                                                                                                                                                                                                                                                                                                         | `side="CLIENT"`                              |
| `referralUrl`  | string  | _nothing_      | 依赖下载页面的 URL。目前未使用。                                                                                                                                                                                                                                                                                                                                                                                                            | `referralUrl="https://library.example.com/"` |

> **危险**
>
> 两个模组的 `ordering` 可能因循环依赖而导致崩溃，例如模组 A 必须在模组 B 之前（`"BEFORE"`）加载，同时模组 B 又必须在模组 A 之前（`"BEFORE"`）加载。

## 模组入口点

现在 `neoforge.mods.toml` 已填写完毕，我们需要为模组提供入口点。入口点本质上是执行模组的起点。入口点本身由 `neoforge.mods.toml` 中使用的语言加载器决定。

### `javafml` 与 `@Mod`

`javafml` 是 NeoForge 为 Java 编程语言提供的语言加载器。入口点通过一个带有 `@Mod` 注解的 public 类来定义。`@Mod` 的值必须包含 `neoforge.mods.toml` 中指定的某个模组 id。由此，所有初始化逻辑（例如[注册事件][events]或[添加 `DeferredRegister`][registration]）都可以在该类的构造函数中指定。

主模组类只能有一个 public 构造函数；否则会抛出 `RuntimeException`。构造函数可以以**任意**顺序接受以下**任意**参数；它们都不是显式必需的。不过，不允许出现重复的参数。

| 参数类型     | 描述                                                                                              |
|------------------|----------------------------------------------------------------------------------------------------------|
| `IEventBus`       | [模组专属事件总线][modbus]（注册、事件等所需）                             |
`ModContainer`    | 持有此模组元数据的抽象容器                                                       |
`FMLModContainer` | 由 `javafml` 定义、持有此模组元数据的实际容器；是 `ModContainer` 的扩展 |
`Dist`            | 此模组加载所在的[物理侧][sides]                                                        |

```java
@Mod("examplemod") // Must match a mod id in the neoforge.mods.toml
public class ExampleMod {
    // Valid constructor, only uses two of the available argument types
    public ExampleMod(IEventBus modBus, ModContainer container) {
        // Initialize logic here
    }
}
```

默认情况下，`@Mod` 注解会在[两侧][sides]都加载。可以通过指定 `dist` 参数来改变这一点：

```java
// Must match a mod id in the neoforge.mods.toml
// This mod class will only be loaded on the physical client
@Mod(value = "examplemod", dist = Dist.CLIENT) 
public class ExampleModClient {
    // Valid constructor
    public ExampleModClient(FMLModContainer container, IEventBus modBus, Dist dist) {
        // Initialize client-only logic here
    }
}
```

>
> `neoforge.mods.toml` 中的条目并不需要对应的 `@Mod` 注解。同样，`neoforge.mods.toml` 中的一个条目也可以有多个 `@Mod` 注解，例如当你想要将通用逻辑与仅客户端逻辑分开时。

### `lowcodefml`

`lowcodefml` 是一种语言加载器，用于将数据包与资源包作为模组分发，而无需代码内的入口点。它被命名为 `lowcodefml` 而非 `nocodefml`，是为了未来可能加入需要极少编码的次要功能。
