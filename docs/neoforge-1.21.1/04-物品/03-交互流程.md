# 交互流程

本页旨在让"玩家右键点击"这一相当复杂且令人困惑的过程更易理解，并阐明在何处应使用何种结果、以及为什么。

## 右键点击时会发生什么？

当你在世界中的任何地方右键点击时，会发生一系列事情，具体取决于你当前正看着什么以及你手中有什么 `ItemStack`。系统会调用若干返回两种结果类型之一（见下文）的方法。这些方法大多在返回显式成功或显式失败时终止流程。为便于阅读，下文将这种"显式成功或显式失败"称为"确定性结果"。

- 以鼠标右键和主手触发 `InputEvent.InteractionKeyMappingTriggered`。如果事件被取消，流程结束。
- 会检查若干情形，例如你不在旁观者模式，或主手中 `ItemStack` 所需的所有功能开关均已启用。如果至少有一项检查失败，流程结束。
- 根据你正看着什么，会发生不同的事情：
    - 如果你正看着一个在你触及范围内且不在世界边界之外的实体：
        - 触发 `PlayerInteractEvent.EntityInteractSpecific`。如果事件被取消，流程结束。
        - **在你正看着的实体上**调用 `Entity#interactAt`。如果它返回确定性结果，流程结束。
            - 如果你想为自己的实体添加行为，请重写此方法。如果你想为原版实体添加行为，请使用事件。
        - 如果该实体打开了某个界面（例如村民交易界面或箱子矿车界面），流程结束。
        - 触发 `PlayerInteractEvent.EntityInteract`。如果事件被取消，流程结束。
        - **在你正看着的实体上**调用 `Entity#interact`。如果它返回确定性结果，流程结束。
            - 如果你想为自己的实体添加行为，请重写此方法。如果你想为原版实体添加行为，请使用事件。
            - 对于 `Mob`，`Entity#interact` 的重写会处理诸如拴绳，以及当主手中的 `ItemStack` 是刷怪蛋时生成幼年个体之类的事情，然后把特定于生物的处理交给 `Mob#mobInteract`。`Entity#interact` 的结果规则在这里同样适用。
        - 如果你正看着的实体是 `LivingEntity`，则对主手中的 `ItemStack` 调用 `Item#interactLivingEntity`。如果它返回确定性结果，流程结束。
    - 如果你正看着一个在你触及范围内且不在世界边界之外的方块：
        - 触发 `PlayerInteractEvent.RightClickBlock`。如果事件被取消，流程结束。你也可以在此事件中专门只拒绝方块使用或物品使用。
        - 调用 `IItemExtension#onItemUseFirst`。如果它返回确定性结果，流程结束。
        - 如果玩家没有潜行且事件未拒绝方块使用，则触发 `UseItemOnBlockEvent`。如果事件被取消，则使用取消结果。否则调用 `Block#useItemOn`。如果它返回确定性结果，流程结束。
        - 如果 `ItemInteractionResult` 为 `PASS_TO_DEFAULT_BLOCK_INTERACTION` 且执行的手是主手，则调用 `Block#useWithoutItem`。如果它返回确定性结果，流程结束。
        - 如果事件未拒绝物品使用，则调用 `Item#useOn`。如果它返回确定性结果，流程结束。
- 调用 `Item#use`。如果它返回确定性结果，流程结束。
- 上述过程会再执行一次，这次使用副手而非主手。

## 结果类型

共有三种不同的结果类型：`InteractionResult`、`ItemInteractionResult` 和 `InteractionResultHolder<T>`。大多数情况下使用 `InteractionResult`，只有 `Item#use` 使用 `InteractionResultHolder<ItemStack>`，只有 `BlockBehaviour#useItemOn` 和 `CauldronInteraction#interact` 使用 `ItemInteractionResult`。

`InteractionResult` 是一个包含五个值的枚举：`SUCCESS`、`CONSUME`、`CONSUME_PARTIAL`、`PASS` 和 `FAIL`。此外还提供了 `InteractionResult#sidedSuccess` 方法，它在服务端返回 `SUCCESS`，在客户端返回 `CONSUME`。

`InteractionResultHolder<T>` 是对 `InteractionResult` 的包装，为 `T` 添加了额外的上下文。`T` 可以是任何东西，但在 99.99% 的情况下它是 `ItemStack`。`InteractionResultHolder<T>` 为这些枚举值提供了包装方法（`#success`、`#consume`、`#pass` 和 `#fail`），以及 `#sidedSuccess`，后者在服务端调用 `#success`、在客户端调用 `#consume`。

`ItemInteractionResult` 是专用于"在方块上使用物品"场景的、与 `InteractionResult` 平行的类型。它是一个包含六个值的枚举：`SUCCESS`、`CONSUME`、`CONSUME_PARTIAL`、`PASS_TO_DEFAULT_BLOCK_INTERACTION`、`SKIP_DEFAULT_BLOCK_INTERACTION` 和 `FAIL`。每个 `ItemInteractionResult` 都可以通过 `#result` 映射为一个 `InteractionResult`；`PASS_TO_DEFAULT_BLOCK_INTERACTION`、`SKIP_DEFAULT_BLOCK_INTERACTION` 都表示 `InteractionResult#PASS`。类似地，`ItemInteractionResult` 也有 `#sidedSucess`。

一般来说，各个值的含义如下：

- 如果该操作应被视为成功，并且你希望手臂挥动，应使用 `InteractionResult#sidedSuccess`（或在需要处使用 `InteractionResultHolder#sidedSuccess` / `ItemInteractionResult#sidedSucess`）。流程将结束。
- 如果该操作应被视为成功，并且你希望手臂挥动，但只在一侧如此，应使用 `InteractionResult#SUCCESS`（或在需要处使用 `InteractionResultHolder#success` / `ItemInteractionResult#SUCCESS`）。只有当你出于某种原因想在另一逻辑侧返回不同的值时才使用它。流程将结束。
- 如果该操作应被视为成功，但你不希望手臂挥动，应使用 `InteractionResult#CONSUME`（或在需要处使用 `InteractionResultHolder#consume` / `ItemInteractionResult#CONSUME`）。流程将结束。
- `InteractionResult#CONSUME_PARTIAL` 与 `InteractionResult#CONSUME` 基本相同，唯一的区别在于它在 [`Item#useOn`][itemuseon] 中的用法。
    - `ItemInteractionResult#CONSUME_PARTIAL` 在 `BlockBehaviour#useItemOn` 中的用法与之类似。
- 如果物品功能应被视为失败且不应再执行后续交互，应使用 `InteractionResult.FAIL`（或在需要处使用 `InteractionResultHolder#fail` / `ItemInteractionResult#FAIL`）。流程将结束。它可以在任何地方使用，但在 `Item#useOn` 和 `Item#use` 之外应谨慎使用。许多情况下，使用 `InteractionResult.PASS` 更合理。
- 如果该操作应被视为既不成功也不失败，应使用 `InteractionResult.PASS`（或在需要处使用 `InteractionResultHolder#pass`）。流程将继续。这是默认行为（除非另有说明）。
    - `ItemInteractionResult#PASS_TO_DEFAULT_BLOCK_INTERACTION` 允许为主手调用 `BlockBehaviour#useWithoutItem`，而 `#SKIP_DEFAULT_BLOCK_INTERACTION` 则完全阻止该方法执行。`#PASS_TO_DEFAULT_BLOCK_INTERACTION` 是默认行为（除非另有说明）。

某些方法有特殊行为或要求，将在下面各章中说明。

## `IItemExtension#onItemUseFirst`

`InteractionResult#sidedSuccess` 和 `InteractionResult.CONSUME` 在这里没有效果。这里只应使用 `InteractionResult.SUCCESS`、`InteractionResult.FAIL` 或 `InteractionResult.PASS`。

## `Item#useOn`

如果你希望该操作被视为成功，但不希望手臂挥动，也不希望被授予 `ITEM_USED` 统计点，请使用 `InteractionResult.CONSUME_PARTIAL`。

## `Item#use`

这是唯一返回类型为 `InteractionResultHolder<ItemStack>` 的地方。如果 `InteractionResultHolder<ItemStack>` 中的结果 `ItemStack` 发生了变化，它会替换发起使用时的那个 `ItemStack`。

`Item#use` 的默认实现：当物品可食用且玩家能食用该物品时（因为他们饥饿，或因为该物品始终可食用）返回 `InteractionResultHolder#consume`；当物品可食用但玩家不能食用该物品时返回 `InteractionResultHolder#fail`；当物品不可食用时返回 `InteractionResultHolder#pass`。

在考虑主手时返回 `InteractionResultHolder#fail` 会阻止副手行为运行。如果你希望副手行为运行（通常你确实希望如此），请改为返回 `InteractionResultHolder#pass`。
