# 物品

> 相关 Minecraft Wiki：[物品](https://zh.minecraft.wiki/w/物品)

与方块一样，物品也是 Minecraft 的关键组成部分。方块构成了你周围的世界，而物品存在于物品栏中。

## 物品究竟是什么？

> 相关 Minecraft Wiki：[物品](https://zh.minecraft.wiki/w/物品)

在进一步深入物品的创建之前，理解物品实际上是什么、以及它与[方块][block]的区别很重要。让我们用一个例子来说明：

- 在世界中，你遇到一个泥土方块并想挖掘它。这是一个**方块**，因为它被放置在世界中。（实际上它不是方块，而是方块状态。详见[方块状态文章][blockstates]。）
    - 并非所有方块被破坏时都会掉落自身（例如树叶），更多信息见[战利品表][loottables]文章。
- 一旦你[挖掘了该方块][breaking]，它会被移除（= 被替换为空气方块），泥土随之掉落。掉落的泥土是一个物品**实体**。这意味着与其他实体（猪、僵尸、箭等）一样，它天生可以被水流推动，或被火与熔岩烧毁。
- 一旦你拾起泥土物品实体，它就会成为你物品栏中的一个**物品堆叠**（item stack）。简单来说，物品堆叠是物品的一个实例，并带有一些额外信息，例如堆叠数量。
- 物品堆叠由其对应的**物品**（也就是我们要创建的东西）支撑。物品持有[数据组件][datacomponents]，其中包含所有物品堆叠初始化时使用的默认信息（例如每把铁剑的最大耐久度都是 250），而物品堆叠可以修改这些数据组件，从而让同一物品的两个不同堆叠拥有不同的信息（例如一把铁剑还剩 100 次使用次数，而另一把还剩 200 次）。关于哪些事情通过物品完成、哪些通过物品堆叠完成，请继续阅读。
    - 物品与物品堆叠之间的关系大致相当于[方块][block]与[方块状态][blockstates]之间的关系：方块状态总是由一个方块支撑。这个类比并不完全准确（例如物品堆叠不是单例），但它能很好地说明这里的概念。

## 创建物品

> 相关 Minecraft Wiki：[物品](https://zh.minecraft.wiki/w/物品)

现在我们理解了物品是什么，那就来创建一个吧！

与基础方块类似，对于不需要特殊功能的基础物品（想想木棍、糖等），可以直接使用 `Item` 类。为此，在注册期间用 `Item.Properties` 参数实例化 `Item`。这个 `Item.Properties` 参数可以通过 `Item.Properties#of` 创建，并可以通过调用其方法来自定义：

- `stacksTo` —— 设置该物品的最大堆叠数量（通过 `DataComponents#MAX_STACK_SIZE`）。默认值为 64。例如末影珍珠或其他只能堆叠到 16 的物品会使用它。
- `durability` —— 设置该物品的耐久度（通过 `DataComponents#MAX_DAMAGE`），并将初始伤害设为 0（通过 `DataComponents#DAMAGE`）。默认值为 0，表示"无耐久度"。例如铁质工具在这里使用 250。注意，设置耐久度会自动将最大堆叠数量锁定为 1。
- `craftRemainder` —— 设置该物品的合成剩余物。原版将其用于合成后留下空桶的装满的桶。
- `fireResistant` —— 使使用该物品的物品实体免疫火焰与熔岩（通过 `DataComponents#FIRE_RESISTANT`）。各种下界合金物品使用了它。
- `setNoRepair` —— 禁用该物品的铁砧与合成格修复。原版未使用。
- `rarity` —— 设置该物品的稀有度（通过 `DataComponents#RARITY`）。目前这只会改变物品的颜色。`Rarity` 是一个枚举，包含四个值：`COMMON`（白色，默认）、`UNCOMMON`（黄色）、`RARE`（青色）和 `EPIC`（淡紫色）。请注意，模组可能会添加更多稀有度类型。
- `requiredFeatures` —— 设置该物品所需的功能开关。这主要用于原版在次要版本中的功能锁定系统。除非你要与由原版通过功能开关锁定的系统集成，否则不推荐使用。
- `food` —— 设置该物品的 [`FoodProperties`][food]（通过 `DataComponents#FOOD`）。

关于示例，或想查看 Minecraft 使用的各种值，可以看看 `Items` 类。

### 食物

> 相关 Minecraft Wiki：[食物](https://zh.minecraft.wiki/w/食物)

`Item` 类为食物物品提供了默认功能，这意味着你不需要为此单独写一个类。要让你的物品可食用，你只需通过 `Item.Properties` 中的 `food` 方法为其设置 `FoodProperties`。

`FoodProperties` 通过 `FoodProperties.Builder` 创建。然后你可以在其上设置各种属性：

- `nutrition` —— 设置恢复多少饥饿点数。以半个饥饿点为单位计数，因此例如 Minecraft 的牛排恢复 8 个饥饿点。
- `saturationMod` —— 计算食用该食物时恢复的[饱和度值][hunger]所用的饱和度修正系数。计算方式为 `min(2 * nutrition * saturationMod, playerNutrition)`，这意味着使用 `0.5` 会让有效饱和度值等于营养值。
- `alwaysEdible` —— 该物品是否始终可食用，即使饥饿条已满。默认为 `false`，金苹果以及其他除了填饱饥饿条之外还提供增益的物品为 `true`。
- `fast` —— 是否为该食物启用快速进食。默认为 `false`，原版中的干海带为 `true`。
- `effect` —— 添加一个在食用该物品时施加的 [`MobEffectInstance`][mobeffectinstance]。第二个参数表示施加该效果的概率；例如腐肉被食用时有 80%（= 0.8）的概率施加饥饿效果。该方法有两个变体；你应使用接受 supplier 的那个（另一个直接接受状态效果实例，由于类加载问题已被 NeoForge 弃用）。
- `usingConvertsTo` —— 设置该物品被使用后会变成的物品。
- `build` —— 一旦设置好所有你想设置的内容，调用 `build` 以获得一个可供进一步使用的 `FoodProperties` 对象。

关于示例，或想查看 Minecraft 使用的各种值，可以看看 `Foods` 类。

要获取某个物品的 `FoodProperties`，调用 `Item#getFoodProperties(ItemStack, LivingEntity)`。这可能返回 null，因为并非每个物品都可食用。要判断某个物品是否可食用，请对 `getFoodProperties` 调用的结果做 null 检查。

### 更多功能

直接使用 `Item` 只能实现非常基础的物品。如果你想添加功能，例如右键交互，就需要一个继承 `Item` 的自定义类。`Item` 类有许多可以重写以实现不同功能的方法；更多信息见 `Item` 和 `IItemExtension` 类。

物品最常见的两个用例是左键点击和右键点击。关于左键点击，见[破坏方块][breaking]与攻击实体（待完成）。关于右键点击，见[交互流程][interactionpipeline]。

### `DeferredRegister.Items`

所有注册表都使用 `DeferredRegister` 来注册其内容，物品也不例外。然而，由于添加新物品是绝大多数模组的基本功能，NeoForge 提供了 `DeferredRegister.Items` 辅助类，它继承 `DeferredRegister<Item>` 并提供了一些物品专用的辅助方法：

```java
public static final DeferredRegister.Items ITEMS = DeferredRegister.createItems(ExampleMod.MOD_ID);

public static final Supplier<Item> EXAMPLE_ITEM = ITEMS.registerItem(
    "example_item",
    Item::new, // The factory that the properties will be passed into.
    new Item.Properties() // The properties to use.
);
```

在内部，它会将 properties 参数应用到提供的物品工厂（通常是构造函数）上，从而简单地调用 `ITEMS.register("example_item", () -> new Item(new Item.Properties()))`。

如果你想使用 `Item::new`，可以完全省略工厂，改用 `simple` 方法变体：

```java
public static final Supplier<Item> EXAMPLE_ITEM = ITEMS.registerSimpleItem(
    "example_item",
    new Item.Properties() // The properties to use.
);
```

这与上一个示例完全相同，只是稍短一些。当然，如果你想使用 `Item` 的子类而不是 `Item` 本身，就必须改用前一种方法。

这两个方法也都有省略 `new Item.Properties()` 参数的重载：

```java
public static final Supplier<Item> EXAMPLE_ITEM = ITEMS.registerItem("example_item", Item::new);
// Variant that also omits the Item::new parameter
public static final Supplier<Item> EXAMPLE_ITEM = ITEMS.registerSimpleItem("example_item");
```

最后，还有针对方块物品的快捷方式：

```java
public static final Supplier<BlockItem> EXAMPLE_BLOCK_ITEM = ITEMS.registerSimpleBlockItem(
    "example_block",
    ExampleBlocksClass.EXAMPLE_BLOCK, new Item.Properties()
);
// Variant that omits the properties parameter:
public static final Supplier<BlockItem> EXAMPLE_BLOCK_ITEM = ITEMS.registerSimpleBlockItem(
    "example_block",
    ExampleBlocksClass.EXAMPLE_BLOCK
);
// Variant that omits the name parameter, instead using the block's registry name:
public static final Supplier<BlockItem> EXAMPLE_BLOCK_ITEM = ITEMS.registerSimpleBlockItem(
    ExampleBlocksClass.EXAMPLE_BLOCK,
    new Item.Properties()
);
// Variant that omits both the name and the properties:
public static final Supplier<BlockItem> EXAMPLE_BLOCK_ITEM = ITEMS.registerSimpleBlockItem(
    ExampleBlocksClass.EXAMPLE_BLOCK
);
```

> **注意**
> 如果你把注册的方块放在单独的类中，你应在物品类之前加载（classload）你的方块类。

### 资源

如果你注册了物品并获得了它（通过 `/give` 或通过[创造模式标签页][creativetabs]），你会发现它缺少合适的模型和纹理。这是因为纹理和模型由 Minecraft 的资源系统处理。

对于每个物品，你都会想要为以下内容添加——或[生成][datagen]——JSON 文件：

- 一个带有相应[纹理][texture]的[物品模型][model]
- 一个[翻译][i18n]
- 一个[配方][recipes]（可选）
- 一些物品[标签][tags]（可选）

对于上述所有内容，也请参考相似的原版方块的文件和数据生成器。

## `ItemStack`

与方块和方块状态一样，大多数你期望使用 `Item` 的地方实际上使用的是 `ItemStack`。`ItemStack` 表示容器（例如物品栏）中一个或多个物品组成的堆叠。同样与方块和方块状态类似，方法应由 `Item` 重写并在 `ItemStack` 上调用，`Item` 中的许多方法也会接收一个 `ItemStack` 实例作为参数。

一个 `ItemStack` 由三个主要部分组成：

- 它所表示的 `Item`，可通过 `ItemStack#getItem` 获取。
- 堆叠数量，通常在 1 到 64 之间，可通过 `getCount` 获取，并可通过 `setCount` 或 `shrink` 修改。
- [数据组件][datacomponents]映射，存储特定于堆叠的数据。可通过 `getComponents` 获取。组件值通常通过 `has`、`get`、`set`、`update` 和 `remove` 来访问和修改。

要创建新的 `ItemStack`，调用 `new ItemStack(Item)` 并传入支撑它的物品。默认情况下，它使用数量 1 且没有 NBT 数据；如果需要，也有接受数量和 NBT 数据的构造函数重载。

`ItemStack` 是可变对象（见下文），但有时需要将它们视为不可变对象。如果你需要修改一个将被视为不可变的 `ItemStack`，可以使用 `#copy` 克隆该堆叠，或者如果应使用特定的堆叠数量，则使用 `#copyWithCount`。

如果你想表示某个堆叠没有物品，请使用 `ItemStack.EMPTY`。如果你想检查某个 `ItemStack` 是否为空，请调用 `#isEmpty`。

### `ItemStack` 的可变性

`ItemStack` 是可变对象。这意味着如果你调用例如 `#setCount` 或任何数据组件映射方法，`ItemStack` 本身会被修改。原版大量利用了 `ItemStack` 的可变性，多个方法也依赖于此。例如，`#split` 会从被调用的堆叠中分离出指定数量，在此过程中既修改调用者又返回一个新的 `ItemStack`。

然而，在同时处理多个 `ItemStack` 时，这有时会导致问题。最常见的情形是处理物品栏槽位，因为你必须同时考虑光标当前选中的 `ItemStack`，以及你试图插入/取出所用的 `ItemStack`。

> **提示**
> 有疑问时，宁可稳妥一些，对堆叠执行 `#copy`。

### JSON 表示

在许多情况下，例如[配方][recipes]中，物品堆叠需要表示为 JSON 对象。物品堆叠的 JSON 表示如下所示：

```json5
{
    // The item ID. Required.
    "id": "minecraft:dirt",
    // The item stack count. Optional, defaults to 1.
    "count": 4,
    // A map of data components. Optional, defaults to an empty map.
    "components": {
        "minecraft:enchantment_glint_override": true
    }
}
```

## 创造模式标签页

> 相关 Minecraft Wiki：[创造模式物品栏](https://zh.minecraft.wiki/w/创造模式物品栏)

默认情况下，你的物品只能通过 `/give` 获得，而不会出现在创造模式物品栏中。让我们改变这一点！

把物品放进创造模式菜单的方式取决于你想把它加到哪个标签页。

### 已有的创造模式标签页

> **注意**
> 此方法用于把你的物品添加到 Minecraft 的标签页，或其他模组的标签页。要把物品添加到自己的标签页，见下文。

可以通过 `BuildCreativeModeTabContentsEvent` 将物品添加到已有的 `CreativeModeTab`，该事件在[模组事件总线][modbus]上触发，且仅在[逻辑客户端][sides]触发。通过调用 `event#accept` 来添加物品。

```java
//MyItemsClass.MY_ITEM is a Supplier<? extends Item>, MyBlocksClass.MY_BLOCK is a Supplier<? extends Block>
@SubscribeEvent // on the mod event bus
public static void buildContents(BuildCreativeModeTabContentsEvent event) {
    // Is this the tab we want to add to?
    if (event.getTabKey() == CreativeModeTabs.INGREDIENTS) {
        event.accept(MyItemsClass.MY_ITEM.get());
        // Accepts an ItemLike. This assumes that MY_BLOCK has a corresponding item.
        event.accept(MyBlocksClass.MY_BLOCK.get());
    }
}
```

该事件还提供了一些额外信息，例如 `getFlags` 用于获取已启用的功能开关列表，或 `hasPermissions` 用于检查玩家是否有权限查看管理员物品标签页。

### 自定义创造模式标签页

`CreativeModeTab` 是一个注册表，这意味着自定义的 `CreativeModeTab` 必须被[注册][registering]。创建创造模式标签页使用构建器系统，构建器可通过 `CreativeModeTab#builder` 获取。构建器提供了设置标题、图标、默认物品以及其他若干属性的选项。此外，NeoForge 还提供了额外方法来自定义标签页的图像、标签与槽位颜色，以及标签页应排在何处等。

```java
//CREATIVE_MODE_TABS is a DeferredRegister<CreativeModeTab>
public static final Supplier<CreativeModeTab> EXAMPLE_TAB = CREATIVE_MODE_TABS.register("example", () -> CreativeModeTab.builder()
    //Set the title of the tab. Don't forget to add a translation!
    .title(Component.translatable("itemGroup." + MOD_ID + ".example"))
    //Set the icon of the tab.
    .icon(() -> new ItemStack(MyItemsClass.EXAMPLE_ITEM.get()))
    //Add your items to the tab.
    .displayItems((params, output) -> {
        output.accept(MyItemsClass.MY_ITEM.get());
        // Accepts an ItemLike. This assumes that MY_BLOCK has a corresponding item.
        output.accept(MyBlocksClass.MY_BLOCK.get());
    })
    .build()
);
```

## `ItemLike`

`ItemLike` 是一个接口，在原版中由 `Item` 和 [`Block`][block] 实现。它定义了方法 `#asItem`，用于返回该对象实际对应的物品表示：`Item` 只返回自身，而 `Block` 若存在关联的 `BlockItem` 则返回它，否则返回 `Blocks.AIR`。`ItemLike` 被用于各种不关心物品"来源"的场景，例如许多[数据生成器][datagen]中。

你也可以在自己的自定义对象上实现 `ItemLike`。只需重写 `#asItem` 即可。
