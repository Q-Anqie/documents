# 侧

像许多其他程序一样，Minecraft 遵循客户端-服务端概念：客户端负责显示数据，服务端负责更新数据。使用这些术语时，我们对它们的含义有相当直观的理解……对吧？

事实证明，并非如此。许多混乱源于 Minecraft 根据上下文对"侧"有两种不同概念：物理侧和逻辑侧。

## 逻辑侧与物理侧

### 物理侧

当你打开 Minecraft 启动器、选择一个 Minecraft 安装并按下开始游戏时，你启动的是一个**物理客户端**。这里的"物理"是在"这是一个客户端程序"的意义上使用的。这尤其意味着客户端侧的功能（例如所有渲染相关的东西）在此可用，可以按需使用。相对地，**物理服务端**（也称为专用服务器）是在启动 Minecraft 服务器 JAR 时打开的东西。虽然 Minecraft 服务端带有简陋的 GUI，但它缺少所有仅客户端的功能。最值得注意的是，这意味着服务器 JAR 中缺少各种客户端类。在物理服务端上调用这些类会导致类缺失错误，即崩溃，因此我们需要对此加以防护。

### 逻辑侧

逻辑侧主要关注 Minecraft 的内部程序结构。**逻辑服务端**是游戏逻辑运行的地方。时间与天气变化、实体 tick、实体生成等都在服务端上运行。各类数据（例如物品栏内容）也由服务端负责。另一方面，**逻辑客户端**负责显示所有需要显示的内容。Minecraft 把所有客户端代码放在独立的 `net.minecraft.client` 包中，并在一个称为渲染线程（Render Thread）的单独线程中运行，而其他一切都视为通用（即客户端与服务端共用）代码。

### 区别何在？

物理侧与逻辑侧的区别最好用两个场景来说明：

- 玩家加入**多人**世界。这相当直接：玩家的物理（也是逻辑）客户端连接到位于别处的物理（也是逻辑）服务端——玩家并不关心它在哪里；只要能连上，这就是客户端所知的一切，也是客户端需要知道的一切。
- 玩家加入**单人**世界。这里就有意思了。玩家的物理客户端启动一个逻辑服务端，然后以逻辑客户端的身份连接到同一台机器上的那个逻辑服务端。如果你熟悉网络，可以把它想象成连接到 `localhost`（仅是概念上的；并不涉及实际的套接字之类）。

这两个场景也揭示了主要问题：如果一个逻辑服务端能与你的代码配合工作，单凭这一点并不能保证物理服务端也能。这就是为什么你应当始终用专用服务器进行测试，以检查意外行为。因客户端与服务端分离不当而导致的 `NoClassDefFoundError` 和 `ClassNotFoundException` 是模组开发中最常见的错误之一。另一个常见错误是使用静态字段并从两个逻辑侧访问它们；这尤其棘手，因为通常没有任何迹象表明出了问题。

> **提示**
> 如果你需要把数据从一侧传输到另一侧，必须[发送数据包][networking]。

在 NeoForge 代码库中，物理侧由名为 `Dist` 的枚举表示，逻辑侧由名为 `LogicalSide` 的枚举表示。

> **说明**
> 历史上，服务器 JAR 曾拥有客户端没有的类。在现代版本中已不再如此；可以说物理服务端是物理客户端的子集。

## 执行分侧操作

### `Level#isClientSide()`

这个布尔检查将是你最常用的判断侧的方式。在 `Level` 对象上查询该字段可以确定该 level 所属的**逻辑**侧：如果该字段为 `true`，则 level 运行在逻辑客户端上；如果为 `false`，则 level 运行在逻辑服务端上。由此可知，物理服务端中该字段始终为 `false`，但不能假定 `false` 就意味着物理服务端，因为对于物理客户端内部的逻辑服务端（即单人世界），该字段也可能为 `false`。

当你需要判断游戏逻辑和其他机制是否应当运行时，就使用这个检查。例如，如果你想在玩家每次点击你的方块时对其造成伤害，或让你的机器把泥土加工成钻石，就应仅在确认 `#isClientSide` 为 `false` 之后才执行。把游戏逻辑应用到逻辑客户端，最好的情况是导致不同步（幽灵实体、属性不同步等），最坏的情况是崩溃。

> **提示**
> 这个检查应当作为你的首选默认方案。只要手头有 `Level`，就用这个检查。

### `FMLEnvironment.dist`

`FMLEnvironment.dist` 是 `Level#isClientSide()` 检查的**物理**侧对应物。如果该字段为 `Dist.CLIENT`，你处于物理客户端。如果该字段为 `Dist.DEDICATED_SERVER`，你处于物理服务端。

#### `@Mod`

在处理仅客户端类时，检查物理环境很重要。分离只应在一个物理客户端上执行的代码，推荐做法是指定一个单独的 [`@Mod` 注解][mod]，把 `dist` 参数设为该模组类应被加载到的物理侧：

```java
@Mod("examplemod")
public class ExampleMod {
    public ExampleMod(IEventBus modBus) {
        // Perform logic in that should be executed on both sides
    }
}

@Mod(value = "examplemod", dist = Dist.CLIENT) 
public class ExampleModClient {
    public ExampleModClient(IEventBus modBus) {
        // Perform logic in that should only be executed on the physical client
        Minecraft.getInstance().whatever();
    }
}

@Mod(value = "examplemod", dist = Dist.DEDICATED_SERVER) 
public class ExampleModDedicatedServer {
    public ExampleModDedicatedServer(IEventBus modBus) {
        // Perform logic in that should only be executed on the physical server
    }
}
```

> **提示**
> 模组通常被期望在任一侧都能工作。这尤其意味着，如果你开发的是仅客户端模组，应当验证该模组确实能在物理客户端上运行，并在不能运行时不做任何操作（no-op）。
