# 事件

NeoForge 的主要特性之一是事件系统。游戏中所发生的各种事情都会触发事件。例如，玩家右键点击、玩家或其他实体跳跃、方块被渲染、游戏被加载等都有对应的事件。模组作者可以把事件处理器订阅到这些事件上，然后在事件处理器中执行所需的行为。

事件在其各自的事件总线上触发。最重要的总线是 `NeoForge.EVENT_BUS`，也称为**游戏**总线。除此之外，在启动期间，每个被加载的模组都会生成一个模组总线，并传入该模组的构造函数。许多模组总线事件是并行触发的（与始终在同一线程上运行的主总线事件相对），这大幅提升了启动速度。更多信息见[下文][modbus]。

## 注册事件处理器

注册事件处理器有多种方式。所有这些方式的共同点是：每个事件处理器都是一个带有单个事件参数、且没有返回值（即返回类型为 `void`）的方法。

### `IEventBus#addListener`

注册方法处理器最简单的方式是注册其方法引用，如下所示：

```java
@Mod("yourmodid")
public class YourMod {
    public YourMod(IEventBus modBus) {
        NeoForge.EVENT_BUS.addListener(YourMod::onLivingJump);
    }

    // Heals an entity by half a heart every time they jump.
    private static void onLivingJump(LivingJumpEvent event) {
        Entity entity = event.getEntity();
        // Only heal on the server side
        if (!entity.level().isClientSide()) {
            entity.heal(1);
        }
    }
}
```

### `@SubscribeEvent`

另一种方式是通过注解驱动：创建一个事件处理器方法，并用 `@SubscribeEvent` 标注它。然后，你可以把包含该方法的类的实例传给事件总线，从而注册该实例上所有带 `@SubscribeEvent` 注解的事件处理器：

```java
public class EventHandler {
    @SubscribeEvent
    public void onLivingJump(LivingJumpEvent event) {
        Entity entity = event.getEntity();
        if (!entity.level().isClientSide()) {
            entity.heal(1);
        }
    }
}

@Mod("yourmodid")
public class YourMod {
    public YourMod(IEventBus modBus) {
        NeoForge.EVENT_BUS.register(new EventHandler());
    }
}
```

也可以静态地这样做。只需把所有事件处理器都设为静态，并传入类本身而非类实例：

```java
public class EventHandler {
	@SubscribeEvent
    public static void onLivingJump(LivingJumpEvent event) {
        Entity entity = event.getEntity();
        if (!entity.level().isClientSide()) {
            entity.heal(1);
        }
    }
}

@Mod("yourmodid")
public class YourMod {
    public YourMod(IEventBus modBus) {
        NeoForge.EVENT_BUS.register(EventHandler.class);
    }
}
```

### `@EventBusSubscriber`

**Latest**

我们可以更进一步，用 `@EventBusSubscriber` 标注事件处理器类。该注解会被 NeoForge 自动发现，因此你可以从模组构造函数中删除所有与事件相关的代码。本质上，它等价于在模组构造函数末尾调用 `NeoForge.EVENT_BUS.register(EventHandler.class)` 与 `modBus.register(EventHandler.class)`。这也意味着所有处理器都必须是静态的。

**[21.1.0,21.1.180]**

我们可以更进一步，用 `@EventBusSubscriber` 标注事件处理器类。该注解会被 NeoForge 自动发现，因此你可以从模组构造函数中删除所有与事件相关的代码。本质上，它等价于在模组构造函数末尾调用 `NeoForge.EVENT_BUS.register(EventHandler.class)`。这也意味着所有处理器都必须是静态的。

虽然不是必需的，但强烈建议在注解中指定 `modid` 参数，以便于调试（尤其是在处理模组冲突时）。

```java
@EventBusSubscriber(modid = "yourmodid")
public class EventHandler {
    @SubscribeEvent
    public static void onLivingJump(LivingJumpEvent event) {
        Entity entity = event.getEntity();
        if (!entity.level().isClientSide()) {
            entity.heal(1);
        }
    }
}
```

## 事件选项

### 字段与方法

字段与方法大概是事件中最显而易见的部分。大多数事件都包含供事件处理器使用的上下文，例如引发事件的实体，或事件发生的 `Level`。

### 继承层次

为了利用继承的优势，有些事件不直接继承 `Event`，而是继承它的某个子类，例如 `BlockEvent`（包含与方块相关事件的方块上下文）或 `EntityEvent`（同样包含实体上下文）及其子类 `LivingEvent`（针对 `LivingEntity` 的上下文）和 `PlayerEvent`（针对 `Player` 的上下文）。这些提供上下文的父事件是 `abstract` 的，无法被监听。

> **危险**
> 如果你监听一个 `abstract` 事件，游戏会崩溃，因为这绝不是你想要的结果。你应当始终监听其子事件之一。

### 可取消事件

有些事件实现了 `ICancellableEvent` 接口。这些事件可以用 `#setCanceled(boolean canceled)` 取消，取消状态可以用 `#isCanceled()` 检查。如果事件被取消，该事件的其他事件处理器将不会运行，并且与"取消"相关的某种行为会被启用。例如，取消 `LivingJumpEvent` 会阻止跳跃。

事件处理器可以选择显式接收已取消的事件。这通过把 `IEventBus#addListener`（或 `@SubscribeEvent`，取决于你挂载事件处理器的方式）中的 `receiveCanceled` 布尔参数设为 true 来实现。

### TriState 与 Result

有些事件有三种可能的返回状态，由 `TriState` 表示，或由事件类上直接定义的 `Result` 枚举表示。返回状态通常可以取消事件所处理的行为（`TriState#FALSE`）、强制该行为执行（`TriState#TRUE`），或执行原版默认行为（`TriState#DEFAULT`）。

具有三种可能返回状态的事件会有一些 `set*` 方法来设置所需的结果。

```java
// In some event handler class

@SubscribeEvent // on the game event bus
public static void renderNameTag(RenderNameTagEvent event) {
    // Uses TriState to set the return state
    event.setCanRender(TriState.FALSE);
}

@SubscribeEvent // on the game event bus
public static void mobDespawn(MobDespawnEvent event) {
    // Uses a Result enum to set the return state
    event.setResult(MobDespawnEvent.Result.DENY);
}
```

### 优先级

事件处理器可以选择性地被分配优先级。`EventPriority` 枚举包含五个值：`HIGHEST`、`HIGH`、`NORMAL`（默认）、`LOW` 和 `LOWEST`。事件处理器按优先级从高到低执行。若优先级相同，在主总线上它们按注册顺序触发（这大致与模组加载顺序相关），在模组总线上则严格按模组加载顺序触发（见下文）。

优先级可以通过在 `IEventBus#addListener` 或 `@SubscribeEvent` 中设置 `priority` 参数来定义，取决于你挂载事件处理器的方式。注意，对于并行触发的事件，优先级会被忽略。

### 分侧事件

有些事件只在某一[侧][side]触发。常见的例子是各种渲染事件，它们只在客户端触发。由于仅客户端的事件通常需要访问 Minecraft 代码库中其他仅客户端的部分，它们必须相应地注册。

使用 `IEventBus#addListener()` 的事件处理器应通过 `FMLEnvironment.dist` 或你在模组构造函数中获取的 `Dist` 参数检查当前物理侧，并在单独的仅客户端类中添加监听器，如[侧][side]一文中所述。

使用 `@EventBusSubscriber` 的事件处理器可以把侧指定为注解的 `value` 参数，例如 `@EventBusSubscriber(value = Dist.CLIENT, modid = "yourmodid")`。

## 事件总线

虽然大多数事件都发布在 `NeoForge.EVENT_BUS` 上，但有些事件改为发布在模组事件总线上。这些通常被称为模组总线事件。模组总线事件可以通过其父接口 `IModBusEvent` 与常规事件区分。

**Latest**

模组事件总线作为参数传入模组构造函数，你随后可以向它订阅模组总线事件。如果你使用 `@EventBusSubscriber`，事件会自动订阅到正确的总线。

**[21.1.0,21.1.180]**

模组事件总线作为参数传入模组构造函数，你随后可以向它订阅模组总线事件。如果你使用 `@EventBusSubscriber`，也可以把总线设为注解参数，像这样：`@EventBusSubscriber(bus = Bus.MOD, modid = "yourmodid")`。默认总线是 `Bus.GAME`。

### 模组生命周期

大多数模组总线事件就是所谓的生命周期事件。生命周期事件在启动期间每个模组的生命周期中运行一次。其中许多通过继承 `ParallelDispatchEvent` 而并行触发；如果你想在这些事件之一中于主线程上运行代码，请使用 `#enqueueWork(Runnable runnable)` 将它们加入队列。

生命周期通常遵循以下顺序：

- 调用模组构造函数。在这里或下一步中注册你的事件处理器。
- 所有 `@EventBusSubscriber` 被调用。
- 触发 `FMLConstructModEvent`。
- 触发注册表事件，包括 [`NewRegistryEvent`][newregistry]、[`DataPackRegistryEvent.NewRegistry`][newdatapackregistry]，以及针对每个注册表的 [`RegisterEvent`][registerevent]。
- 触发 `FMLCommonSetupEvent`。各种杂项设置在这里进行。
- 触发[分侧][side]设置：如果处于物理客户端则为 `FMLClientSetupEvent`，如果处于物理服务端则为 `FMLDedicatedServerSetupEvent`。
- 处理 `InterModComms`（见下文）。
- 触发 `FMLLoadCompleteEvent`。

#### `InterModComms`

`InterModComms` 是一个允许模组作者向其他模组发送消息以实现兼容性功能的系统。该类保存发往各模组的消息，所有方法都是线程安全可调用的。该系统主要由两个事件驱动：`InterModEnqueueEvent` 和 `InterModProcessEvent`。

在 `InterModEnqueueEvent` 期间，你可以使用 `InterModComms#sendTo` 向其他模组发送消息。这些方法接受要发送消息的目标模组 id、与消息数据关联的键（用于区分不同消息），以及持有消息数据的 `Supplier`。发送者也可以选择性地指定。

随后，在 `InterModProcessEvent` 期间，你可以使用 `InterModComms#getMessages` 获取所有已接收消息的流，形式为 `IMCMessage` 对象。这些对象持有数据的发送者、数据的预期接收者、数据键，以及实际数据的 supplier。

### 其它模组总线事件

除生命周期事件外，还有少数杂项事件在模组事件总线上触发，主要是出于历史原因。这些通常是你注册、设置或初始化各种内容的事件。与生命周期事件不同，这些事件大多不并行运行。几个例子：

- `RegisterColorHandlersEvent`
- `ModelEvent.BakingCompleted`
- `TextureAtlasStitchedEvent`

> **警告**
> 这些事件大多计划在未来的版本中迁移到主事件总线。
