# 界面

> 相关 Minecraft Wiki：[物品栏](https://zh.minecraft.wiki/w/物品栏)

界面（Screen）通常是 Minecraft 中所有图形用户界面（GUI）的基础：接收用户输入，在服务端验证，并将结果操作同步回客户端。它们可以与[菜单]结合，构建类似物品栏视图的通信网络，也可以是独立的，模组开发者可以通过自己的[网络]实现来处理。

界面由众多部分组成，因此很难完整理解 Minecraft 中的"界面"究竟是什么。所以，本文档会先逐一介绍界面的各个组成部分及其应用方式，然后再讨论界面本身。

## 相对坐标

无论渲染什么，都需要有某种标识符来指定它将出现的位置。在众多抽象之下，Minecraft 的大多数渲染调用都在一个坐标平面中接收 x、y 和 z 值。X 值从左到右递增，y 从上到下递增，z 从远到近递增。然而，坐标并不固定于某个指定范围。它们的范围会随屏幕大小以及游戏选项中指定的"GUI 缩放"而变化。因此必须格外小心，确保传给渲染调用的坐标值能正确缩放——即正确地相对化——以适应可变的屏幕尺寸。

关于如何相对化坐标的信息见[界面](#the-screen-subtype)一节。

> **警告**
>
> 如果你选择使用固定坐标或错误地缩放屏幕，渲染的对象可能看起来很奇怪或位置错乱。检查坐标是否相对化正确的一个简单方法是点击视频设置中的"GUI 缩放"按钮。该值在确定 GUI 应渲染的缩放比例时，会作为显示器宽度和高度的除数。

## GUI 图形

Minecraft 渲染的任何 GUI 通常都使用 `GuiGraphics` 完成。`GuiGraphics` 是几乎所有渲染方法的第一个参数；它包含渲染常用对象的基本方法。这些方法分为五类：彩色矩形、字符串、纹理、物品和工具提示。此外还有一个用于渲染组件片段的额外方法（`#enableScissor` / `#disableScissor`）。`GuiGraphics` 还暴露了 `PoseStack`，用于应用正确渲染组件位置所需的变换。另外，颜色采用 [ARGB][argb] 格式。

### 彩色矩形

彩色矩形通过位置颜色着色器（position color shader）绘制。所有填充方法都可以接收一个可选的 `RenderType`，以指定矩形应如何渲染。可以绘制三种类型的彩色矩形。

第一类是彩色水平与垂直单像素宽线条，分别为 `#hLine` 和 `#vLine`。`#hLine` 接收定义左右端（含）的两个 x 坐标、顶部 y 坐标以及颜色。`#vLine` 接收左侧 x 坐标、定义上下端（含）的两个 y 坐标以及颜色。

第二类是 `#fill` 方法，它向屏幕绘制一个矩形。线条方法内部会调用该方法。它接收左侧 x 坐标、顶部 y 坐标、右侧 x 坐标、底部 y 坐标以及颜色。`#fillRenderType` 作用相同；不过它绘制顶点时不校正坐标位置。

最后是 `#fillGradient` 方法，它绘制带有垂直渐变的矩形。它接收右侧 x 坐标、底部 y 坐标、左侧 x 坐标、顶部 y 坐标、z 坐标以及底部和顶部颜色。

### 字符串

字符串通过其 `Font` 绘制，通常由用于普通、透视和偏移模式的各自着色器组成。可以渲染两种对齐方式的字符串，各自带有背景阴影：左对齐字符串（`#drawString`）和居中对齐字符串（`#drawCenteredString`）。两者都接收用于渲染字符串的字体、要绘制的字符串、分别表示字符串左侧或中心的 x 坐标、顶部 y 坐标以及颜色。

如果文本应在给定边界内换行，则可以改用 `#drawWordWrap`。它默认渲染左对齐字符串。

> **注意**
>
> 字符串通常应以 [`Component`][component] 形式传入，因为它们能处理多种用例，包括该方法的另外两个重载。

### 纹理

纹理通过 blit 绘制，因此方法名为 `#blit`——在此语境下，它复制图像的位并直接绘制到屏幕上。这些通过位置纹理着色器（position texture shader）绘制。

每个 `#blit` 方法都接收一个 `ResourceLocation`，表示纹理的绝对位置：

```java
// Points to 'assets/examplemod/textures/gui/container/example_container.png'
private static final ResourceLocation TEXTURE = ResourceLocation.fromNamespaceAndPath("examplemod", "textures/gui/container/example_container.png");
```

虽然 `#blit` 有许多不同的重载，我们只讨论其中两个。

第一个 `#blit` 接收六个整数，并假定所渲染的纹理位于 256 x 256 的 PNG 文件中。它接收屏幕上的左侧 x 与顶部 y 坐标、PNG 内的左侧 x 与顶部 y 坐标，以及要渲染图像的宽度和高度。

> **提示**
>
> 必须指定 PNG 文件的大小，以便将坐标归一化以获得关联的 UV 值。

第一个 `#blit` 所调用的第二个 `#blit` 将其扩展为 PNG 坐标的七个整数和两个浮点数，且只假定图像位于某个 PNG 文件中。它接收屏幕上的左侧 x 与顶部 y 坐标、z 坐标（称为 blit 偏移）、PNG 内的左侧 x 与顶部 y 坐标、要渲染图像的宽度和高度，以及 PNG 文件的宽度和高度。

#### `blitSprite`

`#blitSprite` 是 `#blit` 的一种特殊实现，其中纹理被写入 GUI 纹理图集。大多数叠加在背景之上的纹理（例如熔炉 GUI 中的"燃烧进度"叠加层）都是 sprite。所有 sprite 纹理都相对于 `textures/gui/sprites`，且无需指定文件扩展名。

```java
// Points to 'assets/examplemod/textures/gui/sprites/container/example_container/example_sprite.png'
private static final ResourceLocation SPRITE = ResourceLocation.fromNamespaceAndPath("examplemod", "container/example_container/example_sprite");
```

有一组 `#blitSprite` 方法的参数与 `#blit` 相同，只是没有 sprite 内的 x 和 y 坐标。

另一组 `#blitSprite` 方法接收更多纹理信息，以允许渲染 sprite 的一部分。这些方法接收纹理宽度和高度、sprite 中的 x 和 y 坐标、屏幕上的左侧 x 与顶部 y 坐标、z 坐标（称为 blit 偏移），以及要渲染图像的宽度和高度。

如果 sprite 大小与纹理大小不匹配，则可以通过三种方式之一缩放 sprite：`stretch`、`tile` 和 `nine_slice`。`stretch` 将图像从纹理大小拉伸到屏幕大小。`tile` 反复渲染纹理，直到达到屏幕大小。`nine_slice` 将纹理划分为一个中心、四条边和四个角，以将纹理平铺到所需的屏幕大小。

这通过在 mcmeta 文件中添加与纹理文件同名的 `gui.scaling` JSON 对象来设置。

```json5
// For some texture file example_sprite.png
// In example_sprite.png.mcmeta

// Stretch example
{
    "gui": {
        "scaling": {
            "type": "stretch"
        }
    }
}

// Tile example
{
    "gui": {
        "scaling": {
            "type": "tile",
            // The size to begin tiling at
            // This is usually the size of the texture
            "width": 40,
            "height": 40
        }
    }
}

// Nine slice example
{
    "gui": {
        "scaling": {
            "type": "nine_slice",
            // The size to begin tiling at
            // This is usually the size of the texture
            "width": 40,
            "height": 40,
            "border": {
                // The padding of the texture that will be sliced into the border texture
                "left": 1,
                "right": 1,
                "top": 1,
                "bottom": 1
            }
        }
    }
}
```

#### Blit 偏移

渲染纹理时的 z 坐标通常设为 blit 偏移。该偏移负责在查看界面时正确分层渲染。z 坐标较小的渲染绘制在背景，反之 z 坐标较大的渲染绘制在前景。z 偏移可以通过 `#translate` 直接在 `PoseStack` 上设置。`GuiGraphics` 的某些方法（例如物品渲染）内部会应用一些基本的偏移逻辑。

> **警告**
>
> 设置 blit 偏移时，必须在渲染完对象后重置它。否则，界面中的其他对象可能被渲染到错误的图层，导致图形问题。建议在平移前推入当前姿态，并在该偏移下的所有渲染完成后弹出。

## Renderable

`Renderable` 本质上是会被渲染的对象。这包括界面、按钮、聊天框、列表等。`Renderable` 只有一个方法：`#render`。它接收用于向屏幕渲染内容的 `GuiGraphics`、按相对屏幕大小缩放的鼠标 x 和 y 位置，以及 tick delta（自上一帧以来经过的 tick 数）。

一些常见的可渲染对象是界面和"控件"（widget）：通常是渲染在屏幕上的可交互元素，例如 `Button`、其子类型 `ImageButton`，以及用于在屏幕上输入文本的 `EditBox`。

## GuiEventListener

Minecraft 中渲染的任何界面都实现了 `GuiEventListener`。`GuiEventListener` 负责处理用户与界面的交互。这包括来自鼠标（移动、点击、释放、拖动、滚动、悬停）和键盘（按下、释放、键入）的输入。每个方法都返回相应操作是否成功影响了界面。按钮、聊天框、列表等控件也实现了该接口。

### ContainerEventHandler

与 `GuiEventListener` 几乎同义的是其子类型：`ContainerEventHandler`。它们负责处理包含控件的界面上的用户交互，管理当前聚焦的是哪个控件以及如何应用相关交互。`ContainerEventHandler` 增加了三个额外特性：可交互子元素、拖动和聚焦。

事件处理器持有子元素，用于确定元素的交互顺序。在鼠标事件处理器中（不包括拖动），列表中鼠标悬停的第一个子元素会执行其逻辑。

用鼠标拖动元素通过 `#mouseClicked` 和 `#mouseReleased` 实现，提供更精确执行的逻辑。

聚焦允许在事件执行期间（例如键盘事件或拖动鼠标期间）优先检查并处理特定子元素。聚焦通常通过 `#setFocused` 设置。此外，可交互子元素可以使用 `#nextFocusPath` 循环切换，根据传入的 `FocusNavigationEvent` 选择子元素。

> **注意**
>
> 界面通过 `AbstractContainerEventHandler` 实现 `ContainerEventHandler`，后者为拖动和聚焦子元素添加了 setter 和 getter 逻辑。

## NarratableEntry

`NarratableEntry` 是可以通过 Minecraft 的无障碍叙述功能朗读的元素。每个元素可以根据所悬停或选中的内容提供不同的叙述，优先级通常是聚焦、悬停，然后是其他所有情况。

`NarratableEntry` 有三个方法：一个确定元素的优先级（`#narrationPriority`），一个确定是否朗读叙述（`#isActive`），最后一个将叙述提供给其关联输出（朗读或读取，`#updateNarration`）。

> **注意**
>
> Minecraft 的所有控件都是 `NarratableEntry`，因此如果使用可用的子类型，通常无需手动实现。

## Screen 子类型

掌握上述所有知识后，就可以构建一个基本界面。为便于理解，将按通常遇到的顺序介绍界面的各个组成部分。

首先，所有界面都接收一个 `Component`，表示界面标题。该组件通常由某个子类型绘制到屏幕上。在基础界面中它只用于叙述消息。

```java
// In some Screen subclass
public MyScreen(Component title) {
    super(title);
}
```

### 初始化

界面初始化后会调用 `#init` 方法。`#init` 方法从 `Minecraft` 实例中设置界面内部的初始设置，包括按游戏缩放后的相对宽度和高度。任何设置工作（例如添加控件或预计算相对坐标）都应在此方法中完成。如果游戏窗口被调整大小，界面将通过调用 `#init` 方法重新初始化。

有三种方式向界面添加控件，各自服务于不同目的：

方法                   | 描述
:---:                  | :---
`#addWidget`           | 添加一个可交互、可叙述但不渲染的控件。
`#addRenderableOnly`   | 添加一个仅渲染的控件；它不可交互也不可叙述。
`#addRenderableWidget` | 添加一个可交互、可叙述且会渲染的控件。

通常 `#addRenderableWidget` 使用得最多。

```java
// In some Screen subclass
@Override
protected void init() {
    super.init();

    // Add widgets and precomputed values
    this.addRenderableWidget(new EditBox(/* ... */));
}
```

### 界面 Tick

界面还会使用 `#tick` 方法进行 tick，以执行某种程度的客户端逻辑用于渲染目的。

```java
// In some Screen subclass
@Override
public void tick() {
    super.tick();

    // Execute some logic every frame
}
```

### 输入处理

由于界面是 `GuiEventListener` 的子类型，输入处理器也可以被重写，例如用于处理特定[按键][keymapping]的逻辑。

### 渲染界面

最后，界面通过作为 `Renderable` 子类型所提供的 `#render` 方法渲染。如前所述，`#render` 方法每帧绘制界面需要渲染的所有内容，例如背景、控件、工具提示等。默认情况下，`#render` 方法只将控件渲染到屏幕上。

界面中通常不由子类型处理的两项最常见渲染内容是背景和工具提示。

背景可以使用 `#renderBackground` 渲染，其中一个方法接收一个 v 偏移，用于在其后方维度无法渲染时渲染选项背景。

工具提示通过 `GuiGraphics#renderTooltip` 或 `GuiGraphics#renderComponentTooltip` 渲染，它们可以接收要渲染的文本组件、可选的自定义工具提示组件，以及工具提示应在屏幕上渲染的相对 x / y 坐标。

```java
// In some Screen subclass

// mouseX and mouseY indicate the scaled coordinates of where the cursor is in on the screen
@Override
public void render(GuiGraphics graphics, int mouseX, int mouseY, float partialTick) {
    // Background is typically rendered first
    this.renderBackground(graphics);

    // Render things here before widgets (background textures)

    // Then the widgets if this is a direct child of the Screen
    super.render(graphics, mouseX, mouseY, partialTick);

    // Render things after widgets (tooltips)
}
```

### 关闭界面

界面关闭时，有两个方法处理清理工作：`#onClose` 和 `#removed`。

`#onClose` 在用户做出关闭当前界面的输入时调用。该方法通常用作回调，用于销毁并保存界面自身内部的任何过程。这包括向服务端发送数据包。

`#removed` 在界面切换之前、被释放给垃圾回收器之前调用。它处理界面打开之前尚未重置回初始状态的任何内容。

```java
// In some Screen subclass

@Override
public void onClose() {
    // Stop any handlers here

    // Call last in case it interferes with the override
    super.onClose();
}

@Override
public void removed() {
    // Reset initial states here

    // Call last in case it interferes with the override
    super.removed()
;}
```

## `AbstractContainerScreen`

如果界面直接附加到[菜单][menus]，则应改为继承 `AbstractContainerScreen`。`AbstractContainerScreen` 充当菜单的渲染器和输入处理器，并包含与槽位同步和交互的逻辑。因此，通常只需重写或实现两个方法即可获得可用的容器界面。同样，为便于理解，将按通常遇到的顺序介绍容器界面的各个组成部分。

`AbstractContainerScreen` 通常需要三个参数：正在打开的容器菜单（由泛型 `T` 表示）、玩家物品栏（仅用于显示名称），以及界面本身的标题。在其中可以设置若干定位字段：

字段              | 描述
:---:             | :---
`imageWidth`      | 用于背景的纹理宽度。这通常位于 256 x 256 的 PNG 中，默认为 176。
`imageHeight`     | 用于背景的纹理高度。这通常位于 256 x 256 的 PNG 中，默认为 166。
`titleLabelX`     | 界面标题渲染位置的相对 x 坐标。
`titleLabelY`     | 界面标题渲染位置的相对 y 坐标。
`inventoryLabelX` | 玩家物品栏名称渲染位置的相对 x 坐标。
`inventoryLabelY` | 玩家物品栏名称渲染位置的相对 y 坐标。

> **警告**
>
> 在前一节中提到，预计算的相对坐标应在 `#init` 方法中设置。这一点仍然成立，因为这里提到的值不是预计算坐标，而是静态值和相对化坐标。
>
> 图像值是静态且不变的，因为它们表示背景纹理大小。为使渲染更方便，`#init` 方法中会预计算两个额外值（`leftPos` 和 `topPos`），标记背景将被渲染的左上角。标签坐标相对于这些值。
>
> `leftPos` 和 `topPos` 也被用作渲染背景的便捷方式，因为它们已经表示了要传入 `#blit` 方法的位置。

```java
// In some AbstractContainerScreen subclass
public MyContainerScreen(MyMenu menu, Inventory playerInventory, Component title) {
    super(menu, playerInventory, title);

    this.titleLabelX = 10;
    this.inventoryLabelX = 10;

    /*
     * If the 'imageHeight' is changed, 'inventoryLabelY' must also be
     * changed as the value depends on the 'imageHeight' value.
     */
}
```

### 菜单访问

由于菜单被传入界面，菜单中并被同步的任何值（通过槽位、数据槽或自定义系统）现在都可以通过 `menu` 字段访问。

### 容器 Tick

当玩家存活且正在查看界面时，容器界面会在 `#tick` 方法内通过 `#containerTick` 进行 tick。它实质上取代了容器界面中的 `#tick`，最常见的用途是 tick 配方书。

```java
// In some AbstractContainerScreen subclass
@Override
protected void containerTick() {
    super.containerTick();

    // Tick things here
}
```

### 渲染容器界面

容器界面的渲染跨越三个方法：`#renderBg`，渲染背景纹理；`#renderLabels`，渲染背景之上的任何文本；以及 `#render`，它包含前两个方法，并额外提供灰色遮罩背景和工具提示。

从 `#render` 开始，最常见的重写（通常也是唯一的情况）会添加背景、调用 super 渲染容器界面，最后在其上渲染工具提示。

```java
// In some AbstractContainerScreen subclass
@Override
public void render(GuiGraphics graphics, int mouseX, int mouseY, float partialTick) {
    this.renderBackground(graphics);
    super.render(graphics, mouseX, mouseY, partialTick);

    /*
     * This method is added by the container screen to render
     * the tooltip of the hovered slot.
     */
    this.renderTooltip(graphics, mouseX, mouseY);
}
```

在 super 中，会调用 `#renderBg` 渲染界面背景。最标准的写法使用三次方法调用：两次用于设置，一次用于绘制背景纹理。

```java
// In some AbstractContainerScreen subclass

// The location of the background texture (assets/<namespace>/<path>)
private static final ResourceLocation BACKGROUND_LOCATION = ResourceLocation.fromNamespaceAndPath(MOD_ID, "textures/gui/container/my_container_screen.png");

@Override
protected void renderBg(GuiGraphics graphics, float partialTick, int mouseX, int mouseY) {
    /*
     * Renders the background texture to the screen. 'leftPos' and
     * 'topPos' should already represent the top left corner of where
     * the texture should be rendered as it was precomputed from the
     * 'imageWidth' and 'imageHeight'. The two zeros represent the
     * integer u/v coordinates inside the 256 x 256 PNG file.
     */
    graphics.blit(BACKGROUND_LOCATION, this.leftPos, this.topPos, 0, 0, this.imageWidth, this.imageHeight);
}
```

最后，调用 `#renderLabels` 渲染背景之上、工具提示之下的任何文本。它只是使用字体绘制相关的组件。

```java
// In some AbstractContainerScreen subclass
@Override
protected void renderLabels(GuiGraphics graphics, int mouseX, int mouseY) {
    super.renderLabels(graphics, mouseX, mouseY);

    // Assume we have some Component 'label'
    // 'label' is drawn at 'labelX' and 'labelY'
    graphics.drawString(this.font, this.label, this.labelX, this.labelY, 0x404040);
}
```

> **注意**
>
> 渲染标签时，你**不需要**指定 `leftPos` 和 `topPos` 偏移。这些已经在 `PoseStack` 中平移过了，因此该方法内的所有内容都是相对于这些坐标绘制的。

## 注册 AbstractContainerScreen

要在菜单中使用 `AbstractContainerScreen`，需要注册它。这可以通过在[**模组事件总线**][modbus]上的 `RegisterMenuScreensEvent` 中调用 `register` 完成。

```java
@SubscribeEvent // on the mod event bus only on the physical client
public static void registerScreens(RegisterMenuScreensEvent event) {
    event.register(MY_MENU.get(), MyContainerScreen::new);
}
```
