# 按键映射

按键映射（key mapping，或称按键绑定）定义了应绑定到某个输入的特定操作：鼠标点击、按键按下等。按键映射所定义的每个操作都可以在客户端能够接收输入时被检查。此外，每个按键映射都可以通过[控制选项菜单][controls]分配到任意输入。

## 注册 `KeyMapping`

`KeyMapping` 可以通过仅在物理客户端上监听[模组事件总线][eventbus]上的 `RegisterKeyMappingsEvent` 并调用 `#register` 来注册。

```java
// In some physical client only class

// Key mapping is lazily initialized so it doesn't exist until it is registered
public static final Lazy<KeyMapping> EXAMPLE_MAPPING = Lazy.of(() -> /*...*/);

@SubscribeEvent // on the mod event bus only on the physical client
public static void registerBindings(RegisterKeyMappingsEvent event) {
    event.register(EXAMPLE_MAPPING.get());
}
```

## 创建 `KeyMapping`

`KeyMapping` 可以使用其构造方法创建。`KeyMapping` 接收定义映射名称的[翻译键][tk]、映射的默认输入，以及定义该映射将被放入[控制选项菜单][controls]中哪个分类的[翻译键][tk]。

> **提示**
>
> 通过提供原版未提供的分类[翻译键][tk]，可以将 `KeyMapping` 添加到自定义分类。自定义分类翻译键应包含模组 id（例如 `key.categories.examplemod.examplecategory`）。

### 默认输入

每个按键映射都有一个关联的默认输入。这通过 `InputConstants.Key` 提供。每个输入由一个 `InputConstants.Type`（定义提供输入的设备）和一个整数（定义该输入在设备上的关联标识符）组成。

原版提供三种输入类型：`KEYSYM`，通过所提供的 `GLFW` 键令牌定义键盘；`SCANCODE`，通过平台相关的扫描码定义键盘；以及 `MOUSE`，定义鼠标。

> **注意**
>
> 对于键盘，强烈建议使用 `KEYSYM` 而非 `SCANCODE`，因为 `GLFW` 键令牌不绑定到任何特定系统。你可以在 [GLFW 文档][keyinput]中了解更多。

该整数取决于所提供的类型。所有输入码都定义在 `GLFW` 中：`KEYSYM` 令牌以 `GLFW_KEY_*` 为前缀，而 `MOUSE` 码以 `GLFW_MOUSE_*` 为前缀。

```java
new KeyMapping(
    "key.examplemod.example1", // Will be localized using this translation key
    InputConstants.Type.KEYSYM, // Default mapping is on the keyboard
    GLFW.GLFW_KEY_P, // Default key is P
    "key.categories.misc" // Mapping will be in the misc category
)
```

> **注意**
>
> 如果该按键映射不应映射到默认值，则输入应设为 `InputConstants#UNKNOWN`。原版构造方法要求你通过 `InputConstants$Key#getValue` 提取输入码，而 NeoForge 的构造方法可以直接提供原始输入字段。

### `IKeyConflictContext`

并非所有映射都会在每个上下文中使用。有些映射只在 GUI 中使用，而另一些则只纯粹在游戏中使用。为避免在不同上下文中使用相同按键的映射相互冲突，可以指定 `IKeyConflictContext`。

每个冲突上下文包含两个方法：`#isActive`，定义该映射是否可在当前游戏状态下使用；以及 `#conflicts`，定义该映射是否与相同或不同冲突上下文中的按键冲突。

目前 NeoForge 通过 `KeyConflictContext` 定义了三个基本上下文：`UNIVERSAL`，即默认值，表示该按键可在任何上下文中使用；`GUI`，表示该映射只能在 `Screen` 打开时使用；以及 `IN_GAME`，表示该映射只能在 `Screen` 未打开时使用。新的冲突上下文可以通过实现 `IKeyConflictContext` 创建。

```java
new KeyMapping(
    "key.examplemod.example2",
    KeyConflictContext.GUI, // Mapping can only be used when a screen is open
    InputConstants.Type.MOUSE, // Default mapping is on the mouse
    GLFW.GLFW_MOUSE_BUTTON_LEFT, // Default mouse input is the left mouse button
    "key.categories.examplemod.examplecategory" // Mapping will be in the new example category
)
```

### `KeyModifier`

模组开发者可能不希望映射在同时按住修饰键时具有相同行为（例如 `G` 与 `CTRL + G`）。为解决这个问题，NeoForge 在构造方法中增加了额外参数以接收 `KeyModifier`，它可以将控制键（`KeyModifier#CONTROL`）、Shift（`KeyModifier#SHIFT`）或 Alt（`KeyModifier#ALT`）应用于任何输入。`KeyModifier#NONE` 是默认值，不应用任何修饰键。

在[控制选项菜单][controls]中，可以通过按住修饰键和关联输入来添加修饰键。

```java
new KeyMapping(
    "key.examplemod.example3",
    KeyConflictContext.UNIVERSAL,
    KeyModifier.SHIFT, // Default mapping requires shift to be held down
    InputConstants.Type.KEYSYM, // Default mapping is on the keyboard
    GLFW.GLFW_KEY_G, // Default key is G
    "key.categories.misc"
)
```

## 检查 `KeyMapping`

可以检查 `KeyMapping` 是否已被点击。根据时机不同，该映射可用于条件判断中以应用关联逻辑。

### 游戏内

在游戏内，应通过监听[事件总线][eventbus]上的 `ClientTickEvent.Post`，并在 while 循环中检查 `KeyMapping#consumeClick` 来检查映射。`#consumeClick` 仅在输入被执行且此前尚未处理过时返回 `true`，因此不会无限阻塞游戏。

```java
@SubscribeEvent // on the game event bus only on the physical client
public static void onClientTick(ClientTickEvent.Post event) {
    while (EXAMPLE_MAPPING.get().consumeClick()) {
        // Execute logic to perform on click here
    }
}
```

> **警告**
>
> 不要使用 `InputEvent` 作为 `ClientTickEvent.Post` 的替代。键盘和鼠标输入只有各自独立的事件，因此它们无法处理任何额外的输入。

### GUI 内

在 GUI 内，可以在某个 `GuiEventListener` 方法中使用 `IKeyMappingExtension#isActiveAndMatches` 检查映射。最常检查的方法是 `#keyPressed` 和 `#mouseClicked`。

`#keyPressed` 接收 `GLFW` 键令牌、平台相关的扫描码，以及按住修饰键的位域。通过使用 `InputConstants#getKey` 创建输入，可以将按键与映射进行比对。修饰键已在映射方法本身中被检查。

```java
// In some Screen subclass
@Override
public boolean keyPressed(int key, int scancode, int mods) {
    if (EXAMPLE_MAPPING.get().isActiveAndMatches(InputConstants.getKey(key, scancode))) {
        // Execute logic to perform on key press here
        return true;
    }
    return super.keyPressed(x, y, button);
} 
```

> **注意**
>
> 如果你不拥有试图检查**按键**的那个界面，可以改为监听[事件总线][eventbus]上 `ScreenEvent.KeyPressed` 的 `Pre` 或 `Post` 事件。

`#mouseClicked` 接收鼠标的 x 位置、y 位置以及所点击的按钮。通过使用 `MOUSE` 输入调用 `InputConstants.Type#getOrCreate` 创建输入，可以将鼠标按钮与映射进行比对。

```java
// In some Screen subclass
@Override
public boolean mouseClicked(double x, double y, int button) {
    if (EXAMPLE_MAPPING.get().isActiveAndMatches(InputConstants.TYPE.MOUSE.getOrCreate(button))) {
        // Execute logic to perform on mouse click here
        return true;
    }
    return super.mouseClicked(x, y, button);
} 
```

> **注意**
>
> 如果你不拥有试图检查**鼠标**的那个界面，可以改为监听[事件总线][eventbus]上 `ScreenEvent.MouseButtonPressed` 的 `Pre` 或 `Post` 事件。
