# 调试分析器

Minecraft 提供了一个调试分析器（Debug Profiler），可提供系统数据、当前游戏设置、JVM 数据、维度数据以及分侧 tick 信息，用于找出耗时的代码。考虑到 `TickEvent` 和正在 tick 的 `BlockEntity` 等因素，这对想要查找卡顿来源的模组开发者和服务器所有者非常有用。

## 使用调试分析器

调试分析器使用起来非常简单。需要按下调试快捷键 `F3 + L` 来启动分析器。10 秒后它会自动停止；不过也可以再次按下该快捷键提前停止。

> **注意**
>
> 自然，你只能分析实际被执行到的代码路径。你想分析的 `Entity` 和 `BlockEntity` 必须存在于维度中，才会出现在结果里。

停止调试器后，它会在运行目录的 `debug/profiling` 子目录中创建一个新的 zip 文件。
文件名将按日期和时间格式化为 `yyyy-mm-dd_hh_mi_ss-WorldName-VersionNumber.zip`

## 阅读分析结果

在每个分侧文件夹（`client` 和 `server`）中，你会找到一个包含结果数据的 `profiling.txt` 文件。文件顶部首先会告诉你它运行了多少毫秒，以及在这段时间内运行了多少 tick。

在此之下，你会看到类似下面片段的信息：

```
[00] levels - 96.70%/96.70%
[01] |   Level Name - 99.76%/96.47%
[02] |   |   tick - 99.31%/95.81%
[03] |   |   |   entities - 47.72%/45.72%
[04] |   |   |   |   regular - 98.32%/44.95%
[04] |   |   |   |   blockEntities - 0.90%/0.41%
[05] |   |   |   |   |   unspecified - 64.26%/0.26%
[05] |   |   |   |   |   minecraft:furnace - 33.35%/0.14%
[05] |   |   |   |   |   minecraft:chest - 2.39%/0.01%
```

以下简要说明各部分含义：

| [02]                     | tick                    | 99.31%       | 95.81%       |
| :----------------------- | :---------------------- | :----------- | :----------- |
| 该小节的深度 | 该小节的名称 | 相对于其父级所耗时间的百分比。对于第 0 层，它是一个 tick 所耗时间的百分比。对于第 1 层，是其父级所耗时间的百分比。 | 第二个百分比告诉你它占整个 tick 的时间比例。 |

## 分析你自己的代码

调试分析器对 `Entity` 和 `BlockEntity` 有基本支持。如果你想分析其他内容，可能需要像下面这样手动创建小节：

```java
ProfilerFiller#push(yourSectionName : String);
//The code you want to profile
ProfilerFiller#pop();
```
你可以从 `Level`、`MinecraftServer` 或 `Minecraft` 实例获取 `ProfilerFiller` 实例。
现在你只需要在结果文件中搜索你的小节名称。
