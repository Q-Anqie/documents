# 资源位置

`ResourceLocation` 是 Minecraft 中最重要的东西之一。它们被用作[注册表][registries]中的键、数据或资源文件的标识符、代码中对模型的引用，以及许多其他地方。一个 `ResourceLocation` 由两部分组成：命名空间和路径，二者以 `:` 分隔。

命名空间表示该位置所指向的模组、资源包或数据包。例如，模组 id 为 `examplemod` 的模组将使用 `examplemod` 命名空间。Minecraft 使用 `minecraft` 命名空间。额外命名空间可以随意定义，只需创建对应的数据文件夹即可，这通常由数据包完成，以便将其逻辑与和原版集成的部分分开。

路径是对命名空间内你想要的任何对象的引用。例如，`minecraft:cow` 是对 `minecraft` 命名空间中名为 `cow` 的某个东西的引用——通常该位置会用于从实体注册表获取牛实体。另一个例子是 `examplemod:example_item`，它很可能用于从物品注册表获取你模组的 `example_item`。

`ResourceLocation` 只能包含小写字母、数字、下划线、点和连字符。路径还可以额外包含正斜杠。注意，由于 Java 模块限制，模组 id 不能包含连字符，进而意味着模组命名空间也不能包含连字符（路径中仍然允许）。

> **说明**
>
> 单独的 `ResourceLocation` 并不能说明我们用它来指代何种对象。例如，名为 `minecraft:dirt` 的对象存在于多个地方。将对象与其关联取决于接收该 `ResourceLocation` 的一方。

新的 `ResourceLocation` 可以通过调用 `ResourceLocation.fromNamespaceAndPath("examplemod", "example_item")` 或 `ResourceLocation.parse("examplemod:example_item")` 创建。如果使用 `withDefaultNamespace`，该字符串将被用作路径，而 `minecraft` 将被用作命名空间。因此例如 `ResourceLocation.withDefaultNamespace("example_item")` 将得到 `minecraft:example_item`。

`ResourceLocation` 的命名空间和路径可以分别通过 `ResourceLocation#getNamespace()` 和 `#getPath()` 获取，组合形式可以通过 `ResourceLocation#toString` 获取。

`ResourceLocation` 是不可变的。`ResourceLocation` 上的所有工具方法（例如 `withPrefix` 或 `withSuffix`）都会返回一个新的 `ResourceLocation`。

## 解析 `ResourceLocation`

某些地方（例如注册表）直接使用 `ResourceLocation`。然而，另一些地方会按需解析 `ResourceLocation`。例如：

- `ResourceLocation` 被用作 GUI 背景的标识符。例如，熔炉 GUI 使用资源位置 `minecraft:textures/gui/container/furnace.png`。它映射到磁盘上的文件 `assets/minecraft/textures/gui/container/furnace.png`。注意，此资源位置中必须包含 `.png` 后缀。
- `ResourceLocation` 被用作方块模型的标识符。例如，泥土的方块模型使用资源位置 `minecraft:block/dirt`。它映射到磁盘上的文件 `assets/minecraft/models/block/dirt.json`。注意，此处不需要 `.json` 后缀。另请注意，该资源位置会自动映射到 `models` 子文件夹中。
- `ResourceLocation` 被用作配方的标识符。例如，铁块合成配方使用资源位置 `minecraft:iron_block`。它映射到磁盘上的文件 `data/minecraft/recipe/iron_block.json`。注意，此处不需要 `.json` 后缀。另请注意，该资源位置会自动映射到 `recipe` 子文件夹中。

`ResourceLocation` 是否需要文件后缀，或者该资源位置究竟解析为什么，取决于具体用例。

## `ModelResourceLocation`

> 相关 Minecraft Wiki：[模型](https://zh.minecraft.wiki/w/模型)

`ModelResourceLocation` 是一种特殊的资源位置，它包含第三部分，称为变体（variant）。Minecraft 主要用它们来区分模型的不同变体，这些不同变体用于不同的显示场景（例如三叉戟在第一人称、第三人称和物品栏中拥有不同的模型）。对于物品，变体始终是 `inventory`；对于方块状态，变体是逗号分隔的属性-值对字符串（例如 `facing=north,waterlogged=false`，对于没有方块状态属性的方块则为空）。

变体附加在常规资源位置之后，并以 `#` 分隔。例如，钻石剑物品模型的完整名称是 `minecraft:diamond_sword#inventory`。不过，在大多数场景中，`inventory` 变体可以省略。

`ModelResourceLocation` 是一个[仅客户端][sides]的类。这意味着引用该类的服务端将以 `NoClassDefFoundError` 崩溃。

## `ResourceKey`

`ResourceKey` 将注册表 id 与注册表名称组合在一起。一个例子是注册表 id 为 `minecraft:item`、注册表名称为 `minecraft:diamond_sword` 的注册表键。与 `ResourceLocation` 不同，`ResourceKey` 实际上指向唯一的元素，因而能够清晰地标识一个元素。它们最常用于许多不同注册表相互接触的场景。一个常见的用例是数据包，尤其是世界生成。

新的 `ResourceKey` 可以通过静态方法 `ResourceKey#create(ResourceKey<? extends Registry<T>>, ResourceLocation)` 创建。这里的第二个参数是注册表名称，而第一个参数是所谓的注册表键。注册表键是一种特殊的 `ResourceKey`，其注册表是根注册表（即所有其他注册表的注册表）。注册表键可以通过 `ResourceKey#createRegistryKey(ResourceLocation)` 使用所需注册表的 id 创建。

`ResourceKey` 在创建时会被驻留（intern）。这意味着可以通过引用相等（`==`）进行比较，而且这是被鼓励的做法，但它们的创建相对昂贵。
