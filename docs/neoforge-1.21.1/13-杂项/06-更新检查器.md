# NeoForge 更新检查器

NeoForge 提供了一个非常轻量、需主动启用的更新检查框架。如果有任何模组存在可用更新，它会在主菜单和模组列表的"Mods"按钮上显示闪烁的图标，并附带相应的更新日志。它*不会*自动下载更新。

## 入门

你首先要做的是在 `mods.toml` 文件中指定 `updateJSONURL` 参数。该参数的值应是一个指向更新 JSON 文件的有效 URL。该文件可以托管在你自己的 Web 服务器、GitHub 或任何你想要的地方，只要你的模组所有用户都能可靠地访问它。

## 更新 JSON 格式

JSON 本身的格式相对简单，如下所示：

```json5
{
    "homepage": "<homepage/download page for your mod>",
    "<mcversion>": {
        "<modversion>": "<changelog for this version>", 
        // List all versions of your mod for the given Minecraft version, along with their changelogs
        // ...
    },
    "promos": {
        "<mcversion>-latest": "<modversion>",
        // Declare the latest "bleeding-edge" version of your mod for the given Minecraft version
        "<mcversion>-recommended": "<modversion>",
        // Declare the latest "stable" version of your mod for the given Minecraft version
        // ...
    }
}
```

这相当不言自明，但有一些注意事项：

- `homepage` 下的链接是模组过期时向用户显示的链接。
- NeoForge 使用内部算法判断你的模组的某个版本字符串是否比另一个"更新"。大多数版本方案都应兼容，但如果你担心自己的方案是否受支持，请参阅 `ComparableVersion` 类。强烈建议遵循 [Maven 版本命名][mvnver]。
- 更新日志字符串可以使用 `\n` 分行。有些人喜欢先放一段简短的更新日志，然后链接到提供完整更改列表的外部站点。
- 手动输入数据可能很繁琐。由于 Groovy 原生支持 JSON 解析，你可以配置 `build.gradle` 在构建发布版时自动更新该文件。这留给读者作为练习。

- 一些示例可在此处找到：[nocubes]、[Corail Tombstone][corail] 和 [Chisels & Bits 2][chisel]。

## 获取更新检查结果

你可以使用 `VersionChecker#getResult(IModInfo)` 获取 NeoForge 更新检查器的结果。你可以通过 `ModContainer#getModInfo` 获取自己的 `IModInfo`，其中 `ModContainer` 可以作为参数添加到模组构造方法中。你可以使用 `ModList.get().getModContainerById(<modId>)` 获取任何其他模组的 `ModContainer`。返回的对象有一个方法 `#status`，指示版本检查的状态。

|          状态 | 描述 |
|----------------:|:------------|
|        `FAILED` | 版本检查器无法连接到所提供的 URL。 |
|    `UP_TO_DATE` | 当前版本等于推荐版本。 |
|         `AHEAD` | 如果不存在最新版本，当前版本比推荐版本更新。 |
|      `OUTDATED` | 存在新的推荐版本或最新版本。 |
| `BETA_OUTDATED` | 存在新的最新版本。 |
|          `BETA` | 当前版本等于或新于最新版本。 |
|       `PENDING` | 所请求的结果尚未完成，因此你应稍后再试。 |

返回的对象还会包含目标版本以及 `update.json` 中指定的任何更新日志行。
