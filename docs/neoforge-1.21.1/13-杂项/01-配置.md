# 配置

配置定义了可以应用于模组实例的设置与用户偏好。NeoForge 使用基于 [TOML][toml] 文件、由 [NightConfig][nightconfig] 读取的配置系统。

## 创建配置

配置可以使用 `IConfigSpec` 的子类型创建。NeoForge 通过 `ModConfigSpec` 实现该类型，并通过 `ModConfigSpec.Builder` 支持其构建。构建器可以通过 `Builder#push` 创建小节、`Builder#pop` 离开小节，从而将配置值分到各个小节中。之后，可以使用以下两种方法之一构建配置：

 方法        | 描述
 :---       | :---
`build`     | 创建 `ModConfigSpec`。
`configure` | 创建持有配置值的类与 `ModConfigSpec` 组成的对。

> **注意**
>
> `ModConfigSpec.Builder#configure` 通常与 `static` 块以及一个在构造方法中接收 `ModConfigSpec.Builder` 的类配合使用，以附加并持有这些值：
>
> ```java
> //Define a field to keep the config and spec for later
> public static final ExampleConfig CONFIG;
> public static final ModConfigSpec CONFIG_SPEC;
>     
> //CONFIG and CONFIG_SPEC are both built from the same builder, so we use a static block to seperate the properties
> static {
>     Pair<ExampleConfig, ModConfigSpec> pair =
>             new ModConfigSpec.Builder().configure(ExampleConfig::new);
>         
>     //Store the resulting values
>     CONFIG = pair.getLeft();
>     CONFIG_SPEC = pair.getRight();
> }
> ```

每个配置值都可以附带额外上下文以提供额外行为。上下文必须在配置值完全构建之前定义：

| 方法           | 描述                                                                     |
|:---------------|:------------------------------------------------------------------------|
| `comment`      | 提供该配置值作用的描述。可以提供多个字符串以形成多行注释。                    |
| `translation`  | 提供该配置值名称的翻译键。                                                |
| `worldRestart` | 在配置值可以更改之前必须重启世界。                                         |

### ConfigValue

配置值可以使用任意 `#define` 方法，结合所提供的上下文（若已定义）来构建。

所有配置值方法都至少接收两个组成部分：

- 表示变量名称的路径：一个以 `.` 分隔的字符串，表示配置值所在的小节
- 当不存在有效配置时使用的默认值

`ConfigValue` 专用方法还会接收两个额外组成部分：

- 用于确保反序列化对象有效的验证器
- 表示该配置值数据类型的类

```java
//Store the config properties as public finals
public final ModConfigSpec.ConfigValue<String> welcomeMessage;

private ExampleConfig(ModConfigSpec.Builder builder) {
    //Define each property
    //One property could be a message to log to the console when the game is initialised
    welcomeMessage = builder.define("welcome_message", "Hello from the config!");
}
```

这些值本身可以通过 `ConfigValue#get` 获取。这些值还会被缓存，以避免多次从文件读取。

#### 额外的配置值类型

- **范围值（Range Values）**
    - 描述：值必须位于所定义的边界之间
    - 类类型：`Comparable<T>`
    - 方法名：`#defineInRange`
    - 额外组成部分：
        - 该配置值可用的最小值与最大值
        - 表示该配置值数据类型的类

> **注意**
>
> `DoubleValue`、`IntValue` 和 `LongValue` 都是范围值，它们分别将类指定为 `Double`、`Integer` 和 `Long`。

- **白名单值（Whitelisted Values）**
    - 描述：值必须位于所提供的集合中
    - 类类型：`T`
    - 方法名：`#defineInList`
    - 额外组成部分：
        - 配置可取的允许值集合

- **列表值（List Values）**
    - 描述：值为条目列表
    - 类类型：`List<T>`
    - 方法名：`#defineList`；如果列表可以为空，则为 `#defineListAllowEmpty`
    - 额外组成部分：
        - 一个提供器，返回在配置界面中添加新条目时使用的默认值
        - 用于确保列表中反序列化元素有效的验证器
        - （可选）用于确保列表条目不过少或过多的验证器

- **枚举值（Enum Values）**
    - 描述：所提供的集合中的某个枚举值
    - 类类型：`Enum<T>`
    - 方法名：`#defineEnum`
    - 额外组成部分：
        - 用于将字符串或整数转换为枚举的 getter
        - 配置可取的允许值集合

- **布尔值（Boolean Values）**
    - 描述：一个 `boolean` 值
    - 类类型：`Boolean`
    - 方法名：`#define`

## 注册配置

`ModConfigSpec` 构建完成后，必须注册它，以便 NeoForge 按需加载、跟踪并同步配置设置。配置应在模组构造方法中通过 `ModContainer#registerConfig` 注册。配置可以使用表示该配置所属侧的[给定类型][configtype]、`ModConfigSpec`，以及可选的特定配置文件名来注册。

```java
// In the main mod file with a ModConfigSpec CONFIG_SPEC
public ExampleMod(ModContainer container) {
    ...
    //Register the config
    container.registerConfig(ModConfig.Type.COMMON, ExampleConfig.CONFIG_SPEC);
    ...
}
```

### 配置类型

配置类型决定配置文件的位置、加载时机，以及该文件是否通过网络同步。默认情况下，所有配置都从物理客户端的 `.minecraft/config` 或物理服务器的 `<server_folder>/config` 加载。各配置类型之间的一些细微差别见以下小节。

> **提示**
>
> NeoForge 在其代码库中[记录了配置类型][type]。

- `STARTUP`
    - 在物理客户端和物理服务器上均从 config 文件夹加载
    - 在注册时立即读取
    - **不会**通过网络同步
    - 默认带 `-startup` 后缀

> **警告**
>
> 以 `STARTUP` 类型注册的配置可能导致客户端与服务端之间不同步，例如当该配置被用于禁用某些内容的注册时。因此，强烈建议 `STARTUP` 中的任何配置都不要用于启用或禁用可能改变模组内容的特性。

- `CLIENT`
    - **仅**在物理客户端上从 config 文件夹加载
        - 该配置类型没有服务端位置
    - 在 `FMLCommonSetupEvent` 触发之前立即读取
    - **不会**通过网络同步
    - 默认带 `-client` 后缀
- `COMMON`
    - 在物理客户端和物理服务器上均从 config 文件夹加载
    - 在 `FMLCommonSetupEvent` 触发之前立即读取
    - **不会**通过网络同步
    - 默认带 `-common` 后缀
- `SERVER`
    - 在物理客户端和物理服务器上均从 config 文件夹加载
        - 可通过将配置添加到以下位置来为每个世界覆盖：
            - 客户端：`.minecraft/saves/<world_name>/serverconfig`
            - 服务器：`<server_folder>/world/serverconfig`
    - 在 `ServerAboutToStartEvent` 触发之前立即读取
    - 通过网络同步到客户端
    - 默认带 `-server` 后缀

## 配置事件

每当配置被加载或重新加载时发生的操作，可以使用 `ModConfigEvent.Loading` 和 `ModConfigEvent.Reloading` 事件完成。这些事件必须[注册][events]到模组事件总线。

> **警告**
>
> 这些事件会为该模组的所有配置调用；应使用所提供的 `ModConfig` 对象来标明正在加载或重新加载的是哪个配置。

## 配置界面

配置界面允许用户在游戏内编辑模组的配置值，而无需打开任何文件。该界面会自动解析你已注册的配置文件并填充界面。

模组可以使用 NeoForge 提供的内置配置界面。模组可以继承 `ConfigurationScreen` 以改变默认界面的行为，或制作自己的配置界面。模组也可以从头创建自己的界面，并通过下面的扩展点将该自定义界面提供给 NeoForge。

可以通过在模组构造期间在[客户端][client]注册 `IConfigScreenFactory` 扩展点，为模组注册配置界面：

```java
// In the main client mod file
public ExampleModClient(ModContainer container) {
    ...
    // This will use NeoForge's ConfigurationScreen to display this mod's configs
    container.registerExtensionPoint(IConfigScreenFactory.class, ConfigurationScreen::new);
    ...
}
```

在游戏中可以通过进入"Mods"页面、从侧边栏选择模组并点击"Config"按钮来访问配置界面。Startup、Common 和 Client 配置选项在任何时候都可编辑。Server 配置仅在本地游玩世界时可在界面中编辑。如果连接到服务器或他人的局域网世界，Server 配置选项将在界面中被禁用。模组配置界面的第一页会显示该模组所有已注册的配置文件，供玩家选择要编辑哪一个。

> **警告**
>
> 如果你要制作界面，应为所有配置条目添加翻译键，并在 lang JSON 中定义文本。
>
> 你可以使用 `ModConfigSpec$Builder#translation` 方法为配置指定翻译键，因此可以把前面的代码扩展为：
>
> ```java
> ConfigValue<T> value = builder.comment("This value is called 'config_value_name', and is set to defaultValue if no existing config is present")
>     .translation("modid.config.config_value_name")
>     .define("config_value_name", defaultValue);
> ```
>
> 为便于翻译，请打开配置界面并浏览所有配置及其子小节。然后返回模组列表界面。此时所有遇到的未翻译配置条目都会打印到控制台。这可以让你更容易知道需要翻译什么以及翻译键是什么。
