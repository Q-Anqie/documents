# 事件系统

> 读完这一篇，你能分清两条事件总线、写出三种监听方式，并且能独立完成"右键触发效果"和"改变伤害数值"这两件最常见的事。

## 学习目标

- 能用自己的话说清 `modEventBus` 和 `NeoForge.EVENT_BUS` 的分工，并给出各自三个事件的例子
- 能写出 `addListener`、`@SubscribeEvent`、`@EventBusSubscriber` 三种监听方式
- 能判断一个事件能不能取消、该怎么取消、取消之后会发生什么
- 能查表找到"玩家右键""实体受伤""服务器启动完成"分别对应哪个事件

## 一、事件是什么

Minecraft 的源码你改不了（改了也没法发布）。但你想在"玩家右键""实体受伤""世界加载完成"这些时刻插一脚，怎么办？

NeoForge 的做法是：在这些时刻，游戏主动喊一声"我要做某事了，谁想插手？"，然后把一个装着上下文的对象（就是**事件对象**）传给所有报名插手的人。这个对象里通常有"谁干的""在哪""涉及哪个方块/物品"，有时还允许你改数值、甚至叫停整件事。

这套机制叫**发布-订阅**（publish-subscribe）：

```text
游戏内部代码                     你的模组
     │                              │
     │  "有人右键了！"               │
     ├──── 事件对象 ────────────────►│  你的处理方法
     │                              │  （读上下文 / 改数值 / 取消）
     │◄──── 事件对象（可能被改过）────┤
     │                              │
     │  继续按（可能被改过的）结果执行 │
```

所以写事件处理器，本质是三件事：

1. **选对事件**：游戏在哪个时刻喊的这句话？
2. **挂对总线**：这句话是在哪条广播频道上喊的？
3. **写对方法**：签名必须是一个事件参数、返回 `void`。

第 2 点是新手翻车最多的地方，我们放到第三节专门讲。

## 二、先认识两条总线

NeoForge 有两套广播频道，官方叫**事件总线**（event bus）：

| | 模组总线 `modEventBus` | 游戏总线 `NeoForge.EVENT_BUS` |
|---|---|---|
| 怎么拿到 | 模组构造器的第一个参数 | 静态字段，全局唯一 |
| 别名 | mod bus | game bus / main bus / 主总线 |
| 什么时候用 | **启动期**的一次性事件：注册、初始化、加载资源 | **运行期**反复发生的事件：玩家动作、实体 tick、伤害 |
| 触发频率 | 每个模组生命周期各一次 | 每 tick / 每次交互，非常频繁 |
| 线程 | 很多事件**并行**触发（多个模组同时跑） | 固定在主线程（服务端线程 / 渲染线程）串行 |
| 事件特征 | 事件的父接口里有 `IModBusEvent` | 没有 |
| 生命周期顺序 | 构造器 → `FMLConstructModEvent` → `RegisterEvent` → `FMLCommonSetupEvent` → `FMLClientSetupEvent` → `FMLLoadCompleteEvent` | 游戏跑起来之后才陆续触发 |

一句话记忆：**"开机时干一次的事"走模组总线，"玩的时候一直发生的事"走游戏总线。**

### 为什么必须分两条

因为启动期的很多事是"每个模组各做各的"，可以并行跑，这样 200 个模组也能快速启动；而运行期的事件必须严格按顺序、在同一个线程上处理，否则世界状态会乱。

这也带来一个副作用：**模组总线上的事件常常是并行的**，你在里面直接操作世界、改静态字段，可能和其他模组撞车。如果确实需要回主线程做事，用：

```java
@SubscribeEvent
public static void commonSetup(FMLCommonSetupEvent event) {
    event.enqueueWork(() -> {
        // 这里已经在主线程了，可以安全地做各种事
    });
}
```

### 挂错总线的后果：静默失败

这是本教程里最阴的 bug，没有之一：

```java
// 错误示范：RegisterEvent 是模组总线事件，却被挂到了游戏总线上
NeoForge.EVENT_BUS.addListener(MyMod::onRegister);
```

结果：编译通过、启动成功、日志干干净净、**你的注册代码一次都没跑**。因为游戏总线只会转发游戏总线事件，它不认识 `RegisterEvent`，也不会提醒你。

同理，把 `PlayerTickEvent` 挂到 `modEventBus` 上，也是同样的静默。

判断办法有两个：

1. 看事件类的继承链，如果某个父接口是 `net.neoforged.bus.api.Event` 之外的 `IModBusEvent`，就是模组总线事件；
2. 直接查本文后面的速查表。

### `@EventBusSubscriber` 会不会挂错

不会。用注解时 NeoForge 会自动判断事件属于哪条总线（21.1.x 上你也可以手动指定 `bus = Bus.MOD`）。这也是我推荐新手优先用注解的原因之一。

## 三、三种监听写法

### 写法一：`addListener` + 方法引用

最短，适合只在构造器里挂一两个事件。

文件：`src/main/java/com/dafeiyu/DafeiyuMod.java`

```java
@Mod(DafeiyuMod.MOD_ID)
public class DafeiyuMod {
    public static final String MOD_ID = "dafeiyu";

    public DafeiyuMod(IEventBus modEventBus, ModContainer modContainer) {
        ModItems.ITEMS.register(modEventBus);

        // 把静态方法 onLivingJump 注册到游戏总线
        NeoForge.EVENT_BUS.addListener(DafeiyuMod::onLivingJump);
    }

    private static void onLivingJump(LivingJumpEvent event) {
        // 只有服务端才改状态，客户端改了会不同步
        if (!event.getEntity().level().isClientSide()) {
            event.getEntity().heal(1.0f);
        }
    }
}
```

`DafeiyuMod::onLivingJump` 就是[方法引用](../02-Java补充篇/02-双冒号与方法引用.md)：把"这个方法"当成一个函数对象传进去。这里能这么写，是因为 `addListener` 需要一个"接收事件、无返回值"的函数，而 `onLivingJump` 正好符合。

`addListener` 还有带参数的版本：

```java
NeoForge.EVENT_BUS.addListener(
        EventPriority.HIGH,      // 优先级
        false,                   // 是否接收已被取消的事件
        DafeiyuMod::onLivingJump
);
```

### 写法二：`@SubscribeEvent` + 注册实例

适合处理器比较多、想按功能分组的场景。

文件：`src/main/java/com/dafeiyu/event/PlayerEvents.java`

```java
package com.dafeiyu.event;

import net.neoforged.bus.api.SubscribeEvent;
import net.neoforged.neoforge.event.entity.living.LivingJumpEvent;

public class PlayerEvents {
    @SubscribeEvent
    public void onLivingJump(LivingJumpEvent event) {
        if (!event.getEntity().level().isClientSide()) {
            event.getEntity().heal(1.0f);
        }
    }
}
```

文件：`src/main/java/com/dafeiyu/DafeiyuMod.java`

```java
public DafeiyuMod(IEventBus modEventBus, ModContainer modContainer) {
    ModItems.ITEMS.register(modEventBus);
    // 传实例：这个实例上所有带 @SubscribeEvent 的方法都会被注册
    NeoForge.EVENT_BUS.register(new PlayerEvents());
}
```

注意 `onLivingJump` 这里**不是** `static`——因为注册的是对象，方法可以是实例方法。方法内部要访问别的字段时，这种方式更自然。

### 写法三：`@EventBusSubscriber`（推荐）

给类打上注解，NeoForge 启动时自动扫描并注册，构造器里一行都不用写。

文件：`src/main/java/com/dafeiyu/event/CommonEvents.java`

```java
package com.dafeiyu.event;

import com.dafeiyu.DafeiyuMod;
import net.neoforged.bus.api.SubscribeEvent;
import net.neoforged.fml.common.EventBusSubscriber;
import net.neoforged.neoforge.event.entity.living.LivingJumpEvent;

@EventBusSubscriber(modid = DafeiyuMod.MOD_ID)
public class CommonEvents {
    // 用注解时必须 static
    @SubscribeEvent
    public static void onLivingJump(LivingJumpEvent event) {
        if (!event.getEntity().level().isClientSide()) {
            event.getEntity().heal(1.0f);
        }
    }
}
```

三个要点：

1. **方法必须是 `static`**。因为注册的是 `CommonEvents.class`，没有实例可依附。
2. **强烈建议写 `modid`**。不写也能跑，但出问题时日志里分不清是谁的处理器，尤其模组冲突时。
3. 默认挂游戏总线。要挂模组总线，21.1.x 上写 `@EventBusSubscriber(modid = "dafeiyu", bus = EventBusSubscriber.Bus.MOD)`；21.2 之后总线由事件类型自动判断，这个参数就不需要了。客户端专属见[侧](03-侧-客户端与服务端.md)。

一个类里可以放任意多个 `@SubscribeEvent` 方法，它们各自独立注册，互不影响。

## 四、优先级、可取消、返回值

### EventPriority

`EventPriority` 有五个值，从先到后：

```text
HIGHEST → HIGH → NORMAL（默认） → LOW → LOWEST
```

优先级高的先执行。用途是：你想在别的模组之前/之后处理同一个事件。比如你想在别人改完伤害之后再翻倍，就用 `LOW`。

```java
@SubscribeEvent(priority = EventPriority.LOW)
public static void afterOthers(LivingDamageEvent.Pre event) { ... }
```

同一优先级内，主总线上按注册顺序（大致等于模组加载顺序）执行，模组总线上严格按加载顺序。

**注意：并行触发的模组总线事件会忽略优先级**（大家同时跑，没有先后）。

### 可取消事件

实现了 `ICancellableEvent` 的事件可以取消：

```java
@SubscribeEvent
public static void onRightClickBlock(PlayerInteractEvent.RightClickBlock event) {
    if (event.getItemStack().is(ModItems.RUBY.get())) {
        event.setCanceled(true);   // 叫停：后面的处理器不跑了，原版行为也不执行
    }
}
```

规则：

- `setCanceled(true)` 之后，**后续的处理器默认不再收到这个事件**；
- 想"即使被取消我也要处理"，注册时声明 `receiveCanceled = true`：`@SubscribeEvent(receiveCanceled = true)`；
- 取消的语义由事件自己定义。`LivingJumpEvent` 取消 = 跳不起来；`PlayerInteractEvent` 取消 = 这次交互作废。

**不是所有事件都能取消。** 编译期不会拦你，但 `setCanceled` 只存在于 `ICancellableEvent` 的实现上，写错了编译器会直接报错。

### TriState 与 Result

有些事件用三态表示结果（`TriState.TRUE / FALSE / DEFAULT`），有些用自己的 `Result` 枚举。它们通过 `setXxx(...)` 设置：

```java
@SubscribeEvent
public static void hideNameTag(RenderNameTagEvent event) {
    event.setCanRender(TriState.FALSE);   // 不显示名字
}
```

这类事件**不是**"取消"，而是"替游戏做决定"，语义更细。

## 五、常用事件速查表

| 事件 | 总线 | 触发时机 | 典型用途 | 可取消 |
|---|---|---|---|---|
| `FMLCommonSetupEvent` | 模组 | 注册完成后、分侧初始化前 | 各种杂项初始化 | 否 |
| `RegisterEvent` | 模组 | 每个注册表注册时 | 手写注册（`DeferredRegister` 的底层） | 否 |
| `BuildCreativeModeTabContentsEvent` | 模组 | 构建创造模式标签页内容时（仅逻辑客户端） | 把物品塞进原版/别人的标签页 | 否 |
| `ModifyDefaultComponentsEvent` | 模组 | 物品默认组件确定前 | 给原版物品加数据组件 | 否 |
| `FMLClientSetupEvent` | 模组 | 物理客户端初始化 | 注册渲染层、按键 | 否 |
| `PlayerTickEvent.Post` | 游戏 | 玩家每 tick 结束时 | 持续效果、计时器 | 否 |
| `LivingDamageEvent.Pre` | 游戏 | 伤害数值已算出、即将扣除 | 改伤害数值（`setNewDamage`） | 否 |
| `LivingIncomingDamageEvent` | 游戏 | 即将受伤（还没算护甲） | 免疫伤害、改原始伤害 | 是 |
| `PlayerInteractEvent.RightClickItem` | 游戏 | 玩家右键使用物品 | 自定义右键行为 | 是 |
| `PlayerInteractEvent.RightClickBlock` | 游戏 | 玩家右键方块 | 自定义方块交互 | 是 |
| `ServerStartedEvent` | 游戏 | 专用服务器/单人世界服务端启动完成 | 初始化全局数据、打印信息 | 否 |
| `ItemTooltipEvent` | 游戏 | 生成物品提示文本时 | 往 tooltip 里加一行 | 否 |
| `EntityJoinLevelEvent` | 游戏 | 实体加入世界 | 给新生成的实体加效果 | 是 |
| `BlockEvent.BreakEvent` | 游戏 | 玩家破坏方块前 | 禁止破坏、替换掉落 | 是 |

记住两条规律，表就不用背：

- 名字里带 `FML` / `Register` / `Build...Contents` / `Modify...Components` 的，基本都是模组总线；
- 名字里带 `Player` / `Living` / `Entity` / `Block` / `Server` 的，基本都是游戏总线。

## 完整示例

两个功能：① 右键红宝石，消耗一个并回血；② 手持红宝石剑时伤害翻倍。

文件：`src/main/java/com/dafeiyu/event/CommonEvents.java`

```java
package com.dafeiyu.event;

import com.dafeiyu.DafeiyuMod;
import com.dafeiyu.registry.ModItems;
import net.minecraft.network.chat.Component;
import net.minecraft.world.entity.player.Player;
import net.minecraft.world.item.ItemStack;
import net.neoforged.bus.api.EventPriority;
import net.neoforged.bus.api.SubscribeEvent;
import net.neoforged.fml.common.EventBusSubscriber;
import net.neoforged.neoforge.event.entity.living.LivingDamageEvent;
import net.neoforged.neoforge.event.entity.player.PlayerInteractEvent;

@EventBusSubscriber(modid = DafeiyuMod.MOD_ID)
public class CommonEvents {

    /**
     * 右键物品：手里是红宝石就消耗一个、回 2 点血。
     * 这个事件在两端都会触发，所以必须先判逻辑侧，再改状态。
     */
    @SubscribeEvent
    public static void onRightClickItem(PlayerInteractEvent.RightClickItem event) {
        ItemStack stack = event.getItemStack();
        if (!stack.is(ModItems.RUBY.get())) {
            return;                      // 不是我们的物品，什么都不做
        }
        if (event.getLevel().isClientSide()) {
            return;                      // 客户端只负责显示，不负责改数据
        }

        Player player = event.getEntity();
        player.heal(2.0f);               // 服务端改血量，客户端会自动同步
        stack.shrink(1);                 // 消耗一个
        player.displayClientMessage(Component.literal("红宝石碎了，你恢复了 1 颗心"), true);

        // 取消掉，避免原版的"使用物品"流程再跑一遍
        event.setCanceled(true);
    }

    /**
     * 伤害结算前：手持红宝石剑的玩家造成双倍伤害。
     * 伤害计算是纯服务端逻辑，这里不需要判侧。
     */
    @SubscribeEvent(priority = EventPriority.LOW)
    public static void onLivingDamage(LivingDamageEvent.Pre event) {
        if (event.getSource().getEntity() instanceof Player player
                && player.getMainHandItem().is(ModItems.RUBY_SWORD.get())) {
            event.setNewDamage(event.getNewDamage() * 2.0f);
        }
    }
}
```

逐段解释：

- `stack.is(...)`：1.21 里判断"是不是某个物品"的标准写法。它接受 `Item`，也接受 `ItemLike`/标签，比 `stack.getItem() == xxx` 更稳。
- `event.getLevel().isClientSide()`：这个判断是**服务端逻辑的开关**。少了它，你在客户端把血量加上去了，服务端一同步又变回去，看起来像"回血闪一下"，更糟的是物品消耗可能双份。
- `stack.shrink(1)`：把数量减 1。注意 `ItemStack` 是可变的，直接改就行，不用重新 `set`。
- `event.setCanceled(true)`：告诉游戏"这次右键我已经处理完了，别再走原版流程"。
- `LivingDamageEvent.Pre` 的 `getNewDamage()` / `setNewDamage()`：读和写"这次要扣多少血"。用 `LOW` 优先级是为了排在别的模组后面，改的是最终结果。

> 想拦"还没算护甲"的原始伤害，用 `LivingIncomingDamageEvent`，它有 `getAmount()` / `setAmount(float)`，而且**可以取消**（`setCanceled(true)` 等于完全免伤）。两者选一个就行，别同时改，容易算重复。

## 常见坑与报错

| 现象 | 原因 | 解决 |
|---|---|---|
| 处理器完全不执行，无报错 | 事件挂错总线 | 查速查表；`RegisterEvent` 等必须挂 `modEventBus` |
| 启动崩：`Invalid event handler method` | 方法签名不对（多个参数 / 有返回值 / 参数不是事件） | 一个事件参数、返回 `void` |
| 启动崩：`IllegalArgumentException` 提到 abstract | 监听了抽象事件（如 `LivingEvent`、`BlockEvent`） | 改监听具体子类 |
| 用注解后处理器不执行 | 方法没写 `static` | 加 `static` |
| 客户端有效果，服务端没有 / 数据回滚 | 忘了判 `isClientSide()` | 状态改动一律放服务端 |
| 改了 `event.getXxx()` 但没生效 | 只读了 getter，没调 setter | 找对应的 `setXxx(...)` |
| 取消后自己的后续逻辑也没跑 | 取消会中断后续处理器 | 把需要执行的部分放在 `setCanceled` 之前 |
| 在 `FMLCommonSetupEvent` 里操作世界时崩溃 | 该事件并行触发 | 用 `event.enqueueWork(...)` |
| 服务端报 `NoClassDefFoundError` | 处理器里直接引用了客户端类 | 见[侧](03-侧-客户端与服务端.md) |

## 练习

1. **热身**：写一个处理器，玩家每次跳跃时给自己 1 秒跳跃提升（提示：`MobEffectInstance` + `MobEffects.JUMP`），记得判侧。
2. **进阶**：让"红宝石剑"攻击亡灵生物时伤害再乘 1.5。提示：`event.getEntity()` 是被打的那个，`event.getSource().getEntity()` 是打的；判断亡灵可以用 `event.getEntity().getMobType() == MobType.UNDEAD`。
3. **思考**：把 `RegisterEvent` 的处理器用 `NeoForge.EVENT_BUS.addListener` 注册，会发生什么？先预测，再动手验证，然后解释为什么这个 bug 特别难查。
