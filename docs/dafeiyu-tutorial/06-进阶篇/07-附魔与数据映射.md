# 附魔与数据映射

> 读完这篇，你能给红宝石剑做一个「击杀掉落额外红宝石」的附魔，并且学会用数据映射给原版物品挂数据、而完全不用碰原版代码。

## 学习目标

- 说清 1.21 的附魔为什么是「数据驱动的」：json 定义附魔本身，代码只提供「效果组件」。
- 能独立写一个 `enchantment` json，并把 `description`、`supported_items`、`weight`、`max_level`、`anvil_cost`、`effects` 都填对。
- 能实现一个 `EnchantmentEntityEffect` 并注册到 `Registries.ENCHANTMENT_ENTITY_EFFECT_TYPE`，让 json 里的 `"type"` 能找到它。
- 能创建自定义 `DataMapType`，用 json 给任意物品附加数据，并在代码里用 `getData` 取出来。
- 能区分「附魔不出现」的四种原因：路径、标签、`supported_items`、附魔台条件。

## 一、1.21 的附魔是「数据」，不是「类」

在 1.20 及以前，附魔是一个 Java 类：`Enchantment` 的子类，构造函数里写死名字、等级、适用范围，行为靠一堆 `if (enchantment == Enchantments.SHARPNESS)` 硬编码。

1.21 彻底改了。现在的附魔是一个**数据包注册表**（datapack registry），一份 json 就是一个附魔：

```
data/dafeiyu/enchantment/ruby_harvest.json   ← 附魔本体：名字、等级、适用物品、效果
```

代码侧只负责两件事：

1. **定义「效果组件类型」**——告诉游戏「这个附魔可以带一种叫 X 的数据」。
2. **实现效果本身**——当这个数据被触发时，到底发生什么。

这么设计的好处很直接：整合包作者改一个 json 就能调整附魔强度，不用等你重编译；两个模组可以给同一个附魔挂不同的效果组件；附魔也能被 `/reload` 热重载。

代价是：**光写 json 不够**。如果你的效果不是原版内置的那几种，必须先在代码里注册一个「效果类型」，否则 json 里写了 `"type": "dafeiyu:drop_ruby"` 会直接加载失败，报「未知的附魔实体效果类型」。

先看整体结构：

```
附魔 json
 ├─ 元数据：description / weight / max_level / anvil_cost / slots ...
 └─ effects
      └─ "minecraft:post_attack": [ { effect: { type: "dafeiyu:drop_ruby", ... } } ]
                                    ↑ 组件类型（原版内置）   ↑ 效果实现（我们写的）
```

## 二、附魔 json 的每个字段

红宝石剑的「收割」附魔长这样：

```json
// src/main/resources/data/dafeiyu/enchantment/ruby_harvest.json
{
  "description": { "translate": "enchantment.dafeiyu.ruby_harvest" },
  "supported_items": ["dafeiyu:ruby_sword"],
  "weight": 5,
  "max_level": 3,
  "min_cost": { "base": 10, "per_level_above_first": 8 },
  "max_cost": { "base": 40, "per_level_above_first": 8 },
  "anvil_cost": 2,
  "slots": ["mainhand"],
  "effects": {
    "minecraft:post_attack": [
      {
        "enchanted": "attacker",
        "affected": "victim",
        "effect": { "type": "dafeiyu:drop_ruby", "count": 1 }
      }
    ]
  }
}
```

逐个说：

| 字段 | 作用 | 注意 |
|---|---|---|
| `description` | 游戏内显示的名字，可以是 `{"translate": "..."}` 或纯字符串 | 用 `translate` 就必须在 `lang` 里补键，否则显示原始键名 |
| `supported_items` | 这个附魔**能附在哪些物品上**（铁砧、命令、创造模式） | 可以是 id、id 列表、或 `#` 开头的物品标签 |
| `primary_items` | 可选。附魔台**会刷出**哪些物品的附魔 | 不写时等于 `supported_items`；写了不影响铁砧 |
| `weight` | 附魔台的权重，1~1024，越大越常见 | 原版锋利是 10，经验修补是 2 |
| `max_level` | 最大等级，1~255 | 等级上限，不是「默认等级」 |
| `min_cost` / `max_cost` | 附魔台的「附魔能力」区间，`base` 是 1 级的消耗，`per_level_above_first` 是每级递增 | 想让它早期就能出，就把 `base` 调低 |
| `anvil_cost` | 铁砧上每级额外消耗的等级数 | 附魔书减半 |
| `slots` | 在哪些装备槽生效：`any`、`mainhand`、`armor`、`head` 等 | 武器写 `mainhand`，盔甲写对应的槽 |
| `exclusive_set` | 可选。互斥的附魔 id 或标签 | 和锋利冲突就写 `#minecraft:exclusive_set/damage` |
| `effects` | 效果组件表 | 键是**组件类型 id**，值是组件数据 |

一个很常见的误解：`supported_items` 写了物品，附魔台就一定会给你刷出来。不是。附魔台还要求这个物品出现在 `primary_items` 里（不写则等同 `supported_items`），并且这次的附魔能力落在 `min_cost`~`max_cost` 之间。三个条件缺一个，附魔台上就看不到它。

## 三、效果组件：附魔真正的「行为」在哪里

`effects` 里的键不是随便写的，必须是已注册的**附魔效果组件类型**（enchantment effect component）。原版已经提供了一整套，覆盖绝大多数需求：

| 组件 id | 什么时候触发 | 典型用途 |
|---|---|---|
| `minecraft:damage` | 计算攻击伤害时 | 锋利、亡灵杀手 |
| `minecraft:damage_protection` | 计算受伤时 | 保护、火焰保护 |
| `minecraft:post_attack` | 攻击命中并结算伤害后 | 火焰附加、荆棘、抢夺 |
| `minecraft:hit_block` | 弹射物击中方块 | 引雷 |
| `minecraft:tick` | 每 tick | 灵魂疾行 |
| `minecraft:location_changed` | 持有者换方块位置 | 冰霜行者 |
| `minecraft:attributes` | 装备时施加属性修饰符 | 各种「+属性」附魔 |
| `minecraft:equipment_drops` | 被击杀者掉落装备时 | 抢夺 |
| `minecraft:item_damage` | 物品掉耐久时 | 耐久 |

「击杀掉落额外红宝石」用 `post_attack` 最合适：它在伤害结算之后触发，此时受害者如果已经死了，`isDeadOrDying()` 就是 `true`。

`post_attack` 的值是一个列表，每项有三个关键字段：

- `enchanted`：谁身上要有这个附魔才生效——`attacker`（攻击者）、`victim`（受害者）、`damaging_entity`（弹射物）。
- `affected`：效果作用在谁身上，取值同上。
- `effect`：真正要执行的效果，也就是我们自定义的那个。

原版很多组件还会把值包在 `ConditionalEffect` 里，让你能加 `requirements`（战利品表条件）。我们的例子里先不加，保持最小。

### 反过来：在代码里读附魔

不是所有逻辑都适合塞进效果组件。有时你只是想在别处问一句「这把剑有没有某个附魔、几级」。这时用 `EnchantmentHelper`：

```java
// 附魔是数据包条目，代码里只能用 ResourceKey 指代它
private static final ResourceKey<Enchantment> RUBY_HARVEST = ResourceKey.create(
        Registries.ENCHANTMENT,
        ResourceLocation.fromNamespaceAndPath(DafeiyuMod.MOD_ID, "ruby_harvest"));

// stack 是任意 ItemStack
EnchantmentHelper.runIterationOnItem(stack, (enchantmentHolder, level) -> {
    // enchantmentHolder 是 Holder<Enchantment>，level 是等级
    if (enchantmentHolder.is(RUBY_HARVEST)) {
        // 这里做你想做的事
    }
});
```

`runIterationOnItem` 会对物品上的每个附魔回调一次，第二个参数是等级。注意它是**回调**而不是返回一个 Map——这是 1.21 为了性能做的设计，你不需要自己遍历 `DataComponents.ENCHANTMENT` 的内部结构。

### 自定义效果组件类型

上一节用的是原版现成的组件键（`minecraft:post_attack`），只是换了个「值」。如果你想要的是一个**全新的键**——比如 `dafeiyu:ruby_charge`，让附魔能带一个「充能层数」——那就得自己注册一个组件类型。

这些组件在代码里对应 `EnchantmentEffectComponents` 里的常量，注册表键是 `Registries.ENCHANTMENT_EFFECT_COMPONENT_TYPE`，类型是 `DataComponentType<?>`：

```java
// src/main/java/com/dafeiyu/enchantment/ModEnchantmentEffects.java（追加）
// 补一个 import：net.minecraft.core.component.DataComponentType
public static final DeferredRegister<DataComponentType<?>> ENCHANTMENT_COMPONENTS =
        DeferredRegister.create(Registries.ENCHANTMENT_EFFECT_COMPONENT_TYPE, DafeiyuMod.MOD_ID);

public static final DeferredHolder<DataComponentType<?>, DataComponentType<Integer>> RUBY_CHARGE =
        ENCHANTMENT_COMPONENTS.register("ruby_charge",
                () -> DataComponentType.<Integer>builder()
                        .persistent(Codec.INT)
                        .build());
```

注册之后，json 的 `effects` 里就能写 `"dafeiyu:ruby_charge": 3`，代码里这样读：

```java
// enchantmentHolder 来自 runIterationOnItem 的回调
Integer charge = enchantmentHolder.value().effects().get(ModEnchantmentEffects.RUBY_CHARGE.get());
```

两者的区别要分清：**新效果（`EnchantmentEntityEffect`）是「做什么」，新组件（`DataComponentType`）是「在哪个时机做」**。绝大多数需求只需要前者，因为原版的时机（攻击后、被攻击、tick、换位置）已经够用了。

## 四、写一个自己的效果实现

效果实现就是一个实现了 `EnchantmentEntityEffect` 接口的类。这个接口只有一个必须实现的方法：

```java
void apply(ServerLevel level, int enchantLevel, EnchantedItemInUse item, Entity target, Vec3 pos);
```

注意第三个参数是 `EnchantedItemInUse`，不是 `Enchantment`。它包着**触发这次效果的那件物品**（`itemStack()`）、它在哪个槽（`inSlot()`）、以及持有者（`owner()`）。这一点很关键——有了它，我们才能在效果里读武器身上的数据。

文件：`src/main/java/com/dafeiyu/enchantment/DropRubyEffect.java`

```java
package com.dafeiyu.enchantment;

import com.dafeiyu.ModItems;
import com.dafeiyu.datamap.ModDataMaps;
import com.dafeiyu.datamap.RubyAffinity;
import com.mojang.serialization.Codec;
import com.mojang.serialization.MapCodec;
import com.mojang.serialization.codecs.RecordCodecBuilder;
import net.minecraft.server.level.ServerLevel;
import net.minecraft.world.entity.Entity;
import net.minecraft.world.entity.LivingEntity;
import net.minecraft.world.entity.item.ItemEntity;
import net.minecraft.world.item.ItemStack;
import net.minecraft.world.item.enchantment.EnchantedItemInUse;
import net.minecraft.world.item.enchantment.effects.EnchantmentEntityEffect;
import net.minecraft.world.phys.Vec3;

public record DropRubyEffect(int count) implements EnchantmentEntityEffect {

    public static final MapCodec<DropRubyEffect> CODEC = RecordCodecBuilder.mapCodec(instance -> instance.group(
            Codec.INT.fieldOf("count").forGetter(DropRubyEffect::count)
    ).apply(instance, DropRubyEffect::new));

    @Override
    public void apply(ServerLevel level, int enchantLevel, EnchantedItemInUse item, Entity target, Vec3 pos) {
        // 只处理"这一下把人打死了"的情况
        if (!(target instanceof LivingEntity living) || !living.isDeadOrDying()) {
            return;
        }

        // 等级越高掉得越多
        int total = count * enchantLevel;

        // 武器身上如果挂了数据映射，再追加一份
        RubyAffinity affinity = item.itemStack().getItemHolder().getData(ModDataMaps.RUBY_AFFINITY);
        if (affinity != null) {
            total += affinity.extraDrops();
        }
        if (total <= 0) {
            return;
        }

        ItemStack drop = new ItemStack(ModItems.RUBY.get(), total);
        ItemEntity entity = new ItemEntity(level, living.getX(), living.getY() + 0.5, living.getZ(), drop);
        level.addFreshEntity(entity);
    }

    @Override
    public MapCodec<? extends EnchantmentEntityEffect> codec() {
        return CODEC;
    }
}
```

逐行解释几个点：

- **为什么用 record**：效果是纯数据（只有一个 `count`），record 自动生成构造器、`equals`、`hashCode`，正好符合「不可变数据」的要求。
- **`MapCodec` 而不是 `Codec`**：附魔效果在 json 里是一个对象（`{"type": ..., "count": 1}`），`type` 由外层分发器处理，剩下的字段由 `MapCodec` 读。`RecordCodecBuilder.mapCodec` 就是干这个的。
- **`fieldOf("count")`**：json 里的键名必须和这里一致。你写 `count`，json 就必须是 `count`；写成 `amount` 会报「缺少字段 count」。
- **`codec()` 返回什么**：外层分发器靠它把 json 的 `"type"` 映射到具体类，所以必须返回你注册时用的那个 `CODEC`。

注册它：

文件：`src/main/java/com/dafeiyu/enchantment/ModEnchantmentEffects.java`

```java
package com.dafeiyu.enchantment;

import com.dafeiyu.DafeiyuMod;
import com.mojang.serialization.MapCodec;
import net.minecraft.core.registries.Registries;
import net.minecraft.world.item.enchantment.effects.EnchantmentEntityEffect;
import net.neoforged.neoforge.registries.DeferredHolder;
import net.neoforged.neoforge.registries.DeferredRegister;

public class ModEnchantmentEffects {
    public static final DeferredRegister<MapCodec<? extends EnchantmentEntityEffect>> ENTITY_EFFECTS =
            DeferredRegister.create(Registries.ENCHANTMENT_ENTITY_EFFECT_TYPE, DafeiyuMod.MOD_ID);

    public static final DeferredHolder<MapCodec<? extends EnchantmentEntityEffect>, MapCodec<DropRubyEffect>> DROP_RUBY =
            ENTITY_EFFECTS.register("drop_ruby", () -> DropRubyEffect.CODEC);
}
```

注册名 `drop_ruby` 就是 json 里 `"type": "dafeiyu:drop_ruby"` 的后半截。主类里别忘了 `ModEnchantmentEffects.ENTITY_EFFECTS.register(modEventBus);`。

顺便补语言文件：

```json
// src/main/resources/assets/dafeiyu/lang/zh_cn.json（在已有内容里追加）
{
  "enchantment.dafeiyu.ruby_harvest": "红宝石收割",
  "enchantment.dafeiyu.ruby_harvest.desc": "击杀生物时额外掉落红宝石"
}
```

进游戏后，手持红宝石剑执行 `/enchant @s dafeiyu:ruby_harvest 3`，就能拿到 3 级附魔。

## 五、数据映射：给已有对象挂数据

现在回到 `RubyAffinity` 那行代码。它是「数据映射（data map）」。

数据映射解决的问题是：**你想给一个已经注册好的对象（原版物品、原版方块、甚至别人的模组物品）附加一点数据，但不想为它写子类，也不想 Mixin。**

你可以把它理解成「标签的加强版」：标签是「对象 → 布尔值」，数据映射是「对象 → 任意结构化数据」。它同样是**增量**的——多个模组、多个数据包往同一张映射里加值，而不是互相覆盖。而且它支持 `/reload` 热重载，还能同步到客户端。

NeoForge 已经内置了一批，直接写 json 就能用，不用写一行 Java：

| 内置映射 | 作用 | 文件位置 |
|---|---|---|
| `neoforge:furnace_fuels` | 物品的燃烧时间 | `neoforge/data_maps/item/furnace_fuels.json` |
| `neoforge:compostables` | 堆肥桶成功率 | `neoforge/data_maps/item/compostables.json` |
| `neoforge:waxables` | 上蜡后的方块 | `neoforge/data_maps/block/waxables.json` |
| `neoforge:oxidizables` | 铜的下一氧化阶段 | `neoforge/data_maps/block/oxidizables.json` |
| `neoforge:villager_types` | 群系对应的村民类型 | `neoforge/data_maps/worldgen/biome/villager_types.json` |

比如让红宝石能当燃料，只要一个 json：

```json
// src/main/resources/data/dafeiyu/data_maps/item/furnace_fuels.json
{
  "values": {
    "dafeiyu:ruby": { "burn_time": 1600 }
  }
}
```

注意这个文件放在**你自己的**命名空间下（`data/dafeiyu/data_maps/item/...`），路径里的 `item` 是**注册表**的名字，不是映射的名字。

### 自定义数据映射

内置的映射不够用时，自己定义一个。分三步：定义数据类、创建 `DataMapType`、注册。

**第一步，数据类。** 必须是不可变的，所以用 record：

文件：`src/main/java/com/dafeiyu/datamap/RubyAffinity.java`

```java
package com.dafeiyu.datamap;

import com.mojang.serialization.Codec;
import com.mojang.serialization.codecs.RecordCodecBuilder;

public record RubyAffinity(int extraDrops) {
    public static final Codec<RubyAffinity> CODEC = RecordCodecBuilder.create(instance -> instance.group(
            Codec.intRange(0, 16).fieldOf("extra_drops").forGetter(RubyAffinity::extraDrops)
    ).apply(instance, RubyAffinity::new));
}
```

**第二步，创建映射。** 指定 id、挂到哪个注册表、用什么 codec：

文件：`src/main/java/com/dafeiyu/datamap/ModDataMaps.java`

```java
package com.dafeiyu.datamap;

import com.dafeiyu.DafeiyuMod;
import net.minecraft.core.registries.Registries;
import net.minecraft.resources.ResourceLocation;
import net.minecraft.world.item.Item;
import net.neoforged.bus.api.SubscribeEvent;
import net.neoforged.fml.common.EventBusSubscriber;
import net.neoforged.neoforge.registries.datamaps.DataMapType;
import net.neoforged.neoforge.registries.datamaps.RegisterDataMapTypesEvent;

@EventBusSubscriber(modid = DafeiyuMod.MOD_ID, bus = EventBusSubscriber.Bus.MOD)
public class ModDataMaps {

    public static final DataMapType<Item, RubyAffinity> RUBY_AFFINITY = DataMapType.builder(
                    ResourceLocation.fromNamespaceAndPath(DafeiyuMod.MOD_ID, "ruby_affinity"),
                    Registries.ITEM,
                    RubyAffinity.CODEC)
            // 第二个参数 false 表示"非强制"：客户端没有这张映射也不会被踢
            .synced(RubyAffinity.CODEC, false)
            .build();

    @SubscribeEvent
    public static void register(RegisterDataMapTypesEvent event) {
        event.register(RUBY_AFFINITY);
    }
}
```

`ResourceLocation` 的路径 `ruby_affinity` 决定了 json 放哪儿：`data/dafeiyu/data_maps/item/ruby_affinity.json`。

**第三步，写数据。**

```json
// src/main/resources/data/dafeiyu/data_maps/item/ruby_affinity.json
{
  "values": {
    "dafeiyu:ruby_sword": { "extra_drops": 2 },
    "minecraft:diamond_sword": { "extra_drops": 1 }
  }
}
```

看到了吗？第二行给**原版的钻石剑**也挂了数据，我们一行原版代码都没改。这就是数据映射最大的价值。

**第四步，读数据。** 数据映射挂在 `Holder` 上，不是挂在对象上，所以要用 `getItemHolder()` 拿 holder：

```java
// 任何能拿到 ItemStack 的地方
RubyAffinity affinity = stack.getItemHolder().getData(ModDataMaps.RUBY_AFFINITY);
if (affinity != null) {
    int extra = affinity.extraDrops();
}
```

没有数据时返回 `null`，不是返回默认值——所以永远要判空。

## 六、把两者串起来

回头看 `DropRubyEffect.apply`，它做了三件事：判断目标是否死亡、按等级算基础数量、**从武器的 holder 上读数据映射追加数量**。

这就是附魔和数据映射的正确组合方式：**附魔负责「什么时候触发」，数据映射负责「不同物品的差异化参数」**。以后你想让「红宝石斧」也触发这个效果但掉得更多，只要在 `ruby_affinity.json` 里加一行，不用改 Java。

## 完整示例

```text
src/main/java/com/dafeiyu/enchantment/DropRubyEffect.java
src/main/java/com/dafeiyu/enchantment/ModEnchantmentEffects.java
src/main/java/com/dafeiyu/datamap/RubyAffinity.java
src/main/java/com/dafeiyu/datamap/ModDataMaps.java
src/main/resources/data/dafeiyu/enchantment/ruby_harvest.json
src/main/resources/data/dafeiyu/data_maps/item/ruby_affinity.json
src/main/resources/assets/dafeiyu/lang/zh_cn.json
```

主类里补两行注册：

```java
// src/main/java/com/dafeiyu/DafeiyuMod.java
public DafeiyuMod(IEventBus modEventBus, ModContainer container) {
    ModItems.ITEMS.register(modEventBus);
    ModBlocks.BLOCKS.register(modEventBus);
    // ... 其他注册
    ModEnchantmentEffects.ENTITY_EFFECTS.register(modEventBus);
    // 只有你要自定义"效果组件类型"时才需要这一行
    ModEnchantmentEffects.ENCHANTMENT_COMPONENTS.register(modEventBus);
    // 数据映射走 @EventBusSubscriber，不需要手动注册
}
```

验证步骤：进世界 → 拿到红宝石剑 → `/enchant @s dafeiyu:ruby_harvest 3` → 杀一只猪 → 地上应该有 3 个红宝石（3 级 × count 1），如果剑上有 `extra_drops: 2`，就是 5 个。

## 常见坑与报错

| 现象 | 原因 | 解决 |
|---|---|---|
| 附魔完全不加载，日志说 `Unknown enchantment` | json 放进了 `enchantments/`（复数） | 目录是 `data/dafeiyu/enchantment/`，单数 |
| 附魔加载失败，日志提到 `Unknown item tag` | `supported_items` 用了 `#dafeiyu:xxx`，但标签文件不存在 | 要么补标签文件，要么直接写物品 id 列表 |
| 铁砧能附，附魔台永远刷不出 | `min_cost`/`max_cost` 区间太窄或太高，或者没写 `primary_items` | 先照抄原版某个附魔的 cost，再微调 |
| 附魔名字显示 `enchantment.dafeiyu.ruby_harvest` | `lang` 里没这个键，或文件名不是 `zh_cn.json` | 补 `enchantment.<命名空间>.<路径>` |
| 启动崩溃：`Unknown enchantment entity effect type` | `"type": "dafeiyu:drop_ruby"` 对应的效果没注册，或注册名拼错 | 检查 `ENTITY_EFFECTS.register("drop_ruby", ...)` 和主类里的 `register(modEventBus)` |
| 附魔生效但什么都不掉 | `post_attack` 的 `affected`/`enchanted` 写反了，效果作用到了攻击者身上 | 攻击者带附魔 → `enchanted: attacker`；掉落在受害者位置 → `affected: victim` |
| 数据映射读出来永远是 `null` | 用了 `Direct` holder（例如 `Holder.direct(stack.getItem())`），或 json 路径写错 | 用 `stack.getItemHolder()`；路径必须是 `data_maps/item/<映射名>.json` |
| 改完数据映射 json，游戏里没变化 | 忘了 `/reload` | 数据映射支持热重载，`/reload` 即可 |
| 客户端读不到数据映射 | 创建时没调 `.synced(...)` | 需要在客户端读就加 `.synced(codec, false)` |
| 多人游戏里客户端崩，提示缺少数据映射 | `.synced(codec, true)` 设成了强制 | 模组的映射一般用 `false` |

## 练习

1. **基础**：把 `ruby_harvest` 的 `max_level` 改成 5，`weight` 改成 30，观察附魔台出现的频率变化；再用 `/enchant` 直接给 5 级，确认掉落数量随等级线性增长。
2. **进阶**：给这个附魔加一个 `minecraft:damage` 组件，让每级额外造成 1 点伤害（提示：`"effect": {"type": "minecraft:add", "value": {"type": "minecraft:linear", "base": 1, "per_level_above_first": 1}}`），并验证它和锋利能叠加。
3. **挑战**：把 `RubyAffinity` 改成 `Map<String, Integer>` 结构，用 `AdvancedDataMapType` 配一个合并器，让两个数据包给同一把剑的 `extra_drops` 相加而不是互相覆盖。
