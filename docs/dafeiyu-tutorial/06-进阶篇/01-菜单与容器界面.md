# 菜单与容器界面

> 读完这篇，你能做出一个真正能用的 3×3「红宝石箱子」：右键打开、九个格子能放能取、Shift 点击能整堆转移、标题显示中文、界面上还有一条跟着格子占用率变化的进度条。

## 学习目标

- 能说清 `AbstractContainerMenu`、`Screen`、`MenuType` 三件套各自负责什么，以及为什么缺一不可。
- 能写出服务端和客户端两个构造器，并解释「客户端那个构造器里的容器为什么是个空壳」。
- 能自己实现 `quickMoveStack`，让 Shift 点击在两个区域之间正确搬运物品。
- 能用 `ContainerData` + `SimpleContainerData` 把服务端的一个整数（进度条）同步到客户端。
- 能说出「打开 GUI 为什么必须由服务端发起」，以及漏掉哪一行会导致界面空白。

## 一、先把三件套摆清楚

你在游戏里右键一个箱子，屏幕上出现一个界面，你把泥土拖进去，退出后泥土还在。这短短几秒里，实际上有**三个完全不同的东西**在配合：

```
        服务端（真正的数据）                客户端（只负责画和收输入）
   ┌──────────────────────────┐      ┌──────────────────────────┐
   │  BlockEntity             │      │  Screen                  │
   │    └ ItemStackHandler    │      │    └ 画背景、画标题、画槽位│
   │         ↑                │      │         ↑                │
   │  AbstractContainerMenu   │ ───→ │  AbstractContainerMenu   │
   │    └ Slot（9 个）        │ 网络  │    └ Slot（9 个，空壳）   │
   │    └ ContainerData       │ 同步  │    └ SimpleContainerData  │
   └──────────────────────────┘      └──────────────────────────┘
              ↑ 由 MenuType 这个"工厂"创建出两边各一份
```

| 东西 | 在哪一侧 | 干什么 | 一句话记住 |
|---|---|---|---|
| `AbstractContainerMenu` | 两侧都有 | 逻辑层：管槽位、管 Shift 点击、管哪些数据要同步 | 「规则」 |
| `Screen`（这里是 `AbstractContainerScreen`） | 只有客户端 | 画图：背景、标题、进度条、鼠标拖着的物品 | 「长相」 |
| `MenuType` | 两侧都注册 | 工厂 + 身份证：告诉游戏「这种菜单怎么 new 出来」 | 「户口本」 |

三个都要有，少一个就出问题：

- 只有 `MenuType` 没有 `Screen` → 右键后屏幕闪一下，什么也不显示（或者直接报「没有对应的界面」）。
- 只有 `Screen` 没有 `MenuType` → 游戏根本不知道该怎么创建这个菜单，崩溃在 `Unknown menu type`。
- 有前两个但没有 `AbstractContainerMenu` → 你没有任何地方放 `Slot`，物品栏格子画不出来。

**为什么菜单不是注册表对象？** 因为菜单是「动态创建、随时销毁」的：你开一次箱子就 new 一个，关掉就丢掉。注册表里放的东西必须全局唯一、永不销毁（比如 `Item`、`Block`）。所以注册表里放的只能是「怎么造菜单」的说明书，也就是 `MenuType`。

## 二、MenuType：一个装着构造器的盒子

`MenuType` 的构造器要两个参数：一个 `MenuSupplier`（其实就是 `(int, Inventory) -> 菜单` 的函数），一个 `FeatureFlagSet`（功能开关，写 `FeatureFlags.DEFAULT_FLAGS` 就行）。

文件：`src/main/java/com/dafeiyu/ModMenus.java`

```java
package com.dafeiyu;

import net.minecraft.core.registries.Registries;
import net.minecraft.world.flag.FeatureFlags;
import net.minecraft.world.inventory.MenuType;
import net.neoforged.bus.api.IEventBus;
import net.neoforged.neoforge.registries.DeferredHolder;
import net.neoforged.neoforge.registries.DeferredRegister;

public class ModMenus {
    public static final DeferredRegister<MenuType<?>> MENUS =
            DeferredRegister.create(Registries.MENU, DafeiyuMod.MOD_ID);

    public static final DeferredHolder<MenuType<?>, MenuType<RubyChestMenu>> RUBY_CHEST =
            MENUS.register("ruby_chest",
                    () -> new MenuType<>(RubyChestMenu::new, FeatureFlags.DEFAULT_FLAGS));

    public static void register(IEventBus modEventBus) {
        MENUS.register(modEventBus);
    }
}
```

注意 `RubyChestMenu::new` 这个**方法引用**（不熟的看 [双冒号与方法引用](../02-Java补充篇/02-双冒号与方法引用.md)）。它必须指向一个**只接收 `(int, Inventory)` 两个参数**的构造器——这是 `MenuSupplier` 的签名，编译器会替你检查。所以你的菜单类里必须有一个这样的构造器：

```java
public RubyChestMenu(int containerId, Inventory playerInventory) { ... }
```

**这个两参数构造器是给客户端用的。** 这点非常重要，后面第六节会专门讲。

`containerId` 是「这个玩家这次打开的菜单编号」，同一个玩家同一时间只会有唯一的一个。它由游戏分配，你只管往下传，不要自己造。

## 三、槽位 Slot：菜单里的「一个格子」

`Slot` 是一个**视图**，它自己不存物品，只是「指向某个容器里的第几个格子，并且规定它在界面上画在哪」。

NeoForge 里推荐用 `SlotItemHandler`，它指向一个 `IItemHandler`（`ItemStackHandler` 就实现了它）：

```java
new SlotItemHandler(handler, 槽位索引, 界面上的x, 界面上的y)
```

四个参数分别是：容器、这个格子是容器里的第几个、左上角 x、左上角 y。**x/y 是相对于界面左上角的坐标，不是屏幕坐标**，这一点新手最容易搞错——你写 `62` 就是「距界面左边 62 像素」，不管窗口多大、GUI 缩放是多少。

`Slot` 的子类可以重写几个方法改变行为，常用的三个：

| 方法 | 作用 | 典型用法 |
|---|---|---|
| `mayPlace(ItemStack)` | 这个格子收不收这件物品 | 只允许放红宝石 |
| `mayPickup(Player)` | 玩家能不能从这里拿走 | 输出格在没完成时不给拿 |
| `getMaxStackSize()` | 这个格子最多堆多少 | 做成「每格 1 个」的展示格 |

### quickMoveStack：Shift 点击的搬运工

你在箱子里按住 Shift 点一个物品，它会「嗖」地飞到玩家背包里。这个动作不是 `Slot` 干的，而是菜单的 `quickMoveStack(Player player, int index)` 干的。

规则很简单：**游戏只负责调用你，往哪搬由你决定**。你必须实现它，否则 Shift 点击什么也不会发生（`AbstractContainerMenu` 里它是抽象方法，不写编译不过）。

搬运用 `moveItemStackTo(堆叠, 起始槽位, 结束槽位, 是否从后往前)`，注意**结束槽位是不包含的**（左闭右开），第四个参数为 `true` 时从后往前找空位。

标准写法是这样的骨架：

```java
@Override
public ItemStack quickMoveStack(Player player, int index) {
    Slot slot = this.slots.get(index);
    if (!slot.hasItem()) {
        return ItemStack.EMPTY;          // 空格子，什么也不做
    }
    ItemStack stackInSlot = slot.getItem();
    ItemStack copy = stackInSlot.copy(); // 返回值：被移动的那堆物品的副本

    if (index < 9) {
        // 从箱子搬到玩家背包（9 ~ 45）
        if (!this.moveItemStackTo(stackInSlot, 9, 45, true)) {
            return ItemStack.EMPTY;
        }
    } else {
        // 从玩家背包搬进箱子（0 ~ 9）
        if (!this.moveItemStackTo(stackInSlot, 0, 9, false)) {
            return ItemStack.EMPTY;
        }
    }

    if (stackInSlot.isEmpty()) {
        slot.set(ItemStack.EMPTY);
    } else {
        slot.setChanged();               // 没搬完，通知容器内容变了
    }
    slot.onTake(player, stackInSlot);
    return copy;
}
```

三个细节：

1. **`index` 是「槽位在菜单里的序号」，不是「容器里的序号」。** 我们先加了 9 个箱子槽位，再加 27 个背包、9 个快捷栏，所以菜单里 `0~8` 是箱子，`9~35` 是背包，`36~44` 是快捷栏。这个对应关系必须和你 `addSlot` 的顺序完全一致，否则 Shift 点击会把物品搬进虚空。
2. **`moveItemStackTo` 返回 `false` 表示一个都没搬动**（目标区域全满），这时要立刻 `return ItemStack.EMPTY`，否则后面 `slot.set(...)` 会把物品清掉——这就是「Shift 点击后物品消失」的经典 bug。
3. **返回值是「原来那堆的副本」**，游戏拿它做客户端预测。返回 `ItemStack.EMPTY` 表示「这次搬运不算数」。

## 四、打开 GUI：为什么必须由服务端发起

这是全篇最重要的一句话：

> **客户端的界面，是服务端「命令」它打开的，不是客户端自己想开就能开的。**

原因在于两侧各跑各的：服务端有真正的 `BlockEntity` 和物品，客户端只有一个「看起来一样」的副本。如果客户端自己 new 一个菜单打开，服务端根本不知道这回事，你放进去的物品没人接收，关掉界面就全没了。

所以流程是：

```
玩家右键
  → 服务端执行 useWithoutItem
  → 服务端 new 出服务端菜单（带真实容器）
  → 服务端发 ClientboundOpenScreenPacket（含 MenuType 的 id、containerId、标题）
  → 客户端收到包，用 MenuType 里的构造器 new 出客户端菜单（带空壳容器）
  → 客户端打开对应的 Screen
```

服务端这边你只需要一行：

```java
serverPlayer.openMenu(provider);
```

`openMenu` 接收一个 `MenuProvider`。`MenuProvider` 就两个方法：`createMenu(...)` 造服务端菜单，`getDisplayName()` 给标题。最省事的实现是让方块实体**自己实现** `MenuProvider`，然后用 `SimpleMenuProvider` 也行：

```java
// 写法一：方块实体实现 MenuProvider，直接传 this
serverPlayer.openMenu(blockEntity);

// 写法二：现场包一个
serverPlayer.openMenu(new SimpleMenuProvider(
        (containerId, playerInventory, player) -> new RubyChestMenu(containerId, playerInventory, ...),
        Component.translatable("container.dafeiyu.ruby_chest")));
```

方块这边还要重写 `getMenuProvider`，因为**旁观者模式**下游戏要靠它打开同一个界面（旁观者不能触发 `useWithoutItem`）。这就是原版那套「右键 + 旁观」双入口的由来。

```java
@Override
protected InteractionResult useWithoutItem(BlockState state, Level level, BlockPos pos, Player player, BlockHitResult hit) {
    if (!level.isClientSide && player instanceof ServerPlayer serverPlayer) {
        serverPlayer.openMenu(state.getMenuProvider(level, pos));
    }
    // 两侧都返回"成功"：客户端不做事但要摆手，服务端负责开界面
    return InteractionResult.sidedSuccess(level.isClientSide);
}
```

`!level.isClientSide` 这个判断不能省。少了它，客户端也会尝试 `openMenu`，而客户端的 `ServerPlayer` 根本不存在（`instanceof` 会失败，不崩，但你会以为代码没生效）。

## 五、客户端注册界面

服务端只发了一个「打开 ruby_chest 菜单」的包，客户端拿到 `MenuType` 之后能 new 出菜单，但**不知道要用哪个 `Screen` 来画**。这个映射关系要你自己注册：

文件：`src/main/java/com/dafeiyu/client/ClientSetup.java`

```java
package com.dafeiyu.client;

import com.dafeiyu.DafeiyuMod;
import com.dafeiyu.ModMenus;
import net.neoforged.api.distmarker.Dist;
import net.neoforged.bus.api.SubscribeEvent;
import net.neoforged.fml.common.EventBusSubscriber;
import net.neoforged.neoforge.client.event.RegisterMenuScreensEvent;

// 只在物理客户端加载这个类；bus = MOD 表示监听模组总线
@EventBusSubscriber(modid = DafeiyuMod.MOD_ID, bus = EventBusSubscriber.Bus.MOD, value = Dist.CLIENT)
public class ClientSetup {
    @SubscribeEvent
    public static void registerScreens(RegisterMenuScreensEvent event) {
        event.register(ModMenus.RUBY_CHEST.get(), RubyChestScreen::new);
    }
}
```

`RubyChestScreen::new` 又是个方法引用，它必须匹配 `(菜单, Inventory, Component) -> Screen` 三参数构造器——正好是 `AbstractContainerScreen` 的构造器签名。

**为什么这个类必须放在 `client` 包里、还要标 `value = Dist.CLIENT`？** 因为 `Screen`、`GuiGraphics` 这些类只在客户端 jar 里有。如果你把 `import net.minecraft.client.gui.screens.Screen` 写在 `RubyChestMenu` 里，那么**专用服务器**启动时会尝试加载这个类，然后 `NoClassDefFoundError` 直接崩服。这是模组发布前最常见的崩溃之一，记住这条界线：

> 任何 `net.minecraft.client.*` 的 import，只能出现在 `client` 包下的类里。

## 六、数据同步：让客户端看见进度条

槽位里的物品不用你操心，游戏每 tick 自动比对并同步。但**你自己加的整数**（比如进度条、能量、燃烧时间）不会自动同步，得用 `DataSlot` 或 `ContainerData`。

- 只有一个整数 → `DataSlot`，用 `addDataSlot(...)` 加。
- 有多个整数 → `ContainerData`，用 `addDataSlots(...)` 加。**推荐这个**，因为它的 `get(int index)` / `set(int index, int value)` 用下标区分，扩展方便。

关键点：**两侧的构造器必须给出一模一样数量的 `ContainerData`**。服务端给真实的（从方块实体读），客户端给一个 `new SimpleContainerData(n)` 空壳（等着被同步填充）。

```java
// 客户端构造器
this(containerId, playerInventory, new ItemStackHandler(9), new SimpleContainerData(1), ContainerLevelAccess.NULL);

// 服务端构造器里检查数量，数量不对会立刻抛异常而不是"默默不同步"
checkContainerDataCount(data, 1);
this.addDataSlots(data);
```

`SimpleContainerData` 就是一个 `int[]`，服务端每 tick 把自己的值推过来覆盖它，所以客户端 `menu.getProgress()` 读到的永远是「上一次同步的值」。这也解释了为什么进度条会有一点点延迟——它不是实时的。

`ContainerData` 的三个方法：

| 方法 | 谁调用 | 你要做什么 |
|---|---|---|
| `get(int index)` | 两侧都调 | 返回第 index 个整数的当前值 |
| `set(int index, int value)` | 只有客户端同步时调 | 写进本地字段（服务端一般不写） |
| `getCount()` | 两侧 | 一共几个整数 |

> **一个坑**：`DataSlot` 走的是 short 通道（-32768~32767），超过会被截断。NeoForge 修补了这个包，但如果你在旧版本代码里看到进度条到 32767 就卡住，就是这个原因。用 `ContainerData` 也一样，**别拿它同步大数**（比如 `System.currentTimeMillis()`），大数走自定义网络包（见 [网络通信](05-网络通信.md)）。

**② `src/main/java/com/dafeiyu/RubyChestBlockEntity.java`**

```java
package com.dafeiyu;

import net.minecraft.core.BlockPos;
import net.minecraft.core.HolderLookup;
import net.minecraft.nbt.CompoundTag;
import net.minecraft.network.chat.Component;
import net.minecraft.world.MenuProvider;
import net.minecraft.world.entity.player.Inventory;
import net.minecraft.world.entity.player.Player;
import net.minecraft.world.inventory.AbstractContainerMenu;
import net.minecraft.world.inventory.ContainerData;
import net.minecraft.world.inventory.ContainerLevelAccess;
import net.minecraft.world.level.block.entity.BlockEntity;
import net.minecraft.world.level.block.state.BlockState;
import net.neoforged.neoforge.items.ItemStackHandler;

public class RubyChestBlockEntity extends BlockEntity implements MenuProvider {
    public static final int SLOT_COUNT = 9;
    private static final String TAG_INVENTORY = "inventory";

    // 九个格子。onContentsChanged 里调 setChanged()，否则退出重进物品全没了
    private final ItemStackHandler inventory = new ItemStackHandler(SLOT_COUNT) {
        @Override
        protected void onContentsChanged(int slot) {
            setChanged();
        }
    };

    // 只有 1 个整数：格子占用率 0~100
    public final ContainerData dataAccess = new ContainerData() {
        @Override
        public int get(int index) {
            return index == 0 ? RubyChestBlockEntity.this.getFillPercent() : 0;
        }

        @Override
        public void set(int index, int value) {
            // 进度是算出来的，不接受外部写入
        }

        @Override
        public int getCount() {
            return 1;
        }
    };

    public RubyChestBlockEntity(BlockPos pos, BlockState state) {
        super(ModBlockEntities.RUBY_CHEST.get(), pos, state);
    }

    public ItemStackHandler getInventory() {
        return inventory;
    }

    private int getFillPercent() {
        int filled = 0;
        for (int i = 0; i < inventory.getSlots(); i++) {
            if (!inventory.getStackInSlot(i).isEmpty()) {
                filled++;
            }
        }
        return filled * 100 / SLOT_COUNT;
    }

    // ---------- MenuProvider ----------

    @Override
    public Component getDisplayName() {
        return Component.translatable("container.dafeiyu.ruby_chest");
    }

    @Override
    public AbstractContainerMenu createMenu(int containerId, Inventory playerInventory, Player player) {
        return new RubyChestMenu(containerId, playerInventory, inventory, dataAccess,
                ContainerLevelAccess.create(this.level, this.worldPosition));
    }

    // ---------- 存档 ----------

    @Override
    protected void saveAdditional(CompoundTag tag, HolderLookup.Provider registries) {
        super.saveAdditional(tag, registries);
        tag.put(TAG_INVENTORY, inventory.serializeNBT(registries));
    }

    @Override
    protected void loadAdditional(CompoundTag tag, HolderLookup.Provider registries) {
        super.loadAdditional(tag, registries);
        if (tag.contains(TAG_INVENTORY)) {
            inventory.deserializeNBT(registries, tag.getCompound(TAG_INVENTORY));
        }
    }
}
```

**③ `src/main/java/com/dafeiyu/RubyChestMenu.java`**

```java
package com.dafeiyu;

import net.minecraft.world.entity.player.Inventory;
import net.minecraft.world.entity.player.Player;
import net.minecraft.world.inventory.AbstractContainerMenu;
import net.minecraft.world.inventory.ContainerData;
import net.minecraft.world.inventory.ContainerLevelAccess;
import net.minecraft.world.inventory.SimpleContainerData;
import net.minecraft.world.inventory.Slot;
import net.minecraft.world.item.ItemStack;
import net.neoforged.neoforge.items.IItemHandler;
import net.neoforged.neoforge.items.ItemStackHandler;
import net.neoforged.neoforge.items.SlotItemHandler;

public class RubyChestMenu extends AbstractContainerMenu {
    private static final int CHEST_SLOTS = 9;
    private static final int PLAYER_START = CHEST_SLOTS;         // 9
    private static final int PLAYER_END = PLAYER_START + 27;     // 36
    private static final int HOTBAR_END = PLAYER_END + 9;        // 45

    private final ContainerData data;
    private final ContainerLevelAccess access;

    /** 客户端构造器：MenuType 用的就是它。容器是空壳，内容靠服务端同步 */
    public RubyChestMenu(int containerId, Inventory playerInventory) {
        this(containerId, playerInventory,
                new ItemStackHandler(CHEST_SLOTS),   // 空壳
                new SimpleContainerData(1),          // 空壳
                ContainerLevelAccess.NULL);          // 客户端不做距离检查
    }

    /** 服务端构造器：容器和 ContainerData 都是真的 */
    public RubyChestMenu(int containerId, Inventory playerInventory,
                         IItemHandler chestInventory, ContainerData data,
                         ContainerLevelAccess access) {
        super(ModMenus.RUBY_CHEST.get(), containerId);
        checkContainerDataCount(data, 1);
        this.data = data;
        this.access = access;

        // 3×3 箱子槽位：索引 0~8
        for (int row = 0; row < 3; row++) {
            for (int col = 0; col < 3; col++) {
                this.addSlot(new SlotItemHandler(chestInventory, col + row * 3,
                        62 + col * 18, 17 + row * 18));
            }
        }

        // 玩家背包 27 格：索引 9~35
        for (int row = 0; row < 3; row++) {
            for (int col = 0; col < 9; col++) {
                this.addSlot(new Slot(playerInventory, 9 + col + row * 9,
                        8 + col * 18, 84 + row * 18));
            }
        }

        // 快捷栏 9 格：索引 36~44
        for (int col = 0; col < 9; col++) {
            this.addSlot(new Slot(playerInventory, col, 8 + col * 18, 142));
        }

        this.addDataSlots(data);
    }

    public int getProgress() {
        return this.data.get(0);
    }

    @Override
    public boolean stillValid(Player player) {
        return stillValid(this.access, player, ModBlocks.RUBY_CHEST.get());
    }

    @Override
    public ItemStack quickMoveStack(Player player, int index) {
        Slot slot = this.slots.get(index);
        if (!slot.hasItem()) {
            return ItemStack.EMPTY;
        }
        ItemStack stackInSlot = slot.getItem();
        ItemStack copy = stackInSlot.copy();

        if (index < CHEST_SLOTS) {
            if (!this.moveItemStackTo(stackInSlot, PLAYER_START, HOTBAR_END, true)) {
                return ItemStack.EMPTY;
            }
        } else {
            if (!this.moveItemStackTo(stackInSlot, 0, CHEST_SLOTS, false)) {
                return ItemStack.EMPTY;
            }
        }

        if (stackInSlot.isEmpty()) {
            slot.set(ItemStack.EMPTY);
        } else {
            slot.setChanged();
        }
        slot.onTake(player, stackInSlot);
        return copy;
    }
}
```

## 常见坑与报错

| 现象 | 原因 | 解决 |
|---|---|---|
| 右键后屏幕闪一下，什么都没 | 忘了 `event.register(ModMenus.RUBY_CHEST.get(), RubyChestScreen::new)` | 补 `RegisterMenuScreensEvent` |
| 界面打开了，但是一片黑/紫色方块 | 贴图路径不对，或 PNG 尺寸不是 176×166 | 路径必须是 `textures/gui/container/xxx.png`，且不带 `assets/dafeiyu/` 前缀 |
| 标题显示 `container.dafeiyu.ruby_chest` 原文 | 语言文件没加，或键名拼错 | 对照 `getDisplayName()` 里的字符串逐字检查 |
| 客户端崩溃 `NullPointerException` 在 `addSlot` | 客户端构造器传了 `null` 容器 | 客户端必须给 `new ItemStackHandler(9)` 这种空壳 |
| 打开界面后槽位里能看到物品，但拿不动 | `stillValid` 恒为 `false` | 客户端要传 `ContainerLevelAccess.NULL`，服务端传 `create(level, pos)` |
| 退出重进物品消失 | `onContentsChanged` 里没调 `setChanged()`，或 `saveAdditional` 没写 inventory | 两个都补上 |
| Shift 点击后物品凭空消失 | `moveItemStackTo` 返回 `false` 时没有提前 `return` | 见第三节第 2 条 |
| 启动崩服 `NoClassDefFoundError: net/minecraft/client/...` | 客户端类被服务端加载了 | 把 `Screen` 相关代码挪进 `client` 包，类上标 `value = Dist.CLIENT` |
| `IndexOutOfBoundsException` 在 `slots.get(i)` | `quickMoveStack` 里的索引范围和 `addSlot` 顺序对不上 | 数一遍：9 + 27 + 9 = 45 |
| 进度条永远是 0 | 客户端 `SimpleContainerData` 的数量和服务端 `ContainerData` 不一致 | 两侧都写 `1`，服务端加 `checkContainerDataCount(data, 1)` |

## 练习

1. **（易）** 把 3×3 改成 5×3（15 格），要求 `quickMoveStack` 的索引范围跟着改对。改完后用 Shift 点击验证两个方向都能搬。
2. **（中）** 让箱子只接受红宝石：重写 `SlotItemHandler#mayPlace`，只允许 `stack.is(ModItems.RUBY.get())` 返回 `true`。再想想——为什么这个限制写在 `Slot` 里就够了，服务端不用另外检查？（提示：`Slot#mayPlace` 在服务端也会被调用。）
3. **（难）** 加第二个同步值「最近一次放入物品的游戏时间」，用一个 `long` 存。你会发现 `ContainerData` 装不下 `long`，请改用 `05-网络通信.md` 里的自定义包把时间发给客户端，并让界面显示成「x 秒前」。
