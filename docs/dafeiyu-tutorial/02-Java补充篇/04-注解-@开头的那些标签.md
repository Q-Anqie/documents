# 注解：@ 开头的那些标签

> 读完这篇，你能看懂主类顶上那行 `@Mod("dafeiyu")`、事件方法顶上那行 `@SubscribeEvent` 各自在管什么，也能一眼判断"代码没错、编译也过、游戏里就是没反应"到底是不是注解的锅。

## 学习目标

- 能用自己的话说清"注解本身不执行，是框架读了标签之后决定怎么做"。
- 能说出 `@Mod("dafeiyu")` 的参数是什么、写错或漏写会怎样。
- 能解释为什么一个 `@SubscribeEvent` 方法可能永远不被调用，并知道怎么修。
- 能读懂 `@EventBusSubscriber` 的三个参数，知道省略时各自默认成什么。
- 看到 `@Nullable`、`@Deprecated`、`@SuppressWarnings` 时不再发怵，知道它们改不改变运行行为。

## 正文

### 先看这一段

你从 Mod Generator 生成工程、打开主类，看到的大概是这样：

文件：`src/main/java/com/dafeiyu/DafeiyuMod.java`

```java
@Mod("dafeiyu")
public class DafeiyuMod {
    public DafeiyuMod(IEventBus modEventBus) {
        ModItems.ITEMS.register(modEventBus);
    }

    @SubscribeEvent
    public static void onPlayerTick(PlayerTickEvent.Post event) {
        // 每个游戏刻、每个玩家都会进这里
    }
}
```

`public class`、构造器、方法体，你都认识。真正陌生的只有两个东西：

- 类名上面孤零零的一行 `@Mod("dafeiyu")`；
- 方法签名上面孤零零的一行 `@SubscribeEvent`。

它们既不声明变量，也不调用方法，看上去像是"注释的另一种写法"。但它们不是注释——注释会被编译器扔掉，这两行会被**保留进 class 文件**，并且被 NeoForge 在启动时读出来。

顺便提前说一个坑：上面这段代码如果原样运行，`onPlayerTick` **一次都不会被调用**。原因在下面「`@SubscribeEvent`：不写就不触发」一节，这是本章最值钱的一句话，请留意。

### 注解是"贴在代码上的标签"

一句话定义：

> 注解（annotation）是贴在类、方法、字段、参数上的标签。它自己不会执行任何代码，作用只是"留下一条信息"。真正干活的是**读标签的人**——在模组开发里，这个"人"就是 NeoForge 的加载器。

打个比方。你托运一个箱子，箱子上贴一张"易碎"的贴纸。贴纸本身不会保护箱子，是搬运工看到贴纸后决定轻拿轻放。注解就是那张贴纸，NeoForge 就是搬运工。

由此可以推出三个很实用的结论：

1. **删掉注解，代码通常还能编译通过。** 因为注解不参与语法结构，`@Mod` 去掉之后 `public class DafeiyuMod { ... }` 依然是合法的 Java 类。
2. **但行为会消失。** 没有 `@Mod`，加载器不知道这个类是模组入口，于是不实例化它、不调它的构造器，你的 `ModItems.ITEMS.register(...)` 从来没被执行过，游戏里自然一个物品都没有。
3. **注解写错不会报"语法错误"，而是报"找不到"。** 比如 modid 拼错，编译器一声不吭，进游戏才发现整个模组像不存在。

这就是注解最坑的地方：**它的错误往往不表现为编译失败，而表现为"什么都没发生"。** 后面所有的坑，本质上都是这一条的变种。

这里你只要知道"标签 + 读标签的人"这个模型就够了，暂时不用管注解在字节码里怎么存、`@Retention` 有几个取值、怎么用反射读注解——这些你在模组开发里基本碰不到。

### `@Override`：最值得无条件加的注解

先看一段你以后天天要写的代码：

文件：`src/main/java/com/dafeiyu/block/RubyAltarBlockEntity.java`

```java
public class RubyAltarBlockEntity extends BlockEntity {
    private int charge;

    @Override
    public void loadAdditional(CompoundTag tag, HolderLookup.Provider registries) {
        super.loadAdditional(tag, registries);
        this.charge = tag.getInt("charge");
    }
}
```

`@Override` 的意思是：**"我声明这个方法是在重写父类（或接口）里已经存在的某个方法。"**

它不改变任何运行行为——加不加，方法都照常被调用。它的价值全在**编译期检查**：

- 加了 `@Override`，如果你把 `loadAdditional` 打成 `loadAddition`，编译器立刻报错："方法未重写或实现超类型方法"。你马上知道拼错了。
- 不加 `@Override`，`loadAddition` 就是一个**全新的方法**，语法完全合法，编译通过。但游戏永远不会调它，你的数据永远读不出来。你会花两小时怀疑 NBT、怀疑存档、怀疑人生。

这是新手最常见的"隐形 bug"来源，没有之一。所以规矩很简单：

> **只要你在重写父类方法，就写 `@Override`。没有例外。**

`@Override` 还能帮你发现"签名变了"。比如 1.20 到 1.21，`load` 改成了 `loadAdditional(CompoundTag, HolderLookup.Provider)`。你从旧教程抄来 `public void load(CompoundTag tag)` 并加了 `@Override`，编译器会直接告诉你"没有可重写的方法"——比运行时静默失效好一万倍。

读别人的代码时，看到 `@Override` 你就知道：这个方法的行为由**父类或接口约定**，去父类里找同名方法能看到默认实现和调用时机。这是读源码时最省力的路标。

### `@Mod("dafeiyu")`：入口的门牌号

```java
@Mod("dafeiyu")
public class DafeiyuMod { ... }
```

括号里的 `"dafeiyu"` 是**模组 ID（modid）**。它必须和 `src/main/resources/META-INF/neoforge.mods.toml` 里 `modId="dafeiyu"` 完全一致——大小写、下划线、连字符都算。`dafeiyu` 和 `DaFeiYu` 是两个不同的 modid，加载器不会帮你纠正。

这个 modid 用来干三件事：

1. 告诉加载器"这个类是哪个模组的入口"，从而在启动时 `new DafeiyuMod(modEventBus)`；
2. 决定构造器收到的那个 `IEventBus` 是哪条总线（每个模组一条，叫模组总线）；
3. 出现在日志、崩溃报告、`ResourceLocation` 的命名空间里。

**能不能不写参数？** 不能。`@Mod` 的 `value` 没有默认值，写 `@Mod` 而不给字符串，编译就过不去。**能不能不写 `@Mod`？** 能编译，但你的模组不会被加载——这属于上面说的"标签被撕掉了"。

还有两条容易踩的：

- **一个 modid 只能有一个 `@Mod` 类。** 写两个，启动时报重复入口。
- **主类不要写成 `final`、不要私有化构造器。** 加载器要 `new` 它。

顺带说，构造器那个参数 `IEventBus modEventBus` 不是你传的，是加载器**注入**进来的。你只要在构造器里把各个 `DeferredRegister` 挂上去：

```java
public DafeiyuMod(IEventBus modEventBus) {
    ModItems.ITEMS.register(modEventBus);
    ModBlocks.BLOCKS.register(modEventBus);
    ModBlockEntities.BLOCK_ENTITIES.register(modEventBus);
}
```

### `@SubscribeEvent`：不写就不触发

事件总线的逻辑是：启动时把所有"事件处理方法"收集起来，事件发生时挨个调用。它靠什么认出哪些方法是处理方法？就靠 `@SubscribeEvent` 这个标签。

```java
@SubscribeEvent
public static void onPlayerTick(PlayerTickEvent.Post event) {
    // 事件发生时被调用
}
```

对方法的要求有三条，缺一不可：

1. **返回值必须是 `void`。** 事件处理不需要返回值，结果通过 `event.setXxx(...)` 写回事件对象。
2. **参数只能有一个，而且必须是事件类型。** 两个参数直接报错。
3. **要么是 `static`，要么这个方法所在的对象被显式注册过。** 详见下一节。

现在回到开头那段代码的坑：

```java
@Mod("dafeiyu")
public class DafeiyuMod {
    @SubscribeEvent
    public static void onPlayerTick(PlayerTickEvent.Post event) { ... }   // 不会触发！
}
```

`@Mod` 只负责"这是入口类"，**它不会顺手把你的 `@SubscribeEvent` 方法挂到任何总线上**。标签贴好了，但没人来读——事件总线根本不知道 `DafeiyuMod` 里有这么个方法。

要让它生效，得有人在构造器里把类注册上去：

```java
public DafeiyuMod(IEventBus modEventBus) {
    ModItems.ITEMS.register(modEventBus);
    NeoForge.EVENT_BUS.register(DafeiyuMod.class);   // 把类里所有 @SubscribeEvent 挂到游戏总线
}
```

注意 `register(DafeiyuMod.class)` 传的是 **Class 对象**，这要求类里所有处理方法都是 `static`。如果你想用非静态方法，就得传实例：`NeoForge.EVENT_BUS.register(new DafeiyuMod(...))`——但主类构造器有参数，一般不会这么干，所以**在主类里写事件处理方法，基本都写 `static`**。

另一种更省事的写法是干脆不注册，改用 `addListener`：

```java
public DafeiyuMod(IEventBus modEventBus) {
    NeoForge.EVENT_BUS.addListener(DafeiyuMod::onPlayerTick);
}

private static void onPlayerTick(PlayerTickEvent.Post event) { ... }   // 不需要注解
```

`addListener` 靠方法引用直接指定方法，压根不需要 `@SubscribeEvent`。两种写法效果一样，选一种用就行，**不要两边都写**（会触发两次）。

### `@EventBusSubscriber`：一次把注册也省了

如果你不想在主类构造器里堆一长串 `register`，可以在事件类上贴这个注解：

文件：`src/main/java/com/dafeiyu/event/RubyEvents.java`

```java
@EventBusSubscriber(modid = "dafeiyu")
public class RubyEvents {
    @SubscribeEvent
    public static void onPlayerTick(PlayerTickEvent.Post event) {
        // ...
    }
}
```

NeoForge 会自己扫描到被 `@EventBusSubscriber` 标注的类，等价于帮你调了一次 `register(RubyEvents.class)`。这样主类构造器就能保持干净。

三个参数分别是：

| 参数 | 管什么 | 省略时 |
|---|---|---|
| `modid` | 这个事件类属于哪个模组，主要用于日志和冲突排查 | 空字符串。**建议永远写**，否则出问题时日志里看不出是谁 |
| `bus` | 挂到哪条总线：`Bus.GAME`（游戏总线）或 `Bus.MOD`（模组总线） | `Bus.GAME` |
| `value` | 这个类在哪个物理侧加载：`Dist.CLIENT` 只客户端、`Dist.DEDICATED_SERVER` 只服务端 | 两侧都加载 |

`value` 是最容易忽略、也最容易出事的一个。渲染、按键、HUD 这类只在客户端存在的东西，如果两侧都加载，专用服务端启动时会因为找不到客户端类而崩溃。所以客户端事件类一定要写：

```java
@EventBusSubscriber(modid = "dafeiyu", value = Dist.CLIENT)
public class RubyClientEvents { ... }
```

关于 `bus` 有一个版本差异要知道：`bus` 参数在 NeoForge 21.1.0 ~ 21.1.180 之间存在，之后被移除了，改为根据事件类型自动判断总线。如果你的工程版本较新，写 `bus = Bus.MOD` 会编译不过——那就直接删掉这个参数，事件类型本身（是否实现 `IModBusEvent`）已经足够判断。

再强调一次前面那条规矩：**用 `@EventBusSubscriber` 时，处理方法必须是 `static`。** 因为注册的是类本身而不是实例，非静态方法没有对象可以调用，启动阶段就会报错。这个报错信息比较直白（大意是"方法不是静态的"），看到就往这上面想。

### `@Nullable` / `@Nonnull`：只是写给人看的

```java
@Nullable
public ItemStack getCarried() { ... }
```

这两个注解**不改变任何运行行为**。它们不会被编译成判空检查，也不会在返回 null 时抛异常。它们的作用只有两个：

1. 告诉 IDE：这里可能是 null，请给我黄色波浪线警告；
2. 告诉读代码的人：调用这个方法之前，你自己负责判空。

`@Nonnull`（或 `@NotNull`）是反过来的约定："我保证不返回 null"。但请注意，这依然只是**约定**，方法内部真返回了 null，编译器也拦不住。

所以读代码时的正确用法是：

- 看到 `@Nullable` → 当成"这里一定会 null，必须判空"来写；
- 看到 `@Nonnull` 或没标注 → **也不能假定安全**，尤其是一堆老代码根本没标注。

具体的判空策略、`Optional` 怎么读，见下一篇 [Optional 与 @Nullable：空值处理](06-Optional与Nullable-空值处理.md)。

### `@Deprecated` / `@SuppressWarnings`

这两个是"提示类"注解，见到时的理解方式如下。

**`@Deprecated`** 表示"这个 API 已过时，将来可能被删除，请改用新的"。看到它时：

- 代码照样能跑，不是错误，只是编译时会有删除线/警告；
- 正确做法是顺着它的 Javadoc 找替代品（通常注释里会写 `@deprecated use XXX instead`）；
- 不要因为"能跑"就一直留着，大版本升级时这些 API 往往第一批消失。

比如 1.21 里 `new ResourceLocation("dafeiyu", "ruby")` 就已经不能用了，必须改成 `ResourceLocation.fromNamespaceAndPath("dafeiyu", "ruby")`。这类变化通常先经过"标记弃用"再"删除"。

**`@SuppressWarnings("xxx")`** 表示"我知道这里会有编译警告，请闭嘴"。常见取值：

| 取值 | 抑制什么 |
|---|---|
| `"unused"` | 变量/方法没被用到（写注册类时很常见） |
| `"deprecation"` | 使用了已弃用的 API |
| `"unchecked"` | 泛型强制转换没做检查 |

原则是：**只在你确定"这个警告是误报或无法避免"时才加，并且加在最小范围内**（能加在方法上就别加在类上）。看到别人的代码里有 `@SuppressWarnings`，说明那里存在一个"编译器不满意但作者认为没问题"的地方，值得多看一眼。

### 能不能自己写注解？

能。Java 允许你定义自己的注解：

```java
public @interface MyMarker { }
```

但你几乎用不到。原因很直接：**注解要生效，必须有人去"读"它**。NeoForge 只读它自己认识的那几个（`@Mod`、`@SubscribeEvent`、`@EventBusSubscriber` 等），你自定义的注解贴上去，没有任何代码会去解析，等于贴了张没人看的贴纸。

在模组开发里，你 99% 的时间是"用别人定义的注解"，而不是"定义注解"。真要自定义，通常是配合 Mixin 或自己的反射框架，属于很后面的内容。

## 完整示例

两个文件，直接落盘就能用。注意职责划分：主类只管注册，事件类只管响应。

文件：`src/main/java/com/dafeiyu/DafeiyuMod.java`

```java
package com.dafeiyu;

import net.neoforged.bus.api.IEventBus;
import net.neoforged.fml.common.Mod;

@Mod(DafeiyuMod.MOD_ID)
public class DafeiyuMod {
    // modid 抽成常量，注解和代码里都用它，避免手打两次打错
    public static final String MOD_ID = "dafeiyu";

    public DafeiyuMod(IEventBus modEventBus) {
        // 三个 DeferredRegister 各自挂到模组总线上
        ModItems.ITEMS.register(modEventBus);
        ModBlocks.BLOCKS.register(modEventBus);
        ModBlockEntities.BLOCK_ENTITIES.register(modEventBus);
    }
}
```

文件：`src/main/java/com/dafeiyu/event/RubyEvents.java`

```java
package com.dafeiyu.event;

import com.dafeiyu.DafeiyuMod;
import net.neoforged.bus.api.SubscribeEvent;
import net.neoforged.fml.common.EventBusSubscriber;
import net.neoforged.neoforge.event.tick.PlayerTickEvent;

// modid 用来在日志里标明归属；不写 value，表示两侧都加载
@EventBusSubscriber(modid = DafeiyuMod.MOD_ID)
public class RubyEvents {

    // 必须是 static、必须 void、必须只有一个事件参数
    @SubscribeEvent
    public static void onPlayerTick(PlayerTickEvent.Post event) {
        // 客户端和服务端都会进这里，所以先判断侧
        if (event.getEntity().level().isClientSide()) {
            return;
        }
        // 服务端逻辑写在这里
    }
}
```

文件：`src/main/java/com/dafeiyu/event/RubyClientEvents.java`

```java
package com.dafeiyu.event;

import com.dafeiyu.DafeiyuMod;
import net.neoforged.api.distmarker.Dist;
import net.neoforged.bus.api.SubscribeEvent;
import net.neoforged.fml.common.EventBusSubscriber;
import net.neoforged.neoforge.client.event.ClientTickEvent;

// 只客户端加载：专用服务端不会碰这个类，也就不会因为找不到客户端类而崩
@EventBusSubscriber(modid = DafeiyuMod.MOD_ID, value = Dist.CLIENT)
public class RubyClientEvents {

    @SubscribeEvent
    public static void onClientTick(ClientTickEvent.Post event) {
        // 纯客户端逻辑，比如 HUD、按键
    }
}
```

## 常见坑与报错

| 现象 | 原因 | 解决 |
|---|---|---|
| 编译通过、进游戏啥也没有，日志也没有明显报错 | 主类没写 `@Mod`，或 modid 与 `neoforge.mods.toml` 不一致 | 两处字符串逐字对照；建议用 `@Mod(DafeiyuMod.MOD_ID)` |
| 事件方法写了，但从来没被调用 | 方法在 `@Mod` 类里，却没 `register`，也没有 `@EventBusSubscriber` | 构造器里 `NeoForge.EVENT_BUS.register(类.class)`，或给类加 `@EventBusSubscriber` |
| 启动报错，提示处理方法不是静态的 | 用了 `@EventBusSubscriber` 但方法是实例方法 | 方法加 `static` |
| 启动报错，提示方法参数不合法 | 处理方法有两个以上参数，或参数不是事件类型 | 只留一个事件参数 |
| 专用服务端启动崩溃，报 `NoClassDefFoundError` 指向客户端类 | 客户端事件类没写 `value = Dist.CLIENT` | 加 `value = Dist.CLIENT` |
| 事件处理执行了两次 | 同时用了 `register` 和 `addListener`，或类被注册了两遍 | 只保留一种注册方式 |
| 重写了方法但游戏没反应，编译也不报错 | 方法名打错，且没加 `@Override` | 补上 `@Override`，编译器会立刻指出来 |
| 从旧教程抄的方法加 `@Override` 后编译失败 | 1.21 方法签名变了（如 `load` → `loadAdditional`） | 按报错提示改成新签名 |
| `bus = Bus.MOD` 编译不过 | 工程版本高于 21.1.180，`bus` 参数已移除 | 删掉该参数，总线由事件类型自动判断 |

## 练习

1. **（易）** 把主类里的 `@Mod("dafeiyu")` 改成 `@Mod("dafeiyu2")`，不改 `neoforge.mods.toml`，启动一次游戏，观察日志里关于模组加载的报错。改回来。这道题的目的是让你记住"注解错误表现为找不到，而不是语法错误"。
2. **（中）** 故意把 `loadAdditional` 写成 `loadAddition`，先不加 `@Override` 编译一次，再加上 `@Override` 编译一次，对比两次结果。
3. **（难）** 新建 `RubyClientEvents`，在里面监听 `ClientTickEvent.Post`，每 20 刻在日志里打一行字。先不写 `value = Dist.CLIENT`，用 `runServer` 启动专用服务端，看看会发生什么；再补上，重启验证。
