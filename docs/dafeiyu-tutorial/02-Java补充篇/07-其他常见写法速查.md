# 其他常见写法速查

> 这是一篇"看到就查"的速查表：14 个在 NeoForge 代码里高频出现、但普通 Java 教程讲得很晚（或根本不讲）的写法。每条只给"怎么读 + 一段真实代码 + 一个坑"。

## 学习目标

- 看到 `var`、`static { }`、`final` 时，能说出它们各自约束了什么。
- 能读懂 `if (be instanceof RubyBlockEntity ruby)` 这种"判断 + 转型 + 起名"三合一的写法。
- 能分清 `Integer` 和 `int`，知道为什么 `Map<..., Integer>` 里不能用 `==` 比较。
- 能认出文本块、可变参数、泛型通配符、匿名内部类，知道它们不影响你改代码。

## 正文

下面 14 条按"你会在哪一类代码里撞见"分成四组。不需要背，遇到时回来查即可。

### 第一组：声明与初始化

#### 1. `var`：让编译器猜类型

**读法**：`var` 不是"动态类型"，类型在编译期就定死了，只是你不用把类型名写出来。

```java
var be = level.getBlockEntity(pos);        // 实际类型就是 BlockEntity
var list = new ArrayList<ItemStack>();     // 实际类型 ArrayList<ItemStack>
var name = "ruby";                         // 实际类型 String
```

**注意**：`var` 只能用在**局部变量**上。字段、方法参数、方法返回值都不能用；`var x = null;` 也不行（编译器猜不出来）。它省的是打字，不是类型安全——`be` 依然是 `BlockEntity`，不能直接调 `RubyAltarBlockEntity` 的方法。

#### 2. `static { ... }`：类加载时跑一次的代码块

**读法**：这个类第一次被用到时，JVM 会先执行 `static` 块，**早于任何构造器和静态方法调用**。

```java
public final class ModItems {
    public static final DeferredRegister.Items ITEMS =
            DeferredRegister.createItems(DafeiyuMod.MOD_ID);

    public static final DeferredItem<Item> RUBY = ITEMS.registerSimpleItem("ruby");

    static {
        // 所有静态字段初始化完之后执行，且只执行一次
        LOGGER.info("ModItems 初始化完成，已登记 {} 个物品", ITEMS.getEntries().size());
    }
}
```

**为什么注册类里常见**：`DeferredRegister` 的字段必须在主类构造器调用 `register(modEventBus)` 之前全部建好。`static` 块提供了一个"字段都初始化完了，但还没人用我"的时机，适合做检查、打日志、给某些字段补默认值。**注意**：静态块里别写需要 `Minecraft` 已启动才能跑的代码，那时游戏还没起来。

#### 3. `final`：只读，不是"更快"

**读法**：`final` 表示"这个变量只能被赋值一次"。对局部变量和参数来说，它纯粹是**约束 + 意图声明**，跟性能无关。

```java
final int maxStack = 64;                       // 之后不能再 maxStack = 32;
public void tick(final Level level) { ... }    // 方法体内不能给 level 重新赋值

// 实际用途：能在 lambda 里被捕获（lambda 只捕获 final 或"事实上 final"的变量）
final BlockPos origin = pos;
list.forEach(stack -> use(origin, stack));
```

**注意**：`final` 修饰对象时，锁的是**引用**不是内容——`final List<ItemStack> list` 里的元素照样能增删。字段上的 `final` 还意味着"必须在构造器里赋值"，这也是 `DeferredRegister` 字段几乎都写 `public static final` 的原因。

### 第二组：判断与分支

#### 4. `instanceof` 模式匹配：判断 + 转型 + 起名

**读法**：`if (be instanceof RubyBlockEntity ruby)` 的意思是"如果 `be` 是 `RubyBlockEntity`，就把它当成 `ruby` 用"。

```java
BlockEntity be = level.getBlockEntity(pos);

// 老写法：判断一次，转型一次，名字还得自己起
if (be instanceof RubyBlockEntity) {
    RubyBlockEntity ruby = (RubyBlockEntity) be;
    ruby.charge();
}

// 新写法（Java 16+）：一次搞定，ruby 只在 if 块内有效
if (be instanceof RubyBlockEntity ruby) {
    ruby.charge();
}
```

**注意**：`instanceof` 对 `null` 永远返回 `false`，所以这一个判断同时挡住了"是 null"和"类型不对"。这是模组里最常用的写法，比 `!= null` 加转型干净得多。

#### 5. 三目运算符 `a ? b : c`

**读法**："如果 a 成立就取 b，否则取 c"。它是个**表达式**，有值，能直接赋给变量。

```java
int count = stack.isEmpty() ? 0 : stack.getCount();
Rarity rarity = data.awakened() ? Rarity.EPIC : Rarity.COMMON;
```

**注意**：嵌套两层以上就该拆成 `if` 了，否则读的人要在脑子里做括号匹配。另外 `a ? b : c` 里 `b` 和 `c` 的类型要能统一，一边 `int` 一边 `Integer` 时可能触发拆箱。

#### 6. `switch` 表达式与 `yield`

**读法**：`switch` 现在能"返回值"了。箭头形式 `case X -> 值`，整个 `switch` 就是一个表达式。

```java
// 表达式形式：整个 switch 有值，直接赋给变量
int damage = switch (tier) {
    case ROUGH -> 2;
    case POLISHED -> 5;
    case AWAKENED -> 9;
};

// 分支里要写多行，就用块 + yield 交回结果
int damage2 = switch (tier) {
    case ROUGH -> 2;
    case AWAKENED -> {
        int base = 9;
        yield base + bonus;      // yield = "这个分支的值是……"
    }
    default -> 5;
};
```

**注意**：`yield` 只能出现在 `switch` 的块分支里，别和 `return` 搞混（`return` 是离开整个方法）。表达式形式的 `switch` 如果漏了某个枚举常量且没有 `default`，会**编译报错**——这其实是好事，加了新枚举值时会提醒你补分支。

### 第三组：类型与数值

#### 7. 强制类型转换 `(RubyBlock) block`

**读法**："我知道它实际是 `RubyBlock`，按这个类型给我"。运行时如果猜错，抛 `ClassCastException`。

```java
Block block = ModBlocks.RUBY_BLOCK.get();
RubyBlock ruby = (RubyBlock) block;    // 确定类型时才能这么写
```

**注意**：模组里 90% 的强转都可以用 `instanceof` 模式匹配替掉，更安全。真正需要裸强转的场景通常是泛型擦除（比如 `(BlockEntityTicker<A>) ticker`），那种地方编译器也没办法。

#### 8. 装箱 / 拆箱：`Integer` vs `int`

**读法**：`int` 是基本类型（存值），`Integer` 是对象（存引用，可以为 null）。两者自动互转叫装箱/拆箱。

```java
Map<ResourceLocation, Integer> counts = new HashMap<>();
counts.put(id, counts.getOrDefault(id, 0) + 1);   // 自动装箱：int -> Integer

Integer a = 1000;
Integer b = 1000;
a == b        // false！比的是引用
a.equals(b)   // true，比的是值
```

**注意**：`Integer` 对 -128~127 有缓存，所以 `Integer a = 100; Integer b = 100; a == b` 居然是 `true`——这个"有时候对有时候错"的特性害过无数人。规矩是：**对象比较一律用 `equals`，只有基本类型才用 `==`**。另外 `Integer x = null; int y = x;` 会在拆箱时 NPE。

#### 9. 泛型通配符 `? extends T` / `? super T`

**读法**：`? extends T` = "某种 T 或 T 的子类"，只能**取**不能放；`? super T` = "某种 T 或 T 的父类"，只能**放**不能取。

```java
// 只能读：你可以从里面取出 Item，但不能往里塞（不知道具体是哪个子类）
void printAll(DeferredRegister<? extends Item> reg) { ... }

// 只能写：set 接受"T 或 T 的父类型"的组件类型
<T> T set(DataComponentType<? super T> type, T value);
```

**注意**：模组里你基本只在**读方法签名**时遇到它，自己写 API 时几乎不需要。看到 `? extends` 就理解成"这里只读"，看到 `? super` 就理解成"这里只写"，足够用了。

### 第四组：调用与结构

#### 10. 可变参数 `Object... args`

**读法**：`Object...` 等价于 `Object[]`，但调用时可以传 0 个、1 个、或任意多个。

```java
// 声明
public static void log(String format, Object... args) {
    LOGGER.info(format, args);
}

// 调用：三种写法都合法
log("hello");
log("charge={}", 5);
log("a={}, b={}", 1, 2);

// 真实场景：注册方块实体时传"能拥有这个方块实体的所有方块"
BlockEntityType.Builder.of(RubyAltarBlockEntity::new,
        ModBlocks.RUBY_ALTAR.get(), ModBlocks.RUBY_ALTAR_2.get());
```

**注意**：可变参数必须是**最后一个**参数；传 `null` 时编译器会警告"可能是想传一个 null 数组"，别这么写。

#### 11. 文本块 `"""..."""`

**读法**：多行字符串字面量，不用写 `\n` 和转义引号。

```java
String json = """
        {
          "parent": "minecraft:block/cube_all",
          "textures": {
            "all": "dafeiyu:block/ruby_block"
          }
        }
        """;
```

**注意**：开头的 `"""` 后面必须换行；整体缩进按"最短缩进行 + 结束的 `"""` 所在列"来削；结束的 `"""` 独占一行时，结果**末尾会带一个换行**。在数据生成里手写一小段 JSON 模板时很常见，但正经的模型/配方还是用 Provider 生成，别手拼字符串。

#### 12. 方法链与"返回 `this`"

**读法**：每个方法返回 `this`（或返回一个新对象），所以能一直点下去。

```java
new Item.Properties()
        .stacksTo(16)
        .rarity(Rarity.RARE)
        .component(ModDataComponents.RUBY_DATA.get(), RubyData.EMPTY);
```

**注意**：这是 Builder 模式的核心，`Item.Properties`、`BlockBehaviour.Properties`、`FoodProperties.Builder` 全是这个套路。什么时候该用 Builder、`build()` 在哪一步，见 [Builder与链式调用](03-Builder与链式调用.md)。

#### 13. `this` / `super`

**读法**：`this` 是"我自己这个对象"，`super` 是"我父类的那一份"。

```java
public RubyAltarBlock(Properties properties) {
    super(properties);        // 必须先调父类构造器
    this.tier = RubyTier.ROUGH;
}

@Override
public InteractionResult useWithoutItem(...) {
    // 先让原版逻辑跑一遍，再决定要不要覆盖结果
    InteractionResult result = super.useWithoutItem(...);
    return result == InteractionResult.PASS ? InteractionResult.SUCCESS : result;
}
```

**注意**：重写方法时**尽量先调 `super`**，尤其是 `loadAdditional` / `saveAdditional` / `appendHoverText` 这类"父类也要干活"的方法，不调会丢数据。匿名内部类里想引用外层对象要用 `Outer.this`。

#### 14. 匿名内部类 `new Thread() { ... }`

**读法**：当场 `new` 一个类，顺便把它的方法实现掉，不留名字。

```java
// 老写法：匿名内部类
Thread t = new Thread() {
    @Override
    public void run() {
        doHeavyWork();
    }
};
t.start();

// 现在更常见的写法：函数式接口直接用 lambda
Thread t2 = new Thread(() -> doHeavyWork());
```

**注意**：模组代码里见到匿名内部类，通常意味着这段代码比较老，或者它实现的接口有多个方法（lambda 只能实现一个）。你能认出"这是个一次性对象"就够了，不需要会写。

### 一页速查表

| 写法 | 一句话 | 最容易踩的坑 |
|---|---|---|
| `var x = ...` | 局部变量让编译器推类型 | 不能用于字段/参数；不能 `= null` |
| `static { }` | 类加载时执行一次 | 里面别碰需要游戏已启动的东西 |
| `final` | 只能赋值一次 | 锁引用不锁内容 |
| `instanceof T t` | 判断 + 转型 + 起名 | 变量只在分支内有效 |
| `a ? b : c` | 二选一表达式 | 嵌套两层就该拆 |
| `switch` 表达式 | 分支直接给值 | 块分支要用 `yield` |
| `(T) x` | 强制转型 | 猜错抛 `ClassCastException` |
| `Integer` / `int` | 对象 / 基本类型 | `==` 比引用，缓存只到 127 |
| `? extends` / `? super` | 只读 / 只写 | 别自己设计 API 时乱用 |
| `Object...` | 可变参数 = 数组 | 必须是最后一个参数 |
| `"""..."""` | 多行字符串 | 结尾换行、缩进规则 |
| 链式调用 | 每步返回 `this` | 忘了最后 `build()` |
| `this` / `super` | 自己 / 父类 | 重写时漏调 `super` |
| `new X() { }` | 一次性对象 | 老写法，能用 lambda 就用 lambda |

最后提醒一句：这张表是用来**查**的，不是用来背的。真正要记住的只有三条——`instanceof` 模式匹配能同时挡 null 和类型不对；`Integer` 比较永远用 `equals`；重写方法先调 `super`。剩下的大部分写法，你在 IDE 里点进去看一眼参数类型就明白了。

## 完整示例

一个文件，把上面大半写法塞进一段真实可用的代码里。

文件：`src/main/java/com/dafeiyu/util/RubyDebug.java`

```java
package com.dafeiyu.util;

import com.dafeiyu.DafeiyuMod;
import com.dafeiyu.block.RubyAltarBlockEntity;
import com.dafeiyu.data.RubyTier;
import net.minecraft.core.BlockPos;
import net.minecraft.world.level.Level;
import net.minecraft.world.level.block.entity.BlockEntity;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

public final class RubyDebug {

    private static final Logger LOGGER = LoggerFactory.getLogger("dafeiyu/debug");

    // 静态块：类第一次被加载时打印一次版本信息
    static {
        LOGGER.info("[{}] 调试工具已加载", DafeiyuMod.MOD_ID);
    }

    private RubyDebug() {
    }

    // 可变参数：想打印几个位置就传几个
    public static void dumpBlockEntities(Level level, BlockPos... positions) {
        for (BlockPos pos : positions) {
            // var：类型由编译器推断为 BlockEntity
            var be = level.getBlockEntity(pos);

            // instanceof 模式匹配：一次挡住 null + 类型不对
            // 这里假设 RubyAltarBlockEntity 有 tier() 和 isCharged()，见方块实体篇
            if (be instanceof RubyAltarBlockEntity altar) {
                LOGGER.info("pos={} tier={} charged={}",
                        pos, altar.tier().id(), altar.isCharged());
            } else {
                LOGGER.info("pos={} 不是红宝石祭坛", pos);
            }
        }
    }

    // switch 表达式 + yield：按档位算伤害
    public static int damageOf(RubyTier tier, int bonus) {
        return switch (tier) {
            case ROUGH -> 2;
            case POLISHED -> 5;
            case AWAKENED -> {
                int base = 9;
                yield base + bonus;     // 块分支必须 yield
            }
        };
    }

    // 文本块：调试时临时输出一段结构说明
    public static String helpText() {
        return """
                RubyDebug 用法：
                  dumpBlockEntities(level, pos1, pos2, ...)
                  damageOf(tier, bonus)
                """;
    }
}
```

## 常见坑与报错

| 现象 | 原因 | 解决 |
|---|---|---|
| `cannot find symbol: class var` / `var` 报错 | 用在了字段或参数上 | `var` 只能修饰局部变量 |
| `cannot infer type` | `var x = null;` 或 lambda 没有目标类型 | 写出明确类型 |
| `Integer` 比较结果时对时错 | `==` 比引用，-128~127 有缓存 | 用 `equals`，或先拆成 `int` |
| `NullPointerException` 在拆箱那行 | `Integer` 为 null 时赋值给 `int` | 先判空或用 `getOrDefault` |
| `ClassCastException` | 强转前没确认实际类型 | 改用 `instanceof` 模式匹配 |
| `switch` 表达式报"不是穷尽的" | 漏了枚举常量且无 `default` | 补分支，或加 `default` |
| `yield` 报错 | 用在了箭头单值分支里 | 只有 `{ }` 块分支才需要 `yield` |
| 文本块开头多了空行 / 缩进不对 | 开头 `"""` 后没换行，或缩进基准算错 | 让结束 `"""` 与内容左边界对齐 |
| 方法链最后类型不对 | 忘了调 `build()`，拿到的是 Builder | 补 `.build()` |
| 重写 `saveAdditional` 后存档丢数据 | 没调 `super.saveAdditional(...)` | 第一行先调父类 |

## 练习

1. **（易）** 把这段老代码改写成 `instanceof` 模式匹配 + `var`：
   ```java
   BlockEntity be = level.getBlockEntity(pos);
   if (be != null && be instanceof RubyAltarBlockEntity) {
       RubyAltarBlockEntity altar = (RubyAltarBlockEntity) be;
       altar.charge();
   }
   ```
2. **（中）** 用 `switch` 表达式写一个 `String describe(RubyTier tier)`，`AWAKENED` 分支里用块 + `yield`，返回"觉醒（倍率 5.0）"这种带数据的描述。
3. **（难）** 写一个 `Map<ResourceLocation, Integer>` 统计每种物品被使用的次数，要求：键不存在时按 0 处理、输出时按次数从高到低排序，并解释为什么不能用 `==` 比较两个计数。
