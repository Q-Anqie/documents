# 学习资源与社区

> 教程会结束，查资料的能力不会。这一篇告诉你官方文档怎么读、源码怎么看、问题怎么问，以及 1.20 到 1.21 那些会让你"抄了就跑不起来"的变化。

## 学习目标

- 能在官方文档里按版本、按主题找到你要的那一页，并且知道哪几页值得反复读
- 会用 IDE 的 Ctrl+点击和 `External Libraries` 追一段原版逻辑，不再靠猜
- 能判断一个开源模组值不值得读、该怎么读
- 提问时能一次性给出别人需要的信息，而不是被回一句"贴日志"
- 知道 1.21 相对 1.20 改了哪些地方，看到旧教程能立刻识别出来

## 一、官方文档：唯一权威，但要用对

地址是 `https://docs.neoforged.net/`。它最重要的特征是**按版本分目录**：

```text
https://docs.neoforged.net/docs/1.21.1/gettingstarted/
https://docs.neoforged.net/docs/1.21.1/blocks/
https://docs.neoforged.net/docs/1.21.1/items/
https://docs.neoforged.net/docs/1.21.1/networking/
```

那个 `1.21.1` 就是你跟的版本。**别用默认跳转的版本**——站点会自动跳到最新版，最新版的 API 跟你手上的工程经常对不上。把带版本的地址存成书签，比每次从首页点进去可靠。

### 怎么读才不浪费时间

官方文档是"参考手册"体例，不是教程。它的写法是"这个类有哪些方法"，而不是"你为什么需要这个类"。所以：

1. **先读每页开头两段。** NeoForge 文档的开头通常是"这个概念解决什么问题"，这段信息密度最高。
2. **代码示例直接抄，但先看 import。** 文档里的示例有时省略 import，`net.minecraft` 和 `net.neoforged` 差一个字母就是两个世界。
3. **看页面底部的 "Last updated"。** 如果某一页很久没更新，里面的写法可能已经过时，交叉验证一下。
4. **善用站内搜索，但别搜中文。** 文档只有英文，搜 `block entity` 比搜"方块实体"有效。

### 值得反复读的几页

| 主题 | 为什么重要 |
|---|---|
| Getting Started 系列 | 工程结构、`neoforge.mods.toml`、主类，一切的地基 |
| Concepts → Registries | 注册表为什么存在，比"怎么写"更重要 |
| Concepts → Sides | 客户端/服务端，写错就是专用服务器崩溃 |
| Blocks / Block Entities | 方块开发 80% 的内容 |
| Items / Data Components | 1.21 的物品系统全在这里 |
| Resources / Data | 资源包与数据包的目录约定，最实用的部分 |
| Networking | 载荷与 `StreamCodec`，旧教程在这里错得最多 |

## 二、NeoForged 官网、论坛与 Discord

- **官网** `https://neoforged.net/`：下载安装器、看版本支持表、找 MDK。装环境卡住时先来这里确认"这个 MC 版本到底有没有对应的 NeoForge"。
- **论坛** `https://forums.neoforged.net/`：适合"贴完整日志求诊断"。它的搜索比 Discord 好用，因为内容会被索引。**提问前先搜**，你的问题大概率已经有人问过。
- **Discord** `https://discord.neoforged.net/`：实时求助，`#modder-support` 之类的频道。它的缺点是消息不留档、搜不到，而且时区不同可能几小时没人回。
- **GitHub** `https://github.com/neoforged/NeoForge`：Issue 区能搜到"这个 API 为什么这样设计""这个行为是不是 bug"。**只在这里报 NeoForge 自身的 bug**，你自己的模组出问题不要开 issue。

### 一个反直觉的建议

**先读 issue，再读文档。** 当你遇到"文档说这么写，但编译不过"的情况，去 GitHub 搜那个方法名，往往能找到"这个 API 在 21.1.x 里改过"的讨论。文档更新总是滞后于代码。

## 三、Minecraft Wiki：查"原版是怎么做的"

`https://zh.minecraft.wiki/`（中文）、`https://minecraft.wiki/`（英文）。它不是给模组开发者写的，但它是**唯一把原版机制讲清楚**的地方。

### 三类页面最有用

**1. 方块 / 物品条目页**
每个条目页右侧有信息框：硬度、爆炸抗性、工具、掉落物、可燃性。你要给自己的方块定参数时，照着原版同类方块抄数值最稳。页面底部还有"方块状态"和"数据值"小节，列出所有属性和 ID。

**2. 数据包 / 资源包页面**
`https://zh.minecraft.wiki/w/数据包` 这一页有完整的目录结构表：哪个 JSON 放哪个文件夹、每个字段什么含义。**1.21 把很多目录改成了单数**（`recipes` → `recipe`），Wiki 的版本页会写明，这是核对路径最快的地方。

**3. 版本页面**
`https://zh.minecraft.wiki/w/Java版1.21` 这类页面列出该版本所有改动。迁移时按"技术性更改"那一节逐条对照，比零散地搜博客靠谱。

### 查 Wiki 的两个技巧

- **用页面内的"历史"小节判断版本。** 同一个机制在 1.13、1.20.5、1.21 可能完全不同，历史小节会写"从 xx 版本起改为……"。
- **中文 Wiki 的译名和代码里的名字不一样。** "方块状态"对应 `BlockState`，"刻"对应 tick。查代码时用英文关键词再搜一次。

## 四、看源码：从"猜"变成"知道"

模组开发里最值钱的技能是**读原版代码**。因为文档只讲"提供了什么"，不讲"内部怎么跑"。

### 在 IDE 里追

1. **Ctrl+点击**（Mac 是 Cmd+点击）：跳到定义。看到 `level.getBlockState(pos)` 想确认它返回什么，点进去。
2. **Ctrl+Alt+点击**：跳到实现类。接口的方法点了没用，用这个能看到所有实现。
3. **Ctrl+H**：看类的继承树。`RubyBlock extends Block extends BlockBehaviour`，很多方法其实在 `BlockBehaviour` 里。
4. **Alt+F7**：找用处。想知道 `setChanged()` 到底谁会调，用这个。

### `External Libraries` 里的 Minecraft 源码

IDEA 左侧的 `External Libraries` 展开后能找到 `minecraft-clientonly-...` 之类的条目。第一次点进去是反编译的 `.class`，右上角会有 "Download Sources" 提示——点一下，之后就能看带参数名的源码。

**注意三件事**：

- 这是**反编译产物**，不是原版源码。变量名可能是 `var1`，`switch` 可能被还原成 `while(true)`，`for` 循环可能变成迭代器写法。读逻辑可以，抄结构不行。
- 反编译代码**不能修改**，也不要复制进你的工程。
- 如果点进去只有一行 `// Compiled from ...`，说明源码没下载成功，重启 IDE 再试。

### 在 GitHub 上读

NeoForge 的补丁代码在 `https://github.com/neoforged/NeoForge`，`patches/` 目录下是它对原版的每一处修改。想知道"NeoForge 在这个方法上加了什么钩子"，直接看对应 patch 文件，比翻文档快。

原版行为的话，Minecraft 本身不开源，但有很多反编译项目可供**阅读参考**。读的时候记住：你看到的是别人的反编译结果，跟你的开发环境可能有细微差异。

## 五、学习路径：读别人的模组

这是进步最快的方式，但九成人读错了。

### 怎么挑

| 标准 | 说明 |
|---|---|
| **版本一致** | 必须是 1.21.1 + NeoForge 21.1。读 1.16 的 Forge 模组只会让你更困惑 |
| **代码量小** | 1000~3000 行最佳。十万行的大模组你读不完，也学不到主线 |
| **还在维护** | 最近半年有提交。说明它的写法没过时 |
| **功能单一** | "只加了几种机器"比"什么都有"更适合学习 |
| **有 README** | 作者愿意解释结构，通常代码也干净 |

### 怎么看

按这个顺序读，不要从 `Main.java` 一路往下翻：

1. **`build.gradle`**：看它用什么插件、什么版本、有哪些依赖。这一步能判断这个工程你能不能直接跑起来。
2. **`neoforge.mods.toml`**：看 modid、依赖、有没有 Mixin 配置。
3. **主类**：看它在构造函数里注册了什么。这是整个模组的"目录"。
4. **`ModItems` / `ModBlocks`**：看它的注册风格，`DeferredRegister.create` 还是 `DeferredRegister.Items`。
5. **挑一个最小的功能，从头追到尾**：注册 → 资源文件 → 逻辑。追完一个，整个模组的套路就懂了。
6. **最后再看它的工具类**：`Util`、`Helper` 这类文件里往往藏着作者踩过的坑。

### 拆解原版实现

比读模组更有效的是**拆原版**。比如"漏斗怎么把东西传进箱子"：

```text
HopperBlockEntity#tryMoveItems
  → getSourceContainer / getAttachedContainer
  → 查 Capabilities.ItemHandler.BLOCK
  → IItemHandler#extractItem / insertItem
```

沿着这条链读下来，你不仅学会了漏斗，还顺便学会了能力系统怎么用。**原版是最规范的模组**，它自己就在用 NeoForge 的能力接口。

## 六、常用工具

| 工具 | 用途 | 注意 |
|---|---|---|
| 官方 MDK / 社区模板生成器 | 生成干净工程骨架 | 生成后先把 `mod_id`、包名、显示名改掉 |
| Blockbench | 做方块/物品模型，导出 Java 模型 JSON | 导出时选 "Java Block/Item"，注意 UV 模式和纹理尺寸 |
| IDE 的 JSON 支持 | 校验 JSON 语法、跳转引用 | 大部分"资源不生效"是 JSON 少个逗号 |
| `latest.log` / `debug.log` | 排查问题 | `debug.log` 更详细，`latest.log` 只保留本次 |
| `crash-reports/` | 完整崩溃报告 | 比启动器弹窗里的信息全得多 |
| spark | 性能分析（TPS、卡顿定位） | 卡顿先看它，别靠猜 |
| 资源包/数据包重载 | `/reload`、F3+T | 只对资源有效，改 Java 代码必须重启 |

### 关于 Blockbench 的两个细节

- 导出的 JSON 里 `texture_size` 和 `textures` 的键名要跟你的实际纹理对上，否则模型会显示成全白或紫黑。
- 做"物品在手"的模型时，导出的 `display` 块决定了第一/第三人称的姿态，不改的话拿在手上会歪。

## 七、提问的艺术

在 Discord 或论坛被忽略，通常不是因为问题太简单，而是因为**信息不够别人判断**。

### 一次问清楚要包含五样东西

1. **最小复现**：能触发问题的最少代码。不要贴 500 行的类，贴那 20 行。
2. **完整日志**：`latest.log` 或 `crash-reports/` 的全文，用 pastebin 之类贴链接。**不要截图**——别人没法从截图里复制报错去搜。
3. **版本信息**：MC 版本、NeoForge 版本、Java 版本、加载器版本。这四样决定了一切。
4. **你已经试过什么**：写"我试过 clean、换 JDK、删掉其他模组"，能省掉一轮来回。
5. **你想要的结果 vs 实际的结果**：一句话说清。

### 一个模板

```text
MC 1.21.1 / NeoForge 21.1.72 / Java 21 / ModDevGradle 2.0.x
现象：放置 ruby_block 后立刻变成空气，日志无报错。
期望：正常放置并保留。
已试：clean 重建、删除其他模组、确认 blockstates 文件存在。
日志：<pastebin 链接>
最小代码：<注册方块的那 10 行>
```

这样一段发出去，被回复的概率比"我的方块放不下去怎么办"高十倍。

### 三条礼仪

- 不要在多个频道同时问同一个问题（crosspost），会被无视。
- 得到答案后回一句"解决了，原因是 xx"。这会让后来搜到这条记录的人受益。
- 不要私聊志愿者。公开频道问，答案才能留给别人。

## 八、版本迁移提示：1.20 → 1.21

这一节不是完整迁移指南，只是让你**看到旧教程时能立刻警觉**。以下每一条都是"照抄必炸"级别的变化。

### 1. 物品 NBT 没了，换成数据组件

1.20.4 及以前：`stack.getOrCreateTag().putInt("mana", 10)`。
1.21：先注册一个 `DataComponentType`，再 `stack.set(ModDataComponents.MANA, 10)`。

```java
// 1.21.1 的写法
int mana = stack.getOrDefault(ModDataComponents.MANA, 0);
stack.set(ModDataComponents.MANA, mana + 1);
```

看到 `getOrCreateTag()`、`getTag()`、`hasTag()` 就知道是旧代码。

### 2. `ResourceLocation` 的构造函数变成私有

```java
// 1.20 及以前
new ResourceLocation("dafeiyu", "ruby");

// 1.21
ResourceLocation.fromNamespaceAndPath("dafeiyu", "ruby");
ResourceLocation.parse("dafeiyu:ruby");
```

这是迁移时第一个撞上的编译错误。

### 3. 数据包目录单数化

| 1.20 | 1.21 |
|---|---|
| `data/<ns>/recipes/` | `data/<ns>/recipe/` |
| `data/<ns>/loot_tables/` | `data/<ns>/loot_table/` |
| `data/<ns>/advancements/` | `data/<ns>/advancement/` |
| `data/<ns>/tags/items/` | `data/<ns>/tags/item/` |
| `data/<ns>/tags/blocks/` | `data/<ns>/tags/block/` |
| `data/<ns>/predicates/` | `data/<ns>/predicate/` |
| `data/<ns>/structures/` | `data/<ns>/structure/` |

**改错了不报错，功能就是不生效。** 这是 1.21 最阴的一处。

### 4. 附魔变成数据驱动

1.21 起附魔是数据包定义的（`data/<ns>/enchantment/xxx.json`），不再是一个个 Java 类。想做自定义附魔，先学会写 JSON，再学 `EnchantmentEffectComponents`。

### 5. `Item.Properties#tab` 早就没了

1.20 之前可以 `new Item.Properties().tab(ModCreativeTabs.MAIN)`。现在必须监听 `BuildCreativeModeTabContentsEvent` 手动 `accept`。

### 6. `StreamCodec` 的缓冲区类型

1.21.1 里 `StreamCodec` 的泛型参数还是 `FriendlyByteBuf`：

```java
StreamCodec<FriendlyByteBuf, RubyPayload> STREAM_CODEC = StreamCodec.composite(
        ByteBufCodecs.VAR_INT, RubyPayload::value,
        RubyPayload::new
);
```

再往后的版本（1.21.6 起）换成了 `ValueInput` / `ValueOutput`。你现在**不用管**，但如果你搜到的教程里写的是 `ValueInput`，那说明那是更新版本的代码，直接抄到 1.21.1 上会编译不过。

### 7. `Holder` 用得更多了

很多地方从 `Item` 变成了 `Holder<Item>`（比如附魔、配方结果）。看到 `Holder<Item>` 不要慌，`.value()` 拿实例。

### 一条总原则

**看教程先看版本号。** 没有版本号的教程默认当成过时资料读——读思路，不读代码。真正要抄的代码，只从这三处来：官方文档对应版本页、你正在读的开源模组（同版本）、以及你自己跑通过的代码。

## 常见坑

| 现象 | 原因 | 解决 |
|---|---|---|
| 照着教程写，编译一堆红 | 教程是 1.20 或 Forge 的 | 看 `import`：`net.minecraftforge` 就是 Forge，`new ResourceLocation` 就是 1.20 之前 |
| 文档里的方法 IDE 里没有 | 文档版本跟你工程不一致 | 把 URL 里的版本号改成 `1.21.1`，再对一遍 |
| 读了三个模组，还是不会写 | 只读了 `Main` 和注册类，没追完整链路 | 挑一个最小功能，从注册追到资源到逻辑，追完一个再读下一个 |
| 提问没人回 | 只贴了截图和"怎么办" | 按第七节的五项信息重发一次 |
| `/reload` 之后改动没生效 | 改的是 Java 代码 | Java 改动必须重启游戏，`/reload` 只管资源与数据 |
| 追新版本，教程全对不上 | 新版本刚出，生态没跟上 | 学习期锁定一个版本（本教程是 1.21.1），做完一个完整模组再考虑升级 |

## 练习

1. **查一次数据格式**：去 Minecraft Wiki 找"进度"页面的 JSON 结构，写出一个"捡到红宝石就完成"的进度文件，放进 `data/dafeiyu/advancement/`。不用跑通，能写对字段名就算过。
2. **追一条调用链**：在 IDE 里从 `Block#use` 一路 Ctrl+点击追到原版某个方块的实现（比如工作台），把调用链写成 5 行以内的文字。
3. **读一个小模组**：在 GitHub 上找一个 1.21.1 + NeoForge 的模组，回答三个问题——它用什么 Gradle 插件？它的注册类怎么组织？它有没有用 Mixin，用来干什么？
