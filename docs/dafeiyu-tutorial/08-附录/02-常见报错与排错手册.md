# 常见报错与排错手册

> 二十九个新手最常撞上的报错，按"现象 → 原因 → 解决"排好，附一套读崩溃报告的固定流程。卡住的时候按关键字搜这一篇。

## 学习目标

- 拿到一段崩溃日志，能在两分钟内定位到"是我的代码、版本不对、还是资源没找到"
- 认识 6 类高频报错的关键字，看到第一行就知道往哪个方向查
- 会用"读崩溃报告 5 步法"，不再从日志最后一行开始瞎猜
- 能区分"改完没生效"和"真的没修好"这两种完全不同的情况

## 一、怎么用这本手册

三条规矩，先看这三条能省你一半时间：

1. **先搜关键字，别读全文。** 每个条目开头都给了"关键字"，那是日志里唯一有辨识度的那一段。Ctrl+F 搜它。
2. **日志只信第一段。** 一个异常会引发后面几十行连锁反应，最后那行往往是"我在清理现场时又摔了一跤"，跟真正的病因无关。
3. **改完先 `gradlew clean` 再跑。** 至少三成的"我明明改了"是构建缓存没刷新。

下面按发生的时间顺序分组：启动时炸的、进游戏看不见东西的、东西注册了但不生效的、跑起来才炸的、打包才炸的。

## 二、启动类

这一类发生在"游戏还没进主菜单"或"刚进主菜单就退出"。特征是：**崩溃报告里根本没有世界信息**，只有模组列表和一堆 `at`。

### 1. `NoSuchMethodError`

- **关键字**：`java.lang.NoSuchMethodError:`
- **典型日志**：

```text
java.lang.NoSuchMethodError: 'net.minecraft.world.item.ItemStack net.minecraft.world.item.ItemStack.copyWithCount(int)'
	at com.dafeiyu.common.RubyHandler.tick(RubyHandler.java:37) ~[dafeiyu-1.0.0.jar:?]
```

- **原因**：编译时用的方法签名，跟运行时那个方法对不上。九成是**版本错配**：你的模组按 1.21.4 编译，却跑在 1.21.1 上；或者依赖库版本跟游戏里的不一致。
- **修法**：核对三处版本必须完全一致——`gradle.properties` 里的 `minecraft_version` / `neo_version`、`neoforge.mods.toml` 里的 `versionRange`、你实际启动的那个实例的版本。三者对上之后 `gradlew clean build` 重来。如果日志里的方法是**你自己的模组**的方法，那是两个同名模组版本冲突，去 `mods/` 里删掉旧 jar。

### 2. `NoClassDefFoundError`

- **关键字**：`java.lang.NoClassDefFoundError: net/minecraft/client/...` 或 `... com/dafeiyu/...`
- **典型日志**：

```text
java.lang.NoClassDefFoundError: net/minecraft/client/gui/screens/Screen
	at com.dafeiyu.common.RubyBlock.onPlace(RubyBlock.java:88)
```

- **原因**：分两种。第一种是**在服务端引用了客户端类**（上面这个例子就是），专用服务器上没有 `net.minecraft.client` 这个包。第二种是**依赖没打包进去**，运行到那一行才发现类不存在。
- **修法**：第一种，把那段代码挪到客户端专用类里，用 `@EventBusSubscriber(value = Dist.CLIENT)` 或 `FMLEnvironment.dist` 隔开。第二种，检查 `build.gradle` 里那个依赖是不是写成了 `compileOnly` 却忘了让玩家自己装。

### 3. `Mixin apply failed`

- **关键字**：`Mixin apply for mod ... failed` / `InjectionError` / `Critical injection failure`
- **典型日志**：

```text
org.spongepowered.asm.mixin.injection.throwables.InjectionError:
Critical injection failure: LVT in net/minecraft/world/level/Level::m_46463_(Lnet/minecraft/core/BlockPos;)Z has no slot of type int
	at ... dafeiyu.mixins.json:LevelMixin from mod dafeiyu
```

- **原因**：Mixin 想在目标方法里找一个"注入点"，但没找到。通常是目标方法签名变了（版本不对）、`@At` 的 `target` 写错、或者你用了 `@Local` 却没开 `-parameters` 导致局部变量表丢失。
- **修法**：先确认 Mixin 的 `target` 类和方法在**当前版本**里还在（Ctrl+点击进去看）。`@At("HEAD")` / `@At("RETURN")` 比 `@At("INVOKE")` 稳，优先用。实在需要注入到具体调用点，用 `target = "Lnet/minecraft/...;方法名(...)V"` 的完整描述符写法，别只写方法名。

### 4. `Missing or unsupported mandatory dependencies`

- **关键字**：`Missing or unsupported mandatory dependencies`
- **典型日志**：

```text
Missing or unsupported mandatory dependencies:
	Mod ID: 'neoforge', Requested by: 'dafeiyu', Expected range: '[21.1,)', Actual version: '21.0.167'
```

- **原因**：`neoforge.mods.toml` 里声明的 `versionRange` 跟实际装的 NeoForge 版本不匹配。
- **修法**：要么升级 NeoForge，要么把 `versionRange` 改宽（比如 `[21.1,22)`）。**不要**直接删掉依赖声明——删了之后你的模组会在不兼容的版本上强行加载，崩得更难看。声明依赖的本意就是"宁可加载失败，也不要运行时出错"。

### 5. `Unsupported class file major version`

- **关键字**：`UnsupportedClassVersionError` / `class file version 65.0`
- **典型日志**：

```text
java.lang.UnsupportedClassVersionError:
com/dafeiyu/DafeiyuMod has been compiled by a more recent version of the Java Runtime
(class file version 65.0), this version of the Java Runtime only recognizes
class file versions up to 61.0
```

- **原因**：JDK 版本不对。`65.0` 是 Java 21，`61.0` 是 Java 17。1.21.1 需要 **Java 21**，你用 Java 17 去跑就报这个。
- **修法**：IDEA 里三处都要设成 21——`File > Project Structure > Project SDK`、`Settings > Build > Build Tools > Gradle > Gradle JVM`、以及 `build.gradle` 里的 `java.toolchain.languageVersion = JavaLanguageVersion.of(21)`。三处有一处是 17 就会复发。

### 6. 模组列表里根本没有你的模组

- **关键字**：无报错（这是最坑的一种）
- **典型日志**：日志里搜 `dafeiyu` 只有一行 `Found mod file dafeiyu-1.0.0.jar`，然后没有下文
- **原因**：`neoforge.mods.toml` 里的 `modId` 跟 `@Mod("...")` 里的字符串不一致，加载器认为"这个 jar 声明的模组没人实现"，静默跳过。
- **修法**：把两个字符串逐字符对一遍（大小写、下划线）。顺手检查 `modLoader="javafml"` 和 `loaderVersion="[1,)"` 有没有写错——这两项错了也是同样的静默失败。

### 7. 同一个 modid 装了两份

- **关键字**：`Duplicate mods` / `Found duplicate mod`
- **典型日志**：

```text
Found duplicate mods:
	dafeiyu-1.0.0.jar
	dafeiyu-1.0.0 (1).jar
```

- **原因**：`mods/` 目录里有两个同 modid 的 jar。常见于"下载了两次"或者"开发环境的 jar 和正式版 jar 混在一起"。
- **修法**：删掉旧的。开发时更推荐用 `runClient` 直接跑，不要往正式游戏的 `mods/` 里塞自己正在改的 jar。

## 三、资源类

这一类不崩游戏，只是"东西长得不对"。特征是：**日志里有 WARN 或 ERROR，但游戏能进**。

### 8. 方块紫黑棋盘格

- **关键字**：`Using missing texture` / `Unable to load model`
- **典型日志**：

```text
[Render thread/ERROR] [minecraft/TextureManager]:
Using missing texture, unable to load dafeiyu:textures/block/ruby_block.png
```

- **原因**：三种可能——纹理文件不存在、路径/文件名拼错、PNG 格式有问题（比如 CMYK 或 16 位色深）。
- **修法**：按这个顺序查。第一，确认文件在 `src/main/resources/assets/dafeiyu/textures/block/ruby_block.png`，**目录名必须是 `textures` 不是 `texture`**。第二，文件名全小写、只用下划线。第三，用画图工具重新另存为 8 位 RGB/RGBA PNG。第四，`gradlew clean` 后重进。

### 9. 物品没有纹理（透明方块）

- **关键字**：`Unable to load model: 'dafeiyu:item/ruby'`
- **典型日志**：

```text
[Render thread/WARN] [ne.ne.fo.cl.ModelBakery]:
Unable to load model: 'dafeiyu:item/ruby#inventory' referenced from: dafeiyu:ruby#inventory
```

- **原因**：缺 `assets/dafeiyu/models/item/ruby.json`，或者 JSON 里的 `parent` 指向了不存在的模型。
- **修法**：物品模型最少要这么写：

```json
{
  "parent": "minecraft:item/generated",
  "textures": {
    "layer0": "dafeiyu:item/ruby"
  }
}
```

`layer0` 的值是**纹理路径去掉 `.png`**，不是文件名。写成 `dafeiyu:item/ruby.png` 就找不到。

### 10. 方块模型显示成一个大立方体 / 全是同一张贴图

- **关键字**：`Missing model` 或干脆没日志
- **原因**：`blockstates/ruby_block.json` 里引用的模型名不存在，游戏退回"缺失模型"（那个黑白棋盘的大方块）。或者你用了 `cube_all` 却把 `textures` 里的键写成了 `all` 之外的名字。
- **修法**：`cube_all` 的写法是：

```json
{
  "parent": "minecraft:block/cube_all",
  "textures": { "all": "dafeiyu:block/ruby_block" }
}
```

键必须叫 `all`。用 `cube` 的话六个面要分别给 `down`/`up`/`north`/`south`/`west`/`east`，漏一个就是那个面变紫黑。

### 11. 语言文件里显示 `item.dafeiyu.ruby`

- **关键字**：界面上直接出现 `item.dafeiyu.ruby` 这样的原文
- **原因**：翻译键没找到。要么 `lang/en_us.json` 里没有这个键，要么文件路径不对，要么 JSON 语法错（多了一个逗号）。
- **修法**：路径必须是 `assets/dafeiyu/lang/en_us.json`（`lang` 目录，文件名小写，`en_us` 不是 `en_US`）。键名规则：物品是 `item.dafeiyu.ruby`，方块是 `block.dafeiyu.ruby_block`，创造栏是 `itemGroup.dafeiyu.main`。JSON 里最后一个键后面**不能有逗号**，这一点用 IDE 的 JSON 高亮能立刻看出来。

### 12. 声音不响

- **关键字**：`Unable to play empty soundEvent` / `FileNotFoundException ... .ogg`
- **原因**：三个环节任意一个断了——`sounds.json` 没写、`.ogg` 文件路径不对、代码里 `SoundEvent` 的注册名跟 `sounds.json` 的键不一致。
- **修法**：`assets/dafeiyu/sounds.json` 的键是**声音事件名**（不带命名空间），`sounds` 数组里是**文件路径**（不带 `.ogg`、不带 `sounds/` 前缀）：

```json
{
  "ruby_break": {
    "subtitle": "subtitles.dafeiyu.ruby_break",
    "sounds": ["dafeiyu:ruby_break"]
  }
}
```

对应文件在 `assets/dafeiyu/sounds/ruby_break.ogg`。三者名字必须完全一致。另外 `.ogg` 必须是 **Vorbis** 编码，用 MP3 改后缀是不行的。

### 13. GUI 打开是空白

- **关键字**：没有报错，就是一片灰
- **原因**：通常是 `render` 方法里 `blit` 的坐标或尺寸算错，纹理被画到了屏幕外；或者 `AbstractContainerScreen` 的 `imageWidth`/`imageHeight` 跟实际贴图尺寸不一致。
- **修法**：先在 `render` 里画一个纯色矩形确认方法确实被调用了：

```java
guiGraphics.fill(leftPos, topPos, leftPos + 176, topPos + 166, 0xFF00FF00);
```

能看到绿块说明 `render` 正常，问题在 `blit` 的参数；看不到说明 Screen 根本没打开（去查 `MenuType` 注册和 `player.openMenu`）。

### 14. 粒子不显示

- **关键字**：无报错
- **原因**：服务端发了但客户端没注册 `ParticleProvider`，或者 `ParticleOptions` 的注册名跟客户端注册时用的对不上。
- **修法**：确认两件事——`RegisterParticleProvidersEvent` 在**客户端**事件总线上注册过；`level.sendParticles(...)` 的坐标在玩家附近（超过 32 格客户端会丢弃）。调试时先把粒子数量调到 50，别用 1 个试。

## 四、注册类

这一类最气人：**没有报错，东西就是不出现**。因为游戏不认为你做错了，它只是"没找到"。

### 15. 物品在创造模式物品栏里找不到

- **关键字**：无
- **原因**：注册成功了，但没往任何创造栏里加。1.21 里物品不会自动出现在创造栏。
- **修法**：监听 `BuildCreativeModeTabContentsEvent`，判断 `event.getTabKey()`，然后 `event.accept(ModItems.RUBY)`。或者自己注册一个 `CreativeModeTab`。注意：`accept` 的是 `ItemLike`，不是 `ItemStack`。

### 16. 方块放下去就消失 / 挖了掉空气

- **关键字**：`Missing loot table 'dafeiyu:blocks/ruby_ore'`
- **原因**：三个常见原因。第一，没注册对应的 `BlockItem`，方块放下去没有物品形态。第二，没有战利品表，挖了什么都不掉。第三，客户端缺 `blockstates`，放下去立刻被替换。
- **修法**：注册方块时同时 `ITEMS.registerSimpleBlockItem(ModBlocks.RUBY_ORE)`；在 `data/dafeiyu/loot_table/blocks/ruby_ore.json` 写战利品表；确认 `assets/dafeiyu/blockstates/ruby_ore.json` 存在。三者缺一个都会表现成"放下去就没了"。

### 17. 配方不生效

- **关键字**：`Parsing error loading recipe` / 完全没有日志
- **原因**：目录名写成了 `recipes`（1.21 是单数 `recipe`）；或者 `type` 字段拼错；或者材料用了标签但标签没定义。
- **修法**：路径 `data/dafeiyu/recipe/ruby_block.json`。先写一个最简的 `minecraft:crafting_shaped` 验证通路，再加复杂度。验证方法：`/reload` 之后看日志有没有 `Loaded 1 recipes`，没有就是路径问题。

### 18. 战利品表不触发

- **关键字**：`Missing loot table`
- **原因**：路径是 `loot_tables`（旧）而不是 `loot_table`（1.21）；或者方块属性里挂了 `.noLootTable()`；或者你用 `/setblock` 放的方块，破坏时走的是玩家掉落逻辑。
- **修法**：路径 `data/dafeiyu/loot_table/blocks/<注册路径>.json`。用 `/loot give @s loot dafeiyu:blocks/ruby_ore` 直接测表本身对不对，能给东西说明表没问题，问题在方块那边。

### 19. `Registry is already frozen`

- **关键字**：`Registry is already frozen` / `Adding duplicate`
- **典型日志**：

```text
java.lang.IllegalStateException: Registry is already frozen
	at com.dafeiyu.ModBlocks.<clinit>(ModBlocks.java:22)
```

- **原因**：在注册表冻结之后才调 `Registry.register(...)`。典型场景是在 `FMLCommonSetupEvent` 里手动注册，或者在某个静态块里延迟太久才执行。
- **修法**：所有注册走 `DeferredRegister`，并且只在 `@Mod` 构造函数里 `.register(modEventBus)`。不要手写 `Registry.register`。

## 五、运行时

这一类发生在游戏跑起来之后：进世界、放方块、开界面、联机。

### 20. `NullPointerException` 怎么定位

- **关键字**：`java.lang.NullPointerException: Cannot invoke "..." because "..." is null`
- **典型日志**：

```text
java.lang.NullPointerException: Cannot invoke "net.minecraft.world.level.Level.getBlockState(...)"
because "this.level" is null
	at com.dafeiyu.common.RubyBlockEntity.tick(RubyBlockEntity.java:41)
```

- **原因**：Java 17+ 的 NPE 消息会直接告诉你**哪个变量是 null**（`"this.level" is null`）。这是最好查的一类崩溃。
- **修法**：先看 `because "xxx" is null` 那句，那就是元凶。再看第一个 `at com.dafeiyu...` 行，那是你的代码位置。常见原因：在构造函数里用了还没赋值的字段、`level` 在方块实体被移除后还在用、`getServer()` 在客户端调用返回 null。加一行 `if (level == null || level.isClientSide()) return;` 之前，先想清楚**为什么它会是 null**，别用判空掩盖逻辑错误。

### 21. `ConcurrentModificationException`

- **关键字**：`java.util.ConcurrentModificationException`
- **原因**：遍历一个集合的同时往里面加/删元素。模组里最常见的场景是"遍历所有加载的区块/实体，然后顺手移除其中一个"。
- **修法**：用迭代器显式删除，或者先收集再处理：

```java
// 错误：边遍历边删
for (Entity e : level.getEntities().getAll()) {
    if (e.isRemoved()) level.removeEntity(e);
}

// 正确：先收集
List<Entity> toRemove = new ArrayList<>();
for (Entity e : level.getEntities().getAll()) {
    if (e.isRemoved()) toRemove.add(e);
}
toRemove.forEach(Entity::discard);
```

顺带一提：跨线程改世界数据也会报这个，Minecraft 的世界数据**只能在主线程改**。

### 22. 客户端正常，专用服务器崩溃

- **关键字**：`Attempted to load class ... for invalid dist DEDICATED_SERVER`
- **典型日志**：

```text
java.lang.RuntimeException: Attempted to load class net/minecraft/client/gui/screens/Screen
for invalid dist DEDICATED_SERVER
```

- **原因**：客户端专用类被服务端加载了。你的 `@EventBusSubscriber` 没写 `value = Dist.CLIENT`，或者你在公共类里 `import` 了客户端类（**只要 import 了、方法体里用到了，就可能在类加载阶段触发**）。
- **修法**：把所有 `net.minecraft.client.*` 的引用收进单独的类，给那个类加 `@EventBusSubscriber(value = Dist.CLIENT)`。不要在公共类里写 `if (dist.isClient()) { ...客户端代码... }`——类加载发生在判断之前，照样崩。

### 23. 多人游戏数据不同步

- **关键字**：无报错，就是"主机看得到，别人看不到"
- **原因**：你在客户端改了本地数据，服务端不知道；或者你改了服务端数据但没发同步包。
- **修法**：记住一句话——**服务端算，客户端显示**。方块实体用 `setChanged()` + `level.sendBlockUpdated(...)`；容器用 `ContainerData`；自定义数据用载荷。客户端永远不要"自己算一个结果然后当真"。

### 24. 越玩越卡 / TPS 掉到个位数

- **关键字**：`Can't keep up! Is the server overloaded?`
- **原因**：`tick()` 里做了重活：每刻 `new` 对象、每刻遍历半径 32 内所有方块、每刻 `stream()`。
- **修法**：把逻辑降频。`if (level.getGameTime() % 20 != 0) return;` 一行就能把开销降到 1/20。再狠一点用 `% 100`。另外把 `new BlockPos(...)` 换成可变对象复用，或者干脆只存 `int x, y, z`。

## 六、构建类

这一类连游戏都没进去，卡在 `gradlew`。

### 25. `gradlew build` 失败

- **关键字**：`error: cannot find symbol` / `Could not resolve all files for configuration`
- **原因**：前者是编译错误（少 import、少 `get()`、API 用错），后者是依赖下载失败（网络、仓库地址）。
- **修法**：先看**第一个** `error:`，不是最后一个。`cannot find symbol` 后面会跟 `symbol: method xxx()` 和 `location: class yyy`，这两行直接告诉你缺什么。依赖问题先试 `gradlew --refresh-dependencies`，不行再检查 `repositories` 里有没有 `maven.neoforged.net`。

### 26. `runData` 报错

- **关键字**：`GatherDataEvent` 相关异常 / `Provider ... already registered`
- **原因**：Provider 没在 `gatherData` 里注册；或者同一个 Provider 注册了两次；或者 Provider 内部抛了 NPE（常见于引用了还没初始化的注册对象）。
- **修法**：先确认 `event.addProvider(...)` 写全了。再确认 Provider 里用的东西都是 `ModBlocks.XXX.get()` 而不是直接引用字段。最后看输出的 `src/generated/resources` 目录有没有被别的进程占用。

### 27. jar 里没有资源

- **关键字**：游戏里一切正常，装到别人电脑上全变紫黑
- **原因**：资源放在了 `src/main/java` 下（不会被当资源打包）；或者 `build.gradle` 的 `processResources` 里有 `exclude` 把 `assets/**` 排掉了。
- **修法**：用压缩软件打开 `build/libs/dafeiyu-1.0.0.jar`，看里面有没有 `assets/dafeiyu/`。没有就回头查 `src/main/resources` 的目录结构和 `processResources` 配置。

### 28. 开发环境正常，正式游戏崩溃

- **关键字**：`NoSuchMethodError` / `NoSuchFieldError`，且只发生在装进正式游戏后
- **原因**：混淆。你在代码里用**字符串**写了方法名或字段名（反射、Mixin 的 `@Shadow`、`@At(target=...)`），开发环境里名字是可读的，正式版里被混淆了。
- **修法**：Mixin 用 `@Shadow` 声明字段/方法让工具链帮你重映射，不要手写字符串。反射能用 Codec 或能力替代就替代。实在要反射，把名字写进 `neoforge.mods.toml` 的 `[[mixins]]` 配套 refmap，或者干脆放弃这条路。

### 29. `OutOfMemoryError` / Gradle 卡死

- **关键字**：`java.lang.OutOfMemoryError: Java heap space` / `Gradle daemon disappeared`
- **原因**：Gradle 默认堆内存太小，datagen 或大工程编译时不够用。
- **修法**：在项目根目录的 `gradle.properties` 里加：

```properties
org.gradle.jvmargs=-Xmx4G
org.gradle.daemon=true
```

改完 `gradlew --stop` 停掉旧 daemon 再跑。

## 七、读崩溃报告的 5 步法

别从下往上读。按这个顺序，两分钟能定位到八成问题。

**第 1 步：找第一个 `Exception` 或 `Error`。**
崩溃报告的结构是"头部信息 → 异常栈 → 模组列表 → 系统信息"。异常栈的第一行才是真正的错误类型。往下翻几十行找"最后一个异常"是新手最常犯的错。

**第 2 步：找第一个 `at com.dafeiyu.` 开头的行。**
那是**你的代码**。上面几行是原版或 NeoForge 的调用链，跟你无关；下面几行是你调用的库。真正要改的是这一行指向的 `文件名:行号`。

**第 3 步：往下找 `Caused by:`，一路看到最深的那个。**
`Caused by` 是因果链。最外层通常很笼统（"Failed to load mod"），最里层才是根因（"FileNotFoundException: ruby_block.json"）。**只看最里层。**

**第 4 步：判断这是环境问题还是代码问题。**
看三个信号：报错里有没有 `Missing or unsupported`（依赖）、有没有 `class file version`（JDK）、有没有 `Unable to load`（资源）。这三个都是环境/资源问题，改代码没用。

**第 5 步：把关键字原样粘进搜索框。**
搜索时做三件事：去掉 `com.dafeiyu` 这类你自己的包名、去掉行号和文件路径、保留英文原句和引号。`"Attempted to load class" "invalid dist"` 比 "服务端崩溃怎么办" 有效一百倍。

### 日志怎么搜才搜得到

| 别这样搜 | 这样搜 |
|---|---|
| 我的模组崩了 | `"Missing or unsupported mandatory dependencies"` |
| 方块变紫黑了 | `"Using missing texture" neoforge` |
| 配方没用 | `"Parsing error loading recipe" 1.21` |
| 服务端崩了 | `"invalid dist DEDICATED_SERVER"` |

搜索时加上版本号（`1.21.1`）和平台（`neoforge`），能过滤掉九成的旧答案。

## 常见坑：排错过程本身的坑

| 现象 | 原因 | 解决 |
|---|---|---|
| 改了代码，行为一点没变 | Gradle 增量编译没刷新，或者你跑的是旧 jar | `gradlew clean` 后重跑；确认 `runClient` 用的是当前工程而不是 `mods/` 里的旧 jar |
| 报错消失了，但功能还是不对 | 你把异常 catch 掉了，问题被掩盖 | 搜代码里的 `catch (Exception e) {}`，改成至少 `e.printStackTrace()` |
| 日志里什么都没有 | 日志被截断，或者你看的是启动器日志不是游戏日志 | 找 `logs/latest.log` 和 `crash-reports/` 下的完整文件 |
| 装了 30 个模组，不知道谁的问题 | 没做二分 | 先只留 NeoForge + 你的模组，能跑再一半一半加回来 |
| 同一个错误反复出现 | 只改了症状没改病因（比如一直加判空） | 问自己"这个值为什么是 null"，而不是"怎么让它不 null" |
| 抄了别人的修复方案还是崩 | 版本不同 | 先确认对方的 MC / NeoForge / 加载器版本，再看方案 |

## 自查

遇到崩溃时，按顺序问自己这六个问题：

1. 这是启动时崩的，还是进世界之后崩的？（决定看第二节还是第五节）
2. 日志里第一个异常类型是什么？
3. 第一个 `at com.dafeiyu.` 在哪一行？
4. 最深的那层 `Caused by` 说了什么？
5. 我上次改动是什么？改完之后有没有 `clean`？
6. 这个错误，把关键字原样搜一遍，前三条结果说的是同一个版本吗？

六问都答完还卡住，再去提问——而且把答案一起贴出去，这样别人才愿意帮你看。
