# 创造模式物品栏

> 读完这篇，你会拥有一个自己的创造模式标签页：有图标、有中文标题、按你定的顺序摆放物品，同时知道往原版标签页里塞东西的正确姿势和常见翻车点。

## 学习目标

- 能说清为什么模组通常要自建创造标签页，而不是都塞进「材料」页。
- 能用 `CreativeModeTab.builder()` + `DeferredRegister<CreativeModeTab>` 注册一个自定义标签页。
- 能用 `displayItems` 控制标签页里放什么、按什么顺序放。
- 能用 `BuildCreativeModeTabContentsEvent` 往原版标签页里插物品，并知道它为什么必须在模组事件总线上。
- 能定位「标签页不出现」「标签页是空的」「物品重复」「标题显示成一串键名」这四类问题。

## 一、为什么要自建标签页

创造模式物品栏是一排标签页：建筑方块、自然、装饰、红石、工具、战斗、食物、材料、刷怪蛋……每个标签页是一组物品的展示清单。

你做的模组如果只有三五个物品，塞进「材料」页完全够用。但只要物品上到十几个（一套工具、一套盔甲、一堆矿石和它们的块），继续往原版页里塞就会有两个问题：

1. **玩家的心智负担**：他在「材料」页里翻到第 8 页，看到你的红宝石、蓝宝石、红宝石块、蓝宝石块、红宝石粉……混在铁锭和金锭中间，根本分不清哪些是一个套系。
2. **你自己的维护成本**：原版标签页的顺序是固定的，你想把「红宝石 → 红宝石块 → 红宝石工具」排在一起，做不到。

自建标签页解决的就是这两件事：**一个模组一个页，页内顺序你说了算**。

顺带一个好处：玩家在创造模式搜索框里搜「红宝石」，只要物品在你的标签页里，就能被搜到——搜索页是从所有标签页汇总的。

## 二、注册一个标签页

创造标签页本身也是一个注册表对象，注册表叫 `Registries.CREATIVE_MODE_TAB`。

文件：`src/main/java/com/dafeiyu/ModCreativeTabs.java`

```java
package com.dafeiyu;

import net.minecraft.core.registries.Registries;
import net.minecraft.network.chat.Component;
import net.minecraft.world.item.CreativeModeTab;
import net.minecraft.world.item.ItemStack;
import net.neoforged.bus.api.IEventBus;
import net.neoforged.neoforge.registries.DeferredHolder;
import net.neoforged.neoforge.registries.DeferredRegister;

public class ModCreativeTabs {
    public static final DeferredRegister<CreativeModeTab> CREATIVE_MODE_TABS =
            DeferredRegister.create(Registries.CREATIVE_MODE_TAB, DafeiyuMod.MOD_ID);

    public static final DeferredHolder<CreativeModeTab, CreativeModeTab> MAIN_TAB =
            CREATIVE_MODE_TABS.register("main", () -> CreativeModeTab.builder()
                    // 标题：必须自己提供翻译
                    .title(Component.translatable("itemGroup.dafeiyu.main"))
                    // 图标：标签页上显示的那个小图标
                    .icon(() -> new ItemStack(ModItems.RUBY.get()))
                    // 内容
                    .displayItems((params, output) -> {
                        output.accept(ModItems.RUBY.get());
                        output.accept(ModBlocks.RUBY_BLOCK.get());
                        output.accept(ModBlocks.COUNTER_BLOCK.get());
                    })
                    .build());

    public static void register(IEventBus modEventBus) {
        CREATIVE_MODE_TABS.register(modEventBus);
    }
}
```

逐行拆：

**`DeferredRegister.create(Registries.CREATIVE_MODE_TAB, MOD_ID)`** —— 注意这里不能用 `DeferredRegister.Items` 之类的专用版本，创造标签页只有通用写法。类型参数是 `CreativeModeTab`。

**`.title(Component)`** —— 标题是一个**组件（`Component`）**，不是字符串。`Component.translatable("键")` 表示「这个标题要去语言文件里查」。键的命名习惯是 `itemGroup.<命名空间>.<名字>`，这是原版的约定（`itemGroup` 是历史遗留的写法，别改成 `creativeTab`）。

**`.icon(() -> new ItemStack(...))`** —— 注意参数是一个 `Supplier<ItemStack>`，不是 `ItemStack`。为什么要延迟？因为注册这个标签页的时候，物品可能还没被创建出来。写成 `.icon(new ItemStack(...))` 会直接编译失败。

**`.displayItems((params, output) -> {...})`** —— 这是标签页的内容生成器。`output.accept(...)` 每调用一次就加一个物品。`params` 里带着当前的功能开关、是否拥有管理员权限等信息，你现在用不到。

**`output.accept(ModBlocks.RUBY_BLOCK.get())`** —— 这里传方块也能工作，因为 `Block` 实现了 `ItemLike`，游戏会自动找到它对应的 `BlockItem`。但如果那个方块**没有**注册 `BlockItem`（比如火），`accept` 会静默什么都不加。

**`.build()`** —— 最后一定要调，否则你拿到的是 builder 而不是标签页，编译直接报错。

### 2.1 注册顺序与主类

```java
public DafeiyuMod(IEventBus modEventBus, ModContainer modContainer) {
    ModBlocks.register(modEventBus);
    ModItems.register(modEventBus);
    ModBlockEntities.register(modEventBus);
    ModCreativeTabs.register(modEventBus);   // 最后
}
```

标签页放在最后，因为它的 `displayItems` 里引用了物品和方块。虽然那些引用是延迟求值的（真正执行在游戏收集物品时），但保持「被依赖的先注册」这个习惯，能帮你避开 90% 的初始化顺序问题。

### 2.2 语言文件

`assets/dafeiyu/lang/zh_cn.json`

```json
{
  "itemGroup.dafeiyu.main": "大肥鱼"
}
```

漏了这一条，标签页标题会显示成 `itemGroup.dafeiyu.main` 这串原始键。标签页本身还是会正常出现、正常显示图标——所以这个错误特别容易被忽略，直到你截图发给别人。

## 三、把物品塞进原版标签页

自建标签页不是唯一选择。有时候你就是想加一个「和铁锭放一起更合理」的材料，那就往原版页里塞。

这件事通过 `BuildCreativeModeTabContentsEvent` 完成。这个事件在**模组事件总线**上触发，且**只在逻辑客户端**触发（因为物品栏是客户端的东西）。

文件：`src/main/java/com/dafeiyu/ModCreativeTabEvents.java`

```java
package com.dafeiyu;

import net.minecraft.world.item.CreativeModeTabs;
import net.neoforged.bus.api.SubscribeEvent;
import net.neoforged.fml.common.EventBusSubscriber;
import net.neoforged.neoforge.event.BuildCreativeModeTabContentsEvent;

@EventBusSubscriber(modid = DafeiyuMod.MOD_ID, bus = EventBusSubscriber.Bus.MOD)
public class ModCreativeTabEvents {
    @SubscribeEvent
    public static void buildContents(BuildCreativeModeTabContentsEvent event) {
        if (event.getTabKey() == CreativeModeTabs.INGREDIENTS) {
            event.accept(ModItems.RUBY.get());
        }
        if (event.getTabKey() == CreativeModeTabs.BUILDING_BLOCKS) {
            event.accept(ModBlocks.RUBY_BLOCK.get());
        }
    }
}
```

几个要点：

**`event.getTabKey()`** 返回 `ResourceKey<CreativeModeTab>`，和 `CreativeModeTabs.INGREDIENTS` 是同一类型，所以可以直接 `==` 比较（枚举式的注册表键是单例，用 `==` 是安全的）。

**这个事件会被所有标签页各触发一次**，所以方法体里必须先判断 `getTabKey()`，否则你的物品会被加进每一个标签页——包括「刷怪蛋」和「管理员物品」。

**`event.accept(...)` 接受 `ItemLike`**，所以既能传 `Item`，也能传 `Block`（前提是有对应的 `BlockItem`）。

**别在这里判断 `level.isClientSide`** —— 这个事件本身就只在客户端触发，没有 `level` 可判断。

除了 `accept`，NeoForge 还给这个事件提供了按位置插入的能力（插到某个物品前面/后面、插到最前面），需要精细排序时查一下 `BuildCreativeModeTabContentsEvent` 的方法列表即可。日常用 `accept` 追加到末尾就够了。

### 3.1 两种方式怎么选

| | 自建标签页 | 塞进原版标签页 |
|---|---|---|
| 适合 | 物品成套、数量多 | 零散的一两个材料 |
| 排序控制 | 完全自主 | 只能追加或相对插入 |
| 玩家感知 | 一眼看到「这是某某模组」 | 融进原版，不容易被发现 |
| 代码量 | 一个类 + 一条翻译 | 一个事件方法 |

实践中的常见组合是：**自建一个主标签页放全部内容**，同时把一两个「原材料」也塞进原版「材料」页，方便玩家按习惯找。这不叫重复，因为它们在两个不同的标签页里。

## 四、图标怎么选

图标是玩家对这个模组的第一印象，几个经验：

- **用你最有代表性的物品**，通常是最核心的那个材料或方块，不要用工具（工具的形状在小尺寸下糊成一团）。
- 图标用的是物品模型渲染出来的 16×16 图像，所以你不需要额外准备图片。
- **不要给一个空堆叠**（`ItemStack.EMPTY`）。图标为空的标签页在部分版本里会直接崩，或者显示成一个空白格，非常难排查。
- 图标物品**不必**出现在这个标签页里。但如果你让它出现，玩家点开时会觉得「对上了」，体验更好。

## 五、两个容易忽略的细节

**第一个：不在任何标签页里的物品，搜索也搜不到。**

创造模式的搜索页不是一个「遍历注册表」的页面，它是把所有标签页的内容汇总起来再过滤。所以一个物品如果既没进你的标签页、也没进原版标签页，那它只存在于 `/give` 里——玩家在创造模式里翻遍所有页、搜遍所有关键词都找不到。这也是为什么「注册完就以为做完了」是个很危险的习惯。

**第二个：`displayItems` 只在打开物品栏时执行，不要在里做重活。**

玩家每按一次 `E`，所有标签页的 `displayItems` 都会重新跑一遍。你在里面遍历几千个方块、读文件、算哈希，就会表现为「按 E 卡半秒」。需要大量物品时，提前算好放进一个 `List` 里缓存，`displayItems` 里只做遍历添加。

## 六、验证

1. `runClient`，进创造模式，按 `E`。
2. 标签页栏最右边（默认位置）应该多出一个「大肥鱼」，图标是红宝石。
3. 点进去，按顺序看到：红宝石、红宝石块、计数器方块。
4. 切到「材料」页，也能看到红宝石（因为第 1 篇的事件还在）。
5. 在搜索框输入「红宝石」，两个都能搜到。

## 完整示例

**① `src/main/java/com/dafeiyu/ModCreativeTabs.java`** —— 见第二节完整代码。

**② `src/main/java/com/dafeiyu/DafeiyuMod.java`**

```java
package com.dafeiyu;

import net.neoforged.bus.api.IEventBus;
import net.neoforged.fml.ModContainer;
import net.neoforged.fml.common.Mod;

@Mod(DafeiyuMod.MOD_ID)
public class DafeiyuMod {
    public static final String MOD_ID = "dafeiyu";

    public DafeiyuMod(IEventBus modEventBus, ModContainer modContainer) {
        ModBlocks.register(modEventBus);
        ModItems.register(modEventBus);
        ModBlockEntities.register(modEventBus);
        ModCreativeTabs.register(modEventBus);
    }
}
```

**③ `src/main/resources/assets/dafeiyu/lang/zh_cn.json`**

```json
{
  "item.dafeiyu.ruby": "红宝石",
  "block.dafeiyu.ruby_block": "红宝石块",
  "block.dafeiyu.counter_block": "计数器方块",
  "itemGroup.dafeiyu.main": "大肥鱼"
}
```

**④ 如果你希望标签页排在「战斗」之后**

NeoForge 的 `CreativeModeTab.Builder` 提供了调整标签页顺序的方法（把某个原版标签页的 `ResourceKey` 传进去即可），在 `.build()` 之前链式调用一行就行。不同小版本的方法名略有差异，写之前先在 IDE 里对 `CreativeModeTab.builder()` 打一个点，看补全列表里有没有 `withTabsBefore`，有就放心用。

## 常见坑与报错

| 现象 | 原因 | 解决 |
|---|---|---|
| 标签页完全不出现 | 忘了在主类里 `ModCreativeTabs.register(modEventBus)` | 补上 |
| 标签页出现了，但点进去是空的 | `displayItems` 里忘了 `output.accept(...)`，或全传了没注册 `BlockItem` 的方块 | 检查每一项是否 `.get()`、方块是否有对应物品 |
| 启动崩溃，日志提到 `ItemStack` 为 null 或 `Empty` | `.icon()` 里用了 `ItemStack.EMPTY`，或物品还没注册 | 图标换成已注册物品，并保持 `() -> new ItemStack(...)` 的延迟写法 |
| 标题显示 `itemGroup.dafeiyu.main` | 语言文件缺这条，或键拼错（大小写、点号） | 逐字符对照，注意是 `itemGroup` 驼峰 |
| 同一个标签页里物品出现两次 | `displayItems` 里 `accept` 了两次，或既 `accept` 又通过别的途径加入 | 每个物品只 `accept` 一次 |
| 物品被加进了「刷怪蛋」「管理员物品」等所有页 | `BuildCreativeModeTabContentsEvent` 里没判断 `getTabKey()` | 先 `if` 再 `accept` |
| 事件方法永远不执行，物品没进原版页 | `@EventBusSubscriber` 少了 `bus = EventBusSubscriber.Bus.MOD` | 默认是游戏总线，必须显式指定模组总线 |
| 编译报错：`ItemStack cannot be converted to Supplier<ItemStack>` | `.icon(...)` 传了 `new ItemStack(...)` | 改成 `.icon(() -> new ItemStack(...))` |
| 服务器启动报客户端类缺失 | 在 `displayItems` 里调用了 `Minecraft.getInstance()` | 标签页代码必须两侧通用，不能碰客户端类 |

## 练习

1. **基础**：把红宝石块从「建筑方块」页里挪出来，只在自建页出现，确认原版页里消失。
2. **进阶**：在自建页里按「材料 → 方块 → 工具 → 食物」的顺序摆放，用注释把每一组隔开，并给每个物品写一行说明它属于哪一组。
3. **挑战**：做第二个标签页「大肥鱼·装饰」，只放方块类物品，图标用计数器方块。想一想：两个标签页的 `displayItems` 里如果有同一个物品，会出现什么现象？会崩溃吗？动手验证一下。
