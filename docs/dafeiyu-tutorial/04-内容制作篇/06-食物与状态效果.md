# 食物与状态效果

> 读完这篇，你会做出一个「红宝石苹果」：能回饥饿值、永远能吃不限饱食度、吃下去给你一个自己写的「红宝石之力」效果，并且知道效果为什么不显示图标、为什么有时候不生效。

## 学习目标

- 能用 `FoodProperties.Builder` 配出营养值、饱和度、总能吃、快速进食、食用后效果。
- 能写一个自定义 `MobEffect` 子类，理解 `applyEffectTick` 与 `shouldApplyEffectTickThisTick` 的配合。
- 能用 `DeferredRegister<MobEffect>` 注册效果，并解释颜色、分类、属性修饰符各自的作用。
- 能把效果挂到食物上，并知道「为什么必须用 Supplier 版本」。
- 能说清效果逻辑为什么必须判侧，以及 `applyEffectTick` 返回 `false` 会发生什么。
- 知道 `Potion` 的注册思路和酿造配方的挂载位置。

## 一、食物不是一种物品，是一个组件

在 1.21 里，「能吃」不是某个 `FoodItem` 类的特权，而是物品身上挂了一个 `minecraft:food` 数据组件。所以做食物**不需要写新类**，只要在 `Item.Properties` 里塞一个 `FoodProperties`：

```java
new Item.Properties().food(new FoodProperties.Builder()...build())
```

`FoodProperties` 是一个不可变对象（record），描述「吃了会怎样」。它用 Builder 造，因为参数多且大部分有默认值。

| 方法 | 含义 | 默认 |
|---|---|---|
| `nutrition(int)` | 回复多少饥饿点（半格 = 1） | 必填 |
| `saturationModifier(float)` | 饱和度**系数**，不是绝对值 | 0 |
| `alwaysEdible()` | 饥饿条满时也能吃 | 否 |
| `fast()` | 吃得快（干海带那种） | 否 |
| `effect(Supplier<MobEffectInstance>, float)` | 吃后施加效果 + 概率 | 无 |
| `usingConvertsTo(Item)` | 吃完变成什么（比如碗） | 无 |
| `build()` | 生成 `FoodProperties` | — |

**饱和度那个坑必须先讲**：`saturationModifier` 不是「回复多少饱和度」，而是一个系数。实际恢复量按

```text
min(2 × nutrition × saturationModifier, 玩家当前饥饿值)
```

计算。所以 `nutrition(6).saturationModifier(0.8f)` 的实际饱和度是 `2 × 6 × 0.8 = 9.6`。你写 `saturationModifier(9.6f)` 会得到一个夸张到离谱的食物。参考值：熟牛排是 `nutrition(8).saturationModifier(0.8f)`，金苹果是 `nutrition(4).saturationModifier(1.2f)`。

## 二、先写效果，再写食物

顺序很重要：食物要引用效果，效果没注册好，食物的效果供应商就会拿到 null。所以先做效果。

### 2.1 效果类

文件：`src/main/java/com/dafeiyu/RubyPowerEffect.java`

```java
package com.dafeiyu;

import net.minecraft.world.effect.MobEffect;
import net.minecraft.world.effect.MobEffectCategory;
import net.minecraft.world.entity.LivingEntity;

public class RubyPowerEffect extends MobEffect {

    public RubyPowerEffect(MobEffectCategory category, int color) {
        super(category, color);
    }

    /**
     * 效果"生效"时被调用。返回值决定效果是否继续存在：
     * 返回 false 会让效果立刻被移除，所以正常情况一律 return true。
     */
    @Override
    public boolean applyEffectTick(LivingEntity entity, int amplifier) {
        // 效果逻辑在两侧都会跑，改世界/改血量必须只在服务端做
        if (!entity.level().isClientSide()) {
            // 每生效一次回 1 点血（amplifier 是等级，0 表示 I 级）
            entity.heal(1.0f + amplifier);
        }
        return true;
    }

    /**
     * 决定"这一 tick 要不要生效"。
     * 返回 true 的刻才会调用 applyEffectTick。
     */
    @Override
    public boolean shouldApplyEffectTickThisTick(int tickCount, int amplifier) {
        // 每 40 刻（2 秒）生效一次
        return tickCount % 40 == 0;
    }
}
```

两个方法的关系是新手最容易搞混的，用一句话概括：

> **`shouldApplyEffectTickThisTick` 是门卫，`applyEffectTick` 是干活的人。** 门卫说「进」，干活的人才动；门卫不说，干活的人这一 tick 就闲着。

如果只重写 `applyEffectTick` 而不重写门卫，父类默认实现返回 `true`，也就是**每 tick 都生效**（每秒 20 次）。回血效果每 tick 回 1 点，那就是每秒回 20 点，强得离谱。所以做持续性效果时，几乎总要重写门卫。

`amplifier` 是效果等级减一：I 级是 0，II 级是 1。所以 `1.0f + amplifier` 表示「I 级回 1 点，II 级回 2 点」。

### 2.2 注册效果

文件：`src/main/java/com/dafeiyu/ModEffects.java`

```java
package com.dafeiyu;

import net.minecraft.core.registries.Registries;
import net.minecraft.resources.ResourceLocation;
import net.minecraft.world.effect.MobEffect;
import net.minecraft.world.effect.MobEffectCategory;
import net.minecraft.world.entity.ai.attributes.AttributeModifier;
import net.minecraft.world.entity.ai.attributes.Attributes;
import net.neoforged.bus.api.IEventBus;
import net.neoforged.neoforge.registries.DeferredHolder;
import net.neoforged.neoforge.registries.DeferredRegister;

public class ModEffects {
    public static final DeferredRegister<MobEffect> MOB_EFFECTS =
            DeferredRegister.create(Registries.MOB_EFFECT, DafeiyuMod.MOD_ID);

    public static final DeferredHolder<MobEffect, MobEffect> RUBY_POWER =
            MOB_EFFECTS.register("ruby_power", () -> new RubyPowerEffect(
                            // 分类：决定药水提示框的颜色基调，也影响"有益/有害"的判定
                            MobEffectCategory.BENEFICIAL,
                            // 粒子颜色，十六进制 RGB
                            0xE0115F)
                    // 顺带加 2 点攻击伤害（相当于力量 I）
                    .addAttributeModifier(
                            Attributes.ATTACK_DAMAGE,
                            ResourceLocation.fromNamespaceAndPath(DafeiyuMod.MOD_ID, "effect.ruby_power"),
                            2.0,
                            AttributeModifier.Operation.ADD_VALUE));

    public static void register(IEventBus modEventBus) {
        MOB_EFFECTS.register(modEventBus);
    }
}
```

几个点：

**`MobEffectCategory`** 有三个值：`BENEFICIAL`（有益）、`HARMFUL`（有害）、`NEUTRAL`（中性）。它主要影响药水提示框的颜色和部分判定逻辑，不影响效果本身。

**颜色** 是 `int`，用 `0xRRGGBB` 写。它决定效果粒子（你身上飘的那些小点）的颜色。

**`addAttributeModifier`** 返回的是 `this`，所以可以链式接在构造器后面。这就是为什么注册的类型参数写的是 `DeferredHolder<MobEffect, MobEffect>` 而不是 `DeferredHolder<MobEffect, RubyPowerEffect>`——链式调用后返回类型变成了 `MobEffect`。

**属性修饰符的 id** 必须是全局唯一的 `ResourceLocation`。如果两个效果用了同一个 id，后加的那个会覆盖前一个，而且不会有任何报错。

### 2.3 效果图标

效果要显示图标，需要一张纹理：

```text
assets/dafeiyu/textures/mob_effect/ruby_power.png
```

- 路径是 `textures/mob_effect/`，**单数**，不是 `mob_effects`。
- 尺寸建议 18×18（原版效果图标就是这个尺寸），带透明背景。
- 文件名必须和注册名一致。

漏了这张图，效果**仍然会生效**，只是右上角的图标位置显示成一个紫黑小方块，或者干脆空白。这是「效果不显示图标」的唯一原因，记住它。

### 2.4 效果、药水、食物，三者怎么分工

很多人第一次做的时候会把这三样混在一起，结果做出一堆「只能用一次」的东西。它们的关系其实是：

- **`MobEffect`** 是「效果本身」：每秒回血、加攻击、减速。它不知道自己是哪来的，也不关心。
- **`MobEffectInstance`** 是「一次具体的施加」：哪个效果、多久、几级。它是真正挂在实体身上的东西。
- **`FoodProperties` 里的 `effect`** 是「吃这个食物时顺手施加一个实例」，一次性、绑死在食物上。
- **`Potion`** 是「一组实例的打包」，可以酿、可以喷溅给别人、可以做成滞留药水和药箭。

所以选择很简单：想让玩家「吃一口就得到」，用食物；想让玩家「提前准备、战斗中喝、还能扔给队友」，用药水；想让效果由方块、事件、装备触发，那就直接 `entity.addEffect(...)`，两者都不用。

## 三、把效果挂到食物上

文件：`src/main/java/com/dafeiyu/ModItems.java`（新增）

```java
public static final DeferredItem<Item> RUBY_APPLE = ITEMS.registerSimpleItem("ruby_apple",
        new Item.Properties().food(new FoodProperties.Builder()
                .nutrition(6)                              // 回 3 格饥饿值
                .saturationModifier(0.8f)                  // 饱和度系数
                .alwaysEdible()                            // 饱了也能吃
                .effect(() -> new MobEffectInstance(ModEffects.RUBY_POWER, 600, 0), 1.0f) // 30 秒，100% 触发
                .build()));
```

新增 import：

```java
import net.minecraft.world.effect.MobEffectInstance;
import net.minecraft.world.food.FoodProperties;
```

**为什么 `effect` 的第一个参数是 `() -> new MobEffectInstance(...)` 而不是直接给实例？**

因为注册 `ModItems` 这个类的静态字段时，`ModEffects.RUBY_POWER` 可能还没注册完成，直接 `.get()` 会拿到 null。写成 Lambda，真正的取值被推迟到「玩家吃东西」那一刻，那时所有注册都完成了。

NeoForge 里还有一个直接接收 `MobEffectInstance` 的重载，但它被标记为弃用，原因正是类加载顺序问题。**永远用 Supplier 版本。**

参数说明：`new MobEffectInstance(effect, 持续时间刻数, 等级, 是否环境效果, 是否可见, 是否显示图标)`。后三个参数可以省略，默认 `false, true, true`。`600` 刻 = 30 秒。

`1.0f` 是触发概率。写 `0.8f` 就是 80% 概率，和腐肉给饥饿效果一样。

## 四、药水（简述）

药水（`Potion`）是一组 `MobEffectInstance` 的集合。它本身不是一个物品，而是一个注册表对象；原版的「药水」「喷溅药水」「滞留药水」「药箭」通过 `minecraft:potion_contents` 组件引用它。

注册一个药水只要一行：

```java
package com.dafeiyu;

import net.minecraft.core.registries.Registries;
import net.minecraft.world.effect.MobEffectInstance;
import net.minecraft.world.item.alchemy.Potion;
import net.neoforged.bus.api.IEventBus;
import net.neoforged.neoforge.registries.DeferredHolder;
import net.neoforged.neoforge.registries.DeferredRegister;

public class ModPotions {
    public static final DeferredRegister<Potion> POTIONS =
            DeferredRegister.create(Registries.POTION, DafeiyuMod.MOD_ID);

    public static final DeferredHolder<Potion, Potion> RUBY_POWER_POTION =
            POTIONS.register("ruby_power", () -> new Potion(
                    new MobEffectInstance(ModEffects.RUBY_POWER, 3600, 0)));

    public static void register(IEventBus modEventBus) {
        POTIONS.register(modEventBus);
    }
}
```

`new Potion(...)` 的参数是可变参数，可以塞多个效果，也可以一个都不塞（原版的「粗制的药水」就是空的）。

**注意：光注册药水，游戏里是拿不到的。** 药水必须通过酿造台或者命令获得。用命令最快，1.21 的组件写法是：

```text
/give @s minecraft:potion[minecraft:potion_contents={potion:"dafeiyu:ruby_power"}]
```

想让它能酿造，需要挂一个酿造配方。酿造配方不支持数据包，只能用代码注册，事件在**游戏事件总线**上：

```java
package com.dafeiyu;

import net.minecraft.world.item.Items;
import net.minecraft.world.item.alchemy.Potions;
import net.neoforged.bus.api.SubscribeEvent;
import net.neoforged.fml.common.EventBusSubscriber;
import net.neoforged.neoforge.event.brewing.RegisterBrewingRecipesEvent;

@EventBusSubscriber(modid = DafeiyuMod.MOD_ID)
public class ModBrewingRecipes {
    @SubscribeEvent
    public static void registerBrewingRecipes(RegisterBrewingRecipesEvent event) {
        event.getBuilder().addMix(
                Potions.AWKWARD,                 // 起始药水：粗制的药水
                ModItems.RUBY.get(),             // 酿造台上面那格放的东西
                ModPotions.RUBY_POWER_POTION);   // 结果
    }
}
```

注意这个注解**没有** `bus = EventBusSubscriber.Bus.MOD`——`RegisterBrewingRecipesEvent` 在游戏总线上，默认值正好对。这和创造标签页那个事件刚好相反，别记混：**注册表相关 → 模组总线；游戏运行相关 → 游戏总线。**

## 五、验证

1. `/give @s dafeiyu:ruby_apple`。
2. 饥饿条满的时候右键——**能吃**（因为 `alwaysEdible()`），饥饿条不变，但右上角出现「红宝石之力」图标。
3. 打一只僵尸，伤害应该比空手高 2 点（属性修饰符生效）。
4. 看血量：每 2 秒回 1 点，持续 30 秒。
5. 按 `E` 打开物品栏，效果图标应该是一个你自己画的图标，不是紫黑方块。
6. 用药水命令验证药水：喝下去效果持续 3 分钟。

```java
package com.dafeiyu;

import net.minecraft.world.effect.MobEffectInstance;
import net.minecraft.world.food.FoodProperties;
import net.minecraft.world.item.Item;
import net.minecraft.world.item.Items;
import net.neoforged.bus.api.IEventBus;
import net.neoforged.neoforge.registries.DeferredItem;
import net.neoforged.neoforge.registries.DeferredRegister;

public class ModItems {
    public static final DeferredRegister.Items ITEMS = DeferredRegister.createItems(DafeiyuMod.MOD_ID);

    // 为节省篇幅，这里只列新增的两个食物；前面几篇的物品请保持原样留着

    /** 红宝石苹果：回 3 格饥饿、饱了也能吃、吃完获得 30 秒红宝石之力 */
    public static final DeferredItem<Item> RUBY_APPLE = ITEMS.registerSimpleItem("ruby_apple",
            new Item.Properties().food(new FoodProperties.Builder()
                    .nutrition(6)
                    .saturationModifier(0.8f)
                    .alwaysEdible()
                    .effect(() -> new MobEffectInstance(ModEffects.RUBY_POWER, 600, 0), 1.0f)
                    .build()));

    /** 一份"快速食物"的例子：吃得快、吃完把碗还给你 */
    public static final DeferredItem<Item> RUBY_SOUP = ITEMS.registerSimpleItem("ruby_soup",
            new Item.Properties().food(new FoodProperties.Builder()
                    .nutrition(8)
                    .saturationModifier(0.6f)
                    .fast()
                    .usingConvertsTo(Items.BOWL)
                    .build()));

    public static void register(IEventBus modEventBus) {
        ITEMS.register(modEventBus);
    }
}
```

## 常见坑与报错

| 现象 | 原因 | 解决 |
|---|---|---|
| 吃了完全没效果 | `ModEffects.register` 排在 `ModItems` 之后，效果还没注册 | 调整主类顺序，效果在前 |
| 饱食度满时吃不了 | 没写 `alwaysEdible()` | 加上；注意它和「营养值」是两回事 |
| 效果生效了，但右上角没图标 | 缺 `assets/dafeiyu/textures/mob_effect/ruby_power.png` | 补图，注意目录是单数 `mob_effect` |
| 效果图标是紫黑方块 | 纹理路径/文件名与注册名不一致 | 文件名必须等于注册名 |
| 效果名字显示 `effect.dafeiyu.ruby_power` | 语言文件缺 `effect.` 前缀的条目 | 补翻译 |
| 效果强到离谱（一秒回满血） | 没重写 `shouldApplyEffectTickThisTick`，每 tick 都生效 | 重写门卫，按需限流 |
| 效果一加上就消失了 | `applyEffectTick` 返回了 `false` | 正常路径一律 `return true` |
| 回血/伤害翻倍 | 没判 `level.isClientSide()`，两侧都执行 | 改世界/改数值的逻辑包进 `if (!entity.level().isClientSide())` |
| 食物吃下去不消耗 | 自己重写了 `use` 却返回了 `PASS` | 返回 `InteractionResultHolder.consume(stack)`，或干脆别重写 |
| 饱和度回得莫名其妙 | 把 `saturationModifier` 当成了绝对值 | 它是系数，实际值 = `2 × nutrition × 系数` |
| 启动崩溃，日志提到 `Unknown effect` | 效果注册名为空或含大写 | 注册名只用小写、数字、下划线 |
| 药水在游戏里拿不到 | 只注册了 `Potion`，没有酿造配方也没用命令 | 用 `/give` 的组件写法，或加 `RegisterBrewingRecipesEvent` |
| 酿造配方不生效 | 事件写在了模组总线上 | 去掉 `bus = Bus.MOD`，酿造事件在游戏总线 |

## 练习

1. **基础**：做一个「蓝宝石曲奇」，`nutrition(2)`、`saturationModifier(0.1f)`、`fast()`，不加任何效果。先确认它能吃、能吃很多个。
2. **进阶**：做一个有害效果「红宝石诅咒」：`MobEffectCategory.HARMFUL`，每 20 刻造成 1 点伤害（提示：`entity.hurt(entity.damageSources().magic(), 1.0f)`），持续 10 秒。把它挂到一个「腐坏的红宝石苹果」上，概率 0.5。
3. **挑战**：做一个「全套装备加成」效果：当玩家同时戴着红宝石头盔和胸甲时，给一个 +4 护甲值的属性修饰符。提示：属性修饰符没法做条件判断，需要用 `PlayerTickEvent` 每 tick 检查装备并手动 `addEffect` / `removeEffect`。做完思考：为什么这类"条件效果"不适合写在 `MobEffect` 里？
