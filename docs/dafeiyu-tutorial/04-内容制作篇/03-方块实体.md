# 方块实体

> 读完这篇，你会做出一个「计数器方块」：右键一次数字加一，数字存在方块实体里，退出游戏再进来还在，并且能正确同步给客户端。

## 学习目标

- 能判断一个需求该用方块状态还是方块实体。
- 能写出 `BlockEntityType` 的注册、`BlockEntity` 子类、以及把两者绑到方块上的 `EntityBlock#newBlockEntity`。
- 能正确实现 `saveAdditional` / `loadAdditional`，并说清 `setChanged()` 为什么不能忘。
- 能写出 `getTicker` 和静态 `tick` 方法，并知道为什么逻辑要只在服务端跑。
- 能说清 `getUpdateTag` / `getUpdatePacket` / `sendBlockUpdated` 三者的分工，知道「客户端数字不刷新」是缺了哪一环。
- 知道方块实体渲染器（BER）注册在哪个事件里。

## 一、什么时候需要方块实体

方块状态（blockstate）能存的数据是**有限且很少**的：朝向 4 个、上下 2 个、开关 2 个。游戏要为每一种组合预先准备好模型，所以状态数量一多，内存和加载时间就会爆炸。

判断标准很简单：

> **数据能枚举完、而且不超过几百种 → 用方块状态。数据是「一个数字、一堆物品、一段文本」这种开放值 → 用方块实体。**

具体来说，下面这些需求都必须用方块实体：

- 要存一个任意整数（计数器、电量、进度）。
- 要存一个物品栏（箱子、熔炉）。
- 要存一段玩家输入的文本（告示牌）。
- 需要每 tick 做一次计算（机器加工、作物生长计时）。
- 需要在世界里额外渲染东西（箱子里的东西、悬浮文字）。

反过来，像「这个方块朝哪个方向」「是不是点亮状态」这种，用方块状态更省事，也更快。

一个常见的误解：**方块实体不是「方块的一种」，它是挂在方块位置上的一个数据容器**。方块本身仍然是那个全局唯一的 `Block` 实例，方块实体则是每个坐标各一份。

## 二、三件套：BlockEntity 类、BlockEntityType、方块

方块实体涉及三个东西，缺一不可：

```text
BlockEntityType<CounterBlockEntity>   ← 注册表里的"类型"，全局唯一，负责"怎么造"
        ↑ 被 BlockEntity 的构造器引用
CounterBlockEntity                    ← 每个坐标一个实例，负责"存什么"
        ↑ 被方块的 newBlockEntity 创建
CounterBlock extends Block implements EntityBlock  ← 负责"什么时候造"
```

顺序上有点绕：`BlockEntity` 的构造器要拿到 `BlockEntityType`，而 `BlockEntityType` 的构建又要拿到 `BlockEntity` 的构造器引用。所以代码里会出现「先写一个还没定义 `type` 的构造器，注册完类型再回来填」的写法。这不是设计得丑，是循环依赖的必然结果，照着写就行。

### 2.1 先写 BlockEntity 类

文件：`src/main/java/com/dafeiyu/CounterBlockEntity.java`

```java
package com.dafeiyu;

import net.minecraft.core.BlockPos;
import net.minecraft.core.HolderLookup;
import net.minecraft.nbt.CompoundTag;
import net.minecraft.network.protocol.Packet;
import net.minecraft.network.protocol.game.ClientGamePacketListener;
import net.minecraft.network.protocol.game.ClientboundBlockEntityDataPacket;
import net.minecraft.world.level.Level;
import net.minecraft.world.level.block.Block;
import net.minecraft.world.level.block.entity.BlockEntity;
import net.minecraft.world.level.block.state.BlockState;

public class CounterBlockEntity extends BlockEntity {
    private static final String TAG_COUNT = "count";

    private int count = 0;

    public CounterBlockEntity(BlockPos pos, BlockState state) {
        // 注意：这里引用的是"已经注册好的类型"
        super(ModBlockEntities.COUNTER_BLOCK_ENTITY.get(), pos, state);
    }

    public int getCount() {
        return count;
    }

    /** 计数 +1，并把变化写进存档、同步给客户端 */
    public void increment() {
        this.count++;
        this.setChanged();  // 告诉游戏：这个区块脏了，保存时别跳过
        if (this.level != null && !this.level.isClientSide()) {
            // 主动发一次方块更新包，让客户端拿到新的 count
            this.level.sendBlockUpdated(this.worldPosition, this.getBlockState(), this.getBlockState(), Block.UPDATE_ALL);
        }
    }

    // ---------- 存档 ----------

    @Override
    protected void saveAdditional(CompoundTag tag, HolderLookup.Provider registries) {
        super.saveAdditional(tag, registries); // 必须调用，父类会写 x/y/z/id 等基础信息
        tag.putInt(TAG_COUNT, this.count);
    }

    @Override
    protected void loadAdditional(CompoundTag tag, HolderLookup.Provider registries) {
        super.loadAdditional(tag, registries);
        this.count = tag.getInt(TAG_COUNT); // 标签不存在时返回 0，正好是默认值
    }

    // ---------- 同步 ----------

    @Override
    public CompoundTag getUpdateTag(HolderLookup.Provider registries) {
        CompoundTag tag = new CompoundTag();
        saveAdditional(tag, registries);
        return tag;
    }

    @Override
    public Packet<ClientGamePacketListener> getUpdatePacket() {
        // 这个包的内容就是 getUpdateTag() 的返回值
        return ClientboundBlockEntityDataPacket.create(this);
    }

    // ---------- 每刻逻辑 ----------

    public static void tick(Level level, BlockPos pos, BlockState state, CounterBlockEntity blockEntity) {
        if (level.isClientSide()) {
            return; // 只让服务端跑逻辑，客户端只负责显示
        }
        // 每 20 刻（1 秒）检查一次：计数超过 999 就归零
        if (level.getGameTime() % 20L == 0L && blockEntity.count > 999) {
            blockEntity.count = 0;
            blockEntity.setChanged();
            level.sendBlockUpdated(pos, state, state, Block.UPDATE_ALL);
        }
    }
}
```

逐点解释几个新手最容易含糊的地方：

**`super(ModBlockEntities.COUNTER_BLOCK_ENTITY.get(), pos, state)`** —— 第一个参数是 `BlockEntityType`，不是 `Block`。`DeferredHolder` 要 `.get()`。`pos` 和 `state` 由方块在创建它的时候传进来。

**`saveAdditional` / `loadAdditional`** —— 一对读写方法。名字里的 "Additional" 意思是「在你自己的数据之外，父类还要存一些基础字段（坐标、类型 id）」，所以**两个方法的第一行都必须调用 `super`**。漏了 `super.loadAdditional`，方块实体的坐标会变成 (0,0,0)，表现是「所有计数器共享同一个数字」这种诡异 bug。

**`setChanged()`** —— Minecraft 的存档系统是「按区块增量保存」的：只有被标记为「脏（dirty）」的区块才会写盘。你改了字段但没调 `setChanged()`，退出重进就回到旧值。这个坑几乎每个人都踩过一次。

**`getUpdateTag`** —— 区块**从磁盘或网络加载**时，服务端会把这段 NBT 一起发给客户端。所以客户端刚进世界时能立刻看到正确的数字。

**`getUpdatePacket`** —— 方块**在运行中发生变化**时用的包。返回非 null 就表示「我要用这个包同步」。包的内容同样来自 `getUpdateTag`。

**`sendBlockUpdated`** —— 光有上面两个方法还不够，得有人**主动触发**。`sendBlockUpdated` 就是那个触发点，它会调用 `getUpdatePacket` 并把包发给追踪这个区块的玩家。三个参数分别是位置、旧状态、新状态，最后一个 `flags` 用 `Block.UPDATE_ALL`（值 3）即可。

**`tick` 是 static 的** —— 因为 ticker 是一个「函数」，不是方块实体实例的方法。参数里的 `blockEntity` 才是当前这个实例。这也是为什么 ticker 要定义在方块上（见 2.3）。

### 2.2 注册 BlockEntityType

文件：`src/main/java/com/dafeiyu/ModBlockEntities.java`

```java
package com.dafeiyu;

import net.minecraft.core.registries.Registries;
import net.minecraft.world.level.block.entity.BlockEntityType;
import net.neoforged.bus.api.IEventBus;
import net.neoforged.neoforge.registries.DeferredHolder;
import net.neoforged.neoforge.registries.DeferredRegister;

public class ModBlockEntities {
    public static final DeferredRegister<BlockEntityType<?>> BLOCK_ENTITY_TYPES =
            DeferredRegister.create(Registries.BLOCK_ENTITY_TYPE, DafeiyuMod.MOD_ID);

    public static final DeferredHolder<BlockEntityType<?>, BlockEntityType<CounterBlockEntity>> COUNTER_BLOCK_ENTITY =
            BLOCK_ENTITY_TYPES.register("counter_block", () -> BlockEntityType.Builder
                    // 第一个参数：怎么 new 出实例（就是上面那个构造器）
                    .of(CounterBlockEntity::new,
                            // 后面是可变参数：哪些方块可以拥有这个方块实体
                            ModBlocks.COUNTER_BLOCK.get())
                    // 参数传 null 即可，原版用它做数据修复，我们不需要
                    .build(null));

    public static void register(IEventBus modEventBus) {
        BLOCK_ENTITY_TYPES.register(modEventBus);
    }
}
```

`DeferredHolder<BlockEntityType<?>, BlockEntityType<CounterBlockEntity>>` 这个类型看着吓人，读法是：「这个 holder 在 `BlockEntityType<?>` 这个注册表里，装的具体东西是 `BlockEntityType<CounterBlockEntity>`」。写成 `DeferredHolder<BlockEntityType<?>, ...>` 是必须的，因为注册表本身的泛型参数就是 `BlockEntityType<?>`。

主类里加一行 `ModBlockEntities.register(modEventBus);`，**放在 `ModBlocks` 之后**（因为 `Builder.of` 里用到了 `ModBlocks.COUNTER_BLOCK.get()`，虽然它是延迟求值的，但顺序清楚一点总没坏处）。

### 2.3 让方块创建它，并给它 ticker

文件：`src/main/java/com/dafeiyu/CounterBlock.java`

```java
package com.dafeiyu;

import net.minecraft.core.BlockPos;
import net.minecraft.network.chat.Component;
import net.minecraft.world.InteractionResult;
import net.minecraft.world.entity.player.Player;
import net.minecraft.world.level.Level;
import net.minecraft.world.level.block.Block;
import net.minecraft.world.level.block.EntityBlock;
import net.minecraft.world.level.block.entity.BlockEntity;
import net.minecraft.world.level.block.entity.BlockEntityTicker;
import net.minecraft.world.level.block.entity.BlockEntityType;
import net.minecraft.world.level.block.state.BlockState;
import net.minecraft.world.phys.BlockHitResult;
import org.jetbrains.annotations.Nullable;

public class CounterBlock extends Block implements EntityBlock {

    public CounterBlock(Properties properties) {
        super(properties);
    }

    // ① 方块被放下（或区块加载）时，游戏调用它来创建方块实体
    @Nullable
    @Override
    public BlockEntity newBlockEntity(BlockPos pos, BlockState state) {
        return new CounterBlockEntity(pos, state);
    }

    // ② 告诉游戏"这个方块要每刻更新"，并返回具体怎么更新
    @Nullable
    @Override
    public <T extends BlockEntity> BlockEntityTicker<T> getTicker(Level level, BlockState state, BlockEntityType<T> type) {
        if (level.isClientSide()) {
            return null; // 客户端不需要 tick
        }
        return createTickerHelper(type, ModBlockEntities.COUNTER_BLOCK_ENTITY.get(), CounterBlockEntity::tick);
    }

    // ③ 右键（手里拿着东西或空手都会走到这里）
    @Override
    protected InteractionResult useWithoutItem(BlockState state, Level level, BlockPos pos, Player player, BlockHitResult hitResult) {
        if (level.getBlockEntity(pos) instanceof CounterBlockEntity counter) {
            if (!level.isClientSide()) {
                counter.increment();
                player.displayClientMessage(Component.literal("计数：" + counter.getCount()), true);
            }
            return InteractionResult.sidedSuccess(level.isClientSide());
        }
        return InteractionResult.PASS;
    }

    // 泛型转换的小工具：类型对得上才返回 ticker，否则返回 null
    @SuppressWarnings("unchecked")
    @Nullable
    private static <E extends BlockEntity, A extends BlockEntity> BlockEntityTicker<A> createTickerHelper(
            BlockEntityType<A> type, BlockEntityType<E> checkedType, BlockEntityTicker<? super E> ticker) {
        return checkedType == type ? (BlockEntityTicker<A>) ticker : null;
    }
}
```

三个关键点：

**`implements EntityBlock`** —— 这是「我有方块实体」的标记接口。不实现它，`newBlockEntity` 根本不会被调用，`level.getBlockEntity(pos)` 永远返回 null。

**`getTicker` 定义在方块上，不定义在方块实体上** —— 因为 ticker 是按「方块类型」注册的，不是按实例。返回 `null` 表示这个方块不参与刻更新。这里客户端返回 `null`，是因为计数逻辑只在服务端跑，客户端只需要接收同步结果。

**`useWithoutItem` 而不是 `use`** —— 1.21 里方块右键分成了两个方法：`useItemOn`（手里拿着物品时，物品与方块交互）和 `useWithoutItem`（方块自己处理右键）。原版的 `use` 已经被拆掉，写 `use` 会提示没有可重写的方法。返回 `InteractionResult.sidedSuccess(...)` 是标准做法：服务端算成功，客户端只播放手臂挥动。

**`instanceof CounterBlockEntity counter`** —— 这是 Java 16 的模式匹配写法，等价于「判断类型 + 强转 + 声明变量」三合一。读作「如果 `getBlockEntity(pos)` 的结果是 `CounterBlockEntity`，就把它叫 `counter`」。

> **小提示**：`useWithoutItem`、`saveAdditional`、`loadAdditional` 这几个方法在 1.21.1 里是 `protected` 的。如果你从别处抄来的代码用了 `public`，或者你的 IDE 报「attempting to assign weaker access privileges」，把修饰符改成和父类一致即可——加宽访问权限（`protected` → `public`）是合法的，收窄则不行。

### 2.4 把方块注册进 ModBlocks

```java
public static final DeferredBlock<CounterBlock> COUNTER_BLOCK = BLOCKS.registerBlock(

        BlockBehaviour.Properties.of()
                .strength(3.5f)
                .requiresCorrectToolForDrops()
```

`registerBlock` 的第二个参数是「接收 `Properties` 的构造器」，也就是 `CounterBlock::new`——这正好对应 `CounterBlock(Properties)` 这个构造器。用 `registerSimpleBlock` 不行，因为它只会 `new Block(...)`。

别忘了方块物品：`ITEMS.registerSimpleBlockItem(ModBlocks.COUNTER_BLOCK)`，以及战利品表（否则挖了不掉）。

## 三、方块实体渲染器（BER）简介

计数器目前把数字显示在**动作栏**（屏幕下方那行字）里。如果你想让它像告示牌那样浮在方块上方，就需要**方块实体渲染器（`BlockEntityRenderer`，简称 BER）**。

BER 存在的意义：静态的 JSON 模型画不出「会变的东西」。箱子里的物品、附魔台飘的字、告示牌的文字，都是 BER 画的。

文件：`src/main/java/com/dafeiyu/client/CounterBlockRenderer.java`

```java
package com.dafeiyu.client;

import com.dafeiyu.CounterBlockEntity;
import com.mojang.blaze3d.vertex.PoseStack;
import net.minecraft.client.renderer.MultiBufferSource;
import net.minecraft.client.renderer.blockentity.BlockEntityRenderer;
import net.minecraft.client.renderer.blockentity.BlockEntityRendererProvider;

public class CounterBlockRenderer implements BlockEntityRenderer<CounterBlockEntity> {

    public CounterBlockRenderer(BlockEntityRendererProvider.Context context) {
        // 需要的话可以在这里存下 context 里的字体、方块渲染器等
    }

    @Override
    public void render(CounterBlockEntity blockEntity, float partialTick, PoseStack poseStack,
                       MultiBufferSource bufferSource, int packedLight, int packedOverlay) {
        // 每一帧都会被调用，次数非常多，不要在这里做重活。
        // 想画字：Minecraft.getInstance().font.drawInBatch(...)
        // 想画物品：Minecraft.getInstance().getItemRenderer().renderStatic(...)
    }
}
```

参数含义：`partialTick` 是两次 tick 之间的插值（0~1，用于平滑动画）；`poseStack` 是当前变换栈（平移、旋转、缩放都靠它）；`bufferSource` 用来取顶点缓冲；`packedLight` 是光照值；`packedOverlay` 一般是 `OverlayTexture.NO_OVERLAY`。

注册它要订阅 `EntityRenderersEvent.RegisterRenderers`，**只在物理客户端**：

```java
package com.dafeiyu.client;

import com.dafeiyu.DafeiyuMod;
import com.dafeiyu.ModBlockEntities;
import net.neoforged.api.distmarker.Dist;
import net.neoforged.bus.api.SubscribeEvent;
import net.neoforged.fml.common.EventBusSubscriber;
import net.neoforged.neoforge.client.event.EntityRenderersEvent;

@EventBusSubscriber(modid = DafeiyuMod.MOD_ID, bus = EventBusSubscriber.Bus.MOD, value = Dist.CLIENT)
public class ClientEvents {
    @SubscribeEvent
    public static void registerRenderers(EntityRenderersEvent.RegisterRenderers event) {
        event.registerBlockEntityRenderer(
                ModBlockEntities.COUNTER_BLOCK_ENTITY.get(),
                CounterBlockRenderer::new);
    }
}
```

三条硬规则：

1. **一个 `BlockEntityType` 只能有一个 BER**。所以「每个实例不同的东西」要存在方块实体里，不能存在 BER 里。
2. 注册必须在 `Dist.CLIENT` 下，否则专用服务器会因为没有 `Minecraft` 类而崩溃。
3. 渲染器类放在 `client` 子包里，别被公共代码 import。

现在这个 renderer 是空的，跑起来什么都不会多画——这没关系，注册链路先通，等你需要时往里填内容即可。

## 常见坑与报错

| 现象 | 原因 | 解决 |
|---|---|---|
| 启动崩溃，`Missing block entity type` / 世界打不开 | 忘了注册 `BlockEntityType`，或注册了但没在主类里 `register` | 补 `ModBlockEntities.register(modEventBus)` |
| 右键没反应，`level.getBlockEntity(pos)` 返回 null | 方块没 `implements EntityBlock`，或没重写 `newBlockEntity` | 两个都要有 |
| 方块一放下去就崩 `NullPointerException`（构造器里） | `super(...)` 传了 null，通常是注册顺序错 | 确认 `COUNTER_BLOCK_ENTITY` 已注册且方块类在之后加载 |
| 数字会涨，退出重进归零 | 忘了 `setChanged()` | 每次改字段后调用 |
| 退出重进后所有计数器显示同一个数字 | `loadAdditional` 里没调 `super.loadAdditional(...)` | 补上 super 调用 |
| 数字只在动作栏对，方块上方/其他地方不更新 | 缺 `getUpdateTag` / `getUpdatePacket` / `sendBlockUpdated` 中的任意一环 | 三样齐全：生成 tag、返回包、主动触发 |
| 点一次涨 2 | 客户端和服务端都执行了 `increment()` | 逻辑包在 `if (!level.isClientSide())` 里 |
| 服务器开服崩溃，报 `NoClassDefFoundError: net/minecraft/client/...` | 渲染器/客户端类被公共代码引用，或事件没加 `value = Dist.CLIENT` | 客户端类隔离到 `client` 包 + 注解限定 Dist |
| 游戏越玩越卡，存档越来越大 | tick 里每刻 `setChanged()` | 只在数据真的变了的时候调 |
| 挖掉方块后重放，数字没清零 | 方块实体的数据在方块被替换时会随区块保存；要清零得在 `playerWillDestroy` 或 `onRemove` 里处理 | 需要时重写对应方法 |

## 练习

1. **基础**：给计数器加一个「上限」逻辑：到 10 就不再增加，并让动作栏显示「已满」。
2. **进阶**：把计数器改成「每 5 秒自动 +1」（用 ticker），同时保留右键 +1。注意客户端不能重复加。
3. **挑战**：把数字画到方块上方。提示：在 BER 的 `render` 里先 `poseStack.pushPose()`，`translate(0.5, 1.0, 0.5)`，再用 `poseStack.mulPose(Minecraft.getInstance().getEntityRenderDispatcher().cameraOrientation())` 让它始终面向玩家，最后用 `Minecraft.getInstance().font.drawInBatch(...)` 画字符串，结束时 `popPose()`。
