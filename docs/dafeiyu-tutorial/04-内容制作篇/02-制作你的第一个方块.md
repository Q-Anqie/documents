# 制作你的第一个方块

> 读完这篇，你会做出一个能放、能挖、能捡回来的「红宝石块」，并且搞清楚方块和方块物品为什么是两个东西、为什么挖了不掉、为什么模型会显示成紫黑。

## 学习目标

- 能用 `DeferredRegister.Blocks` + `DeferredBlock<Block>` 注册一个方块。
- 能说清 `BlockBehaviour.Properties` 里 `destroyTime`、`explosionResistance`、`sound`、`lightLevel`、`requiresCorrectToolForDrops` 各自的作用。
- 能同时注册 `BlockItem`，并解释「不注册会怎样」。
- 能写全方块的四件套资源：`blockstates`、`models/block`、`models/item`、`textures/block`，外加语言文件条目。
- 能写一个「挖了掉自己」的战利品表，并知道它放在哪个目录。
- 能根据「挖了不掉」「紫黑模型」「透明方块边缘发黑」三种现象反推原因。

## 一、方块和「方块物品」是两个东西

这是新手在这一篇里最容易翻车的地方，所以先讲清楚。

世界里的那个方块，是 `Block` 的一个实例。它负责：碰撞箱多大、挖多久、爆炸抗性多少、发光几级、被右键时干什么。

物品栏里那个「长得像方块」的东西，是 **`BlockItem`**——一个 `Item` 的子类，它的唯一职责是「被右键时把对应的方块放到世界上」。

所以：

- 你注册了 `Block`，世界生成、`/setblock`、结构里都能用，**但物品栏里没有它**。
- 你注册了 `BlockItem`，物品栏里才有，才能被玩家拿着放下去。

原版有大量「只有方块没有物品」的例子：火、水、耕地、刷怪笼。它们本来就不该被玩家拿在手里。所以 Minecraft 把这两件事拆开了，`BlockItem` 必须单独注册。

## 二、注册方块

文件：`src/main/java/com/dafeiyu/ModBlocks.java`

```java
package com.dafeiyu;

import net.minecraft.world.level.block.Block;
import net.minecraft.world.level.block.SoundType;
import net.minecraft.world.level.block.state.BlockBehaviour;
import net.neoforged.bus.api.IEventBus;
import net.neoforged.neoforge.registries.DeferredBlock;
import net.neoforged.neoforge.registries.DeferredRegister;

public class ModBlocks {
    // 方块注册表
    public static final DeferredRegister.Blocks BLOCKS = DeferredRegister.createBlocks(DafeiyuMod.MOD_ID);

    public static final DeferredBlock<Block> RUBY_BLOCK = BLOCKS.registerSimpleBlock("ruby_block",
            BlockBehaviour.Properties.of()
                    .strength(5.0f, 6.0f)          // 硬度 5，抗爆 6
                    .requiresCorrectToolForDrops() // 必须用对的工具才掉落
                    .sound(SoundType.METAL));      // 敲击/破坏音效

    public static void register(IEventBus modEventBus) {
        BLOCKS.register(modEventBus);
    }
}
```

几个点：

**`DeferredRegister.createBlocks(...)`** 返回 `DeferredRegister.Blocks`，它的 `register` 返回 `DeferredBlock<T>`，`T` 是你注册的方块类。这里用最普通的 `Block`，所以是 `DeferredBlock<Block>`。

**`registerSimpleBlock`** 是 `BLOCKS.register("ruby_block", () -> new Block(properties))` 的简写。要注册自定义方块类（比如带方块实体的、带朝向的），就得改用 `registerBlock("名字", 构造器, properties)`，或者直接 `register("名字", () -> new MyBlock(...))`。

**`BlockBehaviour.Properties.of()`** 是方块属性的构建器。常用的方法：

| 方法 | 作用 | 参考值 |
|---|---|---|
| `strength(float)` | 同时设硬度和抗爆 | 石头 1.5 / 6.0 |
| `strength(float destroy, float resist)` | 分开设 | 黑曜石 50 / 1200 |
| `destroyTime(float)` | 只设挖多久 | 泥土 0.5；`-1` 表示挖不动（基岩） |
| `explosionResistance(float)` | 只设抗爆 | 泥土 0.5 |
| `sound(SoundType)` | 击打/放置/破坏音效 | `STONE`、`METAL`、`GRAVEL`、`WOOD`、`GLASS` |
| `lightLevel(state -> 15)` | 发光等级 0~15 | 荧石 15，火把 14 |
| `requiresCorrectToolForDrops()` | 工具不对就不掉东西 | 矿石、金属块都用 |
| `noOcclusion()` | 不遮挡相邻面（用于非满方块） | 玻璃、台阶、树叶 |
| `randomTicks()` | 参与随机刻 | 植物、冰 |
| `friction(float)` | 摩擦系数 | 冰 0.98 |

`strength(a, b)` 就是 `destroyTime(a).explosionResistance(b)` 的简写，别写重复了。

## 三、注册方块物品

文件还是 `ModItems.java`，加一行：

```java
public static final DeferredItem<BlockItem> RUBY_BLOCK_ITEM =
        ITEMS.registerSimpleBlockItem(ModBlocks.RUBY_BLOCK);
```

`registerSimpleBlockItem` 会做三件事：用方块的注册名作为物品名、创建 `BlockItem`、把方块传给它。展开写就是：

```java
ITEMS.register("ruby_block", () -> new BlockItem(ModBlocks.RUBY_BLOCK.get(), new Item.Properties()));
```

注意最后那个 `.get()`：`BlockItem` 的构造函数要的是真正的 `Block` 实例，不是 `DeferredBlock`。

这里有个**必须注意的顺序问题**：`ModBlocks.RUBY_BLOCK` 这一行写在 `ModItems` 的静态字段里，类加载 `ModItems` 时会顺带触发 `ModBlocks` 的类加载。所以主类里**先注册方块、再注册物品**：

```java
public DafeiyuMod(IEventBus modEventBus, ModContainer modContainer) {
    ModBlocks.register(modEventBus);
    ModItems.register(modEventBus);
}
```

顺序反了，方块注册表还没挂到总线上，`BlockItem` 拿到的方块可能在注册表里找不到，表现为启动崩溃或物品栏里出现一个「空」物品。

## 四、方块的四件套资源

方块的资源比物品多一层：**物品模型不能直接指向纹理，必须先经过方块状态文件**。

```text
src/main/resources/
└── assets/dafeiyu/
    ├── blockstates/ruby_block.json          ← 1. 方块状态 → 方块模型
    ├── models/block/ruby_block.json         ← 2. 方块模型（真正用纹理拼形状）
    ├── models/item/ruby_block.json          ← 3. 物品模型（手里/物品栏里长什么样）
    └── textures/block/ruby_block.png        ← 4. 纹理
```

### 1. 方块状态：`assets/dafeiyu/blockstates/ruby_block.json`

```json
{
  "variants": {
    "": { "model": "dafeiyu:block/ruby_block" }
  }
}
```

`variants` 的键是**方块状态字符串**。我们的方块没有任何属性（没有朝向、没有开关），所以状态字符串是空字符串 `""`。以后你做楼梯、朝向方块，这里会变成 `"facing=north"`、`"half=top"` 这样的键，那就是「方块状态」那篇的内容。

一个方块**必须有且只有一个** `blockstates` 文件。少了它，游戏根本不知道该用哪个模型，方块会直接渲染成紫黑方块。

### 2. 方块模型：`assets/dafeiyu/models/block/ruby_block.json`

```json
{
  "parent": "minecraft:block/cube_all",
  "textures": {
    "all": "dafeiyu:block/ruby_block"
  }
}
```

`cube_all` 是「六个面用同一张图」的父模型，变量名叫 `all`。如果是上下不同（比如熔炉、工作台），用 `minecraft:block/orientable` 或 `cube_bottom_top`；如果是柱子（原木），用 `cube_column`。

**别忘 `particle` 纹理**：方块模型里最好加一行 `"particle": "dafeiyu:block/ruby_block"`，否则方块被破坏、或者你跑过它时，粒子会变成紫黑色的小方块。用 `cube_all` 时多数情况下游戏会自动回退，但显式写上更保险：

```json
{
  "parent": "minecraft:block/cube_all",
  "textures": {
    "particle": "dafeiyu:block/ruby_block",
    "all": "dafeiyu:block/ruby_block"
  }
}
```

### 3. 物品模型：`assets/dafeiyu/models/item/ruby_block.json`

```json
{
  "parent": "dafeiyu:block/ruby_block"
}
```

就一行。它的意思是「物品栏里那个小方块，直接复用方块模型」。方块物品几乎都这么写。注意 `parent` 的值是 `dafeiyu:block/ruby_block`（`models/` 下的路径），不是 `dafeiyu:blockstates/...`。

### 4. 纹理：`assets/dafeiyu/textures/block/ruby_block.png`

16×16 PNG。注意是 `block`（单数）不是 `blocks`，也不是 `item`。

### 5. 语言文件

`assets/dafeiyu/lang/zh_cn.json` 里加一行，键前缀是 `block.`：

```json
{
  "item.dafeiyu.ruby": "红宝石",
  "block.dafeiyu.ruby_block": "红宝石块"
}
```

方块物品显示的名字用的是 `block.` 开头的键，不是 `item.`。写错了就会显示成 `block.dafeiyu.ruby_block` 这串原始键名。

### 4.6 渲染类型：透明方块为什么必须单独声明

游戏渲染方块时按「批次」走，不同批次用不同的渲染方式：

| 渲染类型 | 适用 | 例子 |
|---|---|---|
| `minecraft:solid` | 完全不透明 | 石头、泥土 |
| `minecraft:cutout` | 每个像素要么全实要么全透明 | 玻璃、树叶（无半透明） |
| `minecraft:cutout_mipped` | 同上，但远处做 mipmap 避免闪烁 | 树叶 |
| `minecraft:translucent` | 像素可以半透明 | 染色玻璃、水 |

如果你的方块有透明部分（比如中间镂空的灯、带玻璃的机器），但没声明渲染类型，游戏会按 `solid` 画它——结果是**透明的地方变成黑色或直接挡住后面的方块**。

声明方式是在**方块模型**里加一行：

```json
{
  "parent": "minecraft:block/cube_all",
  "render_type": "minecraft:cutout",
  "textures": {
    "particle": "dafeiyu:block/ruby_lamp",
    "all": "dafeiyu:block/ruby_lamp"
  }
}
```

同时方块属性里要加 `.noOcclusion()`。这两个东西分工不同：`render_type` 决定「怎么画」，`noOcclusion` 决定「相邻方块的面要不要因为我在旁边而被剔除」。只加一个都会出问题：只加 `render_type`，相邻的石头面会被错误剔除，你能透过玻璃看到地底；只加 `noOcclusion`，画面会变成黑块。

顺带提醒：**别给所有方块都加 `noOcclusion()`**。它会让方块不再遮挡相邻面，区块渲染的顶点数会成倍增加，一个这样的方块多了就会明显掉帧。

## 五、掉落物与战利品表

方块挖掉之后掉什么，**不是代码决定的，是数据决定的**。这套数据叫**战利品表（loot table）**，每个方块默认去 `data/dafeiyu/loot_table/blocks/<注册名>.json` 找自己的表。

文件：`src/main/resources/data/dafeiyu/loot_table/blocks/ruby_block.json`

```json
{
  "type": "minecraft:block",
  "pools": [
    {
      "rolls": 1,
      "entries": [
        {
          "type": "minecraft:item",
          "name": "dafeiyu:ruby_block"
        }
      ],
      "conditions": [
        {
          "condition": "minecraft:survives_explosion"
        }
      ]
    }
  ]
}
```

读法：「掷 1 次；掉落 1 个 `dafeiyu:ruby_block`；前提是方块不是被爆炸炸没的」。

再配两个标签，让它「必须用镐、且至少铁镐」：

`src/main/resources/data/minecraft/tags/block/mineable/pickaxe.json`

```json
{
  "values": [
    "dafeiyu:ruby_block"
  ]
}
```

`src/main/resources/data/minecraft/tags/block/needs_iron_tool.json`

```json
{
  "values": [
    "dafeiyu:ruby_block"
  ]
}
```

- `mineable/pickaxe` 告诉游戏「这个方块归镐管」，决定挖掘速度和能否掉落。
- `needs_iron_tool` 决定「木镐/石镐挖了也不掉」。这个标签要和代码里的 `requiresCorrectToolForDrops()` 配合，只写一边不够。

还有一件新手常困惑的事：**为什么创造模式用什么都能挖下来？** 因为创造模式直接跳过「能否收获」的判定，方块被破坏后由玩家自己决定要不要捡，根本不会去查战利品表。所以「创造模式能挖、生存模式不掉」这个现象，百分之百是标签或战利品表的问题，跟代码逻辑无关。

同理，生存模式下「精准采集」也走的是战利品表——`minecraft:block` 类型的表里通常会带一个 `match_tool` 条件判断附魔，你可以用 `/give @s diamond_pickaxe[enchantments={levels:{"minecraft:silk_touch":1}}]` 快速验证自己的表写得对不对。

注意 1.21 起数据包目录改成了**单数**：`loot_table`、`recipe`、`advancement`、`tags/block`。写成 `loot_tables` 会静默失效——不报错，就是不掉东西。战利品表的完整语法（多池、随机数量、附魔加成、条件）在资源与数据篇讲，这里你先照抄能跑。

## 六、跑起来验证

1. `runClient`，进创造模式世界。
2. `/give @s dafeiyu:ruby_block`，拿到方块。
3. 右键放到地上，确认六面纹理都对。
4. 换生存模式，用铁镐挖——应该掉一个红宝石块。
5. 用木镐挖——方块会碎，但**不掉东西**（因为 `needs_iron_tool`）。
6. 用手挖——非常慢，且不掉。

## 完整示例

**① `src/main/java/com/dafeiyu/ModBlocks.java`**

```java
package com.dafeiyu;

import net.minecraft.world.level.block.Block;
import net.minecraft.world.level.block.SoundType;
import net.minecraft.world.level.block.state.BlockBehaviour;
import net.neoforged.bus.api.IEventBus;
import net.neoforged.neoforge.registries.DeferredBlock;
import net.neoforged.neoforge.registries.DeferredRegister;

public class ModBlocks {
    public static final DeferredRegister.Blocks BLOCKS = DeferredRegister.createBlocks(DafeiyuMod.MOD_ID);

    public static final DeferredBlock<Block> RUBY_BLOCK = BLOCKS.registerSimpleBlock("ruby_block",
            BlockBehaviour.Properties.of()
                    .strength(5.0f, 6.0f)
                    .requiresCorrectToolForDrops()
                    .sound(SoundType.METAL));

    public static void register(IEventBus modEventBus) {
        BLOCKS.register(modEventBus);
    }
}
```

**② `src/main/java/com/dafeiyu/ModItems.java`（在上一篇的基础上加一行）**

```java
package com.dafeiyu;

import net.minecraft.world.item.BlockItem;
import net.minecraft.world.item.Item;
import net.minecraft.world.item.Rarity;
import net.neoforged.bus.api.IEventBus;
import net.neoforged.neoforge.registries.DeferredItem;
import net.neoforged.neoforge.registries.DeferredRegister;

public class ModItems {
    public static final DeferredRegister.Items ITEMS = DeferredRegister.createItems(DafeiyuMod.MOD_ID);

    public static final DeferredItem<Item> RUBY =
            ITEMS.registerSimpleItem("ruby", new Item.Properties().rarity(Rarity.RARE));

    // 方块的物品形态，注册名与方块保持一致
    public static final DeferredItem<BlockItem> RUBY_BLOCK_ITEM =
            ITEMS.registerSimpleBlockItem(ModBlocks.RUBY_BLOCK);

    public static void register(IEventBus modEventBus) {
        ITEMS.register(modEventBus);
    }
}
```

**③ `src/main/java/com/dafeiyu/DafeiyuMod.java`（注意顺序）**

```java
package com.dafeiyu;

import net.neoforged.bus.api.IEventBus;
import net.neoforged.fml.ModContainer;
import net.neoforged.fml.common.Mod;

@Mod(DafeiyuMod.MOD_ID)
public class DafeiyuMod {
    public static final String MOD_ID = "dafeiyu";

    public DafeiyuMod(IEventBus modEventBus, ModContainer modContainer) {
        ModBlocks.register(modEventBus);   // 先方块
        ModItems.register(modEventBus);    // 后物品
    }
}
```

## 常见坑与报错

| 现象 | 原因 | 解决 |
|---|---|---|
| 方块能放，但物品栏里找不到 | 只注册了 `Block`，没注册 `BlockItem` | 加 `ITEMS.registerSimpleBlockItem(ModBlocks.RUBY_BLOCK)` |
| 挖了什么都不掉 | 没有战利品表，或路径写成 `loot_tables` | 文件放在 `data/dafeiyu/loot_table/blocks/ruby_block.json` |
| 挖了不掉，但创造模式能挖到 | 缺 `mineable/pickaxe` 标签，或代码里没写 `requiresCorrectToolForDrops()` | 标签和属性两边都要有 |
| 木镐也能挖下来 | 缺 `needs_iron_tool` 标签 | 加 `data/minecraft/tags/block/needs_iron_tool.json` |
| 方块是紫黑格子 | 缺 `blockstates/ruby_block.json`，或里面的 `model` 路径写错 | 路径必须是 `dafeiyu:block/ruby_block`（`models/` 下） |
| 方块放下去是紫黑，但物品栏里正常 | 缺 `models/block/ruby_block.json` | 补上，注意 `textures` 里变量名是 `all`（配合 `cube_all`） |
| 物品栏里的方块是紫黑 | 缺 `models/item/ruby_block.json` | 补上 `{"parent": "dafeiyu:block/ruby_block"}` |
| 破坏方块时冒出紫色粒子 | 模型里没有 `particle` 纹理 | 在 `textures` 里加 `"particle": "dafeiyu:block/ruby_block"` |
| 玻璃类方块相邻面出现黑边/透视 | 没写 `noOcclusion()` | 非满方块加 `.noOcclusion()`，并在模型里加 `"render_type": "minecraft:cutout"` |
| 名字显示 `block.dafeiyu.ruby_block` | 语言文件用了 `item.` 前缀，或没写 | 方块用 `block.` 前缀 |
| 启动崩溃，日志提到 `BlockItem` 为 null | 主类里先注册了 `ModItems` | 调换顺序，方块在前 |

## 练习

1. **基础**：加一个「蓝宝石块」`sapphire_block`，硬度 4、抗爆 5，用石镐就能挖（不加 `needs_iron_tool`），确认木镐不掉、石镐掉。
2. **进阶**：做一个会发光的「红宝石灯」`ruby_lamp`，`lightLevel(state -> 15)`，`sound(SoundType.GLASS)`，纹理用半透明效果，并加上 `noOcclusion()` + `render_type: cutout`，观察有没有黑边。
3. **挑战**：把红宝石块改成「挖了掉 2~4 个红宝石，而不是掉方块自己」，需要改战利品表。提示：`entries` 里把 `name` 换成 `dafeiyu:ruby`，加上 `functions` 里的 `minecraft:set_count`。做完对照资源与数据篇的战利品表文章检查。
