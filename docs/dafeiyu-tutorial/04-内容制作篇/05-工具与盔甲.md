# 工具与盔甲

> 读完这篇，你会做出整套红宝石工具（剑、镐、斧、锹、锄）和四件套盔甲，知道 1.21 里攻击伤害为什么搬到了属性组件上，并且能给工具加一个自定义右键技能。

## 学习目标

- 能说清 1.21 的工具构造方式和 1.20 的区别，不再照抄 `new SwordItem(tier, 3, -2.4f, props)` 这种老写法。
- 能用 `SimpleTier` 定义一个工具等级，并解释耐久、挖掘速度、攻击加成、附魔能力、修复材料各是什么。
- 能写出「挖不动的方块」标签，让工具拥有正确的挖掘等级。
- 能注册 `ArmorMaterial` 和 `ArmorItem`，把盔甲纹理放对位置。
- 能通过重写 `use` 给工具加右键能力，并知道为什么逻辑要判侧。
- 能根据「挖不动」「耐久不掉」「盔甲不显示」三种现象定位原因。

## 一、1.21 变了什么：从「构造器参数」到「数据组件」

先说这段历史，因为它直接决定你抄到的代码能不能编译。

**1.20 及以前**，攻击伤害和攻击速度是工具构造器的参数：

```java
// 这是 1.20 的老写法，1.21 编译不过
new SwordItem(Tier, 3, -2.4f, new Item.Properties())
```

**1.21 起**，Mojang 把「攻击伤害、攻击速度」搬进了**属性修饰符（attribute modifier）**，构造器只剩下「等级 + 属性」两个参数：

```java
// 1.21.1 的正确写法
new SwordItem(TIER, new Item.Properties().attributes(SwordItem.createAttributes(TIER, 3, -2.4f)))
```

为什么这么改？因为属性系统现在支持「同一个物品在不同槽位给不同加成」「用数据包改属性」这些能力。把伤害写死在构造器里，这些东西就都做不了。代价是我们写代码时要多套一层 `attributes(...)`。

**再往下还有一层**：工具之所以能「挖得快」「挖得动特定方块」，靠的是物品身上的 `minecraft:tool` 数据组件（`DataComponents.TOOL`），里面装一个 `Tool` 对象——它记录了「哪些方块能挖、挖多快、挖一下掉多少耐久」。原版的 `SwordItem`、`PickaxeItem` 这些类，本质上是「帮你把 `Tool` 组件和属性都配好的语法糖」。

所以你在 1.21 有两条路：

| 路线 | 写法 | 适合 |
|---|---|---|
| 用原版工具类 | `new PickaxeItem(tier, props.attributes(...))` | 99% 的情况，尤其是标准五件套 |
| 自己拼 `Tool` 组件 | `props.component(DataComponents.TOOL, new Tool(...))` | 多功能工具（镐+斧合一）、非标准工具 |

这篇主讲第一条路，第二条路在最后简单提一下思路。

## 二、定义工具等级：`Tier`

一个「等级（`Tier`）」描述的是一整套工具的共同属性。原版有木、石、铁、金、钻石、下钻六级，我们加一个红宝石级。

文件：`src/main/java/com/dafeiyu/ModToolTiers.java`

```java
package com.dafeiyu;

import net.minecraft.core.registries.BuiltInRegistries;
import net.minecraft.resources.ResourceLocation;
import net.minecraft.tags.TagKey;
import net.minecraft.world.item.Tier;
import net.minecraft.world.item.crafting.Ingredient;
import net.minecraft.world.level.block.Block;
import net.neoforged.neoforge.common.SimpleTier;

public class ModToolTiers {
    /** 用红宝石工具挖时"不掉落"的方块标签 */
    public static final TagKey<Block> INCORRECT_FOR_RUBY_TOOL = TagKey.create(
            BuiltInRegistries.BLOCK.key(),
            ResourceLocation.fromNamespaceAndPath(DafeiyuMod.MOD_ID, "incorrect_for_ruby_tool"));

    public static final Tier RUBY = new SimpleTier(
            INCORRECT_FOR_RUBY_TOOL,                    // 挖不动的方块（标签）
            1800,                                       // 耐久：钻石是 1561
            9.0f,                                       // 挖掘速度：钻石是 8，下钻是 9
            3.5f,                                       // 攻击伤害加成：钻石是 3
            18,                                         // 附魔能力：金 22，钻石 10
            () -> Ingredient.of(ModItems.RUBY.get())    // 铁砧/合成格修复用的材料
    );
}
```

六个参数逐个说：

**第一个：`TagKey<Block>`**。1.21 之前这里是「挖掘等级」一个整数（0=木、1=石、2=铁……），1.21 换成了标签。语义是「**这个标签里的方块，用这套工具挖了不掉东西**」。命名习惯是 `incorrect_for_<材料>_tool`，和原版的 `minecraft:incorrect_for_iron_tool` 对齐。

**第二个：耐久**。工具的总使用次数。钻石 1561、铁 250、石 131、木 59。设 1800 意味着比钻石稍微耐用一点。

**第三个：挖掘速度**。数值越大挖得越快。木 2、石 4、铁 6、钻石 8、下钻 9。注意它只影响「这套工具能挖的方块」，剑不使用它。

**第四个：攻击伤害加成**。不同工具有不同算法：剑的实际伤害是「加成 + 4」，所以加成 3 的剑打 7 点（3.5 颗心）。镐、斧、锹、锄的算法各不相同，具体由各自的 `createAttributes` 决定。

**第五个：附魔能力**。数值越高，附魔台给出的附魔等级越好。金 22 最高，钻石 10，下钻 15。

**第六个：修复材料**。类型是 `Supplier<Ingredient>`，所以要写成 `() -> Ingredient.of(...)`。这里用延迟的原因很实在：类加载 `ModToolTiers` 的时候，`ModItems.RUBY` 可能还没注册完，直接取 `.get()` 会拿到 null。

### 2.1 写「挖不动」标签

文件：`src/main/resources/data/dafeiyu/tags/block/incorrect_for_ruby_tool.json`

```json
{
  "values": [
    "#minecraft:incorrect_for_iron_tool"
  ]
}
```

意思是「铁工具挖不动的，红宝石工具也挖不动」——也就是红宝石的挖掘等级等于铁。

想让红宝石比铁高一档（能挖钻石矿），就换成 `"#minecraft:incorrect_for_diamond_tool"`；想做成「铁和钻石之间」这种精细等级，就用 `values` + `remove` 组合：

```json
{
  "values": [
    "#minecraft:incorrect_for_iron_tool"
  ],
  "remove": [
    "minecraft:diamond_ore",
    "minecraft:deepslate_diamond_ore",
    "minecraft:emerald_ore",
    "minecraft:deepslate_emerald_ore"
  ]
}
```

`remove` 会把这些方块从「挖不动」名单里拿掉，于是红宝石工具能挖它们了。注意 1.21 的标签目录是单数 `tags/block`，写成 `tags/blocks` 会静默失效。

## 三、注册五件套

文件：`src/main/java/com/dafeiyu/ModItems.java`（新增部分）

```java
// 剑：攻击伤害加成 3，攻速 -2.4（玩家基础攻速 4，最终 1.6）
public static final DeferredItem<SwordItem> RUBY_SWORD = ITEMS.register("ruby_sword",
        () -> new SwordItem(ModToolTiers.RUBY,
                new Item.Properties().attributes(

// 斧：加成 5.5，攻速 -3.0（斧头慢但伤害高）
public static final DeferredItem<AxeItem> RUBY_AXE = ITEMS.register("ruby_axe",
        () -> new AxeItem(ModToolTiers.RUBY,
                new Item.Properties().attributes(
                        AxeItem.createAttributes(ModToolTiers.RUBY, 5.5f, -3.0f))));

// 锹：加成 1.5，攻速 -3.0
public static final DeferredItem<ShovelItem> RUBY_SHOVEL = ITEMS.register("ruby_shovel",
        () -> new ShovelItem(ModToolTiers.RUBY,
                new Item.Properties().attributes(
                        ShovelItem.createAttributes(ModToolTiers.RUBY, 1.5f, -3.0f))));

// 锄：加成 0.5，攻速 -3.0
public static final DeferredItem<HoeItem> RUBY_HOE = ITEMS.register("ruby_hoe",
        () -> new HoeItem(ModToolTiers.RUBY,
                new Item.Properties().attributes(
                        HoeItem.createAttributes(ModToolTiers.RUBY, 0.5f, -3.0f))));
```

需要新增的 import：

```java
import net.minecraft.world.item.AxeItem;
import net.minecraft.world.item.HoeItem;
import net.minecraft.world.item.PickaxeItem;
import net.minecraft.world.item.ShovelItem;
import net.minecraft.world.item.SwordItem;
```

三个注意点：

1. **不用写 `durability(...)`**。工具类（`TieredItem`）会从 `Tier` 里取耐久自动设上。你手动再写一遍反而容易覆盖成错误的值。
2. **`createAttributes` 是每个工具类自己的静态方法**，剑传 3、镐传 1、斧传 5.5……这些数值不是随便编的，原版 `Items` 类里能查到对应值，照抄即可。
3. **攻速是负数**，因为它是「相对玩家基础攻速 4 的修饰符」。剑要 1.6，所以是 -2.4。别写成 1.6，那样你的剑会快到离谱。

### 3.1 工具的资源

每把工具要两个文件：

```text
assets/dafeiyu/models/item/ruby_sword.json
assets/dafeiyu/textures/item/ruby_sword.png
```

```json
// assets/dafeiyu/models/item/ruby_sword.json
{
  "parent": "minecraft:item/handheld",
  "textures": {
    "layer0": "dafeiyu:item/ruby_sword"
  }
}
```

`minecraft:item/handheld` 和普通物品用的 `item/generated` 的区别在于 `display` 里的旋转角度：`handheld` 会让图标斜 45°，拿在手里像握着工具。**工具、武器一律用 `handheld`**，用了 `generated` 会显得平放、拿在手里角度不对。

纹理建议直接改原版：把 `assets/minecraft/textures/item/diamond_sword.png` 复制出来，把青色换成红色。这样手柄位置、剑身长度都是对的，比从零画快得多。

## 四、给工具加右键能力

「右键放技能」需要重写 `Item#use`。因为我们要改剑，所以要写一个 `SwordItem` 的子类。

文件：`src/main/java/com/dafeiyu/RubySwordItem.java`

```java
package com.dafeiyu;

import net.minecraft.sounds.SoundEvents;
import net.minecraft.sounds.SoundSource;
import net.minecraft.world.InteractionHand;
import net.minecraft.world.InteractionResultHolder;
import net.minecraft.world.effect.MobEffectInstance;
import net.minecraft.world.effect.MobEffects;
import net.minecraft.world.entity.player.Player;
import net.minecraft.world.item.Item;
import net.minecraft.world.item.ItemStack;
import net.minecraft.world.item.SwordItem;
import net.minecraft.world.item.Tier;
import net.minecraft.world.level.Level;

public class RubySwordItem extends SwordItem {

    public RubySwordItem(Tier tier, Item.Properties properties) {
        super(tier, properties);
    }

    @Override
    public InteractionResultHolder<ItemStack> use(Level level, Player player, InteractionHand hand) {
        ItemStack stack = player.getItemInHand(hand);

        if (!level.isClientSide()) {
            // 只在服务端真正加效果，客户端加效果是无效的
            player.addEffect(new MobEffectInstance(MobEffects.GLOWING, 200, 0));
        }

        // 两侧都播放声音，这样客户端听起来没有延迟
        level.playSound(null, player.getX(), player.getY(), player.getZ(),
                SoundEvents.AMETHYST_BLOCK_CHIME, SoundSource.PLAYERS, 1.0f, 1.2f);

        // 服务端算成功、客户端算消费：手臂会挥动，且不会重复触发
        return InteractionResultHolder.sidedSuccess(stack, level.isClientSide());
    }
}
```

要点：

**`use` 的返回类型是 `InteractionResultHolder<ItemStack>`**，不是 `InteractionResult`。这是全游戏唯一一个用这个返回类型的地方（见交互流程那篇）。`sidedSuccess(stack, isClientSide)` 是最常用的返回方式。

**为什么要判 `level.isClientSide()`**：`use` 在两侧都会被调用。效果（`addEffect`）如果在客户端执行，不会报错，但也不会有任何效果——因为它没有被同步到服务端。玩家的体验是「有时候生效有时候不生效」，非常难查。

**为什么声音不判侧**：`playSound` 传 `null` 作为玩家参数时，会由客户端自己播放。两侧都调用是标准做法，声音听起来才跟手。

**`Item.Properties` 参数从哪来**：注册时传进去的就是 `new Item.Properties().attributes(SwordItem.createAttributes(...))`，子类只是把它透传给 `super`。

注册这个子类（**把第三节里 `RUBY_SWORD` 那一行替换成下面这行**，不要两行都留，否则同一个名字会注册两次）：

```java
public static final DeferredItem<RubySwordItem> RUBY_SWORD = ITEMS.register("ruby_sword",
        () -> new RubySwordItem(ModToolTiers.RUBY,
                new Item.Properties().attributes(
                        SwordItem.createAttributes(ModToolTiers.RUBY, 3, -2.4f))));
```

## 五、盔甲

盔甲的逻辑和工具很像，但「等级」换了个名字，叫**盔甲材料（`ArmorMaterial`）**，而且它**需要注册**（`Tier` 不需要）。

### 5.1 定义盔甲材料

文件：`src/main/java/com/dafeiyu/ModArmorMaterials.java`

```java
package com.dafeiyu;

import java.util.EnumMap;
import java.util.List;
import net.minecraft.Util;
import net.minecraft.core.registries.Registries;
import net.minecraft.resources.ResourceLocation;
import net.minecraft.sounds.SoundEvents;
import net.minecraft.world.item.ArmorItem;
import net.minecraft.world.item.ArmorMaterial;
import net.minecraft.world.item.crafting.Ingredient;
import net.neoforged.bus.api.IEventBus;
import net.neoforged.neoforge.registries.DeferredHolder;
import net.neoforged.neoforge.registries.DeferredRegister;

public class ModArmorMaterials {
    public static final DeferredRegister<ArmorMaterial> ARMOR_MATERIALS =
            DeferredRegister.create(Registries.ARMOR_MATERIAL, DafeiyuMod.MOD_ID);

    public static final DeferredHolder<ArmorMaterial, ArmorMaterial> RUBY =
            ARMOR_MATERIALS.register("ruby", () -> new ArmorMaterial(
                    // 每个部位提供多少护甲值
                    Util.make(new EnumMap<>(ArmorItem.Type.class), map -> {
                        map.put(ArmorItem.Type.BOOTS, 3);
                        map.put(ArmorItem.Type.LEGGINGS, 6);
                        map.put(ArmorItem.Type.CHESTPLATE, 8);
                        map.put(ArmorItem.Type.HELMET, 3);
                        map.put(ArmorItem.Type.BODY, 11); // 马、狼这类生物的"盔甲"
                    }),
                    15,                              // 附魔能力
                    SoundEvents.ARMOR_EQUIP_DIAMOND, // 穿戴音效
                    () -> Ingredient.of(ModItems.RUBY.get()), // 修复材料
                    // 纹理层：决定去哪个文件找盔甲贴图
                    List.of(new ArmorMaterial.Layer(
                            ResourceLocation.fromNamespaceAndPath(DafeiyuMod.MOD_ID, "ruby"))),
                    2.0f,                            // 韧性：钻石 2.0，下钻 3.0
                    0.0f                             // 击退抗性：只有下钻有
            ));

    public static void register(IEventBus modEventBus) {
        ARMOR_MATERIALS.register(modEventBus);
    }
}
```

`Util.make(...)` 是「造一个对象、改一改、再返回」的小工具，等价于：

```java
EnumMap<ArmorItem.Type, Integer> map = new EnumMap<>(ArmorItem.Type.class);
map.put(...);
```

用它只是为了能在构造器参数里内联写出来。

### 5.2 注册四件套

```java
public static final DeferredItem<ArmorItem> RUBY_HELMET = ITEMS.register("ruby_helmet",
        () -> new ArmorItem(ModArmorMaterials.RUBY, ArmorItem.Type.HELMET,
                new Item.Properties().durability(ArmorItem.Type.HELMET.getDurability(33))));

public static final DeferredItem<ArmorItem> RUBY_CHESTPLATE = ITEMS.register("ruby_chestplate",
        () -> new ArmorItem(ModArmorMaterials.RUBY, ArmorItem.Type.CHESTPLATE,
                new Item.Properties().durability(ArmorItem.Type.CHESTPLATE.getDurability(33))));

public static final DeferredItem<ArmorItem> RUBY_LEGGINGS = ITEMS.register("ruby_leggings",
        () -> new ArmorItem(ModArmorMaterials.RUBY, ArmorItem.Type.LEGGINGS,
                new Item.Properties().durability(ArmorItem.Type.LEGGINGS.getDurability(33))));

public static final DeferredItem<ArmorItem> RUBY_BOOTS = ITEMS.register("ruby_boots",
        () -> new ArmorItem(ModArmorMaterials.RUBY, ArmorItem.Type.BOOTS,
                new Item.Properties().durability(ArmorItem.Type.BOOTS.getDurability(33))));
```

**盔甲必须自己写 `durability(...)`**，这点和工具不同。`getDurability(33)` 里的 33 是「基础耐久倍数」，原版钻石用的是 33，铁 15。乘上部位系数（头盔 11、胸甲 16、护腿 15、靴子 13）就是最终耐久，比如头盔 363。

`ArmorItem.Type` 是个枚举，五个值：`HELMET`、`CHESTPLATE`、`LEGGINGS`、`BOOTS`、`BODY`。`BODY` 是给马、狼这类非玩家生物用的，玩家穿不上。

### 5.3 盔甲的两套纹理

盔甲需要**两种**图，新手最常搞混：

**① 物品图标**（在物品栏里看到的那个）

```text
assets/dafeiyu/models/item/ruby_helmet.json
assets/dafeiyu/textures/item/ruby_helmet.png
```

```json
// assets/dafeiyu/models/item/ruby_helmet.json
{
  "parent": "minecraft:item/generated",
  "textures": {
    "layer0": "dafeiyu:item/ruby_helmet"
  }
}
```

**② 穿在身上的模型纹理**（3D 那层皮）

```text
assets/dafeiyu/textures/models/armor/ruby_layer_1.png   ← 头盔、胸甲、靴子
assets/dafeiyu/textures/models/armor/ruby_layer_2.png   ← 护腿（只有这一件用第二层）
```

路径是 `textures/models/armor/`，比普通纹理多一层 `models/armor`。文件名由 `ArmorMaterial.Layer` 的 `ResourceLocation` 决定：我们传的是 `dafeiyu:ruby`，游戏就会去找 `ruby_layer_1.png` 和 `ruby_layer_2.png`。

这两张图的尺寸是 **64×32**（和原版 `diamond_layer_1.png` 一样），不是 16×16。做法：解压原版资源包，复制 `diamond_layer_1.png` 和 `diamond_layer_2.png`，把蓝色系改成红色系。**不要自己从头画**，UV 布局很难靠猜对上。

## 六、跑起来验证

1. `/give @s dafeiyu:ruby_pickaxe`，去挖石头——应该很快，且掉石头。
2. 挖钻石矿——如果标签用的是 `incorrect_for_iron_tool`，会掉钻石矿（铁镐也能挖）。
3. 挖黑曜石——挖不动（铁也挖不动）。
4. 打一只僵尸，看伤害是不是 7 点（3.5 心）。
5. 右键红宝石剑——身上出现发光效果，并听到紫水晶音效。
6. 穿全套盔甲，按 `E` 看角色预览，护甲条应该满 20 点中的 20 点（3+8+6+3）。

`ModArmorMaterials` 必须排在 `ModItems` **之前**，因为 `ArmorItem` 的构造器要拿 `Holder<ArmorMaterial>`，如果材料还没注册，拿到的 holder 是空的。

## 常见坑与报错

| 现象 | 原因 | 解决 |
|---|---|---|
| 编译报错 `no suitable constructor` 指向 `new SwordItem(...)` | 抄了 1.20 的四参数构造器 | 改成 `new SwordItem(tier, props.attributes(SwordItem.createAttributes(...)))` |
| 工具挖方块跟空手一样慢 | 方块没加 `minecraft:mineable/pickaxe` 标签，工具「管不着」它 | 给方块加对应标签 |
| 工具挖得动，但挖了什么都不掉 | 方块的 `requiresCorrectToolForDrops()` 生效，而工具的等级不够 | 检查 `incorrect_for_xxx_tool` 标签 |
| 工具连石头都挖不动 | 标签文件路径写成 `tags/blocks`（复数），标签是空的 | 1.21 用单数 `tags/block` |
| 耐久永远不掉 | 用的是普通 `Item` 而不是工具类，或没走破坏方块的流程 | 用 `PickaxeItem` 等原版工具类 |
| 工具伤害为 0，打怪不掉血 | 忘了 `.attributes(...)` | 补 `XxxItem.createAttributes(tier, 伤害, 攻速)` |
| 攻速快到异常 / 慢到不能动 | 把最终攻速当成了修饰符（如写 `1.6f`） | 记住是「相对 4 的差值」，剑写 -2.4 |
| 工具拿在手里角度很怪、像平放的图 | 模型用了 `item/generated` | 换成 `minecraft:item/handheld` |
| 盔甲穿上看不见，或者只显示一件 | 缺 `textures/models/armor/ruby_layer_1.png` / `_layer_2.png` | 两张都要，64×32 |
| 护腿穿上看不见，其他正常 | 护腿只用 `_layer_2.png` | 补第二层纹理 |
| 盔甲穿上没护甲值 | `ArmorMaterial` 的 `defense` 映射里缺对应部位 | 五个 key 全填 |
| 启动崩溃，`ArmorMaterial` 为 null | `ModArmorMaterials.register` 排在 `ModItems` 之后 | 调换顺序 |
| 右键技能有时候生效有时候不生效 | 没判 `level.isClientSide()`，客户端也执行了逻辑 | 逻辑包在 `if (!level.isClientSide())` 里 |

## 练习

1. **基础**：把红宝石的挖掘等级改成钻石级（`incorrect_for_diamond_tool`），验证现在能挖黑曜石。再改回去，体会标签的作用。
2. **进阶**：做一个「红宝石战锤」——斧和镐合一。提示：不要继承 `AxeItem`，直接 `extends Item`，然后用 `Item.Properties#component(DataComponents.TOOL, ...)` 自己拼 `Tool`（一个 `Tool.Rule` 列表 + 默认挖掘速度 + 每挖一下掉多少耐久），再配 `.attributes(...)` 加伤害。这是 1.21 里做多功能工具的正路。
3. **挑战**：给红宝石剑加「右键蓄力」：右键后 1 秒内不能移动，1 秒后对前方 3 格内所有生物造成伤害。提示：需要 `use` 里记录时间戳，配合 `inventoryTick` 或 `PlayerTickEvent`；伤害用 `level.getEntitiesOfClass(...)` + `entity.hurt(...)`。做完回头读一遍交互流程那篇，确认你没有把逻辑写在客户端。
