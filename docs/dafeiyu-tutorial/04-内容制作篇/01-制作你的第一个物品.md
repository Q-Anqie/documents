# 制作你的第一个物品

> 读完这篇，你会从零做出一个叫「红宝石」的物品：能注册、有纹理、有模型、有中文名、能在创造模式物品栏里拿到，并且知道每一步漏了会看到什么现象。

## 学习目标

- 能独立写出一个 `ModItems` 注册类，并用 `DeferredRegister.Items` 注册 `DeferredItem<Item>`。
- 能说清 `new Item.Properties()` 里 `stacksTo`、`rarity`、`fireResistant`、`component` 分别在改什么。
- 能不看教程，自己写出物品的三件套资源：纹理 PNG、物品模型 JSON、语言文件条目，并放到正确路径。
- 能启动游戏，用 `/give` 拿到物品，并解释「紫黑方块」「显示 `item.dafeiyu.ruby`」这两种现象分别缺了什么。
- 知道为什么物品必须先注册、后使用，以及 `get()` 漏写会报什么错。

## 一、先建立一个正确的心理模型

你在游戏里捡起一块泥土，物品栏里出现一个泥土图标，右下角写着「64」。这一小格东西，代码里叫**物品堆叠（`ItemStack`）**。

但 `ItemStack` 本身不包含「泥土长什么样」「能不能堆叠」「叫什么名字」这些信息。这些信息属于另一个东西——**物品（`Item`）**。整个游戏里，泥土这个 `Item` 只存在**一个**实例，所有泥土堆叠都指向它。`ItemStack` 只是「某个物品 + 数量 + 这一堆自己的额外数据」。

这个「只有一个实例」的性质非常重要，它直接决定了下面这件事：

> 物品必须在游戏启动、注册表还没冻结的时候创建好，并且只能创建一次。所以我们的代码不会在需要红宝石的时候 `new Item()`，而是在一个固定的时机把「怎么造红宝石」这件事**登记**给游戏，由游戏在合适的时机调用它。

这套「先登记、后创建」的机制叫**延迟注册（deferred registration）**，你已经在前面的核心概念篇学过。这里只强调结论：**所有物品都写在注册类里，用 `DeferredRegister` 登记，用 `DeferredItem` 持有引用，用的时候加 `.get()`。**

## 二、建一个注册类

先建文件 `src/main/java/com/dafeiyu/ModItems.java`。这个类从今天开始会越来越长，你以后做的每一个物品都会往里面加一行。

```java
package com.dafeiyu;

import net.minecraft.world.item.Item;
import net.minecraft.world.item.Rarity;
import net.neoforged.bus.api.IEventBus;
import net.neoforged.neoforge.registries.DeferredItem;
import net.neoforged.neoforge.registries.DeferredRegister;

public class ModItems {
    // 物品注册表，绑定到 dafeiyu 这个命名空间
    public static final DeferredRegister.Items ITEMS = DeferredRegister.createItems(DafeiyuMod.MOD_ID);

    // 红宝石
    public static final DeferredItem<Item> RUBY =
            ITEMS.registerSimpleItem("ruby", new Item.Properties().rarity(Rarity.RARE));

    // 把注册表交给模组事件总线
    public static void register(IEventBus modEventBus) {
        ITEMS.register(modEventBus);
    }
}
```

逐块看：

**`DeferredRegister.createItems(...)`** 是 NeoForge 专门给物品准备的工厂方法，返回 `DeferredRegister.Items`。它和通用的 `DeferredRegister.create(Registries.ITEM, "dafeiyu")` 是同一个东西，只是多了几个物品专用的小工具，`registerSimpleItem` 就是其中之一。

**`DeferredItem<Item>`** 尖括号里的 `Item` 表示「这里面装的是一个 `Item` 或其子类」。你现在做的是最普通的物品，所以就是 `Item`；以后做剑，这里会变成 `DeferredItem<SwordItem>`。`DeferredItem` 本身不是物品，它是一个**供应者（`Supplier`）**，`.get()` 之后才拿到真正的 `Item` 对象。

**`registerSimpleItem("ruby", ...)`** 干的事情等价于：

```java
ITEMS.register("ruby", () -> new Item(new Item.Properties().rarity(Rarity.RARE)))
```

也就是说，它帮你把 `() -> new Item(...)` 这层 Lambda 省掉了。注意第一个参数 `"ruby"` 是**注册名**，最终物品的完整 ID 是 `dafeiyu:ruby`。这个名字只能用小写字母、数字、下划线、点和短横线，**大写会直接崩**。

**`register(IEventBus)`** 这一句不能忘。`DeferredRegister` 只是把名字记在自己的小本子上，只有调用 `register(modEventBus)` 之后，它才会在注册表事件里真正把东西交上去。漏了这一句，物品永远不存在。

## 三、接进主类

文件：`src/main/java/com/dafeiyu/DafeiyuMod.java`

```java
package com.dafeiyu;

import net.neoforged.bus.api.IEventBus;
import net.neoforged.fml.ModContainer;
import net.neoforged.fml.common.Mod;

@Mod(DafeiyuMod.MOD_ID)
public class DafeiyuMod {
    public static final String MOD_ID = "dafeiyu";

    public DafeiyuMod(IEventBus modEventBus, ModContainer modContainer) {
        // 每个注册类都要在这里登记一次
        ModItems.register(modEventBus);
    }
}
```

构造函数里的 `modEventBus` 是**模组事件总线**。注册表相关的事件都在这条总线上，所以注册类的 `register` 方法必须收到它。以后你每加一个 `ModBlocks`、`ModBlockEntities`，就在这里加一行，**顺序有讲究**：方块类要在物品类之前（原因见下一篇「方块物品」一节）。

## 四、`Item.Properties` 到底在配什么

`new Item.Properties()` 是一个 **Builder（构建器）**：你先一步步描述「我要什么样的物品」，最后把它整个交给 `Item` 的构造函数。它内部的每一项配置，最终都会变成物品身上的一个**数据组件（data component）**。

| 方法 | 作用 | 对应的数据组件 | 常见取值 |
|---|---|---|---|
| `stacksTo(int)` | 最大堆叠数 | `minecraft:max_stack_size` | 默认 64；药水、工具是 1 |
| `durability(int)` | 耐久度 | `minecraft:max_damage` + `damage` | 铁剑 250；设了它会强制堆叠数为 1 |
| `rarity(Rarity)` | 稀有度，只影响名字颜色 | `minecraft:rarity` | `COMMON` 白、`UNCOMMON` 黄、`RARE` 青、`EPIC` 淡紫 |
| `fireResistant()` | 掉落物不怕火和岩浆 | `minecraft:fire_resistant` | 下界合金系列 |
| `food(FoodProperties)` | 变成食物 | `minecraft:food` | 见第 6 篇 |
| `component(type, value)` | 直接写任意组件 | 你指定的那个 | 见下 |
| `craftRemainder(Item)` | 合成后剩下的东西 | `minecraft:craft_remainder` | 桶 → 空桶 |
| `setNoRepair()` | 禁止铁砧修复 | `minecraft:repair_cost` 相关 | 很少用 |

`component(...)` 是万能入口。比如你想让红宝石带附魔光效，可以这样写：

```java
public static final DeferredItem<Item> RUBY =
        ITEMS.registerSimpleItem("ruby", new Item.Properties()
                .rarity(Rarity.RARE)
                .component(DataComponents.ENCHANTMENT_GLINT_OVERRIDE, true));
```

需要 `import net.minecraft.core.component.DataComponents;`。`ENCHANTMENT_GLINT_OVERRIDE` 的类型是 `Boolean`，所以第二个参数直接给 `true`。

再比如你想做一个「只能堆 16 个」的红宝石，写 `stacksTo(16)` 和 `component(DataComponents.MAX_STACK_SIZE, 16)` 效果完全一样——前者就是后者的语法糖。**不要两个都写**，后写的会覆盖先写的，虽然不报错但会让你以后调数值时怀疑人生。

小提醒：`Item.Properties` 是**可变对象**，一个实例只能交给一个物品。不要写 `Item.Properties p = new Item.Properties();` 然后两个物品共用，第二个物品会拿到一堆莫名其妙的行为。

## 五、资源三件套（新手最容易漏的地方）

代码跑通了，`/give` 也能拿到物品，但你会发现物品栏里是一个**紫黑相间的小方块**，鼠标悬停显示的是 `item.dafeiyu.ruby` 而不是「红宝石」。这不是代码错了，是资源没给。

物品的「长相」和「名字」由资源包提供，一共三个文件，缺一不可：

```text
src/main/resources/
└── assets/
    └── dafeiyu/
        ├── textures/item/ruby.png        ← 1. 纹理（16×16 的 PNG）
        ├── models/item/ruby.json         ← 2. 模型（告诉游戏怎么用纹理拼出图标）
        └── lang/zh_cn.json               ← 3. 语言文件（名字）
```

### 1. 纹理：`assets/dafeiyu/textures/item/ruby.png`

- 必须是 **PNG**，**16×16 像素**（或 16 的整数倍，比如 32×32，游戏会自动缩放）。
- 必须带**透明通道**。用画图工具存成 24 位无 alpha 的 PNG，背景会变成不透明的黑或白方块。
- **文件名必须和注册名完全一致**，`ruby` 就是 `ruby.png`，不能是 `Ruby.png`、`ruby.PNG`、`ruby_item.png`。
- 路径里的 `item` 是**单数**，不是 `items`。这是最常见的一个错。

画图工具随便哪个都行：Aseprite、Krita、Photoshop，甚至 Windows 自带的画图（存 PNG 时要选「PNG 图片」）。新手最快的办法是解压原版资源包，找 `assets/minecraft/textures/item/diamond.png`，复制一份改颜色——尺寸、色调、明暗关系全都是现成的。

### 2. 模型：`assets/dafeiyu/models/item/ruby.json`

```json
{
  "parent": "minecraft:item/generated",
  "textures": {
    "layer0": "dafeiyu:item/ruby"
  }
}
```

三行解释：

- `parent` 指向父模型 `minecraft:item/generated`，这是「把一张 2D 纹理直接贴成一个平面图标」的通用父模型。绝大多数物品都用它。
- `textures.layer0` 指定第 0 层用哪张图。值 `dafeiyu:item/ruby` 是**资源位置**，冒号前是命名空间，冒号后是 `textures/` 目录下的相对路径且**不带 `.png`**。
- 文件名必须叫 `ruby.json`，放在 `models/item/` 下，和注册名一致。

如果你要做的是「拿在手里像工具那样斜着」的模型，把 `parent` 换成 `minecraft:item/handheld` 即可。这两者的区别只在于 `display` 里的旋转角度。

### 3. 语言文件：`assets/dafeiyu/lang/zh_cn.json`

```json
{
  "item.dafeiyu.ruby": "红宝石"
}
```

- 键的格式是 `item.<命名空间>.<注册名>`。**不要加 `.name` 后缀**，那是 1.12 时代的老写法，现在写了不生效。
- 值就是你希望在游戏里看到的名字。
- 如果还想支持英文，再建一个 `en_us.json`，写 `"item.dafeiyu.ruby": "Ruby"`。游戏会按玩家语言自动挑文件。
- 这个文件是**严格的 JSON**：不能有注释，不能有尾随逗号，最后一项后面不能多一个逗号。多一个逗号，整个语言文件会被静默丢弃，所有名字都变成翻译键——这个现象非常迷惑人，记住它。

## 六、让它出现在创造模式物品栏

现在物品能用 `/give` 拿到，但创造模式物品栏里翻不到。原因很简单：**创造模式物品栏的内容是另一套数据，需要你主动把物品塞进去**。

最快的办法是往原版的「材料」页塞一个。文件：`src/main/java/com/dafeiyu/ModCreativeTabEvents.java`

```java
package com.dafeiyu;

import net.minecraft.world.item.CreativeModeTabs;
import net.neoforged.bus.api.SubscribeEvent;
import net.neoforged.fml.common.EventBusSubscriber;
import net.neoforged.neoforge.event.BuildCreativeModeTabContentsEvent;

@EventBusSubscriber(modid = DafeiyuMod.MOD_ID, bus = EventBusSubscriber.Bus.MOD)
public class ModCreativeTabEvents {
    @SubscribeEvent
    public static void buildContents(BuildCreativeModeTabContentsEvent event) {
        if (event.getTabKey() == CreativeModeTabs.INGREDIENTS) {
            event.accept(ModItems.RUBY.get());
        }
    }
}
```

这里有两个容易错的点，先记住：

1. `bus = EventBusSubscriber.Bus.MOD` 不能省。这个注解默认监听的是**游戏事件总线**，而 `BuildCreativeModeTabContentsEvent` 在**模组事件总线**上。写错了不会报错，只是这个方法永远不会被调用。
2. `event.accept(...)` 里传的是**物品本身**，所以要 `.get()`。传 `ModItems.RUBY`（一个 `DeferredItem`）会编译失败。

建自己的标签页是第 4 篇的事，现在先用原版标签页把流程跑通。

## 七、跑起来验证

1. IDEA 里点 `runClient`，等游戏进主菜单。
2. 新建一个创造模式世界。
3. 按 `E` 打开物品栏，翻到「材料」页，找到红宝石（名字是青色，因为设了 `RARE`）。
4. 也可以直接在聊天框输入 `/give @s dafeiyu:ruby 64`。
5. 如果改了纹理但游戏已经开着，按 `F3 + T` 重载资源包，不用重启。

**验证清单**：

| 你看到的 | 说明 |
|---|---|
| 有图标、名字是「红宝石」、名字青色 | 全对 |
| 紫黑格子 | 纹理或模型缺了 |
| 黑白格子（紫黑棋盘） | 纹理文件存在但读不到（路径/大小写/不是 PNG） |
| 名字显示 `item.dafeiyu.ruby` | 语言文件缺了或 JSON 语法错 |
| `/give` 报「未知物品」 | 注册没生效（`register` 没调用 / 名字大小写错） |
| 游戏崩在启动阶段 | 看日志最后一行 `Caused by:`，通常是注册名为空或含非法字符 |

## 完整示例

下面四组文件全部落盘后即可运行。

**① `src/main/java/com/dafeiyu/DafeiyuMod.java`**

```java
package com.dafeiyu;

import net.neoforged.bus.api.IEventBus;
import net.neoforged.fml.ModContainer;
import net.neoforged.fml.common.Mod;

@Mod(DafeiyuMod.MOD_ID)
public class DafeiyuMod {
    public static final String MOD_ID = "dafeiyu";

    public DafeiyuMod(IEventBus modEventBus, ModContainer modContainer) {
        ModItems.register(modEventBus);
    }
}
```

**② `src/main/java/com/dafeiyu/ModItems.java`**

```java
package com.dafeiyu;

import net.minecraft.core.component.DataComponents;
import net.minecraft.world.item.Item;
import net.minecraft.world.item.Rarity;
import net.neoforged.bus.api.IEventBus;
import net.neoforged.neoforge.registries.DeferredItem;
import net.neoforged.neoforge.registries.DeferredRegister;

public class ModItems {
    public static final DeferredRegister.Items ITEMS = DeferredRegister.createItems(DafeiyuMod.MOD_ID);

    /** 红宝石：稀有度 RARE，名字显示为青色；带附魔光效；不怕火 */
    public static final DeferredItem<Item> RUBY = ITEMS.registerSimpleItem("ruby",
            new Item.Properties()
                    .rarity(Rarity.RARE)
                    .fireResistant()
                    .component(DataComponents.ENCHANTMENT_GLINT_OVERRIDE, true));

    public static void register(IEventBus modEventBus) {
        ITEMS.register(modEventBus);
    }
}
```

**③ `src/main/java/com/dafeiyu/ModCreativeTabEvents.java`**

## 常见坑与报错

| 现象 | 原因 | 解决 |
|---|---|---|
| 物品栏里是紫黑格子 | `models/item/ruby.json` 不存在或路径错 | 确认在 `assets/dafeiyu/models/item/` 下，文件名小写 |
| 紫黑格子里带「missing texture」字样 | 模型写了，但纹理找不到 | 检查 `textures/item/ruby.png`，注意 `item` 是单数、扩展名小写 |
| 纹理显示成黑白棋盘 | PNG 尺寸不是 16 的倍数，或没 alpha 通道 | 用 16×16 重画，导出时保留透明 |
| 名字显示 `item.dafeiyu.ruby` | `lang/zh_cn.json` 缺失、路径错、或 JSON 有语法错（多逗号） | 用在线 JSON 校验器过一遍；确认是 `lang` 不是 `langs` |
| `NoSuchElementException: Item id not set` / 启动崩溃 | 注册名为空或含大写、空格 | 注册名只用小写字母、数字、下划线 |
| 编译报错 `incompatible types: DeferredItem<Item> cannot be converted to Item` | 忘了 `.get()` | 所有「当物品用」的地方都要 `ModItems.RUBY.get()` |
| 创造模式物品栏里找不到 | 没写 `BuildCreativeModeTabContentsEvent`，或事件注解的 `bus` 写错 | 见第六节，确认 `Bus.MOD` |
| 改了纹理没变化 | 资源包被缓存 | 游戏内 `F3 + T`；或在 IDEA 里 `Build > Rebuild Project` 后重启 |
| 两个物品共用一个 `Item.Properties` 实例，行为错乱 | `Properties` 是可变对象 | 每个物品都 `new Item.Properties()` |

## 练习

1. **基础**：加一个「蓝宝石」`sapphire`，堆叠上限 16，稀有度 `UNCOMMON`，纹理自己画。要求不看教程，独立写出注册代码和三个资源文件。
2. **进阶**：给红宝石加一个「耐久条」的外观（`durability(100)`），进游戏看看它在物品栏里长什么样、能不能堆叠。然后思考：为什么设了耐久就不能堆叠？
3. **挑战**：做一个 `ruby_dust`，用 `component(DataComponents.MAX_STACK_SIZE, 1)` 而不是 `stacksTo(1)`，验证两者效果一致；再故意把语言文件里的逗号写错，观察游戏的行为，把现象记进你自己的「坑表」。
