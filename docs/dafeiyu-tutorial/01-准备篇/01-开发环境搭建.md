# 开发环境搭建

> 读完这一篇，你的电脑上会有一个能编译、能启动的 NeoForge 工程骨架，并且你知道每一步为什么这么做。

## 学习目标

- 说清「JDK、IDE、Gradle」各自负责什么，为什么 Gradle 不用你单独安装
- 装好 64 位 JDK 21，配好 `JAVA_HOME`，能用 `java -version` 和 `javac -version` 验证
- 用 Mod Generator 生成 modid 为 `dafeiyu`、包名 `com.dafeiyu`、使用 ModDevGradle 的 1.21.1 工程
- 在 IDEA 里完成第一次 Gradle 同步，并能判断它是在下载还是在卡死
- 遇到下载超时时，知道该改哪个文件，而不是干等

## 一、做模组到底需要什么

做模组不是「打开一个软件点新建项目」。Minecraft 是一堆编译好的 `.class` 文件，NeoForge 在它外面包了一层加载器，你的模组是**在游戏启动时被塞进去的额外代码**。要把它写出来、编译出来、塞进去，需要三个角色：

| 角色 | 干什么 | 你要做什么 |
|---|---|---|
| JDK（Java Development Kit） | 把 `.java` 编译成 `.class`，并提供运行游戏的 JVM | 装 21 版，配环境变量 |
| IDE（集成开发环境） | 写代码：高亮、跳转、补全、调试、看 Minecraft 源码 | 装 IDEA，导入工程 |
| Gradle（构建工具） | 下载依赖、编译、打包、启动游戏 | **什么都不用装**，工程自带 |

前两个要自己装，第三个不用。这一点值得解释清楚。

### 为什么 Gradle 不用单独装

NeoForge 的工程模板里自带 **Gradle Wrapper（Gradle 包装器）**，由四个文件组成：

```text
gradlew                                    ← macOS / Linux / Git Bash 的启动脚本
gradlew.bat                                ← Windows 命令提示符的启动脚本
gradle/wrapper/gradle-wrapper.jar
gradle/wrapper/gradle-wrapper.properties   ← 写着「本项目用哪个 Gradle 版本」
```

`gradle-wrapper.properties` 里有一行 `distributionUrl`，指向某个具体的 Gradle 版本压缩包。你第一次执行 `gradlew` 时，它会读这一行，看你机器上有没有这个版本，没有就下载解压到 `C:\Users\<用户名>\.gradle\wrapper\dists\`，然后用它执行你给的任务。

好处是**版本锁定**：你、你的朋友、以后帮你改代码的人用的都是同一个 Gradle，不会出现「我这能编译你那报错」。所以网上「先安装 Gradle 8.x 并配置 GRADLE_HOME」的教程，对 NeoForge 工程是多余的，照做反而可能因版本不一致出问题。

同理，你不需要单独装 Minecraft 或 NeoForge。Gradle 会把它们当依赖下载、解压到缓存，再反编译出可读源码给你看。

```text
你写代码（IDE） → Gradle 检测改动 → JDK 编译 .class
      → Gradle 打包成 jar → JDK 运行 MC + NeoForge + 你的 jar
```

三个环节缺一个都跑不起来。所以「装不上环境」八成出在 JDK 上——它最底层，也最容易装错。

## 二、装 JDK 21

### 2.1 为什么必须是 21，17 不行吗

1. **Minecraft 1.21.1 本身用 Java 21 编译。** 编译出的 `.class` 带版本号，Java 21 是 65。用 17 的 JVM 加载版本 65 的类，直接抛 `UnsupportedClassVersionError: class file version 65.0`。这不是配置问题，是硬性不兼容。
2. **构建脚本强制 21。** 生成器的 `build.gradle` 里有一行 `java.toolchain.languageVersion = JavaLanguageVersion.of(21)`，意思是「编译必须用 21 的工具链」。你机器上没有，Gradle 要么报错，要么自己去下（国内大概率失败）。
3. **你后面会用到 21 的语法。** `record`、模式匹配 `switch` 等都是 17 之后才稳定的，用 17 编译会报语法错。

用 22、23 行不行？技术上能跑，但不建议：NeoForge 21.1 只对 21 做过完整测试，Gradle 对更高 JDK 的支持也有滞后。这一章的目标是先跑起来，别在这做实验。

### 2.2 为什么必须是 64 位

`java -version` 会输出 `64-Bit Server VM` 或 `Client VM`（32 位）。32 位 JVM 的地址空间只有 4 GB，堆内存实际上限 1.5 GB 左右，而 1.21 加 NeoForge 启动就要 2 GB 以上。结果是启动即 `OutOfMemoryError`，或者你写 `-Xmx4G` 时 JVM 直接拒绝启动，报 `Invalid maximum heap size`。Minecraft 官方也明确不支持 32 位 JVM。

### 2.3 下载与安装

两个推荐来源，都免费：

| 来源 | 说明 |
|---|---|
| Microsoft Build of OpenJDK 21 | NeoForge 官方文档推荐的，Windows 有 msi 安装包，装完自动配环境变量 |
| Eclipse Temurin 21 | 社区最常用的发行版，跨平台，安装包和压缩包都有 |

国内访问不顺时，可以找高校或云厂商的 JDK 镜像站，搜「OpenJDK 21 Windows x64」。认准三件事：版本 21、架构 x64（不是 x86、不是 aarch64）、来源可信。不要下「绿色版 JDK」，这类包常被改过或缺 `javac`。

安装时两个建议：**路径尽量短、全英文**（如 `C:\Java\jdk-21`），以后配命令行工具少一层引号问题；**记住路径**，下一步要用。装完去 `C:\Java\jdk-21\bin` 看一眼，应该有 `java.exe` 和 `javac.exe`。

用 msi 的话它通常已自动设好 `JAVA_HOME`，可以先跳到 2.5 验证，失败再回来做 2.4。

### 2.4 配置 JAVA_HOME

`JAVA_HOME` 的内容是 **JDK 根目录**，不是 `bin` 目录。这是最高频的错误：

```text
正确：C:\Java\jdk-21
错误：C:\Java\jdk-21\bin
```

Windows 步骤：

1. `Win + R` 输入 `sysdm.cpl`，回车，打开「系统属性」。
2. 「高级」→「环境变量」。
3. 在**下半部分**「系统变量」点「新建」：变量名 `JAVA_HOME`，变量值 `C:\Java\jdk-21`。
4. 找到系统变量 `Path`，双击 →「新建」→ 填 `%JAVA_HOME%\bin`，再用右侧「上移」把它挪到最上面。
5. 一路「确定」。

第 4 步的「上移」很关键：如果电脑上装过别的 JDK（很多启动器自带 Java 8），它的 `bin` 可能排在前面，`java -version` 就会显示 8。把 `%JAVA_HOME%\bin` 放最上面能确保优先用 21。

改完环境变量，**已经打开的终端和 IDEA 都不会自动生效**，必须关掉重开。这是第二个高频困惑：「我明明改了，怎么还是旧版本？」

### 2.5 验证

新开终端（`Win + R` 输入 `cmd`）：

```bash
java -version
javac -version
echo %JAVA_HOME%
```

macOS / Linux / Git Bash：

```bash
java -version
javac -version
echo "$JAVA_HOME"
```

期望输出：

```text
java version "21.0.5" 2024-10-15 LTS
Java(TM) SE Runtime Environment (build 21.0.5+11-LTS-201)
Java HotSpot(TM) 64-Bit Server VM (build 21.0.5+11-LTS-201, mixed mode, sharing)

javac 21.0.5

C:\Java\jdk-21
```

三个检查点缺一不可：版本号以 `21` 开头、出现 `64-Bit`、`javac` 也能用（只装 JRE 的话有 `java` 没 `javac`，编译不了）。

版本不对时，在 Windows 上执行 `where java`，它按 `Path` 顺序列出所有 `java.exe`，第一个就是生效的那个。看清楚它属于哪个 JDK，再回头调顺序。

## 三、选一个 IDE

### 3.1 IDEA 社区版够不够用

**够，完全够。** 做 NeoForge 模组需要的功能社区版（Community Edition，免费）全都有：Gradle 工程导入与同步、Java 21 语法支持与补全、重构、断点调试、`Ctrl + 点击` 跳进反编译出的 Minecraft 源码。

社区版**没有**的主要是：数据库工具、Spring 等企业框架支持、JavaScript/TypeScript 支持、内置性能分析器、远程开发。这些和模组开发基本无关。旗舰版对学生和教师免费（学校邮箱申请），有资格就用，补全和重构更强，但**没必要为做模组付费**。

### 3.2 Eclipse 简述

NeoForge 也支持 Eclipse，免费开源、内存占用低。但它对 Gradle 的支持是外挂式的（Buildship 插件），导入 NeoForge 工程时常要手动处理注解处理器、源码附件，报错信息也不如 IDEA 直观。结论：第一次做模组用 IDEA 社区版，熟悉流程后想换什么都行。本教程后面的描述都以 IDEA 为准。

### 3.3 装完 IDEA 先做三件事

1. **设 Gradle 用的 JDK**：`File → Settings → Build, Execution, Deployment → Build Tools → Gradle`，`Gradle JVM` 选 21。
   注意有两个不同的东西：`Project SDK`（编译项目用的）和 `Gradle JVM`（跑 Gradle 本身用的），两个都设 21 最省事。`Gradle JVM` 是 17 会出现「编译能过、同步报 toolchain 错误」这种别扭现象。
2. **统一编码**：`Settings → Editor → File Encodings`，`Global Encoding`、`Project Encoding`、`Default encoding for properties files` 全设 `UTF-8`。这直接影响你后面写中文语言文件、中文日志会不会乱码。
3. **加内存**：`Help → Change Memory Settings`，调到 2048 或 4096 MB。索引 Minecraft 源码是体力活，默认 750 MB 容易卡。

## 四、用 Mod Generator 生成工程

官方网页工具：https://neoforged.net/mod-generator/

你填几个字段，它现场生成一个完整工程压缩包。比去 GitHub 找模板再手动全局替换 `examplemod` 省事得多。

### 4.1 各字段怎么填

| 字段 | 填什么 | 说明 |
|---|---|---|
| Mod Name | `Dafeiyu Mod` | 显示名。先填英文，第 2 篇改成中文「大肥鱼模组」，正好验证改动生效 |
| Mod ID | `dafeiyu` | 全小写，只能字母、数字、下划线，2~64 字符。这是模组的「身份证」 |
| Package Name | `com.dafeiyu` | 主包名，必须和以后放代码的目录一致 |
| Minecraft Version | `1.21.1` | 不要选别的 |
| NeoForge Version | 匹配的 21.1.x | 生成器会列出可选值，选靠后的稳定版 |
| Gradle Plugin | `ModDevGradle` | 本教程全程用它。另一个选项 NeoGradle 也能用，但写法不同，混着看会晕 |
| License | `MIT` 或 `All Rights Reserved` | 没想好就用后者，以后随时能改 |
| Author | 你的名字 | 显示在模组列表里 |
| Description | 一句话介绍 | 可以先随便写，第 3 篇细讲 |

**Mod ID 的规则要记牢**：只能小写字母、数字、下划线，不能有空格、中文、横杠。写成 `DaFeiYu` 或 `dafeiyu-mod` 会引发一连串问题（资源路径找不到、注册失败）。本教程统一用 `dafeiyu`。

### 4.2 下载与解压

解压到**纯英文、无空格、不在 OneDrive 同步目录里**的路径，例如 `D:\mcmods\dafeiyu`。三个理由：

- 中文路径会让部分 Gradle 任务报 `Could not create task` 或乱码；
- 同步盘会锁文件，Gradle 反编译时要读写几万个文件，同步客户端会拖慢甚至报「文件被占用」；
- 路径太长会触发 Windows 的 260 字符上限，报「文件名过长」。

如果生成器给的主类叫 `ExampleMod` 而不是 `DafeiyuMod`，先别改名——等工程在 IDEA 里同步成功后再用 `Shift + F6` 重命名，它会帮你改所有引用，比手改安全。

## 五、导入 IDE 与第一次同步

### 5.1 打开工程

IDEA 启动页点 `Open`，选 `D:\mcmods\dafeiyu` **这个文件夹**（不是里面的文件）。IDEA 认出 `build.gradle` 后会问要不要作为 Gradle 项目导入，选 `Trust Project`。之后右下角出现进度条，标题类似 `Syncing Gradle...`。

### 5.2 同步到底在做什么

第一次同步最耗时，很多人以为卡死了就强关，留下半截缓存，后面一直报错。它按顺序做五件事：

1. **下载 Gradle 本体**：读 `distributionUrl`，下载几十 MB 到 `~/.gradle/wrapper/dists/`。
2. **解析插件和依赖**：去 Maven 仓库下载 ModDevGradle 插件、NeoForge 构件及其依赖。
3. **下载 Minecraft**：从 Mojang 服务器拉 1.21.1 的客户端和服务端 jar，以及**资源文件（assets）**——音效、语言、贴图，几百 MB。
4. **反编译并打补丁**：把混淆的字节码反编译成可读源码，再应用 NeoForge 补丁。CPU 跑满，全程最慢。
5. **建索引**：IDEA 读取源码建索引，之后你才能 `Ctrl + 点击` 跳进 `Block`、`Item`。

视网络和 CPU，**二十分钟到一小时都算正常**。第二次打开工程只要几十秒。

### 5.3 判断「在干活」还是「卡死」

| 观察点 | 在干活 | 大概率卡死 |
|---|---|---|
| 右下角进度条 | 文字在变（`Downloading` → `Executing` → `Decompiling`） | 十分钟不变 |
| 任务管理器 | CPU 有占用（反编译能到 80% 以上），或磁盘/网络有活动 | CPU、网络、磁盘都接近 0 |
| `~/.gradle/caches/` 大小 | 隔一会儿就变大 | 长时间不变 |
| `~/.gradle/daemon/<版本>/daemon-*.log` | 文件在增长，末尾有新时间戳 | 停在某行下载进度上 |

最可靠的依据是第四行：打开最新的 `daemon-xxxx.log` 看最后几行。停在 `Downloading https://...` 且几分钟没新内容，就是网络卡了，去第六节配镜像；在刷 `Decompiling` 就只是慢，耐心等。

**不要做的事**：同步中途点 `Cancel` 然后立刻重来，容易留下下载了一半的缓存。真要中断，先关 IDEA，删掉 `~/.gradle/caches/modules-2/files-2.1/` 下对应的半成品目录。

### 5.4 同步成功的样子

三个标志：进度条消失且没有红色横幅；`DafeiyuMod.java` 的图标是正常 Java 类图标；打开主类按住 `Ctrl` 点 `IEventBus` 能跳进 NeoForge 源码。

只有第三条真正说明「可以开始写代码了」。前两条过了但跳不进去，通常是索引没建完，等几分钟或 `File → Invalidate Caches → Invalidate and Restart`。

## 六、国内网络：镜像与代理

这一节讲**方法**，不给固定地址——镜像站会换域名、会下线，抄死的地址过半年就是 404。

### 6.1 先分清三类下载

| 下载内容 | 从哪来 | 能用国内镜像吗 |
|---|---|---|
| Gradle 本体 | `distributionUrl` 指向的地址（官方是 services.gradle.org） | 能，换成镜像站的同名压缩包 |
| 通用 Java 库（gson、log4j 等） | Maven Central | 能，用云厂商的 Maven 镜像 |
| NeoForge 自己的构件 | maven.neoforged.net | **不能**，只有官方仓库有 |
| Minecraft 客户端/资源 | Mojang 下载服务器 | 一般不能，只能靠代理或换网络 |

看懂这张表，就知道为什么「加了镜像还是慢」——慢的那部分根本不是 Maven Central 的东西。

### 6.2 换 Gradle 发行版镜像

打开 `gradle/wrapper/gradle-wrapper.properties`，找到：

```properties
distributionUrl=https\://services.gradle.org/distributions/gradle-8.10-bin.zip
```

去你信任的镜像站（高校开源镜像、云厂商镜像），站内搜索 `gradle`，找到 `distributions` 目录，换成**同版本、同文件名**的地址。两点注意：必须选 `-bin.zip` 而不是 `-all.zip`（后者带源码文档，体积大一倍，对构建没帮助）；版本号不要改，`8.10` 就得还是 `8.10`。

改完保存重新同步。之前下了一半的话，去 `~/.gradle/wrapper/dists/` 删掉对应半成品目录。

### 6.3 加 Maven 镜像

配置在 `build.gradle` 的 `repositories { }` 和 `settings.gradle` 的 `pluginManagement { repositories { } }` 里。思路是**把镜像加在官方仓库前面**，Gradle 按声明顺序查找，镜像没有的再回落到官方。

```gradle
repositories {
    maven {
        // 换成你所用镜像站公布的 Maven 仓库地址
        url = uri("https://<镜像站域名>/repository/public")
    }
    mavenCentral()
    maven {
        name = "NeoForged"
        url = uri("https://maven.neoforged.net/releases")
    }
}
```

三个原则：官方仓库**不能删**（NeoForge 构件只有它有）；镜像**放最前面**（放后面等于没用）；镜像地址**从镜像站官网抄**，别抄博客（博客里的常是几年前的）。如果加了镜像反而报 `Could not resolve` 或证书错误，先把镜像注释掉确认能同步，再一行一行加回来定位。

### 6.4 配代理

有可用 HTTP 代理时，最省事是写进 `gradle.properties`（`systemProp.` 开头的键会作为 JVM 系统属性传给 Gradle）：

```properties
systemProp.http.proxyHost=127.0.0.1
systemProp.http.proxyPort=7890
systemProp.https.proxyHost=127.0.0.1
systemProp.https.proxyPort=7890
```

端口换成你代理软件的。注意：**只对 Gradle 生效**，`runClient` 起的 Minecraft 是另一个 JVM；**不要同时开全局代理和这里的手动配置**，会绕两层更慢；只支持 SOCKS5 的话换成 `systemProp.socksProxyHost` / `socksProxyPort`。IDEA 自己也有一份代理设置（`Settings → System Settings → HTTP Proxy`），管的是插件市场，和 Gradle 是两套，两边都配好最稳。

### 6.5 不要做的事

- **不要用离线模式（Offline Mode）「解决」下载慢**。它是给「依赖已下好、只是没网」的场景用的，依赖没下完就开，只会得到一堆 `No cached version available for offline mode`。
- **不要为了快就升降 Gradle 版本**。版本是配套的，动了会引发更难查的问题。
- **不要在同步中反复重启 IDEA**。每次重启都要重建索引，越弄越慢。

## 完整示例

这一节没有代码，给你一份可以照着核对的自检清单和验证脚本。

### 环境自检清单

```text
[ ] 磁盘剩余 >= 20 GB（Gradle 缓存 + 反编译产物很占地方）
[ ] 内存 >= 8 GB（16 GB 更稳）
[ ] 工程路径纯英文、无空格、不在同步盘里
[ ] JDK 21 已安装，JAVA_HOME 指向 JDK 根目录（不是 bin）
[ ] java -version 显示 21 且带 64-Bit
[ ] javac -version 显示 21
[ ] IDEA 的 Gradle JVM 设为 21
[ ] IDEA 文件编码全部 UTF-8
[ ] 工程能同步成功，Ctrl+点击 IEventBus 能跳进源码
```

### 一键验证

Windows 命令提示符：

```bash
java -version
javac -version
echo %JAVA_HOME%
where java
```

macOS / Linux / Git Bash（在工程根目录）：

```bash
java -version
javac -version
echo "$JAVA_HOME"
./gradlew --version
```

`./gradlew --version` 是个很好的「终检」，会打印 Gradle 版本、JVM 版本、系统信息：

```text
------------------------------------------------------------
Gradle 8.10
------------------------------------------------------------

Launcher JVM: 21.0.5 (Microsoft 21.0.5+11-LTS)
Daemon JVM:   C:\Java\jdk-21 (no JDK specified, using current Java home)
OS:           Windows 11 10.0 amd64
```

重点看 `Launcher JVM` 和 `Daemon JVM`，都该是 21。如果 `Launcher JVM` 是 17，说明终端里的 `java` 还是旧的，回 2.4 调 `Path` 顺序。

## 常见坑与报错

| 现象 | 原因 | 解决 |
|---|---|---|
| `'java' 不是内部或外部命令` | `Path` 里没有 `%JAVA_HOME%\bin`，或改完没重开终端 | 重开终端；检查 `Path` |
| `java -version` 显示 1.8 或 17 | 机器上有多个 JDK，旧的排在前面 | `where java` 看顺序，把 `%JAVA_HOME%\bin` 上移 |
| `JAVA_HOME` 设成了 `...\jdk-21\bin` | 多写了一层 `bin` | 改成 JDK 根目录，`bin` 只出现在 `Path` 里 |
| 同步报 `Unsupported class file major version 65` | Gradle 用的是 17 或更低 | 改 IDEA 的 `Gradle JVM` 为 21；改 `JAVA_HOME` |
| 报 `Could not resolve net.neoforged:neoforge:...` | 到不了 maven.neoforged.net，或代理没生效 | 配代理；确认 `repositories` 有官方仓库；看 daemon 日志定位 URL |
| 卡在 `Downloading https://services.gradle.org/...` | Gradle 本体下载超时 | 换 `distributionUrl` 为镜像，删掉 `~/.gradle/wrapper/dists` 半成品 |
| `./gradlew: Permission denied` | Linux/macOS 下脚本没执行权限（zip 解压常见） | `chmod +x gradlew`，或用 IDEA 的 Gradle 面板按钮 |
| IDEA 里一片红但命令行 `gradlew build` 能过 | IDEA 的 `Gradle JVM` 和终端 `JAVA_HOME` 不是同一个 | 统一成 21 |
| 同步报 `Could not create task ':compileJava'`，路径含中文 | 工程在中文路径下 | 移到 `D:\mcmods\dafeiyu`，重新导入 |
| 反编译阶段 CPU 100% 很久 | 正常，正在反编译 | 等；别 Cancel；确认磁盘有空间 |
| `OutOfMemoryError: Java heap space` | `org.gradle.jvmargs` 堆太小，或用了 32 位 JVM | 调大到 `-Xmx3G`；确认 `java -version` 是 64-Bit |
| 改了 `gradle.properties` 没生效 | 没重新同步 | 点 IDEA 右上角大象图标，或 `gradlew --refresh-dependencies` |

## 练习

1. **环境体检**：把「环境自检清单」抄到文本文件里逐条打勾。有任何一条打不上，先解决它，不要往下走。
2. **故意破坏再修复**：把 `JAVA_HOME` 改成 `C:\Java\jdk-21\bin`，重开终端执行 `java -version`，记下报错，再改回来。目的是让你以后一眼认出这个错。
3. **观察同步过程**：重新同步一次（`File → Reload Gradle Project`），同时用 `tail -f` 跟着 `~/.gradle/daemon/` 下最新的日志，记下三个阶段的关键词和各自耗时。以后判断「是不是卡死了」就有参照了。
