# 项目结构与配置文件详解

> 读完这一篇，你打开任何一个 NeoForge 工程都能立刻说出「哪个文件管什么、我该改哪里、哪里千万别碰」。

## 学习目标

- 逐键说清 `gradle.properties` 里每个配置项的作用，分清「必须改」「可以改」「别动」
- 逐段读懂 `neoforge.mods.toml`，能自己写出一个合法的版本范围
- 知道 `build.gradle` 里哪些能改、`runs { client { ... } }` 在做什么
- 画出 `assets/` 和 `data/` 的完整目录树，说清每个子目录放什么
- 按功能给代码分包，并解释为什么客户端代码必须单独放
- 用一张速查表在 30 秒内定位「我要加的东西该放哪」

## 一、`gradle.properties`：模组信息的总开关

这个文件是你打开频率最高的一个，原因很简单：**它里面的值会被自动注入到别处**，改一处、处处生效。

文件：`gradle.properties`

```properties
# ---------- Gradle 自身 ----------
org.gradle.jvmargs=-Xmx3G
org.gradle.daemon=false
org.gradle.parallel=true
org.gradle.caching=true
org.gradle.configuration-cache=true

# ---------- 环境版本 ----------
minecraft_version=1.21.1
minecraft_version_range=[1.21.1,1.22)
neo_version=21.1.77
neo_version_range=[21.1.0,22.0.0)
loader_version_range=[4,)

# ---------- 模组信息 ----------
mod_id=dafeiyu
mod_name=大肥鱼模组
mod_license=MIT
mod_version=1.0.0
mod_group_id=com.dafeiyu
mod_authors=大肥鱼
mod_description=一条会做模组的大肥鱼。
```

### 1.1 逐键说明

| 键 | 作用 | 要不要改 |
|---|---|---|
| `org.gradle.jvmargs` | 给 **Gradle 自己**的 JVM 参数。`-Xmx3G` 表示最多用 3 GB 堆 | 卡顿/内存不足时调大（`-Xmx4G`），否则别动 |
| `org.gradle.daemon` | 是否常驻后台进程，`false` 表示每次构建都新起一个 | **别动** |
| `org.gradle.parallel` | 多模块并行构建 | **别动** |
| `org.gradle.caching` | 复用上次的构建结果 | **别动** |
| `org.gradle.configuration-cache` | 缓存配置阶段，加快第二次构建 | **别动**。和个别插件偶有冲突，出怪问题时先设 `false` 试试 |
| `minecraft_version` | 目标 MC 版本 | **别动**。必须和 `neo_version` 匹配 |
| `minecraft_version_range` | 模组能接受的 MC 版本范围，会写进 `mods.toml` | 想支持 1.21.2 时才改，见第二节 |
| `neo_version` | 目标 NeoForge 版本 | **别动**。改了就换了一整套 API |
| `neo_version_range` | 模组能接受的 NeoForge 范围 | 一般**别动** |
| `loader_version_range` | 模组加载器（FML）版本范围 | **别动**。1.21.x 固定是 `[4,)` |
| `mod_id` | 模组唯一标识 | **建工程时定好，之后别改**。改了等于换了个模组，所有资源路径全失效 |
| `mod_name` | 显示名，出现在 Mods 列表 | **经常改** |
| `mod_license` | 许可证（SPDX 标识符） | 发布前必须改对。`MIT`、`Apache-2.0`、`All Rights Reserved` |
| `mod_version` | 模组版本 | **每次发布都改** |
| `mod_group_id` | 组 ID，等于主包名 | 建工程时定好，之后**别改**（改了要连目录一起改） |
| `mod_authors` | 作者，显示在 Mods 列表 | 改成你的名字 |
| `mod_description` | 描述，支持 `\n` 换行 | 可以随时改 |

### 1.2 为什么改这里就能改到 `mods.toml`

这是很多人第一次看会困惑的地方：`neoforge.mods.toml` 里明明写着 `displayName = "${mod_name}"`，为什么我不去改 toml，反而要改 `gradle.properties`？

因为 `build.gradle` 里有一段「资源处理」任务，在打包时把 `${...}` 替换掉：

文件：`build.gradle`（片段）

```gradle
tasks.withType(ProcessResources).configureEach {
    // 把 gradle.properties 里的值收集成一个 map
    var replaceProperties = [
            minecraft_version      : minecraft_version,
            minecraft_version_range: minecraft_version_range,
            neo_version            : neo_version,
            neo_version_range      : neo_version_range,
            loader_version_range   : loader_version_range,
            mod_id                 : mod_id,
            mod_name               : mod_name,
            mod_license            : mod_license,
            mod_version            : mod_version,
            mod_authors            : mod_authors,
            mod_description        : mod_description
    ]
    inputs.properties replaceProperties

    // 只处理这一个文件，把 ${key} 换成对应值
    filesMatching(['META-INF/neoforge.mods.toml']) {
        expand replaceProperties
    }
}
```

所以流程是：

```text
gradle.properties  ──►  build.gradle 的 expand  ──►  打包后的 neoforge.mods.toml
   （你改这里）              （自动替换）                  （游戏读到的是替换后的）
```

`src/main/resources/META-INF/neoforge.mods.toml` 里的 `${mod_name}` 只是**模板占位符**。直接改成 `displayName = "大肥鱼模组"` 也生效（没占位符就没得替换），但这样 `gradle.properties` 的 `mod_name` 就管不到它了，以后两处不一致很难查。

**结论：带 `${}` 的值，去 `gradle.properties` 改；不带 `${}` 的，直接在 toml 里改。**

顺带解释一个前面遇到过的现象：`gradle.properties` 里的中文如果出现乱码，很可能就是这一步替换时编码没对上。这也是为什么有的教程建议「显示名直接写死在 toml 里」——TOML 文件是明确的 UTF-8，不经过 Java 的 Properties 读取。

## 二、`neoforge.mods.toml`：模组的名片

文件：`src/main/resources/META-INF/neoforge.mods.toml`

```toml
modLoader = "javafml"
loaderVersion = "${loader_version_range}"
license = "${mod_license}"

[[mods]]
modId = "${mod_id}"
version = "${mod_version}"
displayName = "${mod_name}"
authors = "${mod_authors}"
description = '''${mod_description}'''
#logoFile = "dafeiyu.png"

[[dependencies.dafeiyu]]
modId = "neoforge"
type = "required"
versionRange = "${neo_version_range}"
ordering = "NONE"
side = "BOTH"

[[dependencies.dafeiyu]]
modId = "minecraft"
type = "required"
versionRange = "${minecraft_version_range}"
ordering = "NONE"
side = "BOTH"
```

这个文件分三段，段落由 `[方括号]` 划分。理解 TOML 的段落语法是读懂它的前提：**一个 `[表头]` 之后的所有键值对，都属于这个表**，直到下一个表头出现。

### 2.1 第一段：文件级属性（不属于某个模组）

| 键 | 含义 | 能填什么 |
|---|---|---|
| `modLoader` | 用什么语言加载器 | `"javafml"`（Java 模组，99% 的情况）或 `"lowcodefml"`（纯资源包，不写代码） |
| `loaderVersion` | 加载器版本范围 | `"[4,)"`，即「4 及以上」。这是 FML 的版本，不是 NeoForge 的版本 |
| `license` | 许可证 | `"MIT"`、`"Apache-2.0"`、`"All Rights Reserved"` |

两个都是**必须存在**的，拼错或删掉都会启动失败，分别报 `Unknown mod loader` 和 `requires loader version`。

### 2.2 第二段：`[[mods]]`，模组自己的信息

`[[mods]]` 的双括号表示「数组，可以有多段」：一个 jar 里可以打包多个模组（少见但合法），每多一个就多一段 `[[mods]]`。

| 键 | 含义 | 我们的值 |
|---|---|---|
| `modId` | 模组 ID，**必须和 `@Mod` 的值一致** | `dafeiyu` |
| `version` | 版本，显示在 Mods 列表 | `1.0.0` |
| `displayName` | 显示名 | 大肥鱼模组 |
| `description` | 描述，用 `'''三个单引号'''` 包住可以写多行 | 一条会做模组的大肥鱼。 |
| `logoFile` | 模组列表左边的小图标 | 见下 |
| `authors` | 作者 | 大肥鱼 |
| `credits` | 致谢 | 可选 |
| `issueTrackerURL` | 问题反馈地址 | 可选，发布后填 |

**`logoFile` 的用法**：PNG 放在 `src/main/resources/` 根目录（不是 `assets/`），toml 里写 `logoFile = "dafeiyu.png"`。建议 128×128，太大加载慢。这一行默认被注释掉了。

**`description` 为什么用三个单引号**：TOML 里普通字符串不能换行，`'''...'''` 是多行字面量字符串，里面的换行会原样保留。写成：

```toml
description = '''大肥鱼模组
第一条鱼，会做模组。'''
```

Mods 列表里会显示两行。

### 2.3 第三段：`[[dependencies.dafeiyu]]`，依赖声明

表头里的 `dafeiyu` 是「谁在声明依赖」，也就是你的 modId。这一段告诉 NeoForge：**我这个模组要跑起来还需要什么**。

| 键 | 含义 | 可选值 |
|---|---|---|
| `modId` | 依赖的模组 ID | `"neoforge"`、`"minecraft"`、`"jei"` 等 |
| `type` | 依赖类型 | `"required"` 必需；`"optional"` 可选；`"incompatible"` 冲突；`"discouraged"` 不推荐但允许 |
| `versionRange` | 版本范围 | Maven 版本范围语法，见下 |
| `ordering` | 加载顺序 | `"BEFORE"` / `"AFTER"` / `"NONE"` |
| `side` | 哪一侧需要 | `"CLIENT"` / `"SERVER"` / `"BOTH"` |
| `reason` | 给用户看的原因 | 任意字符串 |

### 2.4 版本范围怎么写

这是最容易写错的地方。规则来自 Maven，只有四个符号：

| 写法 | 含义 |
|---|---|
| `[1.21.1,1.22)` | 大于等于 1.21.1，**小于** 1.22。方括号是「包含」，圆括号是「不包含」 |
| `[21.1.0,)` | 大于等于 21.1.0，没有上限 |
| `(,1.22)` | 小于 1.22，没有下限 |
| `[1.21.1]` | 精确等于 1.21.1 |
| `*` | 任意版本 |
| `[1.20,1.21),[1.22,1.23)` | 两个区间，逗号表示「或」 |

几条经验：MC 用 `[1.21.1,1.22)`（1.21.x 都能用，1.22 不行）；NeoForge 用 `[21.1.0,22.0.0)`；**不要写 `[1.21.1-1.22]`**，这不是合法语法，区间必须用逗号分隔；给 JEI 这类前置写 `*` 图省事也行，但正式发布建议写具体范围，免得用户装了不兼容版本还来报 bug。

## 三、`build.gradle` 与 `settings.gradle`

### 3.1 哪些能改，哪些别碰

文件：`build.gradle`

```gradle
plugins {
    id 'java-library'
    id 'eclipse'
    id 'idea'
    id 'maven-publish'
    id 'net.neoforged.moddev' version '2.0.78'   // 别动，版本要和模板一致
}

version = mod_version        // 来自 gradle.properties
group = mod_group_id         // 来自 gradle.properties

repositories {
    mavenLocal()
    // 这里可以加镜像仓库，见上一篇第六节
}

base {
    archivesName = mod_id    // 决定 jar 文件名，别改成中文
}

java.toolchain.languageVersion = JavaLanguageVersion.of(21)   // 别动

neoForge {
    version = project.neo_version

    runs {
        client {
            client()
        }
        server {
            server()
        }
        // data / gameTestServer 结构类似，生成器已经写好
    }

    mods {
        "${mod_id}" {
            sourceSet(sourceSets.main)   // 告诉 NeoForge：这个模组的代码在 main 源码集里
        }
    }
}
```

| 位置 | 能不能改 |
|---|---|
| `plugins` 里的插件版本 | **别动**。升级 ModDevGradle 可能引入不兼容的 DSL 变化 |
| `version` / `group` / `neoForge.version` | 别直接改，去 `gradle.properties` 里改 |
| `repositories` | **可以加**，用来配镜像。但 `maven.neoforged.net` 那个不能删 |
| `base.archivesName` | 一般不动，它等于 `mod_id` |
| `java.toolchain` | **别动**，必须是 21 |
| `runs` | **可以改**，见下 |
| `mods` | 别动，除非你加了第二个源码集 |
| `dependencies` | **可以加**。需要引入第三方库时在这里加 |

### 3.2 `runs { client { ... } }` 到底在做什么

这个块定义「怎么启动游戏」。它不是真实任务，而是一份**启动配置模板**：ModDevGradle 读它之后生成 `runClient`、`runServer` 任务，同时给 IDEA 生成运行配置。

```gradle
runs {
    client {
        client()   // 声明这是客户端：会启动带界面的 Minecraft
        systemProperty 'neoforge.enabledGameTestNamespaces', project.mod_id
        // gameDirectory = file('runs/client')   // 游戏的工作目录，默认就是这里
        // jvmArgument '-Xmx4G'                  // 只给游戏进程加 JVM 参数
    }
}
```

逐行看：

- `client()`：类型声明。换成 `server()` 就是服务端，换成 `clientData()` 就是数据生成。**这一行不能删**，删了就不知道要起什么。
- `systemProperty 'key', 'value'`：给游戏进程传 `-Dkey=value`。上面这行开启 GameTest 支持，暂时用不到，但别删。
- `gameDirectory`：游戏的工作目录，也就是它的 `.minecraft`。想换位置就取消注释改路径。
- `jvmArgument`：只影响游戏进程的内存，不影响 Gradle，游戏卡顿时才用。

**改完 `runs` 一定要重新同步 Gradle**，否则 IDEA 里那个运行配置还是旧的。同步之后，IDEA 右上角运行配置里会多出 `runClient` 之类的一项。

### 3.3 `settings.gradle`

```gradle
pluginManagement {
    repositories {
        mavenLocal()
        gradlePluginPortal()
        maven {
            name = 'NeoForged'
            url = 'https://maven.neoforged.net/releases'
        }
    }
}

plugins {
    // 自动下载缺失的 JDK 工具链
    id 'org.gradle.toolchains.foojay-resolver-convention' version '0.8.0'
}

rootProject.name = 'dafeiyu'
```

三件事：

1. `pluginManagement.repositories`：Gradle **插件**从哪下载。这里必须留着 NeoForged 的仓库，否则 `net.neoforged.moddev` 插件找不到。想加镜像也是加在这一段里。
2. `foojay-resolver`：工程要求的 JDK 在你机器上找不到时，它会尝试**自动下载**。国内经常失败，报 `No matching toolchains found for requested specification: {languageVersion=21}`。看到这个报错，说明本机的 21 没被 Gradle 认出来，去查 `JAVA_HOME` 和 IDEA 的 `Gradle JVM`，别指望它自动下。
3. `rootProject.name`：工程名，只影响 IDEA 里显示的名字，随便改，不影响模组。

## 四、资源目录约定

`src/main/resources` 下面有两大分支，它们长得像、作用完全不同：

| 目录 | 叫什么 | 给谁看 | 什么时候加载 |
|---|---|---|---|
| `assets/dafeiyu/` | 资源（assets） | **客户端**：纹理、模型、语言、声音 | 进游戏时加载 |
| `data/dafeiyu/` | 数据（data） | **服务端**：配方、战利品表、标签、进度 | 进世界时加载 |

这个划分就是「侧（side）」在文件层面的体现：客户端没有 `data` 照样能显示物品，但服务端没有 `data` 就没法合成。为什么这么分、搞错了会怎样，见 [侧：客户端与服务端](../03-核心概念篇/03-侧-客户端与服务端.md)。

### 4.1 完整目录树

```text
src/main/resources/
├── META-INF/
│   └── neoforge.mods.toml            ← 模组名片
├── pack.mcmeta                       ← 资源包/数据包版本声明
├── dafeiyu.png                       ← 模组 logo（可选，供 logoFile 用）
│
├── assets/
│   └── dafeiyu/                      ← 命名空间 = modid
│       ├── lang/
│       │   ├── en_us.json            ← 英文语言文件
│       │   └── zh_cn.json            ← 中文语言文件
│       ├── textures/
│       │   ├── item/                 ← 物品纹理 xxx.png
│       │   ├── block/                ← 方块纹理 xxx.png
│       │   ├── gui/                  ← 界面纹理
│       │   ├── entity/               ← 实体纹理
│       │   └── particle/             ← 粒子纹理
│       ├── models/
│       │   ├── item/                 ← 物品模型 xxx.json
│       │   └── block/                ← 方块模型 xxx.json
│       ├── blockstates/              ← 方块状态 xxx.json
│       ├── sounds.json               ← 音效注册表
│       ├── sounds/                   ← 音效文件 xxx.ogg
│       └── font/                     ← 自定义字体（少见）
│
└── data/
    └── dafeiyu/                      ← 命名空间 = modid
        ├── recipe/                   ← 配方 xxx.json（1.21 起是单数）
        ├── loot_table/
        │   └── blocks/               ← 方块掉落表 xxx.json
        ├── tags/
        │   ├── item/                 ← 物品标签 xxx.json
        │   └── block/                ← 方块标签 xxx.json
        ├── advancement/              ← 进度 xxx.json
        ├── damage_type/              ← 自定义伤害类型
        ├── enchantment/              ← 自定义附魔
        └── neoforge/                 ← NeoForge 专属数据（生物群系修改器等）
```

三个必须记住的细节：

1. **命名空间目录名必须等于 modid**，即 `assets/dafeiyu/`、`data/dafeiyu/`。写成 `assets/dafeiyu_mod/` 或 `assets/DaFeiYu/` 游戏就找不到资源——而且**不报错**，只是物品变成紫黑格子。
2. **1.21 起部分目录改成了单数**：`recipes/` → `recipe/`，`loot_tables/` → `loot_table/`，`advancements/` → `advancement/`。照抄 1.20 教程里的复数目录名，资源会静默失效。
3. **`pack.mcmeta` 不能少**：

```json
{
  "pack": {
    "description": "dafeiyu resources",
    "pack_format": 34
  }
}
```

`pack_format` 是资源包格式号，1.21.1 是 `34`。写错会提示「资源包版本不兼容」并拒绝加载。

### 4.2 路径怎么写才对

资源路径用 `ResourceLocation` 表示，格式是 `命名空间:路径`。例如：

```text
纹理文件：src/main/resources/assets/dafeiyu/textures/item/da_fish.png
对应 ID： dafeiyu:item/da_fish
代码写法： ResourceLocation.fromNamespaceAndPath("dafeiyu", "item/da_fish")
```

注意：路径里**不带 `textures/` 和 `.png`**，命名空间和路径之间用**冒号**。详见 [资源位置与命名空间](../03-核心概念篇/04-资源位置与命名空间.md)。

## 五、包结构怎么分

代码全堆在 `com.dafeiyu` 下也能跑，但做到第 10 个类就找不到了。推荐按**功能**分子包，Minecraft 自己也这么做：

```text
src/main/java/com/dafeiyu/
├── DafeiyuMod.java              ← 主类，只放入口和总线注册
├── block/                       ← 方块类：XxxBlock
├── item/                        ← 物品类：XxxItem，以及 ModItems、ModCreativeTabs
├── blockentity/                 ← 方块实体：XxxBlockEntity
├── menu/                        ← 容器菜单：XxxMenu，以及 ModMenus
├── event/                       ← 事件监听器：XxxEvents
├── datagen/                     ← 数据生成 provider：ModBlockStateProvider 等
├── client/                      ← 只在客户端跑的代码：渲染器、界面、按键
└── util/                        ← 工具类：常量、辅助方法
```

### 5.1 每个包放什么

| 包 | 放什么 | 不该放什么 |
|---|---|---|
| `block` | 所有 `Block` 子类、`ModBlocks` 注册类 | 方块实体（那是另一个注册表） |
| `item` | 所有 `Item` 子类、`ModItems`、`ModCreativeTabs` | 物品的模型/纹理（那是资源） |
| `blockentity` | 所有 `BlockEntity` 子类、`ModBlockEntities` | 渲染器（渲染器是客户端代码） |
| `menu` | `AbstractContainerMenu` 子类、`ModMenus` | `Screen`（界面是客户端代码） |
| `event` | 带 `@EventBusSubscriber` 的类、事件处理方法 | 业务逻辑（抽到对应的类里） |
| `datagen` | `DataGenerator` 相关的 provider | 运行时逻辑（只在 datagen 任务里跑） |
| `client` | `Screen`、`BlockEntityRenderer`、`KeyMapping`、`@Mod(dist = Dist.CLIENT)` 的类 | 任何服务端也要用的东西 |
| `util` | 常量、`ResourceLocation` 工厂方法、数学辅助 | 有状态的逻辑 |

### 5.2 为什么 `client` 必须单独一个包

这是唯一一个「分错了会崩」的包。专用服务端（dedicated server）的 jar 里**根本没有客户端类**（`Screen`、`Minecraft`、`RenderType`）。服务端代码只要 import 了 `client` 包，启动时就会抛 `NoClassDefFoundError`——是**加载类的时候**就崩，不是运行到那一行才崩。

把客户端代码集中在 `client` 包，你只要养成一个习惯：**看到 import 里有 `com.dafeiyu.client.` 就警觉这段代码是不是只能跑在客户端**。

「物理侧」「逻辑侧」「`Dist`」的完整解释在 [侧：客户端与服务端](../03-核心概念篇/03-侧-客户端与服务端.md)，现在记住结论：**客户端专属的东西全丢进 `client` 包。**

### 5.3 类名后缀约定

统一用后缀让文件名自己说话：`DaFishItem`、`FishTankBlock`、`FishTankBlockEntity`、`FishTankMenu`、`FishTankScreen`；注册类统一 `Mod` 开头（`ModItems`、`ModBlocks`），数据生成器统一 `Mod` + 类型 + `Provider`。本教程全程遵循这套约定。

```gradle
plugins {
    id 'java-library'
    id 'eclipse'
    id 'idea'
    id 'maven-publish'
    id 'net.neoforged.moddev' version '2.0.78'
}

version = mod_version

repositories {
    mavenLocal()
}

base {
    archivesName = mod_id
}

java.toolchain.languageVersion = JavaLanguageVersion.of(21)

neoForge {
    version = project.neo_version

    runs {
        client {
            client()
            systemProperty 'neoforge.enabledGameTestNamespaces', project.mod_id
        }
        server {
            server()
            programArgument '--nogui'
        }
    }

    mods {
        "${mod_id}" {
            sourceSet(sourceSets.main)
        }
    }
}

tasks.withType(ProcessResources).configureEach {
    var replaceProperties = [
            minecraft_version      : minecraft_version,
            minecraft_version_range: minecraft_version_range,
            neo_version            : neo_version,
            neo_version_range      : neo_version_range,
            loader_version_range   : loader_version_range,
            mod_id                 : mod_id,
            mod_name               : mod_name,
            mod_license            : mod_license,
            mod_version            : mod_version,
            mod_authors            : mod_authors,
            mod_description        : mod_description
    ]
    inputs.properties replaceProperties
    filesMatching(['META-INF/neoforge.mods.toml']) {
        expand replaceProperties
    }
}
```

## 常见坑与报错

| 现象 | 原因 | 解决 |
|---|---|---|
| 改了 `neoforge.mods.toml` 里的 `displayName`，游戏里没变 | 那一行是 `${mod_name}` 占位符，会被 `expand` 覆盖 | 去 `gradle.properties` 改 `mod_name`；或者删掉占位符直接写死 |
| 报 `Unknown mod loader javafml ` 或 `Missing modLoader` | `modLoader` 拼错或删了 | 必须是 `modLoader = "javafml"`，注意引号 |
| 报 `Mod file ... requires loader version [5,)` | `loaderVersion` 写错 | 1.21.x 固定 `"[4,)"` |
| 报 `requires neoforge [21.2.0,)` 之类 | `neo_version_range` 和实际 NeoForge 版本不符 | 检查 `neo_version` 和范围是否自相矛盾 |
| 版本范围写成 `[1.21.1-1.22]`，解析失败 | 区间必须用逗号 | 改成 `[1.21.1,1.22)` |
| `mod_id` 里带了大写或横杠，启动报 `Invalid mod id` | modId 只能小写字母、数字、下划线 | 改成 `dafeiyu` 这类形式，并同步改包名、`@Mod`、资源目录名 |
| 物品显示成紫黑格子 | 资源路径的命名空间不是 modid，或目录名写错 | 确认是 `assets/dafeiyu/textures/item/xxx.png` |
| 配方不生效，但没有任何报错 | 1.21 起 `recipes/` 改成了 `recipe/` | 目录改成单数 |
| 改了 `runs { }` 但 IDEA 里运行配置没变 | 没重新同步 Gradle | `Reload Gradle Project` |
| 服务端启动报 `NoClassDefFoundError: net/minecraft/client/...` | 服务端代码里引用了 `client` 包 | 把那段代码挪进 `client` 包，或加侧判断 |
| `No matching toolchains found for ... 21` | Gradle 找不到 JDK 21，foojay 又下不下来 | 检查 `JAVA_HOME` 和 IDEA 的 `Gradle JVM`，别指望自动下载 |

## 练习

1. **改一遍全套信息**：把 `mod_authors` 改成你的名字，`mod_description` 改成两行（用 `'''` 多行写法），`mod_version` 改成 `0.2.0`。重新运行，在 Mods 列表里确认三处都变了。
2. **读懂一个真实文件**：随便下载一个模组 jar，用解压软件打开，找到 `META-INF/neoforge.mods.toml` 和本教程这份对比：它的 `modId` 是什么？依赖了哪些模组？`versionRange` 怎么写的？这一步能让你对「模组是怎么被识别的」有很直观的认识。
3. **规划你的目录**：假设你要做一个「会钓鱼的方块」，写下它需要哪几个文件、各自放在哪个路径（Java 类、纹理、模型、方块状态、语言、配方、战利品表），写完对照第六节的速查表检查有没有漏。
