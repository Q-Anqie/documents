# 创建并运行第一个模组

> 读完这一篇，你会看着自己写的模组出现在游戏的 Mods 列表里，并且知道刚才那一行 `LOGGER.info` 是怎么跑到日志里的。

## 学习目标

- 画出工程的目录结构，说清 `src/main/java`、`src/main/resources`、`build.gradle`、`gradle.properties` 各自管什么
- 逐行读懂主类 `DafeiyuMod`，包括 `@Mod("dafeiyu")` 和构造方法里的 `IEventBus` 参数
- 用 `gradlew runClient` 启动游戏，进入主菜单，在 Mods 列表里找到自己的模组
- 改一次模组名和版本，重新运行看到变化
- 用 `gradlew build` 产出 jar，丢进正式游戏的 `mods` 文件夹验证

## 一、先认识这个工程

上一篇生成的工程，打开后大概是这样。这份树状图建议你对照 IDEA 的 `Project` 面板看一遍，把每个位置和屏幕上的东西对上：

```text
dafeiyu/
├── build.gradle                 ← 构建脚本：依赖、任务、运行配置
├── settings.gradle              ← 工程名 + 插件仓库地址
├── gradle.properties            ← 模组 id/名字/版本等，改得最多的文件
├── gradlew                      ← macOS/Linux/Git Bash 启动脚本
├── gradlew.bat                  ← Windows 启动脚本
├── gradle/
│   └── wrapper/
│       ├── gradle-wrapper.jar
│       └── gradle-wrapper.properties    ← 锁定 Gradle 版本
├── src/
│   └── main/
│       ├── java/
│       │   └── com/dafeiyu/
│       │       └── DafeiyuMod.java      ← 主类，程序入口
│       └── resources/
│           ├── META-INF/
│           │   └── neoforge.mods.toml   ← 模组「名片」，游戏靠它认识你
│           └── pack.mcmeta              ← 资源包/数据包的版本声明
├── runs/                        ← 运行游戏时自动生成（有些模板叫 run/）
│   ├── client/
│   │   ├── logs/latest.log      ← 你的日志在这里
│   │   └── crash-reports/
│   └── server/
└── build/                       ← 构建产物，自动生成
    └── libs/
        └── dafeiyu-1.0.0.jar
```

最需要先建立的一个概念是：**`java` 目录放代码，`resources` 目录放素材和配置**。

- `src/main/java` 下面按包名分层，`com/dafeiyu/DafeiyuMod.java` 对应的就是 `package com.dafeiyu;`。**目录结构和 `package` 声明必须严格一致**，差一个字母都会编译失败。
- `src/main/resources` 下面的东西会被**原样打包进 jar**。`META-INF/neoforge.mods.toml` 是给加载器看的，`assets/`、`data/` 是给游戏看的（第 3 篇细讲）。
- `runs/` 和 `build/` 是**生成物**，不要手动改，也不要提交到 Git。`runs/client` 相当于一个独立的 `.minecraft` 目录，里面有自己的 `logs`、`saves`、`config`。

`runs` 这个名字在不同模板里可能是单数 `run`。打开你的工程看一眼，哪个存在就用哪个，后面所有路径按实际的来。

## 二、逐行读懂主类

打开 `src/main/java/com/dafeiyu/DafeiyuMod.java`。生成器给的版本可能比我这里多一些内容（比如配置注册、`commonSetup` 监听），我们先把骨架看清楚：

文件：`src/main/java/com/dafeiyu/DafeiyuMod.java`

```java
package com.dafeiyu;

import com.mojang.logging.LogUtils;
import net.neoforged.bus.api.IEventBus;
import net.neoforged.fml.ModContainer;
import net.neoforged.fml.common.Mod;
import org.slf4j.Logger;

@Mod(DafeiyuMod.MODID)
public class DafeiyuMod {
    // 模组 ID，必须和 gradle.properties 里的 mod_id、neoforge.mods.toml 里的 modId 一致
    public static final String MODID = "dafeiyu";

    // 日志工具，等价于一个「带级别的 System.out.println」
    private static final Logger LOGGER = LogUtils.getLogger();

    public DafeiyuMod(IEventBus modEventBus, ModContainer modContainer) {
        LOGGER.info("大肥鱼模组加载成功");
    }
}
```

### 2.1 `package com.dafeiyu;`

第一行声明这个类属于哪个包。包名要和目录对得上：文件在 `src/main/java/com/dafeiyu/` 下，包名就是 `com.dafeiyu`。

为什么要有包？因为全世界的模组作者可能都写一个叫 `Utils` 的类。有了包，`com.dafeiyu.Utils` 和 `com.other.Utils` 就是两个不同的东西，不会打架。这也是为什么你的顶层包要用一个「你拥有的」名字（`com.dafeiyu`），而不是 `com.example` 或 `test`——万一别人也用了 `com.example`，两个模组同时装就会崩。

### 2.2 `import` 那几行

`import` 是「我要用这个类，告诉我它在哪」。四个来自 NeoForge / Minecraft 的包，值得单独认一下：

| 包名前缀 | 是什么 |
|---|---|
| `com.mojang.logging` | Mojang 提供的日志工具，`LogUtils.getLogger()` 给你一个 logger |
| `net.neoforged.bus.api` | 事件总线（event bus），`IEventBus` 在这里 |
| `net.neoforged.fml` | 模组加载器本体，`ModContainer`、`@Mod` 都在这 |
| `org.slf4j` | Java 生态通用的日志门面，`Logger` 是它的接口 |

你暂时不用背这些，IDEA 会自动帮你 import。但要记住一个判断方法：**看到 `net.neoforged.` 开头，就是 NeoForge 提供的；看到 `net.minecraft.` 开头，就是原版 Minecraft 的**。这个区分以后查文档很有用。

### 2.3 `@Mod(DafeiyuMod.MODID)`

这是整个模组最关键的一行。

`@Mod` 是一个**注解（annotation）**，不是注释。注释是写给人看的，编译器直接忽略；注解是写给**框架**看的，NeoForge 会在启动时扫描所有类，找出带 `@Mod` 的那个，然后调用它的构造方法。

换句话说：**没有 `@Mod`，你的类就只是一段没人调用的普通 Java 代码，游戏永远不会理它。** 这就是「入口点（entry point）」的含义。

括号里的 `DafeiyuMod.MODID` 是 `"dafeiyu"` 这个字符串的另一种写法。为什么不直接写 `@Mod("dafeiyu")`？因为同一个字符串要在三个地方出现：`gradle.properties` 的 `mod_id`、`neoforge.mods.toml` 的 `modId`、这里的注解。写成一个常量，至少在自己代码里只改一处。

注解本身是什么、为什么能这样用，在 [注解：@ 开头的那些标签](../02-Java补充篇/04-注解-@开头的那些标签.md) 里有专门讲解，现在你只需要知道：**它是给框架看的标记，值必须和 `neoforge.mods.toml` 里的 modId 一致**。不一致的后果很直接——游戏报「找不到 modId 为 xxx 的入口点」，模组直接加载失败。

### 2.4 `MODID` 和 `LOGGER` 两个静态字段

```java
public static final String MODID = "dafeiyu";
private static final Logger LOGGER = LogUtils.getLogger();
```

`public static final` 意思是「公开的、属于类而不是某个对象的、不可修改的」。所以别的地方可以写 `DafeiyuMod.MODID` 直接拿到这个字符串。

`LOGGER` 为什么不用 `System.out.println`？三个原因：

1. **有级别**。`info`、`warn`、`error`、`debug` 分开，出问题时可以只看 `error`。
2. **带来源**。日志里会自动标出是哪个类打的，模组装多了也能分清是谁在说话。
3. **性能**。`System.out` 是同步阻塞的，高频调用会拖慢游戏；logger 有缓冲和异步处理。

现在养成习惯：**调试信息用 `LOGGER.info`，不要用 `System.out.println`**。后面所有章节的示例都遵循这一点。

### 2.5 构造方法

```java
public DafeiyuMod(IEventBus modEventBus, ModContainer modContainer) {
    LOGGER.info("大肥鱼模组加载成功");
}
```

几个第一次看会疑惑的点：

**为什么没有 `new DafeiyuMod(...)`？** 因为不是你创建的，是 NeoForge 创建的。它在扫描到 `@Mod` 之后，用反射找到这个唯一的 public 构造方法，把参数准备好，然后 `new` 出来。你只要把「启动时要做的事」写进构造方法体就行。

**为什么参数是这两个？** NeoForge 允许构造方法接受下面这几种参数，**顺序任意、可以只要其中几个、但不能重复**：

| 参数类型 | 给你什么 |
|---|---|
| `IEventBus` | 模组专属的事件总线，注册物品/方块、监听启动事件都要用它 |
| `ModContainer` | 你这个模组的元数据容器（版本、id、配置文件等） |
| `FMLModContainer` | 上面那个的具体实现，一般用不到 |
| `Dist` | 当前运行在哪一侧（客户端还是专用服务端） |

所以下面这几种写法都是合法的：

```java
public DafeiyuMod(IEventBus modEventBus) { }
public DafeiyuMod(ModContainer container, IEventBus bus) { }
public DafeiyuMod() { }
```

但**只能有一个 public 构造方法**，写两个会直接抛 `RuntimeException` 启动失败。

**`modEventBus` 到底是什么？** 这是本篇最重要的伏笔。简单说：NeoForge 有两条「广播频道」，`modEventBus` 是其中专门给你这个模组用的那条。你要注册一个物品、要在启动时做点初始化，都得通过它「报名」。后面写第一行注册代码时你会反复用到它。

两条总线的分工、`addListener` 和 `@SubscribeEvent` 的区别、为什么挂错总线会「静默失败」，全部在 [事件系统](../03-核心概念篇/02-事件系统.md) 里讲。现在你只要记住一句话：**这个参数别删，后面全靠它。**

## 三、第一次运行

### 3.1 两种启动方式

命令行（在工程根目录）：

```bash
gradlew runClient
```

macOS / Linux / Git Bash：

```bash
./gradlew runClient
```

或者在 IDEA 里：右侧 `Gradle` 面板 → `Tasks` → `neoforge runs` → 双击 `runClient`。IDEA 还会自动生成一个同名的运行配置，右上角的下拉框里能直接选。

两种方式等价。命令行能看到更完整的输出，出问题时推荐用命令行；日常开发用 IDEA 的绿色三角更顺手。

### 3.2 启动过程中发生了什么

第一次 `runClient` 比后面慢很多，因为它还要下载游戏资源。整个过程大致分六段，你可以对着控制台输出看：

1. **Gradle 准备**（几秒到几分钟）：检查依赖是否齐全。第一次会下载 1.21.1 的客户端 jar 和几百 MB 的 `assets`（音效、语言文件、贴图），下载到 `~/.gradle/caches/` 里。
2. **拼装运行环境**（几十秒）：把 Minecraft、NeoForge、你的代码组装成一个能跑的环境，生成 `runs/client` 目录。
3. **启动 JVM**：控制台开始出现 Minecraft 的日志，第一行通常是 `ModLauncher running: args [...]`。
4. **扫描模组**：NeoForge 读所有 `neoforge.mods.toml`，找到 `@Mod` 类，**调用你的构造方法**——这时候你那行 `LOGGER.info("大肥鱼模组加载成功")` 就会打出来。
5. **注册与加载资源**：注册表填充、模型和纹理加载、语言文件读取。
6. **进主菜单**：出现那个熟悉的背景和 `Singleplayer` / `Multiplayer` 按钮。

第 4 步的日志大概长这样，注意时间戳和 `[main/INFO]` 这些前缀：

```text
[01:23:45] [main/INFO] [dafeiyu/]: 大肥鱼模组加载成功
```

`[dafeiyu/]` 这个标记就是你的 modid，说明这条日志确实来自你的模组，不是别人的。

### 3.3 开发环境和正式游戏的区别

`runClient` 启动的是一个**开发用客户端**：

- 它用的是离线账号（名字通常叫 `Dev`），所以**不能进服务器**，只能玩单人；
- 它的 `.minecraft` 目录是 `runs/client`，和你平时玩的不是同一个，存档、配置都不共享；
- 它加载的是 `src/main/java` 里的**源码**，你改完代码重启就生效，不需要 build。

这三点都很重要。尤其第一点：很多人第一次 `runClient` 后想连朋友的服务器，发现连不上，以为是模组问题，其实是离线账号。

## 四、验证模组真的加载了

### 4.1 在 Mods 列表里找自己

进主菜单后：

1. 点 `Mods`（中文界面是「模组」）；
2. 在左上角的搜索框里输入 `dafeiyu`；
3. 左边列表里应该出现一项，右边显示名称、版本、作者、描述。

看到它就成功了一半。如果列表是空的，先别急着改代码，去第六节看「Mods 列表里没有」那一条——八成是 `neoforge.mods.toml` 和 `@Mod` 的 modId 不一致。

注意：这时显示的名字取决于你生成时填的 `Mod Name`。如果你填的是 `Dafeiyu Mod`，看到的就是英文；填了中文就是「大肥鱼模组」。下一节我们统一改成中文。

### 4.2 在日志里找到自己写的话

Mods 列表能证明「模组被加载了」，但证明不了「你的代码被执行了」。要验证这一点，看日志。

日志位置：

```text
runs/client/logs/latest.log
```

用 IDEA 直接打开这个文件，`Ctrl + F` 搜 `大肥鱼`。你应该能找到刚才那一行。如果搜不到，检查两件事：

- 你的 `LOGGER.info` 是不是写在构造方法里（写到别的方法里、而那个方法没被调用，就不会打）；
- 是不是看错了日志文件（`latest.log` 是本次的，`debug.log` 更详细，`2026-10-31-1.log.gz` 是历史归档）。

顺手把这条日志当成一个「探针」：以后每次改完代码不确定有没有生效，就在构造方法里加一行日志，重启看有没有打出来。这是最便宜的验证手段。

### 4.3 让名字变成中文

打开 `gradle.properties`，找到这几行：

```properties
mod_name=Dafeiyu Mod
mod_version=1.0.0
```

改成：

```properties
mod_name=大肥鱼模组
mod_version=1.0.0
```

保存，回到 IDEA 点右上角的大象图标（`Reload Gradle Project`），或者命令行执行：

```bash
gradlew --refresh-dependencies
```

然后重新 `runClient`，进 Mods 列表，名字应该变成「大肥鱼模组」了。

**如果显示成乱码或问号**，说明编码有问题。原因和处理办法在第六节「中文显示乱码」那一条，先记着这个现象。

### 4.4 改版本号

`mod_version` 就是 Mods 列表里显示的版本。改成 `1.0.1` 再跑一次，列表里会跟着变。这个值同时决定了 `gradlew build` 产出的 jar 文件名（`dafeiyu-1.0.1.jar`），所以发布前一定要改。

## 五、打包成能发给别人的 jar

### 5.1 `gradlew build`

```bash
gradlew build
```

它会做三件事：编译、跑检查、打包。第一次可能要一两分钟。成功后去：

```text
build/libs/
├── dafeiyu-1.0.0.jar
└── dafeiyu-1.0.0-sources.jar
```

`-sources.jar` 是源码包，给别人看代码用的，**不要**放进 `mods` 文件夹。你要的是那个不带后缀的 `dafeiyu-1.0.0.jar`。

### 5.2 丢进正式游戏测试

1. 准备一个装了 **NeoForge 21.1.x for 1.21.1** 的正式 Minecraft 环境（用官方启动器或第三方启动器装 Forge/NeoForge 都行）；
2. 打开 `.minecraft/mods/` 文件夹（没有就新建）；
3. 把 `dafeiyu-1.0.0.jar` 复制进去；
4. 启动游戏，进 Mods 列表，应该能看到「大肥鱼模组」。

这一步和 `runClient` 的差别在于：这次加载的是**编译好的 jar**，不是源码。它能验证「打包有没有漏文件」——比如资源路径写错、`neoforge.mods.toml` 没被打进去，在开发环境里可能看不出来，打包后就暴露了。

**版本必须严格对齐**：1.21.1 的模组放进 1.21.4 的游戏，会在启动时报 `Mod dafeiyu requires minecraft [1.21.1,1.22), which is missing`。这不是 bug，是 `neoforge.mods.toml` 里声明的版本范围在起作用（第 3 篇会讲怎么改）。

## 完整示例

### 完整的主类

文件：`src/main/java/com/dafeiyu/DafeiyuMod.java`

```java
package com.dafeiyu;

import com.mojang.logging.LogUtils;
import net.neoforged.bus.api.IEventBus;
import net.neoforged.fml.ModContainer;
import net.neoforged.fml.common.Mod;
import org.slf4j.Logger;

// 入口点：NeoForge 扫描到这个注解才会加载本类
@Mod(DafeiyuMod.MODID)
public class DafeiyuMod {
    // 全局唯一的模组 ID，和 gradle.properties、neoforge.mods.toml 三处保持一致
    public static final String MODID = "dafeiyu";

    // 本模组专用日志器，日志里会带上 [dafeiyu/] 前缀
    private static final Logger LOGGER = LogUtils.getLogger();

    public DafeiyuMod(IEventBus modEventBus, ModContainer modContainer) {
        // 这行会在游戏启动、模组被构造时打印，用来确认代码真的跑了
        LOGGER.info("大肥鱼模组加载成功");
    }
}
```

### 对应的 `gradle.properties` 片段

文件：`gradle.properties`

```properties
mod_id=dafeiyu
mod_name=大肥鱼模组
mod_version=1.0.0
mod_group_id=com.dafeiyu
```

### 命令清单

```bash

gradlew runClient

# 启动开发客户端（macOS / Linux / Git Bash）
./gradlew runClient

# 只编译，不启动，用来快速检查语法错误
gradlew compileJava

# 打包
gradlew build

# 强制重新解析依赖（改了 gradle.properties 后可以用）
gradlew --refresh-dependencies
```

### 验证清单

```text
[ ] runClient 能进主菜单
[ ] Mods 列表里能搜到 dafeiyu，名字显示为「大肥鱼模组」
[ ] runs/client/logs/latest.log 里能搜到「大肥鱼模组加载成功」
[ ] 改 mod_version 为 1.0.1 后，Mods 列表里版本跟着变
[ ] build/libs/dafeiyu-1.0.1.jar 存在
[ ] 把 jar 放进正式游戏 mods 文件夹后能启动，Mods 列表能看到
```

## 常见坑与报错

| 现象 | 原因 | 解决 |
|---|---|---|
| `runClient` 一启动就崩，控制台刷一大片红字 | 代码或配置有错，游戏直接退出 | 先看 `runs/client/logs/latest.log` 的**最后 50 行**，找第一个 `Caused by:`；再往上找第一处出现 `com.dafeiyu` 的地方 |
| 报 `Missing or unsupported mandatory dependencies` | `neoforge.mods.toml` 里的依赖版本范围和当前 NeoForge 不匹配 | 检查 `neo_version_range`；或把 NeoForge 升到范围内 |
| 报 `Mod dafeiyu requires minecraft [1.21.1,1.22), which is missing` | 游戏版本和模组声明的范围不符 | 换对应版本的 Minecraft，或改 `minecraft_version_range` |
| Mods 列表里搜不到自己的模组 | ① `@Mod` 的值和 `mods.toml` 的 `modId` 不一致；② 主类不在 `mods.toml` 声明的包里；③ 改了代码没重新 build | 三处 modId 对齐；确认包名；重新 `build` 后再测 |
| 模组加载了，但构造方法里的日志没打出来 | 日志写在了没被调用的方法里；或看错了日志文件 | 挪进构造方法；确认看的是 `latest.log` |
| 中文显示成 `????` 或乱码方块 | 文件编码不是 UTF-8，或控制台编码不是 UTF-8 | 见下一条 |
| 游戏内中文乱码 | 语言文件/`gradle.properties` 保存成了 GBK | IDEA `File → File Properties → File Encoding` 选 UTF-8；`Settings → Editor → File Encodings` 全部设 UTF-8 |
| 控制台中文乱码（游戏内正常） | Windows 控制台默认 GBK，JVM 输出 UTF-8 时对不上 | `gradle.properties` 加 `org.gradle.jvmargs=-Xmx3G -Dfile.encoding=UTF-8`；或 IDEA 设置里把控制台编码改 UTF-8 |
| `runClient` 卡在 `Downloading assets` 很久 | 首次要下几百 MB 资源 | 等；或配代理；别 Cancel |
| 改了 `gradle.properties` 但游戏里没变 | 没重新同步/没重新构建 | `Reload Gradle Project`，然后重新 `runClient` |
| `build` 成功但 jar 放进 mods 没反应 | 放的是 `-sources.jar`；或正式环境没装 NeoForge | 用不带后缀的 jar；确认启动器选的是 NeoForge 配置 |
| 启动时报 `UnsupportedClassVersionError` | 运行用的 JDK 不是 21 | 检查 IDEA 的 `Gradle JVM` 和 `JAVA_HOME` |

### 崩溃了怎么读日志

这是新手最需要练的一项技能，给一个固定套路：

```text
1. 打开 runs/client/logs/latest.log
2. 直接跳到文件末尾（Ctrl + End）
3. 从下往上找第一个 "Caused by:"        ← 这是根因
4. 再往上找第一个包含 "com.dafeiyu" 的行  ← 这是你代码出错的位置
5. 看这一行前面几行的类名和方法名        ← 这是出错的动作
```

举个例子，日志末尾是：

```text
java.lang.NullPointerException: Cannot invoke "net.minecraft.world.item.ItemStack.getItem()" because "stack" is null
    at com.dafeiyu.DafeiyuMod.<init>(DafeiyuMod.java:18) ~[dafeiyu-1.0.0.jar:?]
    ...
Caused by: java.lang.NullPointerException: ...
```

第 3 步找到 `NullPointerException`，第 4 步定位到 `DafeiyuMod.java:18`——第 18 行有个 `stack` 是 null。这就够你改了。

不要从日志第一行开始读。前面几百行都是正常的加载信息，读完只会更慌。完整的读日志方法在 [调试与游戏测试](../06-进阶篇/09-调试与游戏测试.md)。

## 练习

1. **加一条自己的日志**：在构造方法里再加一行 `LOGGER.info("当前模组 ID 是 {}", MODID);`，重新运行，在 `latest.log` 里找到它。注意 `{}` 是占位符，会被后面的参数替换——这是 SLF4J 的写法，比字符串拼接快。
2. **改到崩溃再修好**：把 `@Mod(DafeiyuMod.MODID)` 改成 `@Mod("dafeiyu_wrong")`，重新运行，观察崩溃日志里说了什么，然后把 `neoforge.mods.toml` 里的 `modId` 也改成 `dafeiyu_wrong`，看是否能启动。这个练习的目的是让你亲手制造一次「modId 不一致」，以后一眼就能认出来。
3. **完整走一遍发布流程**：把 `mod_version` 改成 `0.1.0`，`gradlew build`，把产出的 jar 放进正式游戏的 `mods` 文件夹，进游戏确认 Mods 列表里版本是 `0.1.0`。这一步做完，你就已经具备「做出一个能发给朋友玩的模组」的完整能力了。
