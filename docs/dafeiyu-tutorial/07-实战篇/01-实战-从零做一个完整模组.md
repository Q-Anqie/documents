# 实战：从零做一个完整模组

> 这一篇不再教新 API。它是一张施工图：把前面七章学到的东西按正确顺序拼成一个能发布的小模组——「大肥鱼模组」。照着做一遍，你就有了自己的第一个完整项目。

## 学习目标

- 能独立搭出一个多包结构的 NeoForge 项目，并说清每个包放什么。
- 能按「方块 → 物品 → 方块实体 → 数据」的依赖顺序推进，而不是想到哪写到哪。
- 能做出一个带世界生成、材料制品、功能方块、进度和配置的完整闭环。
- 能给出每一阶段的验证动作，做到「每步都能进游戏确认」，而不是最后一起 debug。
- 能判断一份数据该放方块实体、数据组件还是数据附件。

## 一、先看全貌：这个模组到底有什么

先把成品列清楚。**动手之前先能一句话说出你要做什么**，否则写到一半一定跑偏。

| 模块 | 具体内容 | 依赖的前置知识 |
|---|---|---|
| 矿物 | 红宝石矿、深板岩红宝石矿，主世界生成 | [世界生成](../06-进阶篇/06-世界生成.md) |
| 材料 | 红宝石、红宝石块 | [制作你的第一个物品](../04-内容制作篇/01-制作你的第一个物品.md) |
| 装备 | 红宝石剑、红宝石镐、红宝石四件套盔甲 | [工具与盔甲](../04-内容制作篇/05-工具与盔甲.md) |
| 功能方块 | 红宝石充能台（方块实体 + GUI + 存数据 + 同步） | [方块实体](../04-内容制作篇/03-方块实体.md)、[菜单与容器界面](../06-进阶篇/01-菜单与容器界面.md) |
| 状态效果 | 红宝石之力（攻击力小幅提升） | [食物与状态效果](../04-内容制作篇/06-食物与状态效果.md) |
| 进度 | 「第一次获得红宝石」 | [进度](../05-资源与数据篇/09-进度.md) |
| 数据 | 模型、语言、配方、战利品表、标签、进度全用 datagen | [数据生成](../05-资源与数据篇/05-数据生成.md) |
| 配置 | 矿脉大小、掉落加成、充能台上限 | [调试与游戏测试](../06-进阶篇/09-调试与游戏测试.md) |

然后是路线图。这张图是这一篇的骨架，**不要跳阶段**：

```text
阶段 0  建项目        → 主类能加载，空模组出现在模组列表
阶段 1  矿物          → 世界里能挖到红宝石矿，掉红宝石
阶段 2  材料与装备    → 红宝石能合成块、剑、镐、盔甲，能穿上
阶段 3  功能方块      → 右键打开 GUI，能放东西、能充能、数字会同步
阶段 4  数据与打磨    → 进度、状态效果、配置、语言、音效全就位
阶段 5  自测          → 干净环境 + 专用服务器 + 多人 全过
```

为什么是这个顺序？因为依赖是单向的：物品要引用方块（方块物品），配方要引用物品，战利品表要引用方块和物品，进度要引用物品。**从被依赖的一方开始写，永远不用回头改。**

## 二、阶段 0：把项目立起来

### 要新建的文件

```text
gradle.properties
src/main/java/com/dafeiyu/DafeiyuMod.java
src/main/java/com/dafeiyu/DafeiyuConfig.java
src/main/resources/META-INF/neoforge.mods.toml
src/main/resources/assets/dafeiyu/icon.png          # 模组列表里的小图标
src/main/resources/pack.mcmeta                       # MDK 自带，确认存在
```

### 先把三个名字定死

`gradle.properties` 里的这几个值会被 Gradle 内联进 `neoforge.mods.toml`，**改一处、处处生效**：

```properties
# gradle.properties
mod_id=dafeiyu
mod_name=大肥鱼模组
mod_license=MIT
mod_version=1.0.0
mod_group_id=com.dafeiyu
mod_authors=大肥鱼
mod_description=一个用来学 NeoForge 的示例模组：红宝石、充能台和一条完整的进度线。

minecraft_version=1.21.1
neo_version=21.1.80
```

> `mod_id` 只能用小写字母、数字、下划线，长度 2~64。它同时是你的注册表命名空间、资源包命名空间、数据包命名空间——**写错一次，后面所有 `ResourceLocation` 全错**。

### 主类：注册的唯一入口

文件：`src/main/java/com/dafeiyu/DafeiyuMod.java`

```java
package com.dafeiyu;

import com.dafeiyu.worldgen.ModFeatures;
import net.neoforged.bus.api.IEventBus;
import net.neoforged.fml.ModContainer;
import net.neoforged.fml.common.Mod;
import net.neoforged.fml.config.ModConfig;

@Mod(DafeiyuMod.MOD_ID)
public class DafeiyuMod {

    public static final String MOD_ID = "dafeiyu";

    // 构造器参数由 NeoForge 注入，顺序无所谓，但不能重复
    public DafeiyuMod(IEventBus modBus, ModContainer container) {
        // 每个注册类只暴露一个 register(IEventBus)，主类只负责把它们串起来
        ModBlocks.register(modBus);
        ModItems.register(modBus);
        ModBlockEntities.register(modBus);
        ModMenus.register(modBus);
        ModEffects.register(modBus);
        ModCreativeTabs.register(modBus);
        ModFeatures.FEATURES.register(modBus);

        container.registerConfig(ModConfig.Type.COMMON, DafeiyuConfig.SPEC);
    }
}
```

这段代码里唯一值得强调的设计是：**主类不写业务，只写装配**。等你的模组长到 30 个类，你会庆幸当初没把注册全塞在这里。

### 包结构

```text
com.dafeiyu
├── DafeiyuMod.java            主类
├── DafeiyuConfig.java         配置
├── ModBlocks.java             方块注册
├── ModItems.java              物品注册
├── ModBlockEntities.java      方块实体注册
├── ModMenus.java              菜单注册

├── menu/                      RubyChargerMenu
├── effect/                    RubyPowerEffect
```

`client` 包单独拎出来不是洁癖，是硬要求：服务端加载到 `net.minecraft.client.*` 会直接 `NoClassDefFoundError` 崩服。判据很简单——**这个文件 import 里出现 `net.minecraft.client` 或 `com.mojang.blaze3d`，它就属于 `client` 包。**

### 验证

```bash

```

进游戏 → 模组列表 → 找到「大肥鱼模组」，图标、描述、版本号都对。此时世界里什么都没有，这是正常的。**这一步没过就别往下走**，因为后面所有报错都会混着环境问题一起出现。

### 方块本身

```java
// src/main/java/com/dafeiyu/block/RubyOreBlock.java
package com.dafeiyu.block;

import net.minecraft.util.valueproviders.UniformInt;
import net.minecraft.world.level.block.DropExperienceBlock;
import net.minecraft.world.level.block.SoundType;
import net.minecraft.world.level.block.state.BlockBehaviour;
import net.minecraft.world.level.material.MapColor;

public class RubyOreBlock extends DropExperienceBlock {

    public RubyOreBlock() {
        super(UniformInt.of(2, 5), BlockBehaviour.Properties.of()
                .mapColor(MapColor.STONE)
                .strength(3.0F, 3.0F)          // 硬度、抗爆
                .requiresCorrectToolForDrops() // 不用镐挖不掉
                .sound(SoundType.STONE));
    }
}
```

`DropExperienceBlock` 是原版现成的类：挖掉时按 `UniformInt` 给经验。**能继承就继承，别自己重写 `playerDestroy`**——重写版本要处理「精准采集不掉经验」「创造模式不掉落」这些细节，很容易漏。

注册时把两个矿都放进去：

```java
// src/main/java/com/dafeiyu/ModBlocks.java（片段）
public static final DeferredBlock<Block> RUBY_ORE = BLOCKS.register("ruby_ore", RubyOreBlock::new);
public static final DeferredBlock<Block> DEEPSLATE_RUBY_ORE =
        BLOCKS.register("deepslate_ruby_ore", RubyOreBlock::new);
public static final DeferredBlock<Block> RUBY_BLOCK = BLOCKS.register("ruby_block",
        () -> new Block(BlockBehaviour.Properties.of()
                .mapColor(MapColor.COLOR_RED)
                .strength(5.0F, 6.0F)
                .requiresCorrectToolForDrops()
                .sound(SoundType.METAL)));
```

### 三个 json

内容在 [世界生成](../06-进阶篇/06-世界生成.md) 里已经给全了，这里只说该盯住的三点：

1. `configured_feature/ruby_ore.json` 的 `targets` 里写两条：石头里放 `dafeiyu:ruby_ore`，深板岩里放 `dafeiyu:deepslate_ruby_ore`。
2. `placed_feature/ruby_ore.json` 的 `count` 就是「生成率」——红宝石定位比钻石常见一点，写 `6` 比较合适。
3. `biome_modifier/add_ruby_ore.json` 的 `phase` 必须是 `underground_ores`，且 `biomes` 用 `#minecraft:is_overworld` 标签而不是手写群系列表。

### 验证

进游戏（**新建世界**，旧世界不会重新生成已加载的区块），然后：

```text
/place feature dafeiyu:ruby_ore ~ ~ ~
```

脚下冒出一团红宝石矿 → json 全对。没反应 → 问题在 json 本身，跟 biome modifier 无关。

再挖一块：掉落 1 个红宝石、冒出经验球。此时红宝石还没有物品形态，掉落表会先给你一个「缺失物品」的紫黑方块——**这说明战利品表还没做，正常**，阶段 4 补。

## 四、阶段 2：材料与装备

### 要新建的文件

```text
src/main/java/com/dafeiyu/ModItems.java
src/main/java/com/dafeiyu/ModToolTiers.java
src/main/java/com/dafeiyu/ModArmorMaterials.java
src/main/java/com/dafeiyu/ModCreativeTabs.java
```

### 顺序：先 Tier，再 ArmorMaterial，最后 Items

`Tier`（工具等级）不需要注册，`ArmorMaterial` 需要注册，两者都必须在 `ModItems` 之前定义好——因为 `ModItems` 的静态字段会在类加载时 `new SwordItem(tier, ...)`，而 `tier` 是个 `static final`。

```java
// src/main/java/com/dafeiyu/ModToolTiers.java（片段）
public static final Tier RUBY = new SimpleTier(
        BlockTags.INCORRECT_FOR_IRON_TOOL,  // 挖不动的方块标签
        1200,                                // 耐久
        8.0F,                                // 挖掘速度
        3.0F,                                // 攻击伤害加成
        22,                                  // 附魔能力
        () -> Ingredient.of(ModItems.RUBY.get())  // 修复材料，延迟取值
);
```

注意最后一个参数是 `Supplier` 而不是 `Ingredient`：`ModItems.RUBY` 此刻可能还没初始化完，直接取会拿到 `null`。**这是注册类互相引用的标准解法——用 Lambda 把取值推迟到真正需要的时候。**

盔甲材料用 `ArmorMaterial` 的 record 构造器，七个参数（各部位护甲值、附魔能力、穿戴音效、修复材料、纹理层、韧性、击退抗性），完整写法见 [工具与盔甲](../04-内容制作篇/05-工具与盔甲.md)。

### 物品注册

```java
// src/main/java/com/dafeiyu/ModItems.java（片段）
public static final DeferredRegister.Items ITEMS = DeferredRegister.createItems(DafeiyuMod.MOD_ID);

public static final DeferredItem<Item> RUBY = ITEMS.registerSimpleItem("ruby");

// 方块物品：名字要和方块一致，否则模型会找不到
public static final DeferredItem<BlockItem> RUBY_BLOCK_ITEM =
        ITEMS.registerSimpleBlockItem("ruby_block", ModBlocks.RUBY_BLOCK);
public static final DeferredItem<BlockItem> RUBY_ORE_ITEM =
        ITEMS.registerSimpleBlockItem("ruby_ore", ModBlocks.RUBY_ORE);

public static final DeferredItem<SwordItem> RUBY_SWORD = ITEMS.register("ruby_sword",
        () -> new SwordItem(ModToolTiers.RUBY,
                new Item.Properties().attributes(
                        SwordItem.createAttributes(ModToolTiers.RUBY, 3, -2.4F))));

public static final DeferredItem<PickaxeItem> RUBY_PICKAXE = ITEMS.register("ruby_pickaxe",
        () -> new PickaxeItem(ModToolTiers.RUBY,
                new Item.Properties().attributes(
                        PickaxeItem.createAttributes(ModToolTiers.RUBY, 1, -2.8F))));
```

1.21 的工具构造器是 `(Tier, Properties)` 两参数版本，属性通过 `createAttributes` 塞进 `Item.Properties`。网上 1.20 的 `new SwordItem(tier, 3, -2.4f, props)` 已经删了，照抄会编译不过。

盔甲四件套的写法是 `new ArmorItem(ModArmorMaterials.RUBY, ArmorItem.Type.HELMET, new Item.Properties().durability(...))`，四件只差 `Type` 和耐久倍数。

### 创造模式标签页

```java
// src/main/java/com/dafeiyu/ModCreativeTabs.java（片段）
public static final DeferredHolder<CreativeModeTab, CreativeModeTab> MAIN =
        TABS.register("main", () -> CreativeModeTab.builder()
                .title(Component.translatable("itemGroup.dafeiyu.main"))
                .icon(() -> new ItemStack(ModItems.RUBY.get()))
                .displayItems((params, output) -> {
                    output.accept(ModItems.RUBY.get());
                    output.accept(ModBlocks.RUBY_ORE.get());
                    output.accept(ModBlocks.DEEPSLATE_RUBY_ORE.get());
                    output.accept(ModBlocks.RUBY_BLOCK.get());
                    output.accept(ModItems.RUBY_SWORD.get());
                    output.accept(ModItems.RUBY_PICKAXE.get());
                    output.accept(ModItems.RUBY_HELMET.get());
                    output.accept(ModItems.RUBY_CHESTPLATE.get());
                    output.accept(ModItems.RUBY_LEGGINGS.get());
                    output.accept(ModItems.RUBY_BOOTS.get());
                })
                .build());
```

`output.accept(...)` 里传 `Block` 会自动包成 `BlockItem`，不用手动 `new ItemStack`。

## 五、阶段 3：红宝石充能台

这是整个项目里唯一有状态的部分，也是唯一需要想清楚「数据放哪」的部分。

### 先做决策：数据放哪

| 方案 | 适合什么 | 不适合什么 |
|---|---|---|
| 方块实体字段 | 位置绑定的状态：机器进度、能量、库存 | 跟着物品走的数据 |
| 数据组件（DataComponent） | 跟着 `ItemStack` 走的数据：充能次数、自定义名字 | 方块的状态 |
| 数据附件（Attachment） | 挂在实体/区块/世界上、跨方块存在的数据 | 单个方块的状态 |
| 存档数据（SavedData） | 全局单例：全服统计、玩家解锁列表 | 高频读写的小数据 |

充能台是「放在地上的机器」→ **方块实体**。充能台上的物品「带着充能值被拿走」→ 那个值应该是**数据组件**，不是方块实体字段。分清这一点，你就不会写出「把物品拿出来充能值就丢了」的 bug。

### 方块：只管「开门」

```java
// src/main/java/com/dafeiyu/block/RubyChargerBlock.java（片段）
public class RubyChargerBlock extends BaseEntityBlock {

    @Override
    protected MapCodec<? extends BaseEntityBlock> codec() {
        return simpleCodec(RubyChargerBlock::new);
    }

    @Override
    public BlockEntity newBlockEntity(BlockPos pos, BlockState state) {
        return new RubyChargerBlockEntity(pos, state);
    }

    @Override
    public InteractionResult useWithoutItem(BlockState state, Level level, BlockPos pos,
                                            Player player, BlockHitResult hit) {
        if (!level.isClientSide && level.getBlockEntity(pos) instanceof RubyChargerBlockEntity be) {
            // 打开 GUI 必须由服务端发起，客户端只是被动接收
            player.openMenu(be, pos);
        }
        return InteractionResult.sidedSuccess(level.isClientSide);
    }

    @Override
    public RenderShape getRenderShape(BlockState state) {
        return RenderShape.MODEL;   // 用普通方块模型，不写 BER
    }
}
```

`useWithoutItem` 是 1.21 的签名（旧的 `use` 仍然存在但接收 `ItemStack`，空手右键走的是 `useWithoutItem`）。写错了的表现是「拿着东西能开、空手打不开」。

### 方块实体：状态 + 保存 + 同步

```java
// src/main/java/com/dafeiyu/blockentity/RubyChargerBlockEntity.java（骨架）
public class RubyChargerBlockEntity extends BlockEntity implements MenuProvider {

    private int charge;                     // 0 ~ 上限，来自配置
    private final ItemStackHandler inventory = new ItemStackHandler(1) {
        @Override
        protected void onContentsChanged(int slot) {
            setChanged();                   // 内容变了才标脏，不要每 tick 调
        }
    };

    public RubyChargerBlockEntity(BlockPos pos, BlockState state) {
        super(ModBlockEntities.RUBY_CHARGER.get(), pos, state);
    }

    public static void tick(Level level, BlockPos pos, BlockState state, RubyChargerBlockEntity be) {
        if (level.isClientSide) return;      // 只有服务端算，客户端等同步
        if (be.charge >= DafeiyuConfig.CHARGER_CAPACITY.get()) return;
        be.charge++;
        be.setChanged();
        if (be.charge % 20 == 0) {           // 每秒同步一次，而不是每 tick
            level.sendBlockUpdated(pos, state, state, Block.UPDATE_CLIENTS);
        }
    }

    // 区块保存 / 客户端首次加载时用
    @Override
    protected void saveAdditional(CompoundTag tag, HolderLookup.Provider registries) {
        super.saveAdditional(tag, registries);
        tag.putInt("charge", charge);
        tag.put("inventory", inventory.serializeNBT(registries));
    }

    @Override
    protected void loadAdditional(CompoundTag tag, HolderLookup.Provider registries) {
        super.loadAdditional(tag, registries);
        charge = tag.getInt("charge");
        inventory.deserializeNBT(registries, tag.getCompound("inventory"));
    }

    // 客户端第一次看到这个方块时拿到的全量数据
    @Override
    public CompoundTag getUpdateTag(HolderLookup.Provider registries) {
        CompoundTag tag = new CompoundTag();
        saveAdditional(tag, registries);
        return tag;
    }

    @Override
    public Component getDisplayName() {
        return Component.translatable("block.dafeiyu.ruby_charger");
    }

    @Override
    public AbstractContainerMenu createMenu(int id, Inventory playerInv, Player player) {
        // 第三个参数是 ContainerData：服务端给真实值
        return new RubyChargerMenu(id, playerInv, this, new SimpleContainerData(1));
    }
}
```

三个 `setChanged()` 的时机值得单独记住：**内容变了才调**。它的作用是「告诉存档这个区块需要重写」，每 tick 都调等于每 tick 都标记整个区块脏，存档时会明显卡。

### 菜单：数字同步的通道

```java
// src/main/java/com/dafeiyu/menu/RubyChargerMenu.java（骨架）
public class RubyChargerMenu extends AbstractContainerMenu {

    private final ContainerData data;

    // 服务端用的构造器
    public RubyChargerMenu(int id, Inventory playerInv, RubyChargerBlockEntity be, ContainerData data) {
        super(ModMenus.RUBY_CHARGER.get(), id);
        this.data = data;
        this.addSlot(new SlotItemHandler(be.getInventory(), 0, 80, 35));
        addPlayerInventory(playerInv);
        checkContainerDataCount(data, 1);   // 数量对不上会在这里立刻炸，比默默显示 0 好
        addDataSlots(data);
    }

    // 客户端用的构造器：ContainerData 必须是同样长度的空壳
    public RubyChargerMenu(int id, Inventory playerInv) {
        this(id, playerInv, null, new SimpleContainerData(1));
    }

    public int getCharge() {
        return data.get(0);
    }

    @Override
    public boolean stillValid(Player player) {
        return true;
    }
}
```

`ContainerData` 只支持 `int`，而且**服务端每 tick 全量推送一次**。所以它适合「一个进度条」，不适合「一整个物品栏」——物品栏的同步由 `AbstractContainerMenu` 的槽位机制自动完成。

### 网络：什么时候真的需要自己发包

充能台这个例子其实**不需要自定义包**：

- 方块实体的 `charge` → `getUpdateTag` + `sendBlockUpdated` 已经同步了。
- GUI 里的进度条 → `ContainerData` 已经同步了。
- 玩家点按钮「开始充能」→ 这个意图需要发包。

只有第三类要自己写。骨架长这样，细节见 [网络通信](../06-进阶篇/05-网络通信.md)：

```java
// src/main/java/com/dafeiyu/network/StartChargingPayload.java（片段）
public record StartChargingPayload(BlockPos pos) implements CustomPacketPayload {
    public static final Type<StartChargingPayload> TYPE =
            new Type<>(ResourceLocation.fromNamespaceAndPath(DafeiyuMod.MOD_ID, "start_charging"));
    // BlockPos 有现成的 STREAM_CODEC，直接用
    public static final StreamCodec<ByteBuf, StartChargingPayload> STREAM_CODEC =
            BlockPos.STREAM_CODEC.map(StartChargingPayload::new, StartChargingPayload::pos);
    // ...
}
```

服务端收到后必须校验 `pos` 距离玩家不超过 8 格、且该位置真的是充能台——**永远不要相信客户端发来的坐标**。

### 六个 Provider 各管什么

| Provider | 产出 | 少了会怎样 |
|---|---|---|
| `BlockStateProvider` | `blockstates/*.json`、`models/block/*.json` | 方块是紫黑格子 |
| `ItemModelProvider` | `models/item/*.json` | 物品是紫黑格子 |
| `LanguageProvider` | `lang/zh_cn.json`、`lang/en_us.json` | 显示 `item.dafeiyu.ruby` |
| `RecipeProvider` | `recipe/*.json` | 合成表里查不到 |
| `LootTableProvider` | `loot_table/blocks/*.json` | 挖了什么都不掉 |
| 标签 Provider | `tags/block/*.json`、`tags/item/*.json` | 镐挖不动、进不了 `mineable` 标签 |

战利品表这一项最容易漏，因为它「不影响方块存在」，只影响掉落。矿石用现成方法：

```java
// src/main/java/com/dafeiyu/datagen/ModLootTableProvider.java（片段）
@Override
protected void generate() {
    dropSelf(ModBlocks.RUBY_BLOCK.get());
    add(ModBlocks.RUBY_ORE.get(), createOreDrop(ModBlocks.RUBY_ORE.get(), ModItems.RUBY.get()));
    add(ModBlocks.DEEPSLATE_RUBY_ORE.get(),
            createOreDrop(ModBlocks.DEEPSLATE_RUBY_ORE.get(), ModItems.RUBY.get()));
}
```

`createOreDrop` 会自动带上「精准采集掉方块本身、否则掉物品、时运影响数量」三个标准行为，比手写 json 可靠得多。

### 进度：第一次获得红宝石

用 NeoForge 的 `AdvancementProvider`（不是原版那个同名类），根进度建标签页、子进度挂 `InventoryChangeTrigger`：

```java
// src/main/java/com/dafeiyu/datagen/ModAdvancementProvider.java（片段）
Advancement.Builder.advancement()
        .parent(root)
        .display(new ItemStack(ModItems.RUBY.get()),
                Component.translatable("advancement.dafeiyu.got_ruby.title"),
                Component.translatable("advancement.dafeiyu.got_ruby.description"),
                null, AdvancementType.TASK, true, true, false)
        .addCriterion("has_ruby",
                InventoryChangeTrigger.TriggerInstance.hasItems(ModItems.RUBY.get()))
        .rewards(AdvancementRewards.Builder.experience(10))
        .save(saver, ResourceLocation.fromNamespaceAndPath(DafeiyuMod.MOD_ID, "got_ruby"),
                existingFileHelper);
```

**为什么要 `parent(root)` 传变量而不是手拼字符串？** 因为根进度的 id 是 `dafeiyu:root`，拼错了不会报错，只会得到一个「孤立的进度」——它永远不显示。传变量，编译器帮你查。

### 状态效果：红宝石之力

附魔和状态效果二选一。附魔要写 json + 效果组件，链更长；状态效果一个类就能跑通，更适合收口。选它。

```java
// src/main/java/com/dafeiyu/effect/RubyPowerEffect.java
package com.dafeiyu.effect;

import net.minecraft.world.effect.MobEffect;
import net.minecraft.world.effect.MobEffectCategory;
import net.minecraft.world.entity.LivingEntity;
import net.minecraft.world.entity.ai.attributes.Attributes;

public class RubyPowerEffect extends MobEffect {

    public RubyPowerEffect() {
        super(MobEffectCategory.BENEFICIAL, 0xE0115F);   // 第二个参数是粒子颜色
    }

    // 1.21 起这个方法返回 boolean：true 表示"这一 tick 要生效"
    @Override
    public boolean applyEffectTick(LivingEntity entity, int amplifier) {
        return true;
    }

    private static final ResourceLocation MODIFIER_ID =
            ResourceLocation.fromNamespaceAndPath("dafeiyu", "ruby_power");

    @Override
    public void onEffectStarted(LivingEntity entity, int amplifier) {
        // 1.21 的属性修改器要带唯一 id，用 ResourceLocation 区分来源
        entity.getAttribute(Attributes.ATTACK_DAMAGE).addTransientModifier(
                new AttributeModifier(MODIFIER_ID, 0.5 * (amplifier + 1),
                        AttributeModifier.Operation.ADD_VALUE));
    }

    @Override
    public void onEffectRemoved(LivingEntity entity, int amplifier) {
        // 必须按同一个 id 移除，否则效果结束后加成会永久留下
        entity.getAttribute(Attributes.ATTACK_DAMAGE).removeModifier(MODIFIER_ID);
    }
}
```

注册就一行 `EFFECTS.register("ruby_power", RubyPowerEffect::new)`。想让它能拿到，最简单的做法是给红宝石剑加个右键给自身效果的逻辑，或者写一瓶药水——两种都在 [食物与状态效果](../04-内容制作篇/06-食物与状态效果.md) 里。

> 如果你选附魔：`data/dafeiyu/enchantment/ruby_harvest.json` 加一个 `minecraft:post_attack` 效果组件即可，不必注册任何类。见 [附魔与数据映射](../06-进阶篇/07-附魔与数据映射.md)。

### 配置：哪些能进，哪些不能

```java
// src/main/java/com/dafeiyu/DafeiyuConfig.java（片段）
public static final ModConfigSpec.IntValue RUBY_ORE_VEIN_SIZE;
public static final ModConfigSpec.IntValue CHARGER_CAPACITY;
public static final ModConfigSpec.DoubleValue RUBY_EXTRA_DROP_CHANCE;

static {
    ModConfigSpec.Builder builder = new ModConfigSpec.Builder();

    RUBY_ORE_VEIN_SIZE = builder
            .comment("一条红宝石矿脉最多几个方块（需要重进世界生效）")
            .defineInRange("ruby_ore_vein_size", 9, 1, 32);

    CHARGER_CAPACITY = builder
            .comment("充能台的能量上限")
            .defineInRange("charger_capacity", 100, 10, 10000);

    RUBY_EXTRA_DROP_CHANCE = builder
            .comment("挖掘红宝石矿额外掉一个的概率，0 表示关闭")
            .defineInRange("ruby_extra_drop_chance", 0.15D, 0.0D, 1.0D);

    SPEC = builder.build();
}
```

这里有一个**必须讲清楚的边界**：`placed_feature` 的 `count`（每个区块试几次）是**数据包内容**，配置改不了它。想让玩家调「生成率」，只有两条路：

1. 自己写一个 `Feature`，在 `place()` 里读 `RUBY_ORE_VEIN_SIZE`，用这个值决定撒几个方块；
2. 让玩家装数据包覆盖 `placed_feature`。

第一种的骨架：

```java
// src/main/java/com/dafeiyu/worldgen/RubyOreFeature.java（骨架）
public class RubyOreFeature extends Feature<OreConfiguration> {

    public RubyOreFeature() {
        super(OreConfiguration.CODEC);
    }

    @Override
    public boolean place(FeaturePlaceContext<OreConfiguration> context) {
        // 用配置里的值覆盖 json 里的 size
        int size = DafeiyuConfig.RUBY_ORE_VEIN_SIZE.get();
        RandomSource random = context.random();
        BlockPos origin = context.origin();
        boolean placed = false;
        for (int i = 0; i < size; i++) {
            BlockPos pos = origin.offset(random.nextInt(3) - 1, random.nextInt(3) - 1,
                    random.nextInt(3) - 1);
            if (context.level().getBlockState(pos).is(BlockTags.STONE_ORE_REPLACEABLES)) {
                context.level().setBlock(pos, ModBlocks.RUBY_ORE.get().defaultBlockState(), 2);
                placed = true;
            }
        }
        return placed;
    }
}
```

**但要诚实地说：这个写法比原版 `minecraft:ore` 差**——它撒出来是立方体团块，不是椭圆矿脉，也不会自动处理深板岩。所以真实项目里的取舍是：**默认用原版 `minecraft:ore`，只有玩家真的需要调参时才换成自定义 Feature**。配置不是越多越好，能不改代码解决的问题就别加代码。

## 七、阶段 5：自测

自测不是「再玩一遍」，是按清单逐项确认。少一项，发布后就会有人来报。

| 关卡 | 怎么做 | 查什么 |
|---|---|---|
| 干净环境 | 新建 `.minecraft` 或换游戏目录，只装 NeoForge + 你的 jar | 有没有漏打包的资源 |
| 生存流程 | 新世界生存模式，从木头做到红宝石镐 | 配方、掉落、进度是否串得起来 |
| 专用服务器 | `runServer`，客户端连 `localhost` | 有没有客户端类泄漏到服务端 |
| 多人 | 两个客户端同时进 | 充能台的数据是否只对一个人可见 |
| 退出重进 | 放东西、退出、重进 | `saveAdditional` / `loadAdditional` 是否对称 |
| 极端分辨率 | GUI 缩放调到「大」和「自动」 | Screen 有没有超出边界 |
| 破坏方块 | 带内容物敲掉充能台 | 物品是否掉落（`getDrops` 或 `playerWillDestroy`） |

专用服务器那关尤其重要，因为它会暴露 `client` 包混进服务端的问题——这类 bug 在单人游戏里永远不会出现。

如果想把「挖矿掉红宝石」变成自动检查，用 GameTest 写一条，写法见 [调试与游戏测试](../06-进阶篇/09-调试与游戏测试.md)。

## 常见坑与报错

| 现象 | 原因 | 解决 |
|---|---|---|
| 启动崩 `Mod id 'dafeiyu' ... already occupied` | `neoforge.mods.toml` 里的 `modId` 和 `@Mod` 的值不一致，或和别的模组撞名 | 两处都改成同一个 id |
| 方块物品放下去变回空气 | 只注册了 `Block` 没注册 `BlockItem` | 补 `registerSimpleBlockItem` |
| 挖矿不掉东西 | 没有 `loot_table/blocks/xxx.json`，或文件名和方块 id 不一致 | 跑 `runData`，检查路径 |
| 挖了掉紫黑方块 | 掉落表引用了还没注册的物品 id | 检查 `ModItems` 里的名字拼写 |
| 方块是紫黑格子但物品正常 | `blockstates/xxx.json` 缺失或 `variants` 的 key 写成了 `"normal"` | datagen 用 `simpleBlockWithItem` 生成 |
| 物品名显示 `item.dafeiyu.ruby` | 语言文件没生成，或 key 拼错 | 检查 `lang/zh_cn.json` 里的 key 是否带 `item.` 前缀 |
| 盔甲穿上隐身 | 纹理路径不是 `textures/models/armor/xxx_layer_1.png` | 按原版命名规则放 |
| GUI 打开是空的/立刻关闭 | `MenuType` 的构造器在客户端拿到了 `null` 方块实体 | 客户端构造器要能独立工作 |
| 进度不显示 | 子进度的 `parent` 拼错，成了孤立节点 | 用变量传 `AdvancementHolder` |
| 专用服务器崩 `NoClassDefFoundError: net/minecraft/client/...` | `client` 包被服务端加载 | 客户端类加 `value = Dist.CLIENT`，且不要从公共代码直接引用 |
| 改了配置没反应 | 配置项在启动时读进了 `static final` | 用 `.get()` 现读，不要缓存到静态字段 |
| 矿只在新区块出现 | 世界生成不回溯 | 新建世界测试 |

## 练习

1. **（易）** 给红宝石块加一个「信标底座」用法：在 `ModBlocks` 里用 `.isBeaconBase()`（`BlockBehaviour.Properties` 没有这个方法，需要事件或 Mixin——想想有没有更简单的路子，比如给方块加 `minecraft:beacon_base_blocks` 标签）。先试着用标签实现，再对比 [标签](../05-资源与数据篇/08-标签.md)。
2. **（中）** 让充能台支持「放入红宝石 → 充能值 +10 / 秒，充满后自动弹出物品」。要求：`ContainerData` 只用来显示，物品进出全部走 `ItemStackHandler`，并保证敲掉方块时里面的东西会掉出来。
3. **（难）** 把「红宝石之力」改成附魔：`ruby_harvest` 在击杀生物时按等级额外掉红宝石。要求用数据映射挂到原版 `minecraft:post_attack` 上，不新增任何 Java 注册，只写 json + 一个自定义效果组件。
