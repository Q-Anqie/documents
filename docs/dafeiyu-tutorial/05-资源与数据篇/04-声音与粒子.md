# 声音与粒子

> 读完这篇，你的方块被右键时会响一声自定义音效、脚下转一圈红色光点，而且你知道为什么「代码写了但游戏里没声音」和「粒子只在单人游戏能看到」这两个经典问题是怎么来的。

## 学习目标

- 能说清声音事件、声音类别、声音定义、声音文件四个概念，并知道它们各自放在哪。
- 能用 `DeferredRegister<SoundEvent>` 注册一个声音，并写出配套的 `sounds.json`。
- 能解释 `level.playSound` 五个参数的含义，尤其是音量和可听距离的关系。
- 能注册一个 `SimpleParticleType`，配上客户端 `ParticleProvider` 和粒子描述 json。
- 能写出「服务端播放声音 + 服务端发粒子」的正确写法，并说清为什么反过来会失效。

## 一、声音的四个概念，别混

Minecraft 的声音系统被拆成了四层，新手最容易在这四层之间错位：

```text
① SoundEvent（声音事件）
     代码里的一个注册对象，id 是 dafeiyu:ruby_chime
     ↓ 通过 sounds.json 映射
② 声音定义（sound definition）
     "ruby_chime" → [一组声音对象]
     ↓ 每个声音对象指向
③ 声音文件（sound file）
     assets/dafeiyu/sounds/ruby_chime.ogg
     ↓ 播放时归入
④ 声音类别（sound source）
     SoundSource.BLOCKS / PLAYERS / AMBIENT …
     决定它受设置里哪个音量滑块控制
```

四个概念各自的文件位置：

| 概念 | 在哪 |
|---|---|
| `SoundEvent` 注册 | Java 代码，`ModSounds` 类 |
| 声音定义 | `assets/dafeiyu/sounds.json`（**命名空间根目录**） |
| 声音文件 | `assets/dafeiyu/sounds/xxx.ogg` |
| 声音类别 | 代码里传参，不需要文件 |

**`sounds.json` 不在 `sounds/` 文件夹里。** 这一条我单独强调，因为它是「我明明放了音效但没声音」的第一大原因。`sounds/` 是装音频的抽屉，`sounds.json` 是抽屉上的标签，标签贴在抽屉外面。

还有一条硬限制：**只支持 `.ogg` 格式**。MP3、WAV、M4A 一律不认，而且不会报错，只是没声音。

## 二、注册 `SoundEvent`

`SoundEvent` 是注册表对象，用 `DeferredRegister` 注册，跟物品方块一个套路。

文件：`src/main/java/com/dafeiyu/ModSounds.java`

```java
package com.dafeiyu;

import net.minecraft.core.registries.BuiltInRegistries;
import net.minecraft.resources.ResourceLocation;
import net.minecraft.sounds.SoundEvent;
import net.neoforged.bus.api.IEventBus;
import net.neoforged.neoforge.registries.DeferredHolder;
import net.neoforged.neoforge.registries.DeferredRegister;

public class ModSounds {
    public static final DeferredRegister<SoundEvent> SOUND_EVENTS =
            DeferredRegister.create(BuiltInRegistries.SOUND_EVENT, DafeiyuMod.MOD_ID);

    // 可变距离声音：会随距离衰减，绝大多数声音都用这个
    public static final DeferredHolder<SoundEvent, SoundEvent> RUBY_CHIME = SOUND_EVENTS.register(
            "ruby_chime",
            () -> SoundEvent.createVariableRangeEvent(
                    ResourceLocation.fromNamespaceAndPath(DafeiyuMod.MOD_ID, "ruby_chime")));

    // 固定距离声音：不衰减，适合 UI 音效、音乐
    public static final DeferredHolder<SoundEvent, SoundEvent> RUBY_CLICK = SOUND_EVENTS.register(
            "ruby_click",
            () -> SoundEvent.createFixedRangeEvent(
                    ResourceLocation.fromNamespaceAndPath(DafeiyuMod.MOD_ID, "ruby_click"), 16));

    public static void register(IEventBus modEventBus) {
        SOUND_EVENTS.register(modEventBus);
    }
}
```

三个必须注意的点：

1. **注册名和 `ResourceLocation` 的路径必须一模一样。** 上面两处都是 `"ruby_chime"`。写成 `"rubyChime"` 一处、`"ruby_chime"` 另一处，游戏启动时不一定报错，但声音永远找不到定义。
2. **`createVariableRangeEvent` 是默认选择。** 它的可听距离由「播放时的音量 × 声音定义里的 `attenuation_distance`」决定。
3. **`createFixedRangeEvent` 的可听距离写死。** 那个 `16` 是方块数，而且受 OpenAL 限制，**写超过 16 也没用，会被截到 16**。

然后在主类里注册：

```java
public DafeiyuMod(IEventBus modEventBus, ModContainer modContainer) {
    ModBlocks.register(modEventBus);
    ModItems.register(modEventBus);
    ModSounds.register(modEventBus);   // 加这一行
}
```

## 三、`sounds.json` 结构

文件：`src/main/resources/assets/dafeiyu/sounds.json`

```json
{
  "ruby_chime": {
    "subtitle": "subtitles.dafeiyu.ruby_chime",
    "sounds": [
      {
        "name": "dafeiyu:ruby_chime",
        "volume": 0.8,
        "pitch": 1.0,
        "weight": 1,
        "attenuation_distance": 16
      },
      "dafeiyu:ruby_chime_alt"
    ]
  },
  "ruby_click": {
    "sounds": [
      "dafeiyu:ui/ruby_click"
    ]
  }
}
```

结构拆解：

**顶层键是声音事件的路径**（不含命名空间，因为命名空间由文件位置决定）。所以 `"ruby_chime"` 对应 `dafeiyu:ruby_chime`。

**`subtitle`** 是无障碍字幕的翻译键。玩家在「声音字幕」选项里会看到这行文字。键名习惯写 `subtitles.<ns>.<path>`，但技术上任意字符串都行——它就是一个普通的翻译键，记得在语言文件里给它一条翻译。

**`sounds`** 是一个数组。**数组里有多个元素时，游戏会按 `weight` 随机挑一个播放。** 这是做出「同一个动作每次听起来略有不同」的关键：录 3 个略有差异的挖掘音，放进同一个数组，玩家就听不出重复感。

**`name`** 是音频文件路径，**相对于 `sounds/` 文件夹**，不带 `.ogg`。所以：

| `name` | 实际文件 |
|---|---|
| `dafeiyu:ruby_chime` | `assets/dafeiyu/sounds/ruby_chime.ogg` |
| `dafeiyu:block/ruby_break` | `assets/dafeiyu/sounds/block/ruby_break.ogg` |
| `dafeiyu:ui/ruby_click` | `assets/dafeiyu/sounds/ui/ruby_click.ogg` |

**单个声音对象的可选字段**：

| 字段 | 范围 | 默认 | 作用 |
|---|---|---|---|
| `volume` | 0.0 ~ 1.0 | 1.0 | 这个文件本身的音量，会乘到播放音量上 |
| `pitch` | 0.0 ~ 2.0 | 1.0 | 音调。0.5 低八度，2.0 高八度 |
| `weight` | 正整数 | 1 | 被随机选中的权重 |
| `stream` | bool | false | 从磁盘流式读取，适合超过几秒的长音效/音乐 |
| `attenuation_distance` | 数字 | 16 | 衰减距离（方块）。固定距离事件忽略此项 |
| `preload` | bool | false | 资源包加载时就载入内存，而不是播放时才读 |
| `type` | `"file"` / `"event"` | `"file"` | `"event"` 表示 `name` 指向另一个声音事件（做音效别名用） |

数组元素也可以直接写字符串 `"dafeiyu:ruby_chime_alt"`，等价于 `{"name": "dafeiyu:ruby_chime_alt"}`。

**关于 `replace`**：`sounds.json` 和别的资源文件不一样，它**是合并的，不是覆盖的**。多个资源包里的 `sounds.json` 会被合到一起。如果你想「干掉下面所有包对这个事件的贡献，只留我的」，在事件对象里写 `"replace": true`。做材质包/音效包时才需要，做模组基本不用。

## 四、播放声音：`level.playSound` 的五个参数

最常用的重载：

```java
level.playSound(Player player, BlockPos pos, SoundEvent sound,
                SoundSource source, float volume, float pitch);
```

| 参数 | 含义 | 怎么填 |
|---|---|---|
| `player` | 要「排除」的玩家 | 一般填 `null`，表示播给所有人 |
| `pos` | 声音位置 | 方块用 `pos`，实体会自动用自身位置 |
| `sound` | 声音事件 | `ModSounds.RUBY_CHIME.get()` |
| `source` | 声音类别 | `SoundSource.BLOCKS` / `PLAYERS` / `AMBIENT` / `MASTER` |
| `volume` | 音量 | `1.0F` 是标准 |
| `pitch` | 音调 | `1.0F` 是原调，`0.8F`~`1.2F` 做随机变化 |

### `player` 参数为什么要填 `null`

这个参数的设计目的很微妙。看它的服务端行为：

> 向**除了传入的这个玩家之外**的所有玩家发送播放包。

为什么排除？因为调用方通常就是那个玩家自己，而客户端已经本地播放过一次了，再收一次包就会**听到两遍**（叠音，听起来像回声）。

所以规则是：

- 你在**服务端**发起的代码里调用（方块实体、方块交互、命令）→ 传 `null`，播给所有人，包括发起者。
- 你在**客户端**发起的代码里调用 → 传 `player`，避免自己听到两遍。

新手写方块交互时，交互方法会在**两侧都执行**，如果你不判断侧就直接调，客户端播一次、服务端又发一次包，玩家会听到「咔咔」两声。正确做法见第七节。

### `volume` 到底控制什么

这是最容易被误解的参数。`volume` 不只是「响度」，它还控制**可听半径**：

```text
可听半径 ≈ volume × attenuation_distance
```

`attenuation_distance` 默认 16，所以 `volume = 1.0` 的声音在 16 格内能听到，`volume = 2.0` 能传到 32 格，`volume = 0.5` 只有 8 格。

而 `volume = 0` 是**完全静音**——不是「很小声」，是根本不播。很多人调试时随手写 `0.0F`，然后以为代码没生效，找了半小时。

`volume` 还受设置里对应 `SoundSource` 滑块的**二次缩放**。所以如果玩家把「方块」音量调到 0，你的 `SoundSource.BLOCKS` 声音永远不会响，无论代码写得多对。调试时先确认音量滑块。

### `pitch` 的实用技巧

`pitch` 是频率倍数，不是「音高等级」：

| `pitch` | 效果 |
|---|---|
| 0.5 | 低一个八度，沉闷 |
| 0.8 | 略低，适合重物 |
| 1.0 | 原调 |
| 1.2 | 略高，清脆 |
| 2.0 | 高一个八度，尖锐 |

做「同一个声音每次略有不同」时，常用 `0.9F + level.random.nextFloat() * 0.2F`，得到一个 0.9~1.1 之间的随机音调。这比录十个音频文件省事得多。

## 五、服务端播放 vs 客户端播放

`Level#playSound` 在两侧的行为**完全不同**：

| | 逻辑客户端 | 逻辑服务端 |
|---|---|---|
| `playSound(player, pos, ...)` | 如果 `player` 是本地玩家，就在本地播；否则什么都不做 | 给附近所有玩家（除了 `player`）发包，让他们本地播 |
| `playLocalSound(...)` | 本地播，不发包 | 什么都不做 |

由此得出三条实战规则：

1. **想让所有人都听到 → 在服务端调 `playSound(null, ...)`。** 服务端会给范围内每个人发包。
2. **只想让当前玩家听到（UI 音效、个人提示）→ 在客户端调 `playLocalSound(...)`。**
3. **绝对不要在客户端调 `playSound(null, ...)` 期待「大家都听到」。** 客户端根本没有能力给别的玩家发包。

还有一个隐蔽的坑：**专用服务器上没有 `Minecraft` 类**。任何 `net.minecraft.client.*` 的引用都会在服务器启动时炸 `NoClassDefFoundError`。声音这块本身是安全的（`SoundEvent`、`SoundSource` 都是通用类），但粒子那块就不安全了，见下。

## 六、粒子：从注册到显示要过四关

粒子和声音一样是「注册对象 + 资源文件」的组合，但它多了一个**纯客户端**的环节：`ParticleProvider`。

```text
① ParticleType 注册（通用侧）      dafeiyu:ruby_spark
        ↓
② ParticleProvider 注册（仅客户端）  决定「怎么创建这个粒子」
        ↓
③ 粒子描述 json（资源）            assets/dafeiyu/particles/ruby_spark.json
        ↓
④ 粒子贴图（资源）                 assets/dafeiyu/textures/particle/ruby_spark_0.png
```

### ① 注册 `ParticleType`

文件：`src/main/java/com/dafeiyu/ModParticles.java`

```java
package com.dafeiyu;

import net.minecraft.core.particles.ParticleType;
import net.minecraft.core.particles.SimpleParticleType;
import net.minecraft.core.registries.BuiltInRegistries;
import net.neoforged.bus.api.IEventBus;
import net.neoforged.neoforge.registries.DeferredHolder;
import net.neoforged.neoforge.registries.DeferredRegister;

public class ModParticles {
    public static final DeferredRegister<ParticleType<?>> PARTICLE_TYPES =
            DeferredRegister.create(BuiltInRegistries.PARTICLE_TYPE, DafeiyuMod.MOD_ID);

    // false = 视频设置里把粒子调成「最少」时，这个粒子会被限制
    // 爆炸、营火烟这类「重要」粒子用 true
    public static final DeferredHolder<ParticleType<?>, SimpleParticleType> RUBY_SPARK =
            PARTICLE_TYPES.register("ruby_spark", () -> new SimpleParticleType(false));

    public static void register(IEventBus modEventBus) {
        PARTICLE_TYPES.register(modEventBus);
    }
}
```

`SimpleParticleType` 覆盖 95% 的需求：它不带任何额外数据，服务端只需要告诉客户端「在 (x,y,z) 生成一个 ruby_spark」。只有当你要传额外参数（比如粒子颜色、大小）时，才需要自定义 `ParticleType` + `ParticleOptions` + 两个 Codec。

那个 `boolean` 参数的含义：`false` 表示「当玩家把粒子效果调成『最少』时，这个粒子会被隐藏」。原版大部分粒子是 `false`；爆炸、营火烟、鱿鱼墨汁这种「有信息量」的是 `true`。

### ② 注册 `ParticleProvider`（仅客户端）

`ParticleProvider` 是纯客户端类，**绝对不能**出现在通用代码里。

文件：`src/main/java/com/dafeiyu/client/RubySparkParticle.java`

```java
package com.dafeiyu.client;

import net.minecraft.client.multiplayer.ClientLevel;
import net.minecraft.client.particle.Particle;
import net.minecraft.client.particle.ParticleProvider;
import net.minecraft.client.particle.ParticleRenderType;
import net.minecraft.client.particle.SpriteSet;
import net.minecraft.client.particle.TextureSheetParticle;
import net.minecraft.core.particles.SimpleParticleType;

public class RubySparkParticle extends TextureSheetParticle {
    private final SpriteSet sprites;

    protected RubySparkParticle(ClientLevel level, double x, double y, double z,
                                double dx, double dy, double dz, SpriteSet sprites) {
        super(level, x, y, z, dx, dy, dz);
        this.sprites = sprites;
        this.lifetime = 20 + level.random.nextInt(10); // 存活 1~1.5 秒
        this.gravity = -0.02F;                          // 负重力 = 往上飘
        this.hasPhysics = false;                        // 不撞方块
        this.quadSize = 0.12F;                          // 粒子大小
        this.setSpriteFromAge(sprites);                 // 先设一帧，防止首帧空白
    }

    @Override
    public void tick() {
        super.tick();
        this.setSpriteFromAge(this.sprites); // 按存活时间推进动画帧
    }

    @Override
    public ParticleRenderType getRenderType() {
        // 纹理有透明区域，必须用 translucent，用 opaque 会出现黑边
        return ParticleRenderType.PARTICLE_SHEET_TRANSLUCENT;
    }
}
```

文件：`src/main/java/com/dafeiyu/client/RubySparkProvider.java`

```java
package com.dafeiyu.client;

import net.minecraft.client.multiplayer.ClientLevel;
import net.minecraft.client.particle.Particle;
import net.minecraft.client.particle.ParticleProvider;
import net.minecraft.client.particle.SpriteSet;
import net.minecraft.core.particles.SimpleParticleType;

public class RubySparkProvider implements ParticleProvider<SimpleParticleType> {
    private final SpriteSet sprites;

    public RubySparkProvider(SpriteSet sprites) {
        this.sprites = sprites;
    }

    @Override
    public Particle createParticle(SimpleParticleType type, ClientLevel level,
                                   double x, double y, double z,
                                   double dx, double dy, double dz) {
        return new RubySparkParticle(level, x, y, z, dx, dy, dz, sprites);
    }
}
```

文件：`src/main/java/com/dafeiyu/client/ClientEvents.java`

```java
package com.dafeiyu.client;

import com.dafeiyu.DafeiyuMod;
import com.dafeiyu.ModParticles;
import net.neoforged.api.distmarker.Dist;
import net.neoforged.bus.api.SubscribeEvent;
import net.neoforged.fml.common.EventBusSubscriber;
import net.neoforged.neoforge.client.event.RegisterParticleProvidersEvent;

// value = Dist.CLIENT 保证这个类只在客户端加载
@EventBusSubscriber(modid = DafeiyuMod.MOD_ID, bus = EventBusSubscriber.Bus.MOD, value = Dist.CLIENT)
public class ClientEvents {
    @SubscribeEvent
    public static void registerParticleProviders(RegisterParticleProvidersEvent event) {
        event.registerSpriteSet(ModParticles.RUBY_SPARK.get(), RubySparkProvider::new);
    }
}
```

**`value = Dist.CLIENT` 是关键。** 少了它，这个类会在专用服务器上被加载，然后 `TextureSheetParticle` 找不到，服务器直接崩。

### ③ 粒子描述 json

文件：`src/main/resources/assets/dafeiyu/particles/ruby_spark.json`

```json
{
  "textures": [
    "dafeiyu:ruby_spark_0",
    "dafeiyu:ruby_spark_1",
    "dafeiyu:ruby_spark_2",
    "dafeiyu:ruby_spark_3"
  ]
}
```

路径是 `assets/dafeiyu/particles/<粒子注册名>.json`，**文件名必须等于粒子类型名**。

`textures` 里的路径**相对于 `textures/particle/`**，不带 `.png`。所以上面四个对应：

```text
assets/dafeiyu/textures/particle/ruby_spark_0.png
assets/dafeiyu/textures/particle/ruby_spark_1.png
assets/dafeiyu/textures/particle/ruby_spark_2.png
assets/dafeiyu/textures/particle/ruby_spark_3.png
```

`SpriteSet` 会按这个列表循环播放，`setSpriteFromAge` 就是按粒子存活时间选第几帧。

> **警告**：粒子描述和 `ParticleProvider` 必须严格配对。你写了 `ruby_spark.json` 但没注册 provider，或者注册了 provider 却没写 json，**游戏会直接抛异常**，不是静默失败。

## 七、生成粒子：`addParticle` 的三个坑

### 坑一：`level.addParticle` 在服务端是空操作

`Level#addParticle(ParticleOptions, x, y, z, dx, dy, dz)` 是「通用代码」的写法，但它的实现分两侧：

- 客户端：真的生成粒子。
- 服务端：**什么都不做**，方法体是空的。

所以你在方块交互里直接写 `level.addParticle(...)`，单人游戏（内置服务器 + 客户端在同一进程）里看起来能用——因为客户端那一半执行了。**一旦上专用服务器，粒子全没了。**

### 坑二：服务端要用 `sendParticles`

```java
if (level instanceof ServerLevel serverLevel) {
    serverLevel.sendParticles(
            ModParticles.RUBY_SPARK.get(),  // 粒子类型
            x, y, z,                        // 中心位置
            8,                              // 数量
            0.5, 0.5, 0.5,                  // x/y/z 方向的散布半径
            0.02                            // 速度
    );
}
```

参数含义：

| 参数 | 含义 |
|---|---|
| `type` | 粒子类型 |
| `x` `y` `z` | 生成区域的中心 |
| `count` | 生成多少个 |
| `xDist` `yDist` `zDist` | 散布范围，每个粒子在中心 ± 这个值的范围内随机 |
| `speed` | 初速度。注意它是**所有方向共用的一个标量**，不是向量 |

`sendParticles` 会给附近所有玩家发包，让各自的客户端生成粒子。这是唯一正确的「服务端发粒子」方式。

### 坑三：`addParticle` 的速度是向量

客户端 `addParticle` 的签名是：

```java
addParticle(ParticleOptions type, double x, double y, double z,
            double xSpeed, double ySpeed, double zSpeed);
```

后三个是**速度向量**，可以分别控制方向。这跟 `sendParticles` 的单个 `speed` 标量不一样，别搞混。

**通用写法**（推荐）：交互方法里先判断侧，服务端走 `sendParticles`，客户端什么都不做。这样单人和多人行为一致。

**③ 自定义方块**

文件：`src/main/java/com/dafeiyu/block/RubyBlock.java`

```java
package com.dafeiyu.block;

import com.dafeiyu.ModParticles;
import com.dafeiyu.ModSounds;
import net.minecraft.core.BlockPos;
import net.minecraft.server.level.ServerLevel;
import net.minecraft.sounds.SoundSource;
import net.minecraft.world.InteractionResult;
import net.minecraft.world.entity.player.Player;
import net.minecraft.world.level.Level;
import net.minecraft.world.level.block.Block;
import net.minecraft.world.level.block.state.BlockState;
import net.minecraft.world.phys.BlockHitResult;

public class RubyBlock extends Block {
    public RubyBlock(Properties properties) {
        super(properties);
    }

    @Override
    protected InteractionResult useWithoutItem(BlockState state, Level level, BlockPos pos,
                                              Player player, BlockHitResult hitResult) {
        // 客户端只负责摆手动画，逻辑全部留给服务端
        if (level.isClientSide) {
            return InteractionResult.SUCCESS;
        }

        // 服务端：player 传 null 表示播给所有人（含发起者）
        level.playSound(null, pos, ModSounds.RUBY_CHIME.get(),
                SoundSource.BLOCKS, 1.0F, 1.0F);

        // 服务端：发一圈粒子，半径 0.6 格，共 16 个
        if (level instanceof ServerLevel serverLevel) {
            for (int i = 0; i < 16; i++) {
                double angle = Math.PI * 2.0 * i / 16.0;
                double ox = Math.cos(angle) * 0.6;
                double oz = Math.sin(angle) * 0.6;

                serverLevel.sendParticles(
                        ModParticles.RUBY_SPARK.get(),
                        pos.getX() + 0.5 + ox,   // 方块中心 + 圆周偏移
                        pos.getY() + 0.6,        // 略高于方块底面
                        pos.getZ() + 0.5 + oz,
                        1,                        // 每个位置 1 个
                        0.0, 0.05, 0.0,           // 几乎不散布，只往上偏一点
                        0.01                      // 很小的初速度
                );
            }
        }

        return InteractionResult.CONSUME;
    }
}
```

## 常见坑与报错

| 现象 | 原因 | 解决 |
|---|---|---|
| 完全没有声音，日志也没有报错 | `sounds.json` 放进了 `sounds/` 文件夹 | 移到 `assets/dafeiyu/` 根目录 |
| 有 `Missing sound for event` 警告 | `sounds.json` 里的键和注册名不一致 | 两处都写 `ruby_chime` |
| 声音只在特定距离响一下就断 | 音频是立体声，不参与衰减 | 导出成单声道 Ogg |
| 声音完全听不到，其他声音正常 | 播放时 `volume` 写了 `0.0F` | 改 `1.0F` |
| 声音很小 | 设置里「方块」音量被调低，或 `volume` 太小 | 检查滑块；`volume` 调到 1.0 |
| 每次右键听到两声（回声） | 客户端和服务端各播了一次 | 交互方法里先 `if (level.isClientSide) return SUCCESS;` |
| 声音文件放对了但还是没声 | 文件不是 `.ogg`，或采样率异常 | 用 Audacity 导出 Ogg Vorbis 44.1kHz 单声道 |
| 启动崩溃，日志有 `NoClassDefFoundError: TextureSheetParticle` | `ClientEvents` 少了 `value = Dist.CLIENT` | 加上 `value = Dist.CLIENT` |
| 单人游戏有粒子，服务器上没有 | 用了 `level.addParticle` | 改成 `serverLevel.sendParticles` |
| 粒子是紫黑小方块 | 缺 `particles/ruby_spark.json`，或贴图路径错 | 检查文件名和 `textures/particle/` 路径 |
| 启动抛异常，提到 `sprite set` | 有 provider 没 json，或有 json 没 provider | 两边必须成对 |
| 粒子有黑边 | `ParticleRenderType` 用了 `PARTICLE_SHEET_OPAQUE` | 改用 `PARTICLE_SHEET_TRANSLUCENT` |
| 粒子一出来就消失 | `lifetime` 没设，默认 0 | 设成 20 以上 |
| 粒子完全不动 | `gravity` 和速度都是 0 | 设 `gravity` 为负值让它上浮 |
| 视频设置调成「最少」后粒子消失 | 注册时 `new SimpleParticleType(false)` | 改 `true`（如果这个粒子有信息量） |

## 练习

1. **基础**：给红宝石块加一个「放置音效」——重写 `onPlace`，播放一个 `ruby_place` 声音。注意 `onPlace` 在两侧都会调用，想想该不该判断侧。
2. **进阶**：让粒子颜色随机。提示：`SimpleParticleType` 不带数据，最省事的做法是在 `RubySparkParticle` 构造函数里用 `level.random` 给 `this.rCol` / `this.gCol` / `this.bCol` 赋值。
3. **挑战**：做一个「红宝石灯」，右键切换开关状态。开的时候循环播放一个低沉的嗡鸣（提示：用 `level.playSound` 的 `pitch` 变化 + 方块实体的 `tick`，或者用 `AmbientSoundHandler`），关的时候停掉。这个练习会逼你想清楚「声音是每 tick 播一次，还是只在状态变化时播一次」。
