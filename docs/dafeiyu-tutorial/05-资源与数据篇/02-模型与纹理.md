# 模型与纹理

> 读完这篇，你能自己写出方块和物品的模型 json，看懂 `layer0`、`parent`、`elements`、`variants` 这些词，并且在遇到紫黑方块、朝向反了、物品显示成一张大平面的时候知道改哪一行。

## 学习目标

- 能说清 `item/generated` 和 `item/handheld` 的区别，知道 `layer0` 到底指什么。
- 能用 `cube_all`、`orientable`、`cube_bottom_top`、`cube_column` 四个父模型覆盖 80% 的方块。
- 能写一个带 `elements` 的自定义形状模型，并解释 `from`、`to`、`faces`、`uv`、`cullface`。
- 能判断一个方块该用 `variants` 还是 `multipart`，并写出对应的方块状态文件。
- 能做出 16×16 的合规纹理，以及一个会动的动画纹理。

## 一、模型是一棵继承树，不是一张图

先把最容易误解的一点说清楚：**模型（model）不是纹理（texture）。**

- **纹理**是一张 PNG 图片，16×16 个像素。
- **模型**是一个 JSON，描述「用哪张图、贴在多大的长方体上、贴在哪几个面」。

一个模型可以只写一行 `parent`，把活儿全交给父模型；也可以写满 `elements`，一个像素一个像素地摆。前者是常态，后者是少数。

继承规则很简单：**父模型的属性先全部应用，然后被子模型里写了的属性覆盖。** 注意是「写了的」才覆盖——你没写的 `textures` 变量会从父模型继承下来。

这就是为什么 `{"parent": "minecraft:block/cube_all", "textures": {"all": "dafeiyu:block/ruby_block"}}` 这两行就能拼出一个完整的立方体：形状、六个面的 uv、光照、`display` 变换全都来自 `cube_all`，你只填了一个叫 `all` 的变量。

**变量（texture variable）** 这个词要记住。父模型里写的是 `"all": "#all"`，意思是「我这个面用名为 `all` 的纹理」；你在子模型里给出 `"all": "dafeiyu:block/ruby_block"`，就是给这个变量赋值。所以变量名对不上，纹理就是紫黑——因为没人给那个变量赋值。

## 二、物品模型：`item/generated` 与 `item/handheld`

物品模型只有两种常见写法，区别就一个词。

### `item/generated`：平铺的 2D 图

文件：`src/main/resources/assets/dafeiyu/models/item/ruby.json`

```json
{
  "parent": "minecraft:item/generated",
  "textures": {
    "layer0": "dafeiyu:item/ruby"
  }
}
```

`item/generated` 的意思是「把这张图当成一个 16×16 的薄片，正对着你放在物品栏里」。它的几何体是**由纹理生成的**，所以你写 `elements` 也没用，会被忽略。

**`layer0` 是什么？** 它是「图层 0」。`item/generated` 支持最多 5 层，从 `layer0` 到 `layer4`，**索引大的画在上面**。原版用这个做「药水 + 瓶身」「皮革盔甲 + 染色层」这类叠加效果：

```json
{
  "parent": "minecraft:item/generated",
  "textures": {
    "layer0": "dafeiyu:item/ruby_base",
    "layer1": "dafeiyu:item/ruby_shine"
  }
}
```

两层图会叠在一起画。`layer0` 是底，`layer1` 是上面那层带透明区域的图。只有 `item/generated` 系列支持 `layerN`，方块模型里写 `layer0` 是无效的。

### `item/handheld`：被握住的样子

```json
{
  "parent": "minecraft:item/handheld",
  "textures": {
    "layer0": "dafeiyu:item/ruby_sword"
  }
}
```

`item/handheld` 是 `item/generated` 的**子模型**，几何体完全一样，唯一的区别是它改写了 `display` 里的几个视角变换：

| 视角 | `item/generated` | `item/handheld` |
|---|---|---|
| `firstperson_righthand`（第一人称手持） | 平放，像拿着张纸 | 旋转成斜握，像握着剑柄 |
| `thirdperson_righthand`（第三人称） | 平放 | 同样斜握 |
| `gui`（物品栏） | 一样 | 一样 |

所以判断标准非常干脆：

- **工具、武器、能「握着」的东西** → `item/handheld`。剑、镐、斧、锹、锄、三叉戟、钓鱼竿。
- **其他一切**（材料、食物、药水、书、方块物品）→ `item/generated`。

用错了不会崩，只是「剑在手里像一张贴纸」，一眼就能看出不对。

### 物品模型的一个铁律

物品模型的文件路径**完全由注册名决定**，没有中间层：

```text
物品注册名 dafeiyu:ruby  →  assets/dafeiyu/models/item/ruby.json
```

文件名不能改、不能放别处。这也是为什么「我明明写了模型但没生效」——八成是文件名叫 `Ruby.json` 或者放在了 `models/block/` 下。

## 三、方块模型：先认这四个父模型

方块模型的路径是 `assets/dafeiyu/models/block/<任意名字>.json`，名字**不受注册名限制**（因为中间隔了一层方块状态文件）。但方块状态里引用的路径必须和它对上。

下面四个父模型能覆盖绝大多数需求：

| 父模型 | 纹理变量 | 用途 | 例子 |
|---|---|---|---|
| `minecraft:block/cube_all` | `all` | 六面同图 | 石头、木板、金属块 |
| `minecraft:block/cube_bottom_top` | `side`、`top`、`bottom` | 上下不同、四周相同 | 砂岩、雕纹石英、泥土+草顶 |
| `minecraft:block/cube_column` | `side`、`end` | 柱子：侧面 + 两个端面 | 原木、石英柱、紫珀柱 |
| `minecraft:block/orientable` | `side`、`front`、`top` | 有正面朝向（底下沿用侧面） | 熔炉、南瓜、工作台 |
| `minecraft:block/cross` | `cross` | 交叉的两个平面 | 花、树苗、草 |
| `minecraft:block/cube` | `down` `up` `north` `south` `east` `west` | 六面各不相同 | 草方块、雕刻过的书架 |

**`orientable` 的变量名是 `front`**，不是 `face`、不是 `north`。写错就是紫黑。它还有个变体 `orientable_with_bottom`，多一个 `bottom` 变量，用于熔炉那种底面也要单独贴图的方块。

`cross` 的几何体是两个平面各转 45 度交叉成 X 形，从上方看像个十字。所有植物都用它，注意它必须配 `"render_type": "minecraft:cutout"`，否则透明区域会变黑。

### 一个容易忽略的变量：`particle`

方块模型还应该给一个 `particle` 纹理。它决定「这个方块被破坏、被踩、掉在地上时飞出来的小碎块长什么样」。不给的话，碎块会是紫黑小方块——很多人做完了方块，破坏时冒紫粒子，就是漏了这个。

```json
{
  "parent": "minecraft:block/cube_all",
  "textures": {
    "particle": "dafeiyu:block/ruby_block",
    "all": "dafeiyu:block/ruby_block"
  }
}
```

用 `cube_all` 时游戏多数情况下会从 `all` 自动回退，但显式写上不亏。

## 四、自己搭形状：`elements`

父模型解决不了的时候（灯柱、机器外壳、台座、带凸起的装饰块），就得自己写 `elements`。

一个 `elements` 数组，每个元素是一个长方体：

```json
{
  "from": [2, 0, 2],
  "to": [14, 4, 14],
  "faces": {
    "down":  { "uv": [2, 2, 14, 14], "texture": "#base", "cullface": "down" },
    "up":    { "uv": [2, 2, 14, 14], "texture": "#base" },
    "north": { "uv": [2, 12, 14, 16], "texture": "#base" },
    "south": { "uv": [2, 12, 14, 16], "texture": "#base" },
    "west":  { "uv": [2, 12, 14, 16], "texture": "#base" },
    "east":  { "uv": [2, 12, 14, 16], "texture": "#base" }
  }
}
```

逐个字段拆开：

**`from` / `to`** 是这个长方体的两个对角，单位是 **1/16 方块**（也就是一个像素）。`[0,0,0]` 是方块的「西北下」角，`[16,16,16]` 是「东南上」角。所以 `[2,0,2]` 到 `[14,4,14]` 就是一个 12×4×12 像素、贴着地面、居中偏小的底座。

坐标轴方向记牢：**x 向东、y 向上、z 向南**。写反了模型会跑到方块外面去。

**`faces`** 最多六个键：`down`、`up`、`north`、`south`、`west`、`east`。没写的面不渲染——这是省性能的好办法，底座贴着地的那个面你永远看不到，可以不写。不过写了 `cullface` 的话更省：它告诉渲染器「这个面朝下，如果下面紧贴着完整方块，就别画了」。

**`uv`** 是 `[u1, v1, u2, v2]`，指这张纹理上从左上角 `(u1,v1)` 到右下角 `(u2,v2)` 的矩形区域，单位也是像素。`[2, 2, 14, 14]` 表示取纹理中间 12×12 的一块。**不写 `uv` 也能跑**，游戏会用默认值，但默认值往往把整张图拉满，导致纹理被拉伸变形。自己写 `elements` 时，老老实实写 `uv`。

**`texture`** 必须以 `#` 开头，指向 `textures` 里的变量名。写 `"#base"` 就是「用 `base` 这个变量指向的图」。

**`cullface`** 是可选的，值是一个方向。它的含义是「当这个方向上紧邻一个完整不透明方块时，跳过这个面」。不做这个优化，你的方块内部的面会被白白画出来，方块一多就掉帧。

**`rotation`** 可选，写在元素层级（不是面层级），用来把整个长方体绕某个轴旋转 ±22.5° 或 ±45°。做斜屋顶、倾斜的支架时用。

### 自定义模型必须加的两个东西

自己写 `elements` 的模型，**一定要 `"parent": "minecraft:block/block"`**。

原因：`block/block` 提供了 `display` 变换（物品栏里怎么摆、手上怎么握、地上怎么转）。你不继承它，模型在物品栏里会以原始尺寸、原始角度出现——表现就是「物品栏里的方块巨大无比，或者角度歪得离谱」。这就是「物品显示成大方块」最常见的原因。

同时 `textures` 里要给 `particle`，理由同上。

## 五、方块状态文件：`variants` 还是 `multipart`

方块状态文件是**方块和模型之间的桥**。它回答一个问题：「这个方块的某个状态，该用哪个模型？」

每个方块**有且只有一个**方块状态文件，路径固定 `assets/dafeiyu/blockstates/<注册名>.json`。两种写法互斥，不能混用。

### `variants`：状态 → 模型，一对一

绝大多数方块用它。键是**方块状态字符串**（属性名=值，逗号分隔，不含方块名），值是模型对象。

没有属性的方块，键就是空字符串：

```json
{
  "variants": {
    "": { "model": "dafeiyu:block/ruby_block" }
  }
}
```

有朝向的方块（比如熔炉类），四个朝向各一个键：

```json
{
  "variants": {
    "facing=north": { "model": "dafeiyu:block/ruby_furnace" },
    "facing=east":  { "model": "dafeiyu:block/ruby_furnace", "y": 90 },
    "facing=south": { "model": "dafeiyu:block/ruby_furnace", "y": 180 },
    "facing=west":  { "model": "dafeiyu:block/ruby_furnace", "y": 270 }
  }
}
```

`y` 是绕竖直轴旋转，只能是 90 的倍数。`x` 是绕水平轴旋转（做上下颠倒的模型）。`uvlock` 为 `true` 时，旋转后纹理不跟着转——贴图有方向性时（比如带文字的牌子）必须开。

**关键技巧：可以省略属性。** 如果某个属性对模型没影响，你可以不写它。比如你的方块有 `waterlogged` 但含水与否不影响外观，那么 `"facing=north"` 这一个键就能同时匹配 `facing=north,waterlogged=true` 和 `facing=north,waterlogged=false`。空字符串 `""` 能匹配**所有**状态——这也是为什么最简单的方块只写一个 `""`。

省略属性时游戏怎么选？**匹配得越具体越优先。** 所以你完全可以写一个 `""` 兜底，再为几个特殊状态单独写键。

### `multipart`：按属性拼装

栅栏、墙、红石线、铁轨这类方块，外观是「几个零件按条件组合」，用 `variants` 写会爆炸（栅栏有 4 个方向布尔属性，组合数是 16）。这时用 `multipart`：

```json
{
  "multipart": [
    {
      "apply": { "model": "dafeiyu:block/ruby_post" }
    },
    {
      "when": { "north": "true" },
      "apply": { "model": "dafeiyu:block/ruby_side", "uvlock": true }
    },
    {
      "when": { "south": "true" },
      "apply": { "model": "dafeiyu:block/ruby_side", "y": 180, "uvlock": true }
    },
    {
      "when": { "east": "true" },
      "apply": { "model": "dafeiyu:block/ruby_side", "y": 90, "uvlock": true }
    },
    {
      "when": { "west": "true" },
      "apply": { "model": "dafeiyu:block/ruby_side", "y": 270, "uvlock": true }
    }
  ]
}
```

读法：**每个元素独立判断，满足 `when` 就画上去，全部叠在一起。** 第一个没有 `when`，所以永远画——那是中心柱。后面四个各管一个方向。

`when` 里可以写多个属性，默认是「与」（AND）。想「或」就写成 `"OR": [...]`。也可以在 `when` 里用 `|` 表示多个值：`"facing": "north|east"`。

### 什么时候必须写方块状态文件

答案：**永远是必须的。** 每个方块都必须有一个，少了就是紫黑。

但「写多复杂」取决于方块有多少属性影响外观：

| 情况 | 写法 |
|---|---|
| 无属性，或属性不影响外观 | 一个 `""` 就够 |
| 有朝向（`facing`）且外观随朝向变 | 每个朝向一个键，配 `y` 旋转 |
| 有开关/等级等状态，每个状态外观不同 | 每个状态一个键 |
| 外观由多个布尔属性「拼」出来（栅栏、墙、管道） | `multipart` |

判断口诀：**如果状态之间是「换一张图」，用 `variants`；如果是「加一个零件」，用 `multipart`。**

## 六、纹理规范

### 尺寸

- **方块和物品纹理标准尺寸是 16×16。**
- 1.21 原生支持更大的尺寸（32×32、64×64 都行），游戏会按比例缩放。做高清材质时用 32 或 64 的倍数。
- 尺寸应该是**2 的幂**：16、32、64、128。非 2 的幂只在你自己的 GUI 里渲染时才勉强可用，而且需要额外处理。
- 缩放时用**最近邻（Nearest Neighbor）**，不要用双线性插值，否则像素会糊成一团。

### 格式

- 只支持 **PNG**。JPG、GIF、WebP 一律不认。
- 必须保留 **alpha 通道**。即使是完全不透明的方块，也存成 32 位 PNG。存成 24 位无 alpha 的图，某些工具链会读成「全透明」或「全黑」。
- 半透明像素（alpha 在 1~254 之间）只有 `translucent` 渲染类型才正确处理。用 `cutout` 时，任何 alpha 小于阈值的像素会被当成完全透明，边缘会出现硬锯齿。

### 动画纹理

动画纹理的原理很朴素：**把每一帧竖着排在一张图里**。一个 16×16、8 帧的动画，就是一个 16×128 的 PNG，从上到下是第 0 帧到第 7 帧。

光有长图不够，还要一个同名的 `.mcmeta` 文件告诉游戏「这是一张动画图」：

文件：`src/main/resources/assets/dafeiyu/textures/block/ruby_lamp.png.mcmeta`

```json
{
  "animation": {
    "frametime": 2,
    "frames": [0, 1, 2, 3, 4, 3, 2, 1],
    "interpolate": false
  }
}
```

| 字段 | 含义 | 默认 |
|---|---|---|
| `frametime` | 每帧停留多少个游戏刻（20 刻 = 1 秒） | 1 |
| `frames` | 播放顺序。不写就是从第 0 帧顺序播到底再循环 | 顺序 |
| `interpolate` | 帧之间是否做插值渐变 | `false` |
| `width` / `height` | 单帧宽高。不写则用纹理宽度 | 纹理宽度 |

`frames` 数组里还可以写对象来单独控制某一帧的时长：`{"index": 0, "time": 10}`。做「亮 0.5 秒、暗 0.5 秒」的呼吸灯效果就用它。

**注意 `.mcmeta` 的文件名是 `xxx.png.mcmeta`**，不是 `xxx.mcmeta`。多一个 `.png` 少一个 `.png`，效果就是「纹理被拉成一条竖条」——因为游戏把它当成了一张 16×128 的静态图。

## 七、完整示例：红宝石方块 + 红宝石台座

### 1. 红宝石方块（`cube_all` 路线）

文件：`src/main/resources/assets/dafeiyu/blockstates/ruby_block.json`

```json
{
  "variants": {
    "": {
      "model": "dafeiyu:block/ruby_block"
    }
  }
}
```

文件：`src/main/resources/assets/dafeiyu/models/block/ruby_block.json`

```json
{
  "parent": "minecraft:block/cube_all",
  "textures": {
    "particle": "dafeiyu:block/ruby_block",
    "all": "dafeiyu:block/ruby_block"
  }
}
```

文件：`src/main/resources/assets/dafeiyu/models/item/ruby_block.json`

```json
{
  "parent": "dafeiyu:block/ruby_block"
}
```

文件：`src/main/resources/assets/dafeiyu/textures/block/ruby_block.png` —— 16×16，深红底 + 浅红高光点，四周一圈略暗的边框（让方块之间有分界感）。

逐字段说明：

- `"variants"` 只有一个键 `""`，因为 `ruby_block` 没有任何 `BlockState` 属性。这个键匹配所有状态。
- `"model": "dafeiyu:block/ruby_block"` 是**相对 `models/` 的路径**，所以实际文件是 `models/block/ruby_block.json`。**不要写成 `dafeiyu:models/block/ruby_block`**，也不要在路径里带 `.json`。
- `"parent": "minecraft:block/cube_all"` 继承六个面、uv、光照。
- `"all"` 是 `cube_all` 定义的变量名。改叫 `"texture"` 就是紫黑。
- `"particle"` 决定破坏粒子。
- 物品模型只有一行 `parent`，直接复用方块模型。**方块物品几乎都这么写**，不要傻乎乎地给它单独画一张 `item/ruby_block.png`。

### 2. 红宝石台座（自定义 `elements` 路线）

这是一个 12×4 的底座 + 6×8 的柱身 + 8×2 的顶板，用来放展示品。

文件：`src/main/resources/assets/dafeiyu/models/block/ruby_pedestal.json`

```json
{
  "parent": "minecraft:block/block",
  "textures": {
    "particle": "dafeiyu:block/ruby_block",
    "base": "dafeiyu:block/ruby_pedestal_base",
    "pillar": "dafeiyu:block/ruby_pedestal_pillar"
  },
  "elements": [
    {
      "from": [2, 0, 2],
      "to": [14, 4, 14],
      "faces": {
        "down":  { "uv": [2, 2, 14, 14], "texture": "#base", "cullface": "down" },
        "up":    { "uv": [2, 2, 14, 14], "texture": "#base" },
        "north": { "uv": [2, 12, 14, 16], "texture": "#base" },
        "south": { "uv": [2, 12, 14, 16], "texture": "#base" },
        "west":  { "uv": [2, 12, 14, 16], "texture": "#base" },
        "east":  { "uv": [2, 12, 14, 16], "texture": "#base" }
      }
    },
    {
      "from": [6, 4, 6],
      "to": [10, 12, 10],
      "faces": {
        "up":    { "uv": [6, 6, 10, 10], "texture": "#pillar" },
        "north": { "uv": [6, 4, 10, 12], "texture": "#pillar" },
        "south": { "uv": [6, 4, 10, 12], "texture": "#pillar" },
        "west":  { "uv": [6, 4, 10, 12], "texture": "#pillar" },
        "east":  { "uv": [6, 4, 10, 12], "texture": "#pillar" }
      }
    },
    {
      "from": [4, 12, 4],
      "to": [12, 14, 12],
      "faces": {
        "up":    { "uv": [4, 4, 12, 12], "texture": "#base" },
        "north": { "uv": [4, 14, 12, 16], "texture": "#base" },
        "south": { "uv": [4, 14, 12, 16], "texture": "#base" },
        "west":  { "uv": [4, 14, 12, 16], "texture": "#base" },
        "east":  { "uv": [4, 14, 12, 16], "texture": "#base" }
      }
    }
  ]
}
```

要点：

- 第二个元素**没写 `down` 面**，因为它永远贴在第一个元素的顶面上，看不到。少画一个面就少一份顶点。
- 第一个元素的 `down` 面写了 `"cullface": "down"`，放在地上时这个面直接不画。
- 三个元素都从 y=0 开始往上堆，总高度 14 像素，比满方块矮 2 像素。
- `parent` 是 `minecraft:block/block`，所以物品栏里的摆放角度是对的。

配套方块状态（台座没有属性，所以还是一个 `""`）：

文件：`src/main/resources/assets/dafeiyu/blockstates/ruby_pedestal.json`

```json
{
  "variants": {
    "": { "model": "dafeiyu:block/ruby_pedestal" }
  }
}
```

物品模型：

文件：`src/main/resources/assets/dafeiyu/models/item/ruby_pedestal.json`

```json
{
  "parent": "dafeiyu:block/ruby_pedestal"
}
```

方块属性里记得加 `.noOcclusion()`，否则相邻方块的面会被错误剔除。

### 3. 红宝石熔炉（`orientable` + 朝向旋转）

文件：`src/main/resources/assets/dafeiyu/models/block/ruby_furnace.json`

```json
{
  "parent": "minecraft:block/orientable",
  "textures": {
    "particle": "dafeiyu:block/ruby_furnace_front",
    "top": "dafeiyu:block/ruby_block",
    "side": "dafeiyu:block/ruby_block",
    "front": "dafeiyu:block/ruby_furnace_front"
  }
}
```

文件：`src/main/resources/assets/dafeiyu/blockstates/ruby_furnace.json`

```json
{
  "variants": {
    "facing=north": { "model": "dafeiyu:block/ruby_furnace" },
    "facing=east":  { "model": "dafeiyu:block/ruby_furnace", "y": 90 },
    "facing=south": { "model": "dafeiyu:block/ruby_furnace", "y": 180 },
    "facing=west":  { "model": "dafeiyu:block/ruby_furnace", "y": 270 }
  }
}
```

为什么 `facing=north` 不加旋转？因为 `orientable` 的正面本来就朝北（-z）。其他三个方向靠 `y` 旋转 90/180/270 度补上。这个「基准朝北」的约定要记住，忘了就是朝向整体偏 90 度。

### 4. 动画纹理

文件：`src/main/resources/assets/dafeiyu/textures/block/ruby_lamp.png` —— 16×64（4 帧）。

文件：`src/main/resources/assets/dafeiyu/textures/block/ruby_lamp.png.mcmeta`

```json
{
  "animation": {
    "frametime": 4,
    "frames": [0, 1, 2, 3]
  }
}
```

`frametime: 4` 表示每帧 4 刻（0.2 秒），一轮 0.8 秒。做呼吸灯就把 `frames` 写成 `[0, 1, 2, 3, 2, 1]`，让它来回走。

## 常见坑与报错

| 现象 | 原因 | 解决 |
|---|---|---|
| 方块紫黑，日志有 `Unable to load model` | `blockstates` 里 `model` 路径写错，或模型文件不存在 | 路径相对 `models/`，不带 `.json` |
| 方块紫黑，但日志没报错 | `textures` 里变量名和父模型对不上（把 `all` 写成 `texture`） | 对照第三节的表 |
| 模型形状对，纹理是紫黑格子 | PNG 路径错，或放在 `textures/items/` | 目录是 `textures/item`、`textures/block` 单数 |
| 破坏方块冒紫色碎块 | 模型里没有 `particle` 纹理 | `textures` 加 `"particle"` |
| 方块朝向整体偏 90 度 | 基准方向搞错，或 `y` 旋转值配错 | `orientable` 正面朝北，`facing=east` 配 `y: 90` |
| 旋转后纹理跟着转，字倒过来了 | 没加 `"uvlock": true` | 加在模型对象里 |
| 物品栏里的方块巨大/角度歪 | 自定义 `elements` 模型没继承 `minecraft:block/block` | 加 `"parent": "minecraft:block/block"` |
| 物品栏里物品是一张 16×16 大平面 | 用 `item/generated` 直接指向方块纹理 | 方块物品的模型应 `parent` 到 `block/xxx` |
| 剑在手里像贴纸 | 用了 `item/generated` 而不是 `item/handheld` | 换父模型 |
| 动画纹理被拉成竖条 | `.mcmeta` 文件名少了 `.png` | 改成 `xxx.png.mcmeta` |
| 透明方块边缘发黑 | 没写 `render_type: cutout` | 模型里加 `"render_type": "minecraft:cutout"` |
| 半透明区域变成全透明 | 用了 `cutout`，它只支持「全透或全不透」 | 改用 `translucent` |
| `multipart` 里零件不出现 | `when` 的属性值写成了布尔 `true` 而不是字符串 `"true"` | JSON 里必须是字符串 |
| 模型文件能加载，但方块不显示 | `blockstates` 文件名和注册名不一致 | 文件名必须是注册名的路径部分 |

## 练习

1. **基础**：给 `ruby_block` 做 32×32 的高清版本，确认游戏里显示正常、没有糊边。
2. **进阶**：做一个 `ruby_lamp`，用 `cube_bottom_top`（顶面亮、侧面暗），配一个 4 帧的动画纹理，`render_type` 用 `cutout`，方块属性加 `.noOcclusion()`。
3. **挑战**：做一个「红宝石栅栏」`ruby_fence`，用 `multipart` 写方块状态。提示：需要 `post` 模型（中心柱）和 `side` 模型（横杆），四个方向各一份，`uvlock` 全部开 `true`。做完把栅栏围成一个圈，检查转角处有没有缝隙。
