# 进度

> 读完这篇，你能给自己的模组做一个带图标、带背景的进度标签页，并让玩家第一次捡到红宝石时弹出「成就达成」的提示。

## 学习目标

- 能说清「进度（advancement）」和玩家口中的「成就」是什么关系，为什么文件不叫 achievement。
- 能默写进度 JSON 的五个顶层字段：`parent`、`display`、`criteria`、`requirements`、`rewards`。
- 能写出 `inventory_changed`、`item_used_on_block`、`player_killed_entity` 三种触发条件的 JSON。
- 能区分根进度和普通进度，知道 `background` 为什么只对根进度有效。
- 能用 `AdvancementProvider` 生成进度，并解释为什么必须用 NeoForge 那个而不是原版那个。
- 能根据「进度不显示」「弹窗不出现」「文字显示成键名」三种现象定位问题。

## 一、进度是什么，和「成就」是什么关系

玩家口中的「成就」，在 Java 版里正式名字叫**进度（advancement）**。1.12 之前确实叫 achievement，1.12 重做系统时改了名，从此：

- 文件叫 `advancement`，不叫 `achievement`。
- 代码里的类是 `Advancement`、`AdvancementHolder`、`CriteriaTrigger`。
- 玩家界面上的标题仍然写「进度」，但弹窗还是那个熟悉的右上角小方块。

进度的本质是**「一组条件 + 满足后的表现」**：

```text
玩家做了某件事
   ↓
某个触发器（trigger）被激活
   ↓
游戏检查所有监听这个触发器的进度：条件满足了吗？
   ↓
满足 → 授予进度 → 弹提示 / 播报 / 发奖励
```

关键点：**进度不是「代码在跑」，而是「游戏在监听」**。你只写数据文件，游戏在玩家做动作时自己去比对。只有当你要加**新的触发条件类型**（比如「玩家第一次钓鱼到红宝石」这种原版没有的事件），才需要写 Java。

这也是为什么进度是最容易上手的「有反馈」的内容：不用写逻辑，改一个 JSON 就能让玩家看到弹窗。

## 二、JSON 结构

进度文件放在：

```text
src/main/resources/data/dafeiyu/advancement/<名字>.json
```

同样是**单数** `advancement`（1.21 的改动）。文件名的路径部分就是进度 id，比如 `advancement/ruby/got_ruby.json` 的 id 是 `dafeiyu:ruby/got_ruby`。

五个顶层字段：

| 字段 | 必填 | 作用 |
|---|---|---|
| `parent` | 否 | 父进度的 id。**不写就是根进度** |
| `display` | 否 | 界面上怎么显示。**不写则不可见，但仍可被触发** |
| `criteria` | 是 | 条件表，键是条件名，值是「触发器 + 参数」 |
| `requirements` | 否 | 哪些条件必须满足。不写 = 全部都要 |
| `rewards` | 否 | 完成时给什么：经验、配方、战利品表、函数 |

### 2.1 `display`

```json
"display": {
  "icon": { "id": "dafeiyu:ruby" },
  "title": { "translate": "advancement.dafeiyu.got_ruby.title" },
  "description": { "translate": "advancement.dafeiyu.got_ruby.description" },
  "frame": "task",
  "background": "dafeiyu:textures/block/ruby_block.png",
  "show_toast": true,
  "announce_to_chat": true,
  "hidden": false
}
```

- `icon`：图标，是**物品堆的 JSON 表示**（`{"id": ...}`），不是纹理路径。想用自定义图？做一个隐藏物品，或者用现成物品。
- `title` / `description`：文本组件。用 `translate` 而不是 `text`，这样语言文件里能翻译；中文玩家看到中文，英文玩家看到英文。
- `frame`：边框样式，`task`（普通，方形）、`goal`（目标，圆角）、`challenge`（挑战，带刺）。默认 `task`。
- `background`：标签页的背景纹理。**只对根进度有效**，子进度写了也没用。路径必须带 `textures/` 前缀，比如 `dafeiyu:textures/block/ruby_block.png`——它不相对于 `textures` 目录，而是相对于资源包根。
- `show_toast`：完成时右上角弹不弹窗，默认 true。
- `announce_to_chat`：完成时聊天栏播报不播报，默认 true。单人游戏里这个播报只有你自己看得见，多人服务器里所有人都看得见。
- `hidden`：完成前在界面里隐藏。默认 false。**对根进度本身无效**，但会隐藏它所有的子进度。

### 2.2 `criteria`

```json
"criteria": {
  "has_ruby": {
    "trigger": "minecraft:inventory_changed",
    "conditions": {
      "items": [
        { "items": "dafeiyu:ruby", "count": { "min": 1 } }
      ]
    }
  }
}
```

- 键（这里是 `has_ruby`）是**你自己起的条件名**，只在 `requirements` 里被引用。
- `trigger`：触发器 id，决定 `conditions` 里能写什么。原版触发器都在 `CriteriaTriggers` 类里，JSON 规范见 Minecraft Wiki。
- `conditions`：可选。不写表示「只要这个触发器被激活就算满足」。

### 2.3 `requirements`

`requirements` 是一个「列表的列表」，语义是：**外层是 AND，内层是 OR**。

```json
"requirements": [
  ["has_ruby"],
  ["craft_ruby_block", "find_ruby_block"]
]
```

意思是：必须满足 `has_ruby`，**并且**（满足 `craft_ruby_block` **或** `find_ruby_block` 其中之一）。

不写 `requirements` 时默认是「所有条件都要满足」，等价于每个条件单独一个内层列表。只写一个条件时，`requirements` 完全可以省略。

### 2.4 `rewards`

```json
"rewards": {
  "experience": 10,
  "recipes": ["dafeiyu:ruby_block"],
  "loot": ["dafeiyu:chests/ruby_reward"],
  "function": "dafeiyu:give_ruby_kit"
}
```

四个都是可选的：`experience`（经验点数）、`recipes`（解锁的配方 id）、`loot`（掷一次并给玩家的战利品表）、`function`（运行的 mcfunction）。想做「完成进度送一套装备」，最省事的写法是 `loot` + 一个战利品表，别去写函数。

## 三、常用触发器

| 触发器 | 什么时候激活 | `conditions` 能写什么 |
|---|---|---|
| `minecraft:inventory_changed` | 背包内容变化 | `items`（物品谓词数组）、`slots` |
| `minecraft:item_used_on_block` | 拿着物品右键方块 | `location`（位置谓词）、`item` |
| `minecraft:player_killed_entity` | 玩家杀死实体 | `entity`（实体谓词） |
| `minecraft:placed_block` | 放置方块 | `location`、`item` |
| `minecraft:consume_item` | 吃掉/喝掉物品 | `item` |
| `minecraft:changed_dimension` | 换维度 | `from`、`to` |
| `minecraft:enter_block` | 身体进入某方块 | `block` |
| `minecraft:tick` | 每刻 | 无（等于「立刻满足」） |
| `minecraft:impossible` | 永不自动激活 | 无（只能靠命令授予） |

三个例子：

```json
"criteria": {
  "use_on_ruby_block": {
    "trigger": "minecraft:item_used_on_block",
    "conditions": {
      "location": [
        {
          "condition": "minecraft:block_state_property",
          "block": "dafeiyu:ruby_block"
        }
      ],
      "item": { "items": "dafeiyu:ruby" }
    }
  }
}
```

```json
"criteria": {
  "kill_zombie_with_ruby_sword": {
    "trigger": "minecraft:player_killed_entity",
    "conditions": {
      "entity": { "type": "minecraft:zombie" }
    }
  }
}
```

```json
"criteria": {
  "place_ruby_block": {
    "trigger": "minecraft:placed_block",
    "conditions": {
      "item": { "items": "dafeiyu:ruby_block" }
    }
  }
}
```

`minecraft:tick` 值得单独说：它每刻都激活，条件永远满足，所以**一进游戏就完成**。这是「根进度」的标准写法——根进度需要有个「入口」，但又不想让玩家真的做什么。

### 3.1 多个条件怎么组合

想做「用红宝石剑杀死僵尸，**或者**用红宝石镐挖到红宝石矿石」这样一个二选一的进度：

```json
{
  "criteria": {
    "kill_with_sword": {
      "trigger": "minecraft:player_killed_entity",
      "conditions": { "entity": { "type": "minecraft:zombie" } }
    },
    "mine_ore": {
      "trigger": "minecraft:inventory_changed",
      "conditions": { "items": [ { "items": "dafeiyu:ruby" } ] }
    }
  },
  "requirements": [
    ["kill_with_sword", "mine_ore"]
  ]
}
```

内层两个名字放在同一个子列表里，就是「满足任意一个即可」。如果把 `requirements` 写成 `[["kill_with_sword"], ["mine_ore"]]`，就变成「两个都要满足」。

**注意**：`criteria` 里的条件一旦满足就会被记录、不会撤销。所以「A 或 B」这种进度，玩家先做了 A，之后再去做 B 也不会重复触发——这符合直觉，但如果你想要「必须按顺序做」，得拆成两个父子进度，靠 `parent` 串起来。

## 四、自定义进度：第一次拿到红宝石

分两个文件：一个根进度（建标签页），一个真正的进度（弹窗）。

### 4.1 根进度

文件：`src/main/resources/data/dafeiyu/advancement/root.json`

```json
{
  "display": {
    "icon": { "id": "dafeiyu:ruby_block" },
    "title": { "translate": "advancement.dafeiyu.root.title" },
    "description": { "translate": "advancement.dafeiyu.root.description" },
    "background": "dafeiyu:textures/block/ruby_block.png",
    "frame": "task",
    "show_toast": false,
    "announce_to_chat": false
  },
  "criteria": {
    "tick": {
      "trigger": "minecraft:tick"
    }
  }
}
```

`show_toast` 和 `announce_to_chat` 都设成 false：根进度是「入口」，不该在玩家进游戏时弹一个「你获得了：大肥鱼」的窗。

### 4.2 第一次拿到红宝石

文件：`src/main/resources/data/dafeiyu/advancement/got_ruby.json`

```json
{
  "parent": "dafeiyu:root",
  "display": {
    "icon": { "id": "dafeiyu:ruby" },
    "title": { "translate": "advancement.dafeiyu.got_ruby.title" },
    "description": { "translate": "advancement.dafeiyu.got_ruby.description" },
    "frame": "task",
    "show_toast": true,
    "announce_to_chat": true,
    "hidden": false
  },
  "criteria": {
    "has_ruby": {
      "trigger": "minecraft:inventory_changed",
      "conditions": {
        "items": [
          {
            "items": "dafeiyu:ruby",
            "count": { "min": 1 }
          }
        ]
      }
    }
  },
  "requirements": [
    ["has_ruby"]
  ],
  "rewards": {
    "experience": 10
  }
}
```

`parent` 写 `dafeiyu:root`（不带 `.json`），指向 4.1 那个文件。`inventory_changed` 在**捡起、合成、从箱子里拿出**红宝石时都会激活，所以「第一次获得」这个语义是天然满足的——进度只会被授予一次。

### 4.3 语言文件

文件：`src/main/resources/assets/dafeiyu/lang/zh_cn.json`

```json
{
  "advancement.dafeiyu.root.title": "大肥鱼",
  "advancement.dafeiyu.root.description": "红宝石的世界从这里开始",
  "advancement.dafeiyu.got_ruby.title": "第一颗红宝石",
  "advancement.dafeiyu.got_ruby.description": "挖到一颗红宝石"
}
```

`en_us.json` 里写英文。**翻译键漏了会直接显示键名**（`advancement.dafeiyu.got_ruby.title` 这一长串），这是「进度能显示但文字很丑」的唯一原因。

## 五、用 `AdvancementProvider` 生成进度

手写进度最烦的是「`parent` 的 id 拼错」和「翻译键打错」。datagen 能解决第一个：父进度用变量传，不写字符串。

（datagen 的通用流程见 [数据生成](05-数据生成.md)，这里只讲进度相关的部分。）

**先注意一个陷阱**：Minecraft 和 NeoForge 各有一个 `AdvancementProvider`：

- `net.minecraft.data.advancements.AdvancementProvider`（原版）
- `net.neoforged.neoforge.common.data.AdvancementProvider`（NeoForge）

**永远用 NeoForge 那个**。原版的接口老旧、不支持 `ExistingFileHelper` 校验，NeoForge 的重写了它。

文件：`src/main/java/com/dafeiyu/datagen/ModAdvancementProvider.java`

```java
package com.dafeiyu.datagen;

import com.dafeiyu.DafeiyuMod;
import com.dafeiyu.ModItems;
import net.minecraft.advancements.Advancement;
import net.minecraft.advancements.AdvancementHolder;
import net.minecraft.advancements.AdvancementRewards;
import net.minecraft.advancements.AdvancementType;
import net.minecraft.advancements.critereon.InventoryChangeTrigger;
import net.minecraft.advancements.critereon.PlayerTrigger;
import net.minecraft.core.HolderLookup;
import net.minecraft.data.PackOutput;
import net.minecraft.network.chat.Component;
import net.minecraft.resources.ResourceLocation;
import net.minecraft.world.item.ItemStack;
import net.neoforged.neoforge.common.data.AdvancementProvider;
import net.neoforged.neoforge.common.data.ExistingFileHelper;

import java.util.List;
import java.util.concurrent.CompletableFuture;
import java.util.function.Consumer;

public class ModAdvancementProvider extends AdvancementProvider {

    public ModAdvancementProvider(PackOutput output,
                                  CompletableFuture<HolderLookup.Provider> lookupProvider,
                                  ExistingFileHelper existingFileHelper) {
        // 第四个参数是生成器列表。拆成多个生成器纯粹是为了好维护，功能上等价
        super(output, lookupProvider, existingFileHelper, List.of(new ModAdvancements()));
    }

    private static final class ModAdvancements implements AdvancementProvider.AdvancementGenerator {

        @Override
        public void generate(HolderLookup.Provider registries,
                             Consumer<AdvancementHolder> saver,
                             ExistingFileHelper existingFileHelper) {

            // ---- 根进度：建标签页 ----
            AdvancementHolder root = Advancement.Builder.advancement()
                    .display(new ItemStack(ModItems.RUBY_BLOCK.get()),
                            Component.translatable("advancement.dafeiyu.root.title"),
                            Component.translatable("advancement.dafeiyu.root.description"),
                            // 背景纹理，必须带 textures/ 前缀
                            ResourceLocation.fromNamespaceAndPath(DafeiyuMod.MOD_ID, "textures/block/ruby_block.png"),
                            AdvancementType.TASK,
                            false,   // showToast
                            false,   // announceToChat
                            false)   // hidden
                    .addCriterion("tick", PlayerTrigger.TriggerInstance.tick())
                    .save(saver, ResourceLocation.fromNamespaceAndPath(DafeiyuMod.MOD_ID, "root"), existingFileHelper);

            // ---- 子进度：第一次拿到红宝石 ----
            Advancement.Builder.advancement()
                    .parent(root)                       // 传变量，不可能拼错
                    .display(new ItemStack(ModItems.RUBY.get()),
                            Component.translatable("advancement.dafeiyu.got_ruby.title"),
                            Component.translatable("advancement.dafeiyu.got_ruby.description"),
                            null,                       // 非根进度不需要背景
                            AdvancementType.TASK,
                            true,
                            true,
                            false)
                    .addCriterion("has_ruby",
                            InventoryChangeTrigger.TriggerInstance.hasItems(ModItems.RUBY.get()))
                    .rewards(AdvancementRewards.Builder.experience(10))
                    .save(saver, ResourceLocation.fromNamespaceAndPath(DafeiyuMod.MOD_ID, "got_ruby"), existingFileHelper);
        }
    }
}
```

几处说明：

- `Advancement.Builder.advancement()`：会自动开启遥测（telemetry）。不想要就用 `recipeAdvancement()`，功能上没有别的差别。
- `.display(...)`：八个参数分别是图标、标题、描述、背景、边框、弹窗、播报、隐藏。图标可以传 `ItemStack` 也可以传 `ItemLike`。
- `.parent(AdvancementHolder)`：直接传上一步 `save` 返回的 holder。**这是 datagen 最大的价值**——手写 JSON 时 parent 是一个字符串，拼错就是「进度不显示」。
- `.addCriterion(名字, 条件)`：条件用对应触发器的静态方法构造。`hasItems(ItemLike)` 就是「背包里有这个物品」。
- `.rewards(...)`：可以链式 `.addLootTable(...)`、`.addRecipe(...)`、`.runs(...)`。
- `.save(saver, id, existingFileHelper)`：`existingFileHelper` 会在生成时校验「引用的纹理/物品真的存在」，比游戏里才发现好得多。

**关于根进度的 `tick` 条件**：`PlayerTrigger.TriggerInstance.tick()` 就是那个「每刻都满足」的条件，对应 JSON 里的 `{"trigger": "minecraft:tick"}`。注意它来自 `net.minecraft.advancements.critereon.PlayerTrigger`，记得补 import。根进度必须有至少一个 `criteria`，用 `tick` 是最省事的做法——它进游戏就完成，等于「解锁这个标签页」。

注册 provider：

```java
generator.addProvider(event.includeServer(),
        new ModAdvancementProvider(output, lookupProvider, existingFileHelper));
```

## 六、根进度与标签页

进度的界面是「标签页 + 树」的结构：

```text
[原版·进度] [原版·下界] [原版·末地] [大肥鱼]   ← 标签页
                                    └── root（根）
                                         ├── got_ruby
                                         └── craft_ruby_block
```

- **标签页由目录决定**。`data/dafeiyu/advancement/root.json` 里的根进度建出「大肥鱼」标签页；如果把文件放到 `data/dafeiyu/advancement/ruby/root.json`，标签页名就是 `ruby`。
- **一个标签页可以有多个根**，每个根长出一棵树。空的标签页会被自动隐藏。
- 原版约定根进度永远叫 `root`，跟着这个习惯走，以后看别人的包不会迷路。
- `background` 只在根进度上生效，决定整个标签页的底图。原版用的是 16×16 的纹理平铺，你拿方块纹理直接当背景就行。

**想挂到原版标签页下面？** 把 `parent` 写成 `minecraft:story/root`，你的进度就会出现在「进度」标签页里，紧跟在「Minecraft」后面。这是模组最常见的做法——玩家不用去找你的新标签页。

## 完整示例

```text
src/main/java/com/dafeiyu/datagen/
├── DataGenerators.java              ← 注册 provider
└── ModAdvancementProvider.java      ← 第五节

src/main/resources/data/dafeiyu/advancement/
├── root.json                        ← 4.1 节
└── got_ruby.json                    ← 4.2 节

src/main/resources/assets/dafeiyu/lang/
├── zh_cn.json                       ← 4.3 节
└── en_us.json
```

验证：

1. 进游戏，按 `L` 打开进度界面，右侧应该多出一个「大肥鱼」标签页，图标是红宝石块，背景是红宝石纹理。
2. `/give @s dafeiyu:ruby`，右上角应该弹出「第一颗红宝石」，聊天栏播报，经验条涨 10 点。
3. 再 `/give @s dafeiyu:ruby`，不再弹窗（进度只授予一次）。
4. `/advancement revoke @s only dafeiyu:got_ruby` 可以撤销，用来反复测试。
5. `/advancement grant @s only dafeiyu:root` 可以在不满足条件的情况下手动授予，用来单独验证显示效果。

## 常见坑与报错

| 现象 | 原因 | 解决 |
|---|---|---|
| 进度完全不显示 | 没有根进度，或 `parent` 指向了一个不存在的 id | 先建 `root.json`（不写 `parent`），子进度的 `parent` 对着文件名核对 |
| 进度树里有个灰框，点不进去 | `parent` 的 id 拼错，游戏建了一个「占位」父节点 | 检查 `dafeiyu:root` 是否真的存在，注意不要写成 `dafeiyu:root.json` |
| 弹窗不出现，但进度已授予 | `display` 里 `show_toast` 是 false，或整个 `display` 没写 | 补 `display`，确认 `show_toast: true` |
| 标题显示成一长串 `advancement.dafeiyu.xxx.title` | 语言文件里没有这个键 | 在 `zh_cn.json` / `en_us.json` 补上，注意大小写和下划线 |
| 加载报 `Unknown criterion 'xxx'` | `requirements` 里引用的名字和 `criteria` 的键不一致 | 两边逐字对齐，建议复制粘贴而不是手打 |
| 背景是一团紫色黑色格子 | `background` 路径写错，或没带 `textures/` 前缀 | 写成 `dafeiyu:textures/block/ruby_block.png` |
| 背景写在子进度上没效果 | `background` 只对根进度有效 | 挪到根进度 |
| 进度文件完全不被读取 | 目录写成了 `advancements/`（1.20 写法） | 1.21 是 `advancement/`（单数） |
| datagen 报找不到纹理 | `existingFileHelper` 校验失败，纹理不存在 | 检查 `assets/dafeiyu/textures/...` 是否真的有这个文件 |
| 一进游戏就弹了一堆窗 | 根进度忘了关 `show_toast` | 根进度设 `show_toast: false`、`announce_to_chat: false` |

## 练习

1. **照抄跑通**：把第四节的三个文件（root、got_ruby、语言文件）落地，进游戏确认弹窗和标签页都对。
2. **加一个 goal**：做一个「合成红宝石块」的进度，`parent` 指向 `got_ruby`，`frame` 用 `goal`，`rewards` 给 20 点经验。观察它和 `task` 在界面上的区别。
3. **挂到原版树**：把 `got_ruby` 的 `parent` 改成 `minecraft:story/root`，看看它出现在哪个标签页、排在哪。
4. **用 datagen 重做**：删掉手写的两个 JSON，用 `ModAdvancementProvider` 生成，对比生成出来的文件和手写版的差别（提示：`sends_telemetry_event` 字段、`requirements` 的写法）。
