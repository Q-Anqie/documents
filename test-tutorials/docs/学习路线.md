# 软件测试学习路线

!!! abstract "新手导读"
    这份路线用于回答"先学什么、后学什么、学到什么程度可以进入下一阶段"。如果你是零基础或转岗学习，建议按顺序推进；如果已经有经验，可以直接跳到薄弱阶段补齐。

    每一个阶段的「达成标准」都写成了**可以当场做一遍的动作**，而不是"理解""掌握"这类形容词——因为形容词无法判断，动作可以。

---

## 一、先判断你是哪类人，再决定怎么走

不同起点的人，最省时间的走法完全不一样。**别从第 1 页开始顺读**，先对号入座：

| 人群 | 你的真实短板 | 建议起手路径 | 大概要花多久 |
|------|--------------|--------------|--------------|
| 完全零基础 / 转行 | 不知道测试在干什么，也没摸过真实系统 | 第 1 阶段全程 → 第 2 阶段的前 4 个工具（SQL / Linux / Git / Postman）→ 停下做一次项目实战 | 6-8 周 |
| 手工测试想转自动化 | 会点点点，但不会写代码、不会看日志 | 跳过第 1 阶段，直接补 **Python 基础**（第 4 阶段里那篇）→ 再回第 2 阶段补 SQL / Linux → 然后第 4 阶段接口自动化 | 8-10 周 |
| 只会 Postman 点点点 | 会用工具，但设计不出完整用例，也不会断言 | 第 3 阶段接口测试方法论 → 第 2 阶段网络知识 → 第 4 阶段 Python 接口自动化 | 3-4 周 |
| 测试在职想涨薪 | 只会功能测试，缺性能 / 安全 / CI 这类"能写进 JD 的加分项" | 直接第 3 阶段（性能 + 安全）→ 第 5 阶段 CI/CD 与项目实战 | 4-6 周 |
| 想转测试开发 / SDET | 完全没有工程能力，代码量不够 | 第 4 阶段全程 + [测试框架设计与设计模式](自动化测试/测试框架设计与设计模式教程.md) + [面试专题：测试岗位技能对照与补课指南](面试专题/测试岗位技能对照与补课指南.md) | 10-14 周 |

!!! tip "不确定自己属于哪类？做一次诊断"
    [测试岗位技能对照与补课指南](面试专题/测试岗位技能对照与补课指南.md) 按 15 类岗位给出覆盖度评分和缺口清单，比自己猜准得多。
    也可以先做一遍 [阶段学习检查清单](阶段学习检查清单.md) 的第 1 阶段部分——**勾得上一半以上，说明你不用从头学**。

## 二、五阶段学习路径

```text
第 1 阶段：测试入门        2-3 周   建立测试思维，能拆测试点、写用例、提缺陷
    ↓
第 2 阶段：工具实战        3-4 周   能用数据库、日志、命令行、接口工具自己查问题
    ↓
第 3 阶段：专项测试        2-3 周   能设计接口用例，能做基础压测和安全验证
    ↓
第 4 阶段：自动化测试      4-6 周   能把用例变成可重复运行的代码
    ↓
第 5 阶段：项目与面试      3-4 周   能把能力变成作品集和 offer
```

学习时不要只看教程。每个阶段都应该完成练习任务，并能说清楚"为什么这样测、怎么定位问题、如何输出结果"。

!!! warning "一条比"按顺序学"更重要的原则"
    每个阶段结束时，**必须有一个可交付的产物**（第 1 阶段是一份用例表，第 2 阶段是一份排查记录，第 4 阶段是能跑起来的脚本仓库……）。

    没有产物的阶段，等同于没学过。因为面试官不会问"你学到第几章"，只会问"你做过什么"。

## 三、第 1 阶段：测试入门 { #stage1 }

**建议学时：2-3 周**（每周投入 8-10 小时）

### 这一阶段到底在练什么

练的是**"看到需求就能想到该怎么测"**这件事。工具一个都不用会，但必须能把一个模糊需求拆成一张别人能照着执行的用例表。

### 学习目标

- 理解软件测试的目的、流程和常见分类。
- 能独立阅读需求并拆分测试点。
- 能编写基础测试用例和缺陷报告。

### 必学教程

- [软件测试理论基础](基础理论/软件测试理论基础教程.md)
- [ISTQB 术语速查](基础理论/ISTQB软件测试术语速查.md)
- [测试金字塔与分层策略](基础理论/测试金字塔与自动化分层策略.md)
- [测试用例设计方法论](基础理论/测试用例设计方法论教程-软件测试版.md)
- [探索式测试](基础理论/探索式测试教程-软件测试版.md)
- [敏捷测试](基础理论/敏捷测试教程-软件测试版.md)

### 练习任务

1. 选择一个登录页面，拆分功能测试点、异常测试点和安全测试点。
2. 按等价类、边界值和场景法设计不少于 20 条测试用例。
3. 模拟 3 个缺陷，并写出缺陷标题、复现步骤、实际结果和期望结果。

!!! tip "直接对着模板做，别自己发明格式"
    - 用例怎么写 → [测试用例模板](模板库/测试用例模板.md)（含完整填写示例与用例粒度判据）
    - 缺陷怎么提 → [缺陷报告模板](模板库/缺陷报告模板.md)（含严重程度 × 优先级四组合）

### 达成标准

!!! success "能当场做出来就算过关（不是"看懂了"）"
    1. **拆测试点**：给一个陌生需求（比如"优惠券满减"），20 分钟内列出不少于 15 个测试点，且覆盖正常、异常、边界、状态、权限五个角度。
    2. **写用例**：从上一步的测试点里挑 5 个，写成别人能直接照着执行的用例（含前置条件、步骤、预期结果），对方看完不需要问你任何问题。
    3. **提缺陷**：拿一条真实缺陷，写出标题、复现步骤、实际结果、期望结果，且标题里**不出现"有问题""不正常""应该"这类词**。
    4. **说清区别**：能用一个例子说明"严重程度高但优先级低"和"严重程度低但优先级高"分别长什么样。

    以上 4 条里**任意一条做不出来，就先不要进第 2 阶段**——第 2 阶段的工具都是为"更好地完成这 4 件事"服务的，顺序颠倒会变成"会用工具但不知道为什么用"。

### 阶段测验

完成教程后，建议做 [软件测试理论基础测验](基础理论/软件测试理论基础测验.md)、[ISTQB 术语测验](基础理论/ISTQB术语速查测验.md)、[测试金字塔测验](基础理论/测试金字塔测验.md)、[测试用例设计测验](基础理论/测试用例设计测验.md)、[探索式测试测验](基础理论/探索式测试测验.md)、[敏捷测试测验](基础理论/敏捷测试测验.md) 检验学习效果。

!!! tip "有一道能自动判分的题"
    [测试用例设计方法论 · 在线自测](基础理论/测试用例设计方法论教程-软件测试版.md#sec-lab)：给你一个有歧义的需求规则，产出边界三元组并正确分类。全对才算通过，通过后会自动把该教程标记为已学习。

## 四、第 2 阶段：工具实战 { #stage2 }

**建议学时：3-4 周**（每周投入 10-12 小时）

### 这一阶段到底在练什么

练的是**"出问题能自己查"**。测试工程师和技术支持的区别就在这里：同样是"订单创建失败"，前者能自己定位到是哪张表、哪条日志、哪个接口出了问题。

### 学习目标

- 能使用 SQL 查询和校验业务数据。
- 能在 Linux 服务器上查看日志、进程、端口和磁盘。
- 能使用 Git 完成日常协作。
- 能用 Docker 启动基础测试环境。
- 能使用 Postman 调试接口。
- 能使用 Fiddler 或 Charles 抓包分析。

### 必学教程

- [数据库 SQL](工具操作/数据库SQL教程-软件测试版.md)
- [Linux 实用](工具操作/Linux实用教程-软件测试版.md)
- [Git 版本控制](工具操作/Git版本控制教程-软件测试版.md)
- [Docker 容器](工具操作/Docker容器教程-软件测试版.md)
- [Postman 接口](工具操作/Postman接口测试教程-软件测试版.md)
- [Fiddler 抓包](工具操作/Fiddler抓包教程-软件测试版.md)
- [Charles 抓包](工具操作/Charles抓包教程-软件测试版.md)（与 Fiddler 二选一，macOS / 移动端首选）
- [Redis 与 MongoDB](工具操作/Redis与MongoDB教程-软件测试版.md)（选学，缓存与文档库校验）
- [接口抓包联调实战](工具操作/接口抓包联调实战教程-软件测试版.md)（选学，串联完整工作流）
- [正则表达式](工具操作/正则表达式教程-软件测试版.md)
- [网络知识](工具操作/网络知识教程-软件测试版.md)
- [禅道与 Jira 实战](工具操作/禅道与Jira实战教程-软件测试版.md)（缺陷提交与流转，JD 高频要求）

!!! tip "不知道先学哪个工具？先看选型指南再回来"
    上面的工具列表是「按阶段」排的，但你可能更关心「我这个岗位到底该重点投入哪个」。
    [工具选型指南](工具选型指南.md) 按测试场景（SQL / Linux / 抓包 / 接口 / 自动化 / CI）给出选择依据和取舍，
    比逐个试一遍省时间。

### 练习任务

1. 写出用户表、订单表、商品表的常见查询 SQL。
2. 在 Linux 中定位一个端口占用问题。
3. 用 Git 新建分支、提交代码、解决一次模拟冲突。
4. 用 Docker 启动一个数据库或接口服务。
5. 用 Postman 调试登录接口并设置 Token。
6. 用 Fiddler 或 Charles 抓取登录请求并分析参数。

### 达成标准

!!! success "能当场做出来就算过关"
    1. **查数据**：给一句话需求"查本周每个渠道的订单数和金额，按金额降序"，不查资料写出 SQL。
    2. **查不一致**：页面显示订单金额 99.50，你知道去数据库算 `单价 × 数量 - 优惠`，并说出该比哪一列。
    3. **查日志**：只被告知"昨天下午 3 点用户 A 下单失败"，说清你依次敲哪几条命令、看哪几个字段。
    4. **复现接口**：打开任意一个真实网站，从浏览器 Network 里抓一个带 Token 的请求，在 Postman 里改成自己的参数复现成功。
    5. **解决冲突**：在练习仓库里故意制造一次 Git 冲突并解决掉，能解释工作区和暂存区的区别。

    ⚠️ 这一阶段最容易自我欺骗：「我照着教程敲过一遍」和「我能自己敲出来」之间差着一整个阶段的功夫。**判据永远是关掉教程重做一遍。**

### 阶段测验

完成教程后，建议做 [SQL 基础测验](工具操作/SQL基础测验.md)、[Linux 基础测验](工具操作/Linux基础测验.md)、[Git 基础测验](工具操作/Git基础测验.md)、[Docker 基础测验](工具操作/Docker基础测验.md)、[Postman 接口测试测验](工具操作/Postman接口测试测验.md)、[Fiddler 抓包测验](工具操作/Fiddler抓包测验.md)、[Charles 抓包测验](工具操作/Charles抓包测验.md)、[正则表达式测验](工具操作/正则表达式测验.md)、[网络知识测验](工具操作/网络知识测验.md)、[Redis 与 MongoDB 测验](工具操作/Redis与MongoDB测验.md)、[接口抓包联调测验](工具操作/接口抓包联调测验.md)、[禅道与 Jira 测验](工具操作/禅道与Jira测验.md) 检验学习效果。

!!! tip "两道能自动判分的题"
    - [数据库 SQL · 在线自测](工具操作/数据库SQL教程-软件测试版.md#sec-lab)：三段真实的数据校验（金额对不上、禁用用户已支付、超卖）
    - [正则表达式 · 在线自测](工具操作/正则表达式教程-软件测试版.md#sec-lab)：从日志里提取字段并统计

    写不出正则表达式时，直接查 [正则表达式速查表](工具操作/正则表达式速查表-软件测试版.md)，按"我要做什么"找现成的。

## 五、第 3 阶段：专项测试 { #stage3 }

**建议学时：2-3 周**（每周投入 10-12 小时）

### 这一阶段到底在练什么

练的是**"不只测表面"**。功能测试能发现"点了没反应"，接口测试能发现"点了有反应但数据写错了"，性能和安全测试能发现"现在没问题但一上量就崩"。

### 学习目标

- 理解 HTTP 请求、响应、状态码、Header、Cookie、Token。
- 能根据接口文档设计正向、异常、安全和数据一致性用例。
- 能完成基础性能测试脚本设计和结果分析。
- 能识别常见 Web 安全风险。

### 必学教程

- [接口测试方法论](专项测试/接口测试完整教程-软件测试版.md)
- [JMeter 性能测试](专项测试/JMeter性能测试教程-软件测试版.md)
- [Web 安全测试](专项测试/Web安全测试教程-软件测试版.md)
- [AI 辅助测试](专项测试/AI辅助测试教程-软件测试版.md)
- [测试左移与右移](专项测试/测试左右移教程-软件测试版.md)
- [移动端专项测试](专项测试/移动端专项测试教程-软件测试版.md)
- [小程序与 H5 测试](专项测试/小程序与H5测试教程-软件测试版.md)（微信生态，独立招聘方向）

!!! tip "接口测试没有靶场等于没法学"
    [练习靶场与工具清单](项目实战/练习靶场与工具清单.md) 列了 6 个实测可用的公开接口服务，标明了每个的鉴权方式、写入是否真持久化、以及已知坑。
    **练接口测试最怕的不是不会写脚本，而是没有一个能随便折腾的被测对象。**

### 练习任务

1. 为登录、商品查询、加入购物车、创建订单设计接口用例。
2. 对登录或查询接口做一次简单压测，并记录 TPS、响应时间和错误率。
3. 检查接口是否存在越权、弱校验、敏感信息泄露。
4. 用 Redis 或 MongoDB 校验缓存和业务数据。

### 达成标准

!!! success "能当场做出来就算过关"
    1. **设计接口用例**：拿一份接口文档，产出正向 / 参数异常 / 鉴权异常 / 业务规则 / 数据一致性五类用例，每类不少于 3 条。
    2. **识别"假成功"**：解释为什么一个接口返回 `200` 且 `message: "success"` 仍可能是失败的，并举一个自己遇到的例子。
    3. **读懂压测报告**：说出 P95 和平均值差距很大意味着什么，以及你会据此提什么建议。
    4. **发现越权**：用两个自己的账号，改 URL 里的 `userId` 尝试访问对方数据，说清 403、404、返回了对方数据分别意味着什么。

### 阶段测验

完成教程后，建议做 [接口测试基础测验](专项测试/接口测试基础测验.md)、[接口测试进阶测验](专项测试/接口测试进阶测验.md)、[JMeter 性能测试测验](专项测试/JMeter性能测试测验.md)、[Web 安全测试测验](专项测试/Web安全测试测验.md)、[AI 辅助测试测验](专项测试/AI辅助测试测验.md)、[测试左右移测验](专项测试/测试左右移测验.md)、[移动端专项测试测验](专项测试/移动端专项测试测验.md)、[小程序与 H5 测验](专项测试/小程序与H5测试测验.md) 检验学习效果。

!!! tip "两道能自动判分的题"
    - [Postman · 在线自测](工具操作/Postman接口测试教程-软件测试版.md#sec-lab)：写一个会抓缺陷的响应校验器（协议层 / 内容层 / 数据层三层断言）

## 六、第 4 阶段：自动化测试 { #stage4 }

**建议学时：4-6 周**（每周投入 10-12 小时）

### 这一阶段到底在练什么

练的是**"把重复的事交给机器"**。判断标准不是"我写出了脚本"，而是"这套脚本三个月后别人还能维护"。

### 学习目标

- 能判断哪些场景适合自动化，哪些不适合。
- 能使用 Python + Requests + Pytest 做接口自动化。
- 能使用 Selenium 或 Playwright 完成 Web 核心流程自动化。
- 能理解 Page Object、等待机制、失败截图和报告。
- 能了解 Appium 移动端自动化的环境和定位方式。

### 必学教程

### 练习任务

1. 将核心接口改写成 Pytest 自动化用例。
2. 自动化登录、搜索、下单前置流程。
3. 为自动化脚本增加显式等待和失败截图。
4. 用 Page Object 重构一个页面流程。
5. 对比 Selenium 和 Playwright 在等待、定位、网络拦截上的差异。

### 达成标准

!!! success "能当场做出来就算过关"
    1. **换个环境不改代码**：把配置文件里的环境地址改成另一个，测试代码一行不改仍能跑通。
    2. **连跑 5 遍全绿**：同一套用例连续运行 5 次，结果完全一致（有偶发失败就必须先解决，不能靠重试掩盖）。
    3. **失败信息够定位**：故意改坏一条断言，报错信息里能看到期望值、实际值和完整响应。
    4. **别人能加用例**：把代码交给一个没参与的人，不解释任何东西让他加一个新用例——他如果问三个以上问题才加得进去，说明封装还不到位。
    5. **说清取舍**：能举出一个"不该自动化"的场景，并说明理由（一次性活动、UI 频繁改版、结果需要人判断视觉差异等）。

### 作品集产出

每个项目完成后，建议沉淀以下内容：

| 产出物 | 说明 |
|--------|------|
| 测试范围 | 明确测什么、不测什么 |
| 测试点清单 | 按模块拆分功能、异常、权限、数据、兼容性风险 |
| 测试用例 | 包含前置条件、步骤、预期结果和优先级 |
| 接口用例 | 包含参数组合、断言、鉴权、幂等和异常场景 |
| 缺陷示例 | 记录典型缺陷和定位思路 |
| 测试报告 | 汇总执行结果、风险、遗留问题和上线建议 |

### 达成标准

!!! success "能当场做出来就算过关"
    1. **换一个需求重做一遍**：关掉教程，换一个**不同**的需求（做过"下单"就换"退款"），从测试计划写到测试报告，独立走完。
    2. **报告有结论**：测试报告的结论必须是"建议上线 / 有条件上线 / 不建议上线"三者之一，并给出依据，不能只罗列数据。
    3. **讲得清**：手机录音讲 2 分钟项目介绍，回放时能听出"背景 → 职责 → 动作 → 结果"四段结构，且至少 3 处量化。
    4. **答得上追问**：别人问你"这个缺陷为什么是 P1 不是 P0""这个用例为什么这么设计"，你能答出取舍理由而不是复述步骤。

!!! danger "这一阶段最常见的自我欺骗"
    「我做了个项目」——但所有材料都是跟着教程抄的，换个需求就写不出来。

    面试官只要追问两个问题就能分辨：**"这里你为什么不这么测？"** 和 **"如果需求变了，你的用例要改哪几行？"** 照着教程抄的人，这两问都答不上来。

## 九、时间怎么排才现实

很多人卡住不是因为难，而是因为**估时不准导致放弃**。下面这张表是"有效学习时间"的分配建议，可以直接拿去排周计划。

### 每周的时间怎么分

| 投入类型 | 占比 | 具体做什么 |
|----------|------|------------|
| 读教程 | 30% | 只读当周要用的那几篇，不要提前通读 |
| 动手练 | 50% | 练习任务、在线自测、自己造数据折腾 |
| 复盘记笔记 | 20% | 把"踩过的坑"写成三五行，比抄教程有用十倍 |

### 总体节奏

- 每周投入 8-12 小时（周中每天 1-1.5 小时 + 周末 3-4 小时），比"周末突击 10 小时"效果好得多。
- 按五阶段顺序，预计 **14-20 周**完成全部学习；只到第 3 阶段能找初级岗，大约需要 8-10 周。
- **可以慢，但不要断。** 中断两周以上，前一个阶段的手感基本要重来。

!!! warning "两个必须提前想清楚的现实"
    1. **你大概率会卡在第 2 和第 4 阶段**——前者是工具多且琐碎，后者是第一次真正写代码。卡住是正常的，不要因此怀疑路线有问题。
    2. **"学完"不等于"能找到工作"**。第 5 阶段不是可选项，它决定前四个阶段的价值能不能被市场看见。

## 十、常见问题

### Q: 我是零基础，应该从哪里开始？

从第 1 阶段「测试入门」开始，先看 [软件测试理论基础](基础理论/软件测试理论基础教程.md)，建立测试思维。

第一周只做一件事：**把"测试在项目里到底做什么"搞清楚**。具体动作是看一遍 [软件测试理论基础](基础理论/软件测试理论基础教程.md) 的前三章，然后找一个你天天用的 App，列出它的 10 个可能出问题的地方。列不出来说明还没入门，别急着往下学。

### Q: 学完一个阶段后怎么判断是否可以进入下一阶段？

**三道关，全过才算**：

1. **教程读完**：该阶段所有必学教程在 [学习中心](学习中心.md) 里标记为已完成。
2. **测验达标**：阶段测验平均分 **80 以上**（低于 60 的必须重做，60-80 之间挑错题回教程补）。
3. **动手验证**：能通过上面每个阶段写的那几条「达成标准」——**这一条最重要，前两条都能靠刷题糊过去，这一条不能**。

也可以直接对着 [阶段学习检查清单](阶段学习检查清单.md) 勾选，**低于 80% 不建议往下走**。

### Q: 我可以直接跳到自动化测试吗？

不建议。自动化测试需要前面阶段的基础（测试理论、SQL、Linux、接口测试）。如果直接跳到自动化，很容易变成"脚本能跑，但不知道测了什么"。

具体会缺三样东西：**不会设计用例**（脚本只是在执行别人的用例）、**不会查数据**（断言只敢断状态码）、**不会看日志**（脚本失败时只能猜）。这三样都是第 2、3 阶段练的。

如果你已经会其中某几样（比如做过手工测试、会用 SQL），可以只补缺的那部分——用 [阶段学习检查清单](阶段学习检查清单.md) 先勾一遍，勾不上的才是你要补的。

### Q: 学完后能找到工作吗？

**能，但不是"学完"就能，而是"做出东西"才能。**

这个路线覆盖的是一份初级测试岗 JD 的绝大部分要求：功能测试、接口测试、基础性能、SQL、Linux、Git、一点自动化。但企业招人看的是证据：

| 企业真正在看的 | 对应本路线 |
|----------------|------------|
| 能不能独立负责一个模块的测试 | 第 1 阶段达成标准 + 第 5 阶段项目实战 |
| 能不能发现问题背后的根因 | 第 2 阶段（SQL / 日志 / 抓包） |
| 会不会写点自动化提升效率 | 第 4 阶段达成标准第 4 条（别人能加用例） |
| 表达和沟通是否清楚 | 第 5 阶段简历与面试表达 |

**最影响结果的不是学到第几阶段，而是你有没有一个能拿出手的项目。** 一个真实测过的电商系统 + 一份像样的测试报告，比把 139 篇教程全读完更有说服力。

求职落地环节请看 [简历撰写与项目包装](面试专题/简历撰写与项目包装.md)、[岗位 JD 对照与投递策略](面试专题/岗位JD对照与投递策略.md)、[面试流程与谈薪](面试专题/面试流程与谈薪.md)；想看自己距离目标岗位还差什么，看 [测试岗位技能对照与补课指南](面试专题/测试岗位技能对照与补课指南.md)。
